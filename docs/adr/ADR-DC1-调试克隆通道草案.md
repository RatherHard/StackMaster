## 一、决策内容(核心条款)

**新增一条独立的调试通道与调试 VM:调试实例与真实实例共享公开条件集与布局结构,秘密值由同一套种子派生器、两个种子分别派生(调试侧经调试变体镜像落地),会话权威动作日志在调试实例上确定性重放以对齐状态;调试侧一切交互不进权威日志、不参与判题与回放。公开投影契约(12 动作、5 命令、投影 7 字段、D3/D5)与既有 WSS 通道(D-API-2 版本锚定)一字不动。**

条款拆解:

1. **通道独立**:调试协议走**独立 WSS 端点**(独立协议版本、独立帧族;同一 Cookie 凭证模型与会话锚定,复用认证实现),不复用、不扩展 `ActionObjectSchema` 的封闭枚举,也不触碰既有 WSS 通道的版本锚定;golden fixture 与 Rust(serde + schemars)消费面随新契约建立。(通道形态的评审修正见 §六 R3。)

2. **生成条件 = 公开条件集 + 双种子秘密派生**:调试实例与真实实例共享同一**公开条件集**(公开描述包、VM Profile、内存布局、代码区、初始可见投影)与**布局结构**(区域几何、大小、权限、相对布局)。**基址是否相同由题目的 ASLR 开关决定**——关闭:两实例同基址(公开包固定基址);开启:各实例按各自种子独立派生基址,结构不变。**秘密值**(canary、隐藏区域内容等)由**同一套 `SeedDeriver`、两个种子**派生:真实实例用会话/包种子,调试实例用调试种子;落地形态 = challenge-compiler 产出**调试变体初始镜像**(布局同构、秘密值来自调试种子派生),调试 worker 装载变体,**真实私有判题包零装载**;引擎零改动。(评审修正:废除原"哑值填充"表述,见 §六 R2。)

3. **状态对齐 = 权威动作日志确定性重放**:调试实例把会话权威动作日志(类型 + 参数;动作参数是玩家输入,属公开面)从 revision 0 起确定性重放(可从任一 checkpoint 对应的日志位置起)。ASLR 开启时,调试实例是"同结构、异基址"的**兄弟实例**:重放后状态语义平行、绝对地址不同——这正是 ASLR 的教学语义,由 what-if 纪律(条款 7)呈现。**禁止把真实 checkpoint 快照恢复进调试进程**——快照含秘密;经置换变换的恢复列为后续优化,不入首版。调试实例自身确定性(固定调试种子)。

4. **调试交互不进权威日志**:调试侧的执行只改调试实例;append-only 权威动作日志仍只含真实会话动作;verifier 回放面与 `replay_mismatch` 语义零改动。调试侧交互不受判题闸门约束(gate/settle 属判题编排,调试实例未装载)——这是 what-if 语义的组成部分,资源面由条款 6 的限额约束。

5. **判题能力 = 输入缺失,而非功能开关**:调试实例的变体镜像不含判题编排(`judgingConfig` / 隐藏测试)与真实种子——它无可判之物,即使实现有缺陷也不存在可泄露的判题逻辑输入与秘密期望值。

6. **资源限额与解题模式一致**:调试动作与解题动作共用同一套每会话动作频率预算(D-API-50~53),不设第二类限额。后果登记:指令粒度的调试步进会产生大量帧,与解题互相挤占预算(429 冻结形态两边一致);以 `/metrics` 观察后调参,不开第二类。

7. **what-if 纪律**:秘密值与(ASLR 开启时的)基址差异是固有属性;"调试通过 ≠ 提交通过"必须由 UI 显式呈现,调试结果不得渲染为权威结论。ASLR 开启时,硬编码绝对地址的 payload 跨实例失效属**预期教学语义**;泄露类 payload(泄露 → 使用)在真实会话重新泄露、自适应——动作参数在 wire 层是绝对地址,但 payload 程序是数据依赖的配方,跨实例转移的是配方而非字节串。

8. **能力承载面**:任意地址视角/窗口重锚定、全内存字节检索、完整伪指令流(服务端生成的**展示数据**,源 = 公开代码区字节;引擎可执行 IR 仍不出进程,D5 边界在调试通道同样适用)、函数表、地址断点 / run-to-breakpoint、pwndbg 式跳转链全延伸——均由调试通道承载。公开投影维持现状(`currentInstruction` 单条、窗口锚定区域起点)。

9. **与"判状态"语义的衔接**:判题考的是 VM 状态满足由种子/私有包决定的谓词期望(`ret_target_equals` / `memory_equals` / `stack_canary_intact` / `memory_contains` 等,《判题语义规约》§二)。同种子的调试视图 = 谓词期望值答案册——这是条款 2 双种子派生的直接动因,不是可选优化。

## 二、备选方案与拒绝理由

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 需求降级:视角/检索限定在已下发窗口内 | 公开视图保留此形态 | 不满足源文档的 pwndbg 式体验;作为解题模式档的形态保留,不作为全局答案 |
| B. 推翻/扩写 D3:公开协议加"任意地址读窗口" | 拒绝 | 等于给选手内存读取原语;接受/拒绝、长度、时序全要逐一论证不泄露映射布局(9.2),D3"服务端一次性组装、无运行时查询面"的论证被放弃 |
| C. COW fork 克隆 | 拒绝 | fork 把真实秘密值物理复制进调试进程,零过滤即泄露;"过滤的 fork"回到方案 B 的论证复杂度。"重生成 + 日志重放"达到状态对齐而不携带秘密 |
| D. 前端本地 VM 执行调试 | 拒绝 | 违反底线 1/3 与产物隔离纪律;且前端无题目包可载 |
| E. 既有 WSS 通道扩帧族 | 否决(评审 R3) | D-API-2 连接级版本锚定("任何帧携带其他版本一律拒绝")与"不另设版本常量"和调试协议独立迭代需求冲突;独立端点零冲突,复用同一套认证实现即可 |
| **F. 调试克隆 + 独立通道(本 ADR)** | **接受** | 真实 pwn 工作流的结构等价物:本地全可见调试 + 远端判题出分;公开协议与既有通道零改动,秘密面以构造方式闭合 |

## 三、与既有纪律的逐条衔接

| 纪律 | 衔接 |
|---|---|
| 底线 1/2(完整状态隔离在后端;浏览器只收可公开的脱敏投影) | 调试通道数据的"可公开性"由零装载在构造上保证:公开性论证从"policy 过滤正确"扩展为"输入里没有秘密"。底线语义不变,论证方式新增一条结构性路径 |
| ADR-7(脱敏在执行域内完成) | 调试 worker 同为执行域(信任域 3);其"全可见策略"作用于无秘密输入的调试变体 |
| D3(窗口锚定区域起点) | 对公开投影**维持冻结**;任意窗口仅存在于调试通道 |
| D5(currentInstruction;"展示数据非可执行 IR") | 公开投影不动;调试通道下发的是服务端生成的伪汇编**展示形态**,引擎 IR 本体不出进程 |
| D-API-2(WSS 版本锚定、"不另设版本常量") | 既有通道零改动;调试通道为独立端点、独立协议版本,锚定机制在调试通道内自建同款 |
| 6.3(确定性) | 调试实例固定调试种子,同条件同日志重放逐字节可复现;ASLR 基址派生是 seed 的应用面,回放元数据既有 `DerivationPathSummary` 承载 |
| 9.2(侧信道) | 调试通道无真实秘密,长度/时序差异不构成泄露面;"某题是否启用调试"是产品可见差异,非秘密 |
| 判题面(verifier 复用同一回放引擎,ADR-8;submit 只回引用,D-W8-9) | 调试通道与 verifier/隐藏测试/真实种子零交集;"提交判题走新进程重放"本就是既定架构(阶段六 verifier),本 ADR 不改变它 |

## 四、影响面与实现前置演进

**前端需求**(见《前端交互需求拆解.md》§十二):受 M3/M4 约束的条目验收拆为"解题模式档 + 调试模式档"双档;FE-ST-05 / FE-FV-04 / FE-IN-01~07 / FE-IN-08 / FE-WS-04c / FE-PB-02 断点积木等在调试模式档获得数据源与原生断点。FE-PB-04(出题者积木,M10)属公开描述包演进,不在本 ADR 覆盖内。工作区菜单新增解题/调试模式切换,内存视图随模式换绑数据源,payload 标签页状态跨模式共用(源文档 2026-09-10 增补,拆解文档 FE-WS-06/07)。

**实现前置演进清单**(按依赖排序):

1. **独立调试通道**:端点(如 `GET /sessions/debug-channel`)、协议版本、帧族(attach / window / step / run-to-breakpoint / search / 展示流)、golden fixture 与 Rust 消费面;
2. **调试变体镜像**:challenge-compiler 产出路径(布局同构、秘密值调试种子派生)、镜像的登记与机检锚点;
3. **公开描述包 Schema 演进**:`debugMode` 字段(opt-out,默认 `true`)、ASLR 开关;ASLR 开启时布局字段的语义修订(结构描述而非绝对基址;投影仍携带会话真实地址)——走 7.1 字段分类 + 双包 Schema + 版本演进,随 M2 通道下发;
4. **SeedDeriver 基址派生应用面**(ASLR 开启时):seed 的首个应用面;回放元数据已承载派生路径,verifier 零改动;
5. **机检与数据分类**:《数据分类与秘密零驻留清单》新增"调试通道"分类行(公开性由零装载保证);ZR 机检扩展——调试通道帧语料 ⊆ 调试变体镜像的包含性断言(复用 ZR-B 系语料扫描思路)。

**工程与资源**:每个启用调试的会话按需 +1 个 vm-worker(变体镜像装载);生命周期(attach 时生成、空闲回收)复用 WP-6 断线保持/回收机制;重放对齐成本 = 重放动作日志长度,MVP 可接受;限额与解题共用(D-API-50~53,条款 6)。

## 六、评审修正记录

- **R1 布局基址(修正"基址不相同"的一般化表述)**:决策讨论中曾提出两实例"地址基址不相同";评审确认修正为**由 ASLR 开关决定**。理由:①共用 payload 的重执行依赖泄露类数据依赖配方,基址差异可被吸收;硬编码绝对地址在 ASLR 开启时跨实例失效是教学语义而非缺陷;②布局是公开常量,差异化没有安全收益;③"调试看的就是这道题",结构必须同构。
- **R2 哑值 → 双种子变体镜像(废除原条款 3"哑值填充")**:调试实例是合法的兄弟实例——走真实引擎语义、无哑值代码路径;秘密值来源统一为种子派生。前置证据:v1 的 canary 期望值来自私有包 `privateObjects`(`vm-core/src/exec.rs` CanarySlotSpec,"期望值在引擎初始化时从初始内存截取"),seed 在 v1 尚无应用面(`declaredSeedPublicPaths` 是判定基准不是应用点)——故"两套种子"必须以**编译器产出的调试变体镜像**为落地形态,否则调试实例要么拿不到值、要么拿到真值(零装载失效)。同时"两套 seed 实现"的表述修正为"同一套派生器、两个种子值",避免触碰 ADR-8"同一份引擎代码"纪律。
- **R3 通道形态(否决"既有通道扩帧族")**:评审曾倾向既有通道扩帧族;确认与 D-API-2 冲突后否决——连接级版本锚定下调试帧无法携带独立版本,而随会话动作协议版本演进会让快速迭代的调试协议反复搅动已冻结面。独立端点复用同一套认证实现,零冲突。

## 七、维护约定

被引用决策(D3/D5/D-API-2/D-J7 等)的变更仍走各自协议版本演进纪律,不得以本 ADR 默认放行;本 ADR 的实现前置演进项(§四)每项落地时按仓库契约纪律先改 `protocol` / `challenge-schema` 与 golden fixture。
