## 一、目标时序

```text
平台后端 ──① POST /auth/launch-tickets   (Authorization: 宿主凭证;body: {challengeId, version})
             │  鉴权(hostBackendTokenMatches,单份实现)→ 租户 = 凭证 × SESSION_API_HOST_TENANTS 白名单
             │  → 题目存在且已发布校验 → 限流闸
             ▼
session-api ──② 201 { launchUrl, expiresAt }        // launchUrl 携带一次性票据(?t=…)
             │
平台后端 ──③ 把 launchUrl 作为**题目链接**下发给学习者(交付纪律:地址只发给对应学习者)
             ▼
学习者浏览器 ──④ GET launchUrl(顶层导航、与 API 同源)
             ▼
session-api(页面服务端) ──⑤ 校验 → 原子消费(单次)→ 签发凭证(Set-Cookie)
             │
             └──⑥ 302 到**不含票据**的干净路径(票据即刻脱离地址栏 / 历史)
             ▼
    页面以「已认证」态加载
```

**设计要点**:⑤⑥ 全部在**服务端**完成 ⇒ **不需要页面 JS 参与换票**,票据不在不可信的浏览器里被处理(D-LT-2 承载方式 = **方案 A**)。这条选择换来的是「零 JS 依赖」,代价是「票据进服务端访问日志」——该代价在 D-LT-3 用**强制日志脱敏机检**与**反代侧运维硬要求**正面关上,不靠"希望不会被记下来"。

## 二、契约面(两份载荷,均已冻结)

### 2.1 `LaunchTicketRequest`(签发请求体,`BOUNDARY`,恰两键)

| 字段 | 类型(冻结) | 分类 | 语义与规则 |
|---|---|---|---|
| `challengeId` | 不透明标识符(非空,≤ 128,`^[A-Za-z0-9_-]+$`) | `BOUNDARY` | 题目标识(公开描述包的可分发定位符,7.1;WP-1 清单 §12.2 已分类 `PUBLIC`)——**公开导航信息** |
| `version` | `X.Y.Z` 语义化版本字面 | `BOUNDARY` | 题目内容版本——**公开导航信息**;与公开描述包 `challengeContentVersion` 同源格式 |

- **恰两键**(`z.strictObject`):`challengeId` / `version`。请求体**不携带 `protocolVersion`**(N-1 受理是路由级事实,回显版本判定细节即扩大探测面,沿 `HostScoresResponse` / `VerdictQueryResponse` 先例;契约版本由 `$id` 命名空间承载);
- **租户不在请求体** —— 这是本契约最重要的一条结构约束:租户**只**由「宿主凭证 × `SESSION_API_HOST_TENANTS` 白名单」在服务端派生(6.2),**请求体 / 查询参数永不派生租户**。故 Schema 无 `tenantId` 位:`test/fixtures/launch-ticket-request/invalid/01-extra-tenant-id-tamper.json` 是自报租户形态的红灯样例;
- 格式常量**单一来源**:`version` 复用 `CHALLENGE_CONTENT_VERSION_PATTERN_SOURCE`(`packages/protocol/src/embed/embed-token-claims.ts` 冻结字面 `^[0-9]+\.[0-9]+\.[0-9]+$`),**不复制第二份正则**;该常量随本批一并从包入口导出(此前只经 server-only 子路径可达)。

### 2.2 `LaunchTicketResponse`(签发响应体,`BOUNDARY`,恰两键)

| 字段 | 类型(冻结) | 分类 | 语义与规则 |
|---|---|---|---|
| `launchUrl` | 字符串:`http(s)` 绝对 URL,1 – `LAUNCH_URL_MAX_LENGTH`(2048) | `BOUNDARY` | 一次性启动地址,票据于 `?t=<ticket>` 承载;值由服务端按部署基址生成 |
| `expiresAt` | 整数(Unix epoch 秒,UTC,≥ 0) | `BOUNDARY` | 票据过期时刻;与 Redis `launch:{jti}` 的 TTL **同值** |

- **票据值只在 `launchUrl` 内**:响应**不另回**票据字段(`ticket` / `jti` 皆无表达位)——票据是不透明持有证明,**不签发、不解析 claims** ⇒ 本族**没有** claims Schema(与 `EmbedTokenClaims` 的关键差异:后者是签名载荷、需跨语言校验)。红灯样例:`invalid/01-extra-ticket-field-tamper.json`;
- **不携带 `protocolVersion` 字段**(D-LT-1「不做」清单第 7 项):沿 `HostScoresResponse` / `VerdictQueryResponse` 先例,契约版本由 `$id` 命名空间承载;
- **不回显 `tenantId` / `userId`**:租户由凭证绑定在服务端派生,回显只扩大跨租户探测面(D-API-124 同款论证);红灯样例:`invalid/09-tenant-id-echo-tamper.json`、`invalid/10-identity-echo-tamper.json`;
- **长度上限 2048 的依据**:2048 是 URL 在浏览器 / 反向代理 / 访问日志链路上的**事实性公共上限**;**而本族最坏形态 ≈ 300 字符**(短基址 + `/app/c/{challengeId}/{version}` + 22 字符票据)⇒ 上限是**外圈护栏而非约束**(与 `MAX_EMBED_MESSAGE_BYTES`「最坏形态远低于上限」同款论证)。绿灯样例取 1848(逼近上限),长度边界(2048 收 / 2049 拒)由契约测试**在测试内合成**断言,不依赖 fixture 的近似值;
- `launchUrl` 用 **pattern 而非 `format: "uri"`**:本仓库 JSON Schema 消费方(Rust `jsonschema`)默认不校验 format,而 TS 侧 `z.url()` 会校验 ⇒ 用 format 会出现「TS 拒、Rust 收」的分歧,违反契约纪律 5.6;pattern 两侧都强制。允许 `http` 是**有意**的(开发 / 集成拓扑的启动地址是 `http://127.0.0.1:13000/app/…`),拒绝的是**相对地址**与无 scheme 的伪地址。

### 2.3 族内形态常量(单源,供 WP-91 / WP-92 引用)

| 常量 | 值 | 说明 |
|---|---|---|
| `LAUNCH_TICKET_ISSUANCE_ROUTE` | `/auth/launch-tickets` | 签发端点(承继 `EMBED_TOKEN_ISSUANCE_ROUTE` 的位置与鉴权姿态) |
| `LAUNCH_TICKET_REDEEM_PATH_TEMPLATE` | `/app/c/:challengeId/:version` | 换票路径模板(占位符与请求体两键同名同义) |
| `LAUNCH_TICKET_QUERY_PARAM` | `t` | 票据查询参数名(方案 A) |
| `LAUNCH_TICKET_TOKEN_LENGTH` | `22` | base64url 22 × 6 = **132 bit ≥ 128 bit** 的最小整数长度(21 字符 = 126 bit 不足) |
| `LAUNCH_URL_MAX_LENGTH` | `2048` | 启动地址长度上限(见 §2.2) |
| `MAX_LAUNCH_TICKET_TTL_SECONDS` | `3600` | 有效期天花板(1 小时外圈护栏) |
| `DEFAULT_LAUNCH_TICKET_TTL_SECONDS` | `300` | 有效期缺省(5 分钟) |

**归属纪律**:数值护栏(地址上限 / TTL 上限与缺省)登记在 `src/common/limits.ts`(沿该文件「协议级数值上限 + 带上限缺省值」的既有惯例:`MAX_EMBED_TOKEN_TTL_SECONDS` / `MAX_BYTES_PER_RANGE_DEFAULT`);**形态常量**(路由 / 路径模板 / 查询参数名 / 令牌长度)登记在 `src/launch-ticket/launch-ticket-contract.ts`。两处都是**单源**:WP-91 / WP-92 **不得**复制字面量。

### 2.4 导出面与分类登记

- 两份载荷 Schema **登记公开注册表**(`src/schema/registry.ts`),分类 = `BOUNDARY`(`src/common/classification.ts`,逐字段登记)——依据:两份载荷本就是**跨到平台后端 / 页面**的形态,页面侧需要可校验响应;
- 两份载荷**不进** server-only 注册表(它们不是"载荷可穿越、解析器只给后端"的凭证类:票据本身不在这两份载荷里);
- **无跨字段 refinement**:两份载荷是纯结构契约 ⇒ 生成管线**不注入** if/then(与 `verdict-query-response` / `host-scores-response` 的耦合注入面无关)。

## 三、票据形态与生命周期(D-LT-2 裁定表)

| 项 | 裁定值 | 落地要点 |
|---|---|---|
| 承载 | **URL query**(`?t=<ticket>`) | 方案 A;服务端消费后 **302** 抹除 |
| 熵 / 编码 | **≥128 bit CSPRNG**,**base64url 22 字符** | 生成器 = 域内单一函数;`LAUNCH_TICKET_TOKEN_LENGTH = 22` |
| 有效期 | **缺省 300 s**,配置键 `SESSION_API_LAUNCH_TICKET_TTL_SECONDS`,**天花板 3600** | 非正 / 超限即**拒绝启动**(三道闸同既有配置键纪律);Redis TTL **同值**;响应回 `expiresAt` |
| 单次消费 | **Redis Lua CAS 原子消费**(先消费成功 → 再签发凭证;失败不留半态) | 消费即删除;**不幂等**(重复打开 = 401) |
| 绑定 | `(tenantId, challengeId, version, expiresAt)` 逐字段校验 | **不绑定 IP / UA**(误伤移动端与共享出口,且引入「绑定不匹配」这一可探测差异面,与统一 401 冲突);**不在 `launchUrl` 内暴露 tenantId** |
| 换票路由 | `GET /app/c/:challengeId/:version?t=<ticket>` | 见 §四 |
| 幂等 | **不幂等**(单次消费即设计) | 重复打开 = 401 + 「地址已失效,请向平台重新获取」 |

**票据不是长期凭证**:计划书 §8.1 的纪律是「不应把长期凭证放入 URL」——启动票据正面回答它:熵 ≥128 bit、TTL 缺省 300 s、**一次性消费**、服务端绑定四要素、302 即刻抹除。它**仍然进了 URL**,而 URL 会进浏览器历史、Referer 与各级访问日志 ⇒ 暴露窗口由 D-LT-3 的三条义务关上(见 §六)。

## 四、换票与失败语义(页面服务端内完成)

| 步骤 | 决定 |
|---|---|
| 触发 | `GET /app/c/:challengeId/:version?t=<ticket>`(**不是独立 API**;对外表现为「打开地址即完成」) |
| 校验 | ⓪ `Sec-Fetch-Mode: navigate`(**拒绝子资源 / 嵌入式换票**;纯请求头校验,不需要 JS);① 票据存在且未过期;② 未消费;③ 绑定字段与路径字段**逐字一致**(tenant / challengeId / version);**任一不满足 ⇒ 401 统一形态** |
| 消费 | **原子消费成功后才签发凭证**(先消费后签发;失败不得留下半态) |
| 签发 | 凭证经 `Set-Cookie` 交付;**同源** ⇒ `SameSite` 保持既有策略(不因本改版放宽);`credentialCookiePath` 沿用既有装配(`"/"`) |
| 响应 | **302 → 不含票据的干净路径**;失败 ⇒ 冻结 `PublicError` 页面(**401 统一形态**),**不泄露失败原因分类** |
| 日志 | 该路由的访问日志**必须脱敏 `t` 参数**(与 §八 机检条目 2 同一条) |

**统一 401 三态同形(硬约束)**:「票据不存在」「已过期」「已消费」以及「绑定不符」四者的响应**逐字节一致** —— 三者不可区分是**防探测**的结构性要求(过期 vs 已消费 vs 不存在若是可区分的,就等于给重放者一个廉价探测面)。机检以**逐字节比对**落地(§八 条目 3)。

## 五、存储与可用性

| 项 | 决定 |
|---|---|
| 载体 | **Redis**,键 **`launch:{jti}`**(新键域,带 TTL) |
| 为何不用 PG | 票据是**瞬时引导物**,不值得新表 / 迁移(与 O-MP-6「不引入新表」姿态一致) |
| 可用性语义 | **fail-closed**:Redis 不可用 ⇒ 换票 **503 `store_unavailable`**,**不降级、不静默放行**(与 `token:{jti}` / `route:{sessionId}` 同纪律——计划书 `:427` 注明这两者不可降级) |
| 丢失语义 | Redis 掉电 / 刷库 ⇒ 未消费票据失效 ⇒ 学习者看到「地址已失效」,须由平台**重新签发**。**可接受**:票据可无限重签,不承载不可重建状态 |
| 绝不入库的东西 | 票据明文**不进 PG、不进审计账、不进指标标签、不进浏览器可读投影** |
| 键域纪律 | `launch:` 键域**禁止** `KEYS` 类全扫(只按 `jti` 精确取键);新键域须同批登记计划书 §5.7 键域清单与 `docs/develop/权威API语义规约.md` 键域表(**不得静默新增键域**) |

## 六、攻击面与残留风险(逐项登记,不以沉默代替结论)

| 攻击面 | 处置 | 残留风险 |
|---|---|---|
| **票据经 Referer 外泄** | 方案 A:302 之前**首屏无子资源**,且 302 即净;并设 `Referrer-Policy: no-referrer` | **低**;若改选 fragment 方案则结构性为零 |
| **票据进访问日志 / 反代日志** | 应用侧**查询串脱敏机检**(§八 条目 2)+ 部署指南把**反代侧脱敏列为运维硬要求** | **中** —— 反代**不在本项目控制内**(D-API-104 定案「反代准入」);**这正是方案 A 的主要代价**,已登记 |
| **票据进浏览器历史** | 302 到干净路径(历史里留的是原 URL);`Cache-Control: no-store` | **低** —— 条目仍在历史里 |
| **重放** | 原子单次消费(消费即删除) | 低 |
| **枚举票据** | ≥128 bit 熵 + 签发端点限流(缺省 60 次/分,天花板 100000) | 极低 |
| **枚举题目 / 租户** | 404 同形(白名单外租户与「题目不存在」同形) | 低 |
| **会话固定(session fixation)** | ⚠ **已正面处置**:攻击者把自己的 `launchUrl` 诱使受害者点击 ⇒ 受害者在**攻击者的会话**里答题、攻击者事后读取成绩。**已采纳基线缓解**:票据**一次性** + **TTL 300 s** + 平台侧「**地址只发给对应学习者**」交付纪律 + `Sec-Fetch-Mode: navigate` 校验。**未采纳**「换票改 POST + 同站校验」——**它与方案 A(零 JS)在结构上不相容**(换票走 POST 就必须由页面 JS 发起) | **中低**(教学场景可接受);**已登记**;若主控判定不可接受,**须回到 fragment 方案** —— 两项必须一致取舍,不能各取一半 |
| **侧信道(过期 vs 已消费 vs 不存在)** | **统一 401 形态**,四态逐字节一致 | 低 |
| 红线:身份不由客户端自报 | 租户 / 题目绑定由**服务端签发的票据**承载;URL 仅导航 | 满足 |
| 红线:浏览器不可信 | 票据一次性短时;页面不做授权判断。**注意:这与「URL 里的东西不可信」不矛盾** —— 票据是**服务端签发的持有证明**,不是客户端自报声明 | 满足 |
| 红线:ADR-7 投影脱敏 | **零改动** | 满足 |

## 八、机检清单(9 条,实施时逐条落地)

| # | 机检 | 说明 |
|---|---|---|
| 1 | **URL / body 参数不得进入租户派生路径** | 结构性断言(比照既有「查询参数不得决定租户」);契约层已由「请求体恰两键、无 `tenantId` 位」预置 |
| 2 | **应用侧日志零票据** | 扫描日志输出:含 `t=` 的查询串必须被脱敏(不得只靠注释,须有机器断言) |

| 5 | **429 逐字节同形态** | 沿 D-API-50 冻结常量 |

## 九、边界声明(本 WP 不做什么)

- **不写任何后端路由实现**:签发端点、换票、Redis 键域、限流、日志脱敏机检归 **WP-91**;`apps/page-app` 归 **WP-92**;
- **不删退役面**:`/auth/embed-tokens` 与嵌入协议面的物理下线须与实现同批(**WP-96**);
- **不改用户文档**:`docs/user/**` 只在退役落地后回填(D-LT-4,**WP-98**);
- **不新增审计 kind**:票据的签发 / 换票**不新增** `audit_log` kind(`audit_log` 的十值封闭集不动);可审计性由受控日志 + 指标 + 披露点 fail-closed 承载;
- **不做票据签名 / claims**:票据是不透明持有证明,绑定由 Redis `launch:{jti}` 服务端写入承载(D-LT-1「不做」清单第 6 项);
- **不在本族回显 `protocolVersion`**:N-1 受理是路由级事实(D-LT-1「不做」清单第 7 项)。
