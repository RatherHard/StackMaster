## 一、四类版本的定义与相互关系(7.4)

| # | 版本 | 载体 | 冻结常量 / 形态 | 回答的问题 |
|---|---|---|---|---|
| 1 | **DSL Schema Version** | 私有判题包 `dslSchemaVersion` | `const 2`(challenge-schema) | 题目的指令面 / 谓词面 / 声明面按哪一版 DSL 词汇写成 |
| 2 | **VM Engine Version** | 私有判题包 `vmEngineVersion`(+ `engineBuildId`) | semver 字符串(必填) | 该题目由哪一版引擎语义执行;确定性以此锁定 |
| 3 | **VM Profile Version** | 公开描述包与私有判题包**双包同值** | semver 字符串(XS-ID-CORR 强制相等) | 虚拟硬件形态:寄存器集、区域布局、位宽声明按哪一版 Profile |
| 4 | **Challenge Content Version** | 双包同值 | semver 字符串(XS-ID-CORR) | 题目内容本身:题面、初始状态、判题配置的内容修订 |

配套信封版本(非 7.4 四类,但同属版本面,详见 §二编号空间):

- `schemaVersion`(双包格式信封,`CHALLENGE_PACKAGE_SCHEMA_VERSION = 1`);
- `protocolVersion`(会话动作协议,`SESSION_ACTION_PROTOCOL_VERSION = 1`;投影 / 错误契约随其演进);
- `protocolVersion`(嵌入协议,`EMBED_PROTOCOL_VERSION = 1`,独立编号空间);
- 引擎进程协议:`ENGINE_PROCESS_PROTOCOL_VERSION = 1`(**2026-09-06 阶段二 WP-1 登记**,投影与错误契约语义 §5.3;语义权威 `docs/develop/引擎进程协议.md` §二——Schema 面复用会话动作协议,帧 / 信封面独立版本);
- IR 格式 `irFormatVersion`(私有包 `compiledIr`,当前 2):IR 序列化格式的内部版本,随 DSL Schema 演进联动;
- 判题规则 `judgingConfig.verdictRuleVersion`(私有包):判题谓词集的内容版本,见 §三记录项。

**相互关系(冻结)**:

1. **内容牵引 Profile,Profile 牵引引擎**:题目内容修订只递增 #4;虚拟硬件形态变化(寄存器、区域、位宽)递增 #3 且**双包同步**(XS-ID-CORR 拒绝错位);要正确执行新 Profile / 新 DSL 词汇,必须声明支持它的 #2。反向不成立——引擎升级不强制内容或 Profile 变更;
2. **DSL(#1)与引擎(#2)解耦**:引擎可跨多个 DSL 版本(向后兼容执行);题目声明它需要哪一版 DSL,由服务端在装载时校验"引擎支持该 DSL 版本",不支持即拒绝装载(9.1 按锁定题目版本解析);
3. **版本不匹配的失败方向**:宁可拒绝装载(`challenge_invalid` 方向),不可"近似执行"——9.1 锁定语义 + 7.4"不得自动使用最新引擎"的协议层表达;
4. **semver 语义按载体区分**:`challengeContentVersion` / `vmProfileVersion` / `verdictRuleVersion` 的 patch 级修订必须保证权威判定与投影形态**逐字节可复现**(回放前提,6.3);不可复现的内容修订必须递增 minor 及以上,并使既有会话与回放记录锚定旧版本不受影响;
5. **扩展 = 递增版本,不靠预留**:任何"为未来留的字段 / 枚举值"都违反 YAGNI 纪律(阶段一任务分解 §六);扩展走版本演进 + N-1 窗口。

## 二、契约编号空间(5.6)

四类契约各自独立版本号,互不共用编号空间;Schema 来源唯一(`protocol` / `challenge-schema` 包):

| 契约 | 版本载体 | 递增规则 | 兼容窗口 |
|---|---|---|---|
| 题目双包 Schema | `CHALLENGE_PACKAGE_SCHEMA_VERSION`(信封)+ 实例 `schemaVersion` | 字段增删 / 类型或语义变化递增 | N-1 双受理,窗口期结束下线 |
| 会话动作协议 | `SESSION_ACTION_PROTOCOL_VERSION` | 同上;投影 / 错误契约随之 | 同上(`…/session-action/v2/` 新目录) |
| 嵌入协议 | `EMBED_PROTOCOL_VERSION` | 同上;消息类型 / 能力枚举扩展 = 破坏性 | 同上(`…/schemas/embed/v2/`) |
| 引擎进程协议 | `ENGINE_PROCESS_PROTOCOL_VERSION`(当前 1;2026-09-06 WP-1 登记,复用会话动作 Schema 面) | 同上;帧 / 信封 / 命令面与受支持 Schema 面的破坏性变更递增(联动会话动作协议版本演进) | 同上(`docs/develop/引擎进程协议.md` §2.2;进程双方同部署,窗口 = 编排器双形态支持) |

窗口期时长为实现期运维参数(阶段三定);窗口语义:过渡期服务端按路由同时接受 N 与 N-1(各自独立 Schema 校验)。规则细节见会话动作协议语义 §5.2、投影与错误契约语义 §5.2、嵌入协议 §变更纪律。

## 三、正式判题与回放的记录项(7.4)

正式判题(verifier 裁决)与一切回放记录**必须**记录以下六项;缺项的裁决不可审计,视同无效:

| # | 记录项 | 来源 | 作用 |
|---|---|---|---|
| 1 | **题目包哈希** | 双包内容哈希(SHA-256;对公开包为规范化序列化哈希,私有包为服务端持有的原始字节哈希) | 锚定"判题时看到的确切题目" |
| 2 | **VM Profile 哈希** | 公开描述包 `vmProfile` 部分哈希 | 虚拟硬件形态可复现;与 #1 分开记录,Profile 独立修订可追溯 |
| 3 | **引擎构建 ID** | `engineBuildId`(私有包声明 + 运行时引擎自报,两者必须一致,不一致 = `challenge_invalid`) | 执行环境可复现;堵"声明 A 构建、实际跑 B"的缝隙 |
| 4 | **判题规则版本** | `judgingConfig.verdictRuleVersion` | 隐藏测试集与谓词的修订锚点 |
| 5 | **随机种子策略** | `seedPolicy.strategy`(`fixed` / `server_random_per_session`)及派生路径声明(**不含 seed 值本身**——seed 是秘密,9.2) | 随机化可复现且秘密零驻留(6.3) |
| 6 | **规范化提交内容哈希** | 提交载荷经 `stackmaster-canonical-json/1`([docs/contracts/规范化JSON序列化.md](规范化JSON序列化.md))规范化后的 SHA-256 | 提交内容可复现、可比对;防篡改(13.5) |

补充约定:

- **哈希的输入一律是规范化序列化**(§四):同一逻辑内容在不同序列化器下必须得到同一哈希;
- 回放记录另按 6.3 携带动作日志(append-only:类型与参数、前后状态哈希、内存 / 寄存器变化、事件序号 + 本表 #1–#5),此处不重复展开;
- 记录项的存储形态(`submissions` / `verdicts` / `verifier_runs` 表)归阶段二 / 三持久化设计(5.7);本阶段冻结的是**记录项集合与语义**。

## 四、生产环境锁定(7.4"不得自动使用最新引擎")

1. **题目装载即锁定**:题目通过校验时记录 #1–#5,该会话与其后的一切回放、重放、裁决固定在该记录上;任何后续部署变更(引擎升级、Profile 修订、内容修订)都产生新版本记录,而**不改动既有记录**;
2. **无"最新"语义**:引擎解析规则是显式版本 / 构建 ID 匹配,不是 `latest` 别名;部署流水线不得把"最新构建"自动绑定到正在服务的题目版本;
3. **升级 = 显式再发布**:题目迁移到新引擎 / 新 Profile 是内容修订(#4 / #3 递增)+ 重新校验 + 新版本发布;旧版本在明确下线前继续可用(由锁定记录保证可运行);
4. **Verifier 与交互执行同锁**:verifier 重放必须使用与交互执行相同的引擎构建(同 #3),否则按 9.1 复现失败处理(`replay_mismatch`);这同时要求两者复用同一份回放引擎代码(ADR-8);
5. **窗口期结束即下线**:N-1 兼容窗口结束、旧版协议下线属于显式运维动作(阶段三),不是自动行为。
