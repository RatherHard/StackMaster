## 一、规范内容与效力声明

### 1.1 硬性规范原文(`docs/develop/Vm 模块设计.md`)

> - vm 的架构:32 位还是 64 位应允许出题人指定;
> - 寄存器的名称、种类与数量应允许出题人自由设定;
> - 虚拟内存设置以 VMA 为一个基本单元,允许出题人自由设定每一个 VMA 的权限(rwx)、类型(栈区、关键区(可以自行命名)、代码区等)和大小(必须为 4KB 的倍数);
> - 指令集应允许出题人自由设定;
> - 向前端提供的 VmState 应当预先对选手还未获取到的内存数据进行隐藏,不应当向前端提前发送这些隐藏信息。

第五条目标(隐藏先行)与计划书 9.2 / WP-1 / WP-3 全部既有工作**完全相容且已被满足**(I-2 / I-9 / 投影白名单),不产生整改项。

### 1.2 规范语义澄清(D4 裁决,2026-09-04)

> "指令集自由设定的含义是指令作用和表现机器码的映射可以自由设定。对于 opcode,移除 read、write 指令,增加 leave 指令,同时 syscall 和 call 可以调用出题人自己写的接口。"

即:自由设定的对象是**每条指令"作用语义 ↔ 机器码表现"的映射**;基线指令集同步调整;`syscall`/`call` 具备派发到出题人声明接口的能力。实现立场(安全调和,详见 §3.4):作者自定义以**私有包内声明式映射表**承载,由引擎按封闭原语解释执行;**不引入宿主侧动态处理函数注册**——红线"题目 DSL 不执行任意宿主代码"保持不变。

### 1.3 效力序与治理约束

1. CLAUDE.md 与计划书规定:**计划书是唯一权威来源**。五条目标中,第一、二、三、五条与计划书正文相容(冲突发生在 WP-1/Schema 层);**第四条经 D4 澄清后仍触及计划书 7.2/7.3 现行文本**——D5 已裁决**修订计划书**,修订工作列为 P0.5 批次;修订完成前,已冻结契约维持现行版本执行;
2. 一切整改遵循统一纪律:先改计划书/WP-1 清单与本文件 → 改 `protocol` / `challenge-schema` 契约与正反 fixture → 评审 → 再改实现。

## 三、逐条冲突与整改方案

### 3.1 G1:架构位宽可选(32/64)

**裁决**:D1 = `archBits` 取值域 **{32, 64}**(2026-09-04)。

**冲突明细**

| 已冻结内容 | 位置 | 冲突点 |
|---|---|---|
| "寄存器全集到 **64 位值**的映射 + FLAG 位" | WP-1 §3.2 | 语义把值宽固定为 64 位 |
| "`valueHex`(64 位,大写十六进制字符串)" | WP-1 §4.2 `PublicRegister` | 公开面按 64 位描述 |
| "地址与 64 位值在 VM Core 内是一等公民(端序内建)" | CLAUDE.md(Rust 引擎纪律节) | "一等公民"被读作定宽 64 |
| `HEX_VALUE_64_PATTERN = ^0x[0-9a-fA-F]{1,16}$`(1–16 hex 字符) | `challenge-schema/src/common/patterns.ts` | 词法是**上限式**而非定宽:32 位值(≤8 hex 字符)本可通过,但**缺"值不得超过 archBits"的校验** |
| 位移模式 `^-?0x[0-9a-fA-F]{1,16}$` | 同上 | 同上 |

**整改方案**

1. 公开描述包 `vmProfile` 新增必填字段 `archBits: 32 | 64`(v1 冻结二元;扩展走 VM Profile Version);
2. 值语义改为"**archBits 宽的架构值,以 64 位容器承载,高位按位宽掩蔽**"——VM Core 内部仍用 64 位一等表示(计划书 6.2 表示法不变),全部算术/移位/比较在掩蔽域内进行,出界与 `carry/borrow` 行为在指令规约中按位宽定义;
3. 新增检查器规则 `XS-ARCH-WIDTH`:
   - 私有包 `initialState.registers` 全部值 ≤ 2^archBits − 1;
   - IR 立即数/位移落在 archBits 有符号范围内;
   - 作者自定义指令的微算子常量同规则(§3.4);
   - 公开包 `initialProjection` 镜像值同规则(作为 `XS-PROJ-VALUES` 的前置);
4. 文档修订:WP-1 §3.2/§4.2 措辞由"64 位值"改为"archBits 宽架构值(64 位容器承载)";CLAUDE.md 同步措辞;`docs/最小DSL范围.md` 增补操作数宽度一节;
5. 公开投影**不新增字段**:`valueHex` 保持变长 hex(现模式天然兼容 32 位短值)。硬门槛论证补入 WP-1:位宽是架构公开常量,值长度差由位宽决定,不含任何秘密派生信息,I-10 来源类不变。

**波及面**:WP-1(v1.4)、`protocol`(`src/common/hex.ts` 语义与校验、golden fixture)、`challenge-schema`(双 Schema、`patterns.ts`、检查器新规则、红灯样例)、`docs/最小DSL范围.md`、CLAUDE.md。

**验收**:64 位题目全量兼容回归;32 位题目初值/立即数越界被 `XS-ARCH-WIDTH` 拒绝(红灯样例必触发)。

### 3.2 G2:寄存器名称/种类/数量自由设定

**裁决**:D3 = **上限放宽**(2026-09-04);具体数值列为微决策 D3.1(建议 `MAX_VM_REGISTERS` 64→256、`MAX_VISIBLE_REGISTERS` 32→64,Schema 评审定稿)。

**冲突明细**

| 已冻结内容 | 位置 |
|---|---|
| 冻结 14 名称基集;"扩展寄存器走 VM Profile Version,不靠本集合预留" | WP-1 §3.2 |
| `BASE_REGISTER_NAMES` 冻结数组 + 模式 `^R[A-Z0-9]{1,3}$` | `challenge-schema/src/common/patterns.ts` |
| 公开包 `vmProfile.registers[].name` 仅允许基集形态模式 | `schema/public-descriptor.schema.json` |
| `XS-REG-FROZEN` / `XS-REG-SUBSET` / `XS-REG-FLAG` | `challenge-schema` 检查器 |
| 双命名空间结构性不相交(秘密汇静态可枚举的安全依据) | WP-1 §12.5 |

**整改方案:双命名空间保留模型**

核心思想:**放宽"一般寄存器"命名面,保留 FLAG 前缀保留区**,使 I-3 的静态可枚举性原样存活。

1. 一般寄存器命名放宽为 `^[A-Z][A-Z0-9_]{0,15}$`,**禁止匹配 `^FLAG[A-Z0-9_]*$`**(前缀保留)。命名空间不相交性质保留 → 秘密汇集合 = `flagRegisterNames ∪ secretSinkRegisters ∪ 污点推导`,仍可静态枚举,WP-1 §12.5 第 1 条的安全论证原文成立;
2. `vmProfile.registers` 语义从"冻结基集的可见子集"改为"**本题目寄存器集的定义性声明**";`flagRegisterNames` 语义不变(名称公开、值永不公开);
3. **必选核心寄存器:`RSP`、`RBP`、`RIP` 必须在集合内**。理由:会话动作(`push`/`pop`/`call`/`ret`)、opcode 的栈语义(含新增 `leave`,§3.4)与 MVP 闭环(栈帧/buffer/返回地址)均建立在这三者上;
4. 检查器调整:`XS-REG-FROZEN` 废止;`XS-REG-SUBSET` 按新语义重锚(初始/可见寄存器 ⊆ `vmProfile.registers` 声明集);`XS-REG-FLAG`、`I3-VISIBLE-REG` 原样保留;新增 `XS-REG-CORE`(必选核心存在)与 `XS-REG-NAMESPACE`(一般名不得落入 FLAG 保留区);
5. "种类"(浮点/向量/段寄存器等非 GP 类):v1 不放开,走 VM Profile Version 受审计演进。在 WP-1 修订中记为**规范的部分实现**(分阶段达标),非违反;
6. 数量:护栏上限按 D3 放宽(数值见 D3.1);上限是资源护栏(内存布局与投影体积),不是自由度限制,PR 理由随 Schema 变更提交。

**波及面**:WP-1 §3.2/§4.1/§12.5(v1.4)、`protocol`(`src/common/register-name.ts`:基集常量改为核心集 + 命名模式)、`challenge-schema`(`patterns.ts`、`limits.ts`、双 Schema、检查器规则替换、跨包一致性测试重锚)、红灯样例。

**验收红灯样例**:一般寄存器命名 `FLAGX` 被拒;缺 `RSP`/`RBP`/`RIP` 被拒;自定义名 `R_MYDATA`、`CTRL` 通过;超新上限被拒;自由命名下 `I3-VISIBLE-REG` 仍能拦截秘密汇进入可见白名单。

### 3.3 G3:VMA 内存模型

**裁决**:D2 = 页大小采用 **4KB 倍数区间**(非常量 4096)(2026-09-04)。

**冲突明细**:权限(rwx)自由设定与"VMA 为基本单元"**已符合现状,无需整改**。两点偏差:

| 偏差 | 已冻结现状 | 规范要求 |
|---|---|---|
| 区域类型 | `REGION_KINDS` 封闭五类(`code`/`global`/`stack`/`heap`/`key`) | "……等"的开放类型面 |
| 大小对齐 | `pageSizeBytes` 允许 256–65536 任意整数(Schema 描述原文"v1 无公倍数约束");区域大小无对齐检查 | VMA 大小必须为 4KB 的倍数 |

**整改方案**

1. **类型**:`REGION_KINDS` 增第六类 `"custom"`(必填 `label`,沿用 `SemanticHighlight` 的 `custom` 先例);关键区(`key`)可命名性质不变;公开对象标签自由度不变;
2. **对齐**:`pageSizeBytes` 改为 `multipleOf 4096`(取值域 {4096, 8192, …, 65536});公开包 `memoryLayout` 与私有包 `initialState.memoryRegions` 的区域 `byteLength` 增加 `multipleOf 4096` + 新检查器规则 `XS-MEM-PAGE-ALIGN`;
3. **对齐只约束区域(VMA)边界**:区域内部对象(buffer/canary/saved_rbp/return_address,字节数 1–8 或有界)不是 VMA,不受对齐约束——否则与 canary 教学(1–8 字节)直接矛盾;
4. 权限面(`^r?w?x?$` 规范序)与资源护栏(`MAX_MEMORY_REGIONS = 64`、单区 16 MiB、总量 64 MiB)不变;
5. WP-1 第十二章补两行论证:`custom` 类型与 4KB 对齐值均为作者声明的公开布局常量,值来源属 I-10"公开布局常量"类,与秘密无相关,硬门槛通过。

**波及面**:`challenge-schema`(`vocabulary.ts`、双 Schema、检查器、fixtures)、WP-1 §12.2/§12.3、`docs/最小DSL范围.md`(引用区域类型处)。

**验收红灯样例**:区域 `byteLength` 非 4KB 倍数被拒;`pageSizeBytes = 256` 被拒;`custom` 区域缺 `label` 被拒;既有五类区域题目全量兼容回归。

### 3.4 G4:指令集——作者可定义的"语义-机器码"映射(D4/D5 裁决后重写)

**裁决原文**(2026-09-04):

> "对于指令集,指令集自由设定的含义是指令作用和表现机器码的映射可以自由设定。对于 opcode,移除 read、write 指令,增加 leave 指令,同时 syscall 和 call 可以调用出题人自己写的接口。"
> D5 = **修订计划书**(7.2/7.3 现行文本随本次整改修订,见 P0.5)。

**规范语义的实现立场**

"自由设定 = 指令作用与机器码表现的映射可由出题人定义"落地为一条架构原则:

> **作者自定义 = 私有包内的声明式映射表(数据),由引擎按封闭原语集解释执行;不存在宿主侧处理函数注册,不存在脚本形态。**

由此,红线"题目 DSL 不执行任意宿主代码"(计划书四底线 4 / 7.3)在修订后的计划书中**保持不变**:被扩展的是"作者可声明的语义面",不是"作者可注入的代码面"。确定性(6.3)成立:映射表是题目包数据,回放按 `vmEngineVersion` 锁定的解释器执行;审计(13.2)成立:发布管线对表项跑 T-SC1/T-SC2/差分与静态检查。

#### 3.4.1 基线指令集变更(opcode v2:21 → 20)

| 变更 | 内容 | 连锁影响 |
|---|---|---|
| **移除** `read` | 教学 IO 收敛 | 玩家程序读取虚拟文件的能力改经 `syscall` 作者接口(§3.4.3),与谓词 `virtual_file_read` 的衔接在接口效果面重建 |
| **移除** `write` | 同上 | 内存写入由会话动作 `write_bytes` 与 `mov R,M` 承担,教学带宽不受损 |
| **新增** `leave` | 栈帧类,无操作数,语义:`RSP ← RBP` 后 `pop RBP`(等价 `mov rsp,rbp; pop rbp`) | 与 `call`/`ret`/`push`/`pop` 构成完整栈帧闭环;**教学价值**:saved `RBP` 被覆写后 `leave` 使 `RSP` 被攻击者数据劫持——MVP 教学目标(栈帧/buffer/返回地址)的直接教具;要求 `RBP` ∈ 必选核心寄存器(§3.2 已保证);弹出值不可执行时报 `invalid_rip`(与 `ret` 同规则) |

`DSL_OPCODES`(v2)= `mov, push, pop, leave, add, sub, cmp, and, or, xor, shl, shr, jmp, je, jne, jb, jae, call, ret, syscall`(20 个,封闭枚举)。`read`/`write` 移除属破坏性契约变更:`dslSchemaVersion` 1→2,无 N-1 兼容负担(尚无发布题目),fixture 同步重建。

#### 3.4.2 作者自定义指令面(方案 B 收窄前置:custom instructions)

私有包新增声明面 `customInstructions[]`,每个条目 = `{mnemonic, displayText, semantics: [微算子有序组合]}`:

- **微算子封闭集 v1**(待 Schema 评审定稿):定步数的寄存器读/写、立即数装载、基址+位移内存读/写(走统一权限与 I-9 检查)、标志置位、位掩蔽运算;
- **v1 约束:直线语义**——自定义指令**不含控制转移**(跳转/调用仍属基线 opcode),CFG 静态分析(XS-STAGE-*、回边预算)完全保持;
- **恒定步数**:单条自定义指令的求值步数 = 组合微算子定步数之和,与操作数值无关——T-SC2(单字节突变步数恒定)对自定义指令逐条可断言;
- **机器码表现**:`displayText` 为该指令在 `controlFlow.currentInstruction` 的展示文本(I-10 静态模板类);作者可定义"表现机器码"即指此面 + IR 助记符;
- 审计:发布管线对每条自定义指令跑 T-SC1/T-SC2/差分 + `XS-ARCH-WIDTH` + 微算子白名单校验。

#### 3.4.3 `syscall` / `call` 作者接口面

私有包新增声明面 `interfaces[]`,每个条目 = `{interfaceId, displayText, effects: [效果原语有序列表]}`:

- **效果原语封闭集 v1**(待 Schema 评审定稿):`exit`(保留内置)、`grant_virtual_file`(沿 stage 副作用先例)、`virtual_file_read`(衔接谓词 `virtual_file_read`)、`set_flag`(置 FLAG 汇寄存器,经 I-3 污点检查)、`noop`;
- **`syscall` 派发**:操作数 I = `interfaceId` 或保留系统号;内置 `exit` 语义不变,其余 ID 必须在 `interfaces[]` 声明,未声明即 `invalid_action`(检查器 `XS-SYSCALL-DECL`);
- **`call` 派发**:操作数联合新增第四种类型化形态 `{kind: "interface", interfaceId}`(结构化引用,沿 `fileId` 先例,**不存在动态拼接 capability 的语法位置**,F-4 保持);派发语义两选项,列微决策 D4.2:
  - ①(建议)引擎管理调用:记录返回地址 → 执行效果 → 返回下一条指令,不占玩家栈——教学上清晰区分"真实 `call`(栈帧)"与"接口 `call`(教学接口)";
  - ② 完整栈语义:压返回地址、`ret` 返回(更贴近真实机器,但效果面与栈面耦合);
- 预算:接口效果求值计入动作/谓词预算;每接口步数 = 效果原语定步数之和,恒定(T-SC2 同断言);
- 侧信道:效果是否可见遵守 I-2/I-3/I-9;`displayText` 属 I-10 静态模板;接口的存在性对玩家可见面 = 公开包显式声明(作者选择公开或隐藏接口清单——隐藏接口的存在性本身不得从任何公开通道推断,由 T-SC1 探针变体覆盖)。

#### 3.4.4 波及面与验收

**波及面**:`challenge-schema`(`vocabulary.ts`:DSL_OPCODES v2 + 新增微算子/效果原语/接口枚举;双 Schema:`compiledIr` 操作数第四 kind、`customInstructions`、`interfaces`;`limits.ts`:表容量上限;检查器:`XS-IR-LABEL` 扩展 + 新 `XS-SYSCALL-DECL` / `XS-IFACE-REF` / `XS-CUSTOM-*` 规则族)、`docs/最小DSL范围.md` §三重写 + §五/§六/§八相应更新、**计划书 6.1/7.2/7.3 修订(P0.5)**、WP-1 §12.3(`compiledIr` 字段面)与新声明面的硬门槛论证补章节、protocol(12 会话动作与投影契约**不变**,`PublicEvent.kind` 已含 `syscall`,无改动)、fixtures 全量重建。
