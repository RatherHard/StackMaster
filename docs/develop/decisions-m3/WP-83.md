- 触发来源:`docs/phases/中期任务分解.md` §一.2.3 风险行(主 chunk > 1.3MB ⇒ 拆分,可选增量转义务)与 §九

  「**首屏静态图**」= 入口文件 + 其全部静态 import 闭包(插件文档页以

  注释增长 —— 见 §七 复现)。

## 三、拆分方案

### 3.1 关键发现:**单点惰性 = 假绿**(本波次最重要的反例)

只把 `tab-registry.ts` 的 payload 工厂改惰性(**L1**):主 chunk 确实降到 428.19 kB,但
`dist/index.js` 仍**静态** import 了 `sm-payload-tab` chunk(因为入口桶 `src/index.ts` 还在
`export * from "./payload/sm-payload-tab.js"`,而 `index.ts` 又是插件文档页直接加载的入口):

| 变体 | 产物 | raw 合计(首屏静态图) | gzip |
|---|---|---|---|
| 拆分前 | index 17,690 + 主 chunk 1,379,016 | 1,396,706 B / 1,396.71 kB | 343,015 B |
| **L1(只改注册表)** | index 17,673 + `sm-payload-tab-*.js` 951,668 + 主 chunk 428,192 | **1,397,533 B / 1,397.53 kB** | 342,904 B |
| **L2(注册表 + 入口桶)** | index 15,830 + eval 6,529 + 主 chunk 428,175 | **450,534 B / 450.53 kB** | 115,547 B |

L1 的首屏静态图与拆分前**持平(甚至 +827 B)** ⇒ **零收益**;仅看「主 chunk 变小」会得出错误结论。
故**两处同改是充分必要条件**,`manualChunks` 单点隔离同理只是把字节搬家、不改首屏图。

### 3.2 落地形态(已实施)

| # | 文件 | 改动 |
|---|---|---|
| ① | `packages/vm-ui/src/payload/lazy-payload-tab.ts`(**新增**) | `<sm-payload-tab-host>`:零样式 light-DOM 透传壳;`connectedCallback` 触发 `import("./sm-payload-tab.js")` ⇒ 创建真组件 + 透传 `dataSource`/`actionSink` + 首次 `refresh()`(复现「挂载即编译」并广播 `payload-breakpoints-changed`);导出 `whenReady(): Promise<SmPayloadTab>` 就绪钩子 |
| ② | `packages/vm-ui/src/workspace/tab-registry.ts`(L27-31 / L158-174) | payload 工厂静态 import `SmPayloadTab` → `SmPayloadTabHost`;工厂体 `new SmPayloadTab()` → `new SmPayloadTabHost()`(**唯一消费面改动**) |
| ③ | `packages/vm-ui/src/index.ts`(L61-82) | 入口桶 Blockly 承载面**退场**:`sm-payload-tab` / `compiler/blocks` / `compiler/compile` 三行 `export *` → `export type *`(类型面零运行时边);新增 `loadPayloadEngine(): Promise<typeof import("./payload/sm-payload-tab.js")>` 惰性访问器;Blockly 无关的 `executor` / `compiler/types` / `compiler/eval` 值面**保留** |
| ④ | 测试面 3 文件 | 见 §五 |

**为什么用「壳 + 动态 import」而不是把 `<sm-payload-tab>` 内部改成 async**:workspace 只经 duck-typing 契约
触达内容元素(`dataSource` / `actionSink` / `refresh` / `breakpointAddresses` / `stepOnce` + 两个事件),
一个壳即可完成惰性化;改组件内部等于把首帧 Blockly inject 拆成两段,行为面风险更高且触碰并发占用文件。

### 3.3 被否决 / 未采纳的形态

- **`manualChunks` 单点隔离**:字节搬家,首屏静态图不变 ⇒ 假绿(§3.1 L1 同机理)。
- **`packages/web-component` 拆分**:主控裁决**维持单产物** —— `codeSplitting:false` 是该包的**嵌入契约**
  (消费者以单个 `<script>` / 单入口加载),改多产物 = 破坏性变更。实测其 `dist/index.js` = **1,686,014 B**
  (23:05 基线)/ **1,722,960 B = 1,722.96 kB(gzip 419.16 kB)**(23:2x `pnpm build` 重建;增量来自并发在途
  改动,非 WP-83 面),动态 import 被压平 ⇒ **该拓扑零收益**(登记为结构性限制,D-API-147)。
  另核实:`packages/web-component/src/index.ts` **不存在**入口桶承载 Blockly 的再导出(其 `export *` 六行
  全是本包模块,`pwn-memory-vm.ts` 只从 vm-ui 按名 import `SessionClient` / `SmWorkspace` 等),
  ⇒「入口桶退场」手段对该包**无适用对象**,无需改动(该包此刻无人占用)。
  另经全包扫描确认:`web-component` / `react-wrapper` / `embed-runtime` 三包 src **零引用** payload 值面
  (`SmPayloadTab` / `compilePayload` / `registerPayloadBlocks` / `PAYLOAD_*` / `payload/`),故本次公开 API
  收窄**无连带改动**。
- **「视口进入 / 首次交互才加载」**:属增量优化,会改变「常驻窗口内容恒在场」(D-MP-1)的既有语义
  ⇒ 本波次不做;触发条件见 §六 遗留 4。

```js
/** generateBundle 归因:按 chunk 汇总 modules[id].renderedLength,按 module id 分桶。 */
const attribution = {
  name: "wp83-attribution",
  generateBundle(_options, bundle) {
    const report = [];
    for (const [file, chunk] of Object.entries(bundle)) {
      if (chunk.type !== "chunk") continue;
      const buckets = new Map();
      for (const [id, mod] of Object.entries(chunk.modules)) {
        const key = id.includes("/blockly") || id.includes("@blockly/") ? "blockly"
          : id.includes("/zod/") ? "zod"
          : id.includes("/lit") || id.includes("@lit-labs/") ? "lit"
          : id.includes("@stackmaster/protocol") ? "protocol"
          : id.includes("/node_modules/") ? "other-nm" : "src/other";
        buckets.set(key, (buckets.get(key) ?? 0) + (mod.renderedLength ?? 0));
      }
      report.push({ file, codeChars: chunk.code.length, buckets: Object.fromEntries(buckets) });
    }
    writeFileSync(process.env.WP83_REPORT, JSON.stringify(report, null, 2));
  },
};
```

## 八、决策条目(D-API-146 ~ D-API-148,待并入 §三·二十三)

### D-API-146 体积口径与「单点惰性 = 假绿」陷阱

- **决策**:主 chunk 体积的**判定口径**固定为 `dist/sm-workspace-*.js`(被两入口共享的静态 chunk),
  并**必须同时登记**「首屏静态图」= 入口文件 + 其全部静态 import 闭包;体积单位 `kB = bytes/1000`;
  gzip 由 Node `zlib.gzipSync` 重算而非采信打包器自报值。任何「把字节搬到另一个 chunk」的手段
  (`manualChunks` 单点隔离、只改注册表一处)**不构成拆分收益**,必须用首屏静态图口径复核。
- **理由**:本波次实测反例 —— 只把 `tab-registry.ts` 的 payload 工厂改惰性时,主 chunk 由 1,379.02 kB
  降到 428.19 kB(表面达标),但入口桶 `src/index.ts` 仍静态再导出 Blockly 承载模块,而该入口是插件
  文档页直接加载的首屏文件 ⇒ **首屏静态图 1,397.53 kB ≈ 拆分前 1,396.71 kB(甚至 +827 B)**,即
  「主 chunk 达标 + 用户首屏零收益」的假绿。两处同改后首屏静态图 1,396.71 → **452.51 kB**。
- **红灯位置**:体积回归机检若只看 `dist/sm-workspace-*.js` 单项,会在「L1 形态」下报绿 ⇒ 机检须
  **两条同时断言**(主 chunk < 1.3MB **且** 入口 `index.js` 的静态 import 闭包不含 `payload` chunk;
  可直接 grep `dist/index.js` 的静态 import 边 + 全 dist「谁静态 import 了 payload chunk = 空集」)。
  > 口径说明:中期回报里曾给出早期部分构建的 **382.96 / 1,385 / 1,392.05 / 440.31 kB**;本文件一律采用
  > **同快照忠实构建**的最终口径(§2.1 / §3.1 / §4),两套数字**结论同向**(单点惰性 = 零收益)。
- **影响面**:后续任何拆分 / 懒加载 / 依赖瘦身波次的验收口径与机检脚本;`docs/phases/中期任务分解.md`
  §一.2.3 与 §九 风险行的「1.3MB」判据解释权;`packages/web-component`(D-API-147)沿用同一「首屏静态图」思维。

### D-API-147 `packages/web-component` 单产物 = 结构性限制(维持不拆)

- **决策**:`packages/web-component` 维持 `rollupOptions.output.codeSplitting: false` 的**单产物**
  形态,**不做拆分**;其动态 import 被压平 ⇒ 该拓扑下 `import()` 拆分**零收益**,登记为**结构性限制**
  (触发条件 = 若未来 web-component 改为多产物入口,则适用同一拆分手段)。
- **理由**:单产物是该包的**嵌入契约**(消费者以单个 `<script>` / 单入口加载,`dist/index.js` 实测
  1,686,014 B,非根路径部署 = 文档页内相对路径引用),为体积改多产物会**改变消费者加载方式**
  = 破坏性变更(红线);且体积义务的判定口径本身是 `dist/sm-workspace-*.js`,以该口径结清。
  另经核实:`packages/web-component/src/index.ts` **不存在**入口桶承载 Blockly 的再导出
  (六行 `export *` 全是本包模块),故「入口桶退场」手段对该包**无适用对象**,改动为零。
- **红灯位置**:无新增机检;该限制登记在本文件与 `docs/develop/decisions-m3/` 中,
  防止后续波次重复评估同一问题(或误把 `codeSplitting:false` 当缺陷「顺手修掉」而破坏嵌入契约)。
- **影响面**:`packages/web-component` 构建配置保持冻结;体积义务的举证责任固定在 `packages/vm-ui`
  产物口径上;不影响 `packages/vm-ui` 的拆分收益(插件文档页拓扑与本包相互独立)。

### D-API-148 拆分实施与判定(主 chunk 由 1,379.02 kB → 428.65 kB,义务关闭)
