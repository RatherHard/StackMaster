## 一、范围

本 WP 交付三块:

1. **worker 装配管线**(`session/assemble.rs`):契约镜像(私有判题包)+ 公开描述包(D-F10)→ `Engine` / `Judge` / `ProjectionPolicy` / `ReplayContext` 的唯一转换点——"契约面经 vm-worker 镜像层转换为本文类型"(判题语义规约 §4.2)的落点;
2. **worker 会话托管与进程资源面**(`session/host.rs`、`session/watchdog.rs`、`main.rs`):命令 → `SessionRuntime` 执行链路、响应面装配、wall-clock 看门狗、引擎 panic 安全终止;
3. **TS 会话编排核心**(`packages/session-core`,进程内服务,HTTP / WSS 网络面归阶段三):生命周期状态机、单会话串行队列、worker 进程管理、服务端校验基线 §六的编排侧条目(#1–#5)、revision / 投影账本、幂等缓存、submit 内部引用、崩溃替换恢复编排。

明确不属于本阶段:认证真实实现(§五替身接口)、PostgreSQL / Redis 持久化、`sync-projection` 网络下发、独立 verifier(阶段六)。

## 二、决策记录

### D-W8-1 投影策略与静态声明面的 worker 侧装配源

`ProjectionPolicy` 整体 SERVER_ONLY,驻留执行域内,由本装配管线派生:

| 策略字段 | 装配来源 | 复验 |
|---|---|---|
| `visibleRegions` | 私有包 `memoryRegions[]` 中 `isHidden = false` 者(声明序) | 与公开描述包 `memoryLayout.regions` 的 regionId 序列**互证相等**(公开布局结构性无隐藏表达位;漂移即 `challenge_invalid`,红灯 `public_layout_mismatch`) |
| `visibleRegisters` | 公开 `vmProfile.registers`(声明序;WP-1 §12.5 冻结的组装来源) | 每项 ∈ 初始寄存器集(`public_register_undeclared`)、非 FLAG(`public_register_flag`)、非秘密汇(`public_register_is_secret_sink`,I3-VISIBLE-REG 装配期复核;策略 `assemble` 内再复核一次) |
| `visibleObjects` | 私有对象 `visibility = public` 的 objectId(声明序) | 策略白名单护栏 |
| `maxBytesPerRange` | 装配常量 = 协议默认 256 | 协议未给题目授权面;演进走契约变更流程 |
| `errorDetailLevel` | 装配常量 = `educational` | 同上 |

静态声明面(`ProjectionStatics`):区域标签 = 公开描述包 `publicLabel`(fail-closed:白名单区域缺标签即拒绝,投影语义规约 §二);语义高亮 = **可见**私有对象的槽位声明(buffer / canary / saved_rbp / return_address 四类;隐藏对象不产生高亮——布局零外泄),几何与区域归属由 `ProjectionStatics::assemble` 复验。

### D-W8-2 双程序形态与公开编码表单点

- IR 模式:`compiledIr` 编译产物直读;`entrypointIndex` 必填;初始 `instructionPointer` 是**指令索引**,越界即装配拒绝(`ir_entrypoint_out_of_range`——WP-4 引擎在取指层报 `invalid_rip`,本检查将作者错误提前到装载,方向不变);
- 字节模式:`entrypointAddressHex` + 公开描述包 `vmProfile.encodingTable`(单点来源,私有包不复制);无公开表即拒绝(`byte_mode_requires_public_encoding_table`);IR 模式禁止携带公开表(`ir_mode_forbids_encoding_table`);
- 双形态互斥由 XS-PROG-MODE 上游强制,装配镜像复验(`program_mode_ambiguous`)。

### D-W8-3 约束预算装配来源表(引擎无时钟;数值常量为装配层冻结,演进走本规约修订)

| `RuntimeConstraints` 字段 | 来源 |
|---|---|
| `steps.limit` | 装配常量 `GLOBAL_STEPS_LIMIT` = 10 000 000(与判题面单阶段预算上界同值;阶段级预算由判题面强制) |
| `memory_bytes_limit` | 装载区域字节总量(固定大小分页不增长,静态护栏取紧界) |
| `wall_clock_ms_limit` | 装配常量 `SESSION_WALL_CLOCK_MS_LIMIT` = 3 600 000(登记;实际执行归看门狗,D-W8-4) |
| `call_depth_limit` | 协议冻结常量 `CALL_STACK_MAX_DEPTH` = 64 |
| `action_log.limit` | 装配常量 `ACTION_LOG_LIMIT` = 10 000(运行时结构护栏以日志真实长度为准) |
| `output_bytes.limit` | 装配常量 `OUTPUT_BYTES_LIMIT` = 4 096 |
| `timeout_ms_limit` | 私有包 `judgingConfig.timeoutMsPerAction`,缺省 5 000(登记;看门狗读取同值) |
| `predicate_evals.limit` | `judgingConfig.maxPredicateEvalSteps`(1–10 000 000);公开 `resourceLimits.predicateEvalBudgetPerSession` 声明存在时必须同值(双真相源复验,`predicate_budget_mismatch`) |
| `rollback_ops.limit` | 公开 `resourceLimits.rollbackBudgetPerSession`,缺省 200 |

### D-W8-4 wall-clock 看门狗(超时的实现层)

引擎 crate 无时钟(ENG-2),单动作 wall-clock 超时由 worker 进程层执行:常驻看门狗线程 + 命令通道;`apply_action` 处理前以 `timeoutMsPerAction` 武装,响应写出后解除。预算耗尽 → 受控日志(`watchdog timeout action_deadline_exceeded`)+ **退出码 3**(§六退出码表之外的专用诊断码,编排器据此与协议违规区分处置)→ 不写任何 stdout 帧(避免与主线程帧写出交错)。看门狗只影响超时故障方向,不改变任何确定性响应(I-4)。编排器侧另有外层兜底超时 + 强制终止(§四.3)。

### D-W8-5 托管故障的安全终止方向

`SessionHost` 故障(`HostFault`)一律终止进程(响应尽力而为 + 非零退出码 1),进程不复用、恢复走崩溃替换:

| 故障 | 命令级错误码 | 方向 |
|---|---|---|
| `Runtime(PredicateBudgetExhausted)` | `challenge_invalid` | 谓词预算安全终止(WP-5 §1.3) |
| `Runtime(MemoryBudgetExceeded / VersionLock)` | `challenge_invalid` | 装配 / 版本锁定方向 |
| `Snapshot(_)`(导入载荷形态失败) | `challenge_invalid` | **不终止**:替换解析先于任何变更,会话未被触及 |
| `Runtime(_)`(判题内部 / 表单化)、`Projection(_)`、出站自检失败 | `internal_error` | engine_error / 引擎缺陷方向 |

引擎 panic(release 溢出检查触发,ENG-3)由二进制入口 `catch_unwind` 捕获:受控日志(`engine_panic engine_error`)+ 退出码 1——绝不静默回绕。

### D-W8-6 隐藏测试输入槽

判题语义规约 D-H2 承接:双包 Schema v1 无输入槽声明字段,装配上下文 `input_sink = None`;`reference_payload` 非空载荷的题目在判题装配复验即拒绝(`challenge_invalid`)。契约面增补走 WP-1 §1.3 变更流程,不在本 WP 私扩。

### D-W8-7 写入预算与写分类的执行前判定序

`write_bytes` 的执行前判定(先于 `SessionRuntime::apply`,拒绝不触碰运行时:revision 不动、无日志条目):

1. **可见性三分类**(D-P1,语义优先):全覆盖 → 放行;越界 → `offset_out_of_range`(`expectedBytesLength` = 起点起可见覆盖前缀,E-3);不可见 → `inaccessible_address`(I-9 统一形态,隐藏映射与未映射不可区分);
2. **题目级写入预算**:公开包 `resourceLimits.maxWriteBytesPerAction`(≤ 协议上限 4096,Schema 承担外圈)→ 超限拒绝 `invalid_payload_length`(`expectedBytesLength` = 题目预算、`actualBytesLength` = 请求字节数;新增 `RejectionReason::WriteExceedsChallengeBudget`)。

可见性先于预算:I-9 零外泄语义优先于预算事实(不可见目标的响应不携带预算信息)。

### D-W8-8 回退步的响应事件段与崩溃替换

- **回退步(undo / checkout / reset)不承载事件段**(与投影差分套件同纪律:历史回退不重发历史事件)——响应 `publicEvents` 为空、增量无脏范围;回退后的内容差异经下一次完整投影(`sync-projection`)对齐;
- 暂停原因不进快照:崩溃替换恢复后 `pausedOn` 确定性清空;
- 恢复后旧 checkpoint 引用随进程消失(协议 §4.7 退化如实记录),checkpoint 时间线的重建归编排器账本(§四.2)。

### D-W8-9 编排核心的幂等与账本语义(会话动作协议 §四的编排侧实现)

| 基线 | 编排侧落点 |
|---|---|
| #1/#2 认证上下文与 token 绑定 | 可注入接口替身(`AuthContext`):阶段二桩实现恒通过并回填固定主体;真实认证归阶段三 |
| #3 `baseRevision` 校验 | 入队前预检:不等当前权威 revision → 确定性 `rejected`(stale_base_revision,revision 返回当前值),不触发 worker 往返 |
| #4 `idempotencyKey` 防重 | `(sessionId, key)` → `{规范化请求, 响应字节}` 缓存:同键同规范化负载 → **字节相同**重放缓存响应(动作不重放);同键异负载 → 确定性 `rejected`(idempotency_conflict) |
| #5 单会话串行 | 会话内互斥队列(一次一个动作);`clientSeq` 高水位:≤ 高水位且非幂等重放 → `rejected`(stale_client_seq);被拒绝的请求同样消耗其 `clientSeq` |
| #6 重校验 | worker(执行域内权威校验点)——编排器**不**复制执行面校验 |
| #8 校验失败响应面 | 编排器预检拒绝面 = 冻结 `PublicError` 形态 + 静态模板(与 worker 协议级拒绝行同构) |

**revision 与投影账本**:权威 revision 来自 worker 响应(编排器不得自行推算);已接受动作(状态 ≠ rejected)恒 +1、被拒绝不动(增量 ∈ {0,+1},ZR-P5 的账本侧断言)。`sync-projection` 只重发最近缓存投影(不触发谓词重询);快照导入后需 `query_projection` 取数。checkpoint 账本由 `create_checkpoint` 的 `checkpointExport` 回执驱动(`checkpointId` / 标签 / 内容 revision / 创建顺序),`list-checkpoints` 是账本查询、无 worker 往返。

**submit 内部引用**(§5.1:提交引用服务端记录的规范化动作日志):编排器按**已接受动作**累积规范化动作序列(被拒绝动作不入日志——与运行时"拒绝不入账"同锚),`submit` 产出内部裁决引用 `{sessionId, 题目身份三元组, 引擎身份, revision, 状态快照, 规范化动作日志, 终态标签}`;最终裁决由阶段六 verifier 重放产生,本阶段只保证日志完整可重放(集成测试以全新 worker 重放该日志并比对最终投影)。

### D-W8-10 worker 进程管理

- **单会话单进程**(ADR-3):`create-session` 即 spawn;会话关闭 / 崩溃后进程**不复用**;
- 版本握手:`ready.protocolVersion` ≠ 编排器常量 → 拒绝建会话并回收进程(协议 §2.2,fail-closed,无协商降级);
- 崩溃分类:退出码 0 = 优雅;3 = 看门狗超时;其他非零 = 协议违规 / 引擎故障;stdin 断裂(SIGKILL)= 强制终止;
- 僵尸回收:close 超时后 SIGKILL + `wait` 回收;退出事件处理器一次性注销,句柄不泄漏;
- 帧纪律(与 Rust 帧层对偶):NDJSON、单帧 16 MiB、stop-and-wait(`seq` 自 1 严格递增)、stdout 每行必须是协议帧。

## 三、秘密零驻留(编排器进程)

- 编排核心对私有包**只透传**:load 帧构造读取 `seedPolicy.strategy` 与身份三元组(装载回执核对用),不解析 secrets / judging / hiddenTests / IR,不持久化、不进日志、不进任何缓存;
- 会话种子(`server_random_per_session`)由编排器生成(D-F9)后仅存在于 load 命令帧构造的瞬时作用域,不进账本与缓存;
- 机检:集成测试对**编排核心全部留存状态**(幂等缓存、投影缓存、checkpoint 账本、submit 引用、事件日志)做语料扫描——seed 十六进制、`secrets.flag`、虚拟文件内容零命中;红灯反例(故意把秘密写入缓存形态)证明扫描器可检出。

### D-W8-11 快照载荷的驻留边界(零驻留的精确读法)

快照信封的 `payload`(`stackmaster-session-snapshot/1`)承载 `VmState` 规范化形态——**含 `seedState.stateBytes`**(恢复所必需,快照与回放语义规约 §四)。协议 §4.4 冻结其处置:编排器将快照存为崩溃恢复点(阶段三 PostgreSQL 持久化)。因此零驻留不变式的精确边界是:

- **编排器进程的计算态**(账本、缓存、日志、submit 引用、响应面)零秘密——机检语料扫描承接;
- **快照载荷**是 worker 所有的 SERVER_ONLY 持久化 blob,经协议 sanctioned 通道落到编排器存储:编排器只存取、不解析、不派生;阶段三落盘必须加密静止(秘密分级随 SERVER_ONLY)。
- load 命令的私有包透传同理(瞬时经过,不留存)。

## 四、TS 编排核心(packages/session-core)

### 4.1 生命周期状态机(9.1)

```text
create-session(spawn → ready 比对 → load → query_projection)
  → action / step / run-to-event / pause(12 动作经 apply_action,单会话串行队列)
  → undo / checkout / reset(同上;编排器零特判——它们本来就是会话动作)
  → create-checkpoint(apply_action;回执驱动 checkpoint 账本)
  → list-checkpoints(账本查询,无 worker 往返)
  → sync-projection(重发最近缓存投影;仅快照导入后 query 取数)
  → submit(内部裁决引用,D-W8-9)
  → close-session(shutdown → 退出码 0 回收)
```

终态会话(won / failed):状态转换动作与 undo / checkout / reset 经 worker 权威拒绝(编排器不复制终态判定,worker 是权威);`sync-projection` / `list-checkpoints` / `submit` / `close-session` 不受终态影响。

### 4.2 崩溃替换恢复(D-F8 编排侧编排)

worker 被强制终止 / 非零退出后:`spawn 新进程 → load(私有包 + 公开包)→ import_snapshot(最近服务端快照)→ query_projection(重同步取数)`;账本重建 = revision 自快照信封续算、缓存投影替换为取数结果、checkpoint 账本清空(§4.7 退化如实记录)。恢复点来源:`export_snapshot` 显式导出与 `create_checkpoint` 回执快照。

### 4.3 编排器外层资源兜底

编排器对每个 worker 往返持有调用级超时;超时 / 进程失联 → 强制终止(SIGKILL)→ 崩溃分类 → 恢复路径可用。与 worker 看门狗构成两层(D-W8-4;阶段二风险表"worker 进程层看门狗 + 编排器外层兜底")。
