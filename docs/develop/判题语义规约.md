## 一、总则

### 1.1 判题链路位置与求值时点(D-J1)

判题发生在每个**已执行动作**的状态转换之后、投影生成之前(计划书 6.2 动作链路的私有目标条件检查位):

```text
gate(动作闸门:终态 / 阶段允许动作 / 阶段动作数预算)
→ 引擎执行动作(WP-4 执行语义)
→ settle(动作后检查点:阶段步数预算 → 失败条件 → 成功条件 → 阶段迁移)
→ 投影生成(WP-7)
```

- **已执行动作**才触发检查点:进入执行前被拒绝的动作(载荷校验失败、闸门拒绝)不推进 revision 也不求值(与会话动作协议 §4.2 修订语义一致);
- **管理类动作**(`undo` / `checkout_checkpoint` / `reset` / `create_checkpoint`)不重新求值历史判定(D1 约束 5:"非终态会话的回退不重新求值");判题阶段状态的回退随 WP-6 快照内容承载,`reset` 的判题侧落点见 §4.6;
- `sync-projection` 是缓存重发,不触发求值(D1 约束 1);
- 检查点内**失败优先于成功**(fail-closed):失败条件与成功条件同帧同时为真时,会话进入 `failed`。

### 1.2 白名单外形态的双层拒绝(WP-5 完成标准)

- **编译期(WP-2 / WP-4 检查器)**:Schema `oneOf` + `additionalProperties: false` + 三级 `$defs` 静态展开(XS-NESTING)在入站面拒绝;
- **运行时(本模块)**:引擎侧类型为封闭枚举(`Predicate` 七变体、`ConditionL1/L2/L3` 三层定深),白名单外形态在 Rust 类型层**结构性不可表达**;装载管线把契约镜像转换为引擎类型时经 `Judge::assemble` **镜像复验**(§4.2),引用不可解析 / 边界越界 / 上限越界一律 `challenge_invalid` 方向拒绝,不近似执行。

### 1.3 判题预算与记账单位(D-J6)

- 一步 = **一次内置谓词实例求值**。该单位与冻结表 `constraints.predicate_evals` 的"私有谓词求值次数预算(按会话累计)"一致(WP-1 §3.2);
- 预算上限的唯一真相源是 `judgingConfig.maxPredicateEvalSteps`(1–10 000 000);引擎 `constraints.predicate_evals.limit` 必须与之同值(装配复验,防双真相源);
- 每次检查点**先静态计数、后一次性预扣**(§4.4):布尔组合不短路(§3.2)⇒ 每次检查点的步耗是判题面的静态函数,与状态内容无关;
- 预算耗尽 → `challenge_invalid` 方向**安全终止**(WP-5 条目语义:恶意题目包谓词组合爆炸的运行时兜底,非玩家可及的 `resource_limit`);引擎侧以 `JudgeError::PredicateBudgetExhausted` 上抛,会话处置归 WP-8;
- 累计性:该预算**跨 undo / reset 不重置**(D1 约束 5)。`Engine::reset` 保留 `predicate_evals` 后再恢复初始状态(本 WP 修正项,原实现随 `initial_state` 整体克隆会把累计量一并回滚,违反冻结表语义)。

### 1.4 恒定成本纪律(I-6 / D1 约束 2 / T-SC2 / ZR-P7)

一切隐藏内容的比较**无提前退出**:

- `memory_equals`:定长切片**全量比对**(逐字节 OR 累积差异,不因首字节不同短路);
- `memory_contains`:**全位置 × 全长度**扫描(每个候选位置都做完整 needle 长度比对,命中与否都扫完全部位置);
- 条件树**不短路**(§3.2):`all` / `any` / `not` 的所有分支无条件全部求值——单字节突变改变某谓词结果时,检查点的求值次数与记账量不变(步耗恒定的引擎侧属性测试锚点,`judge::tests::constant_cost_single_byte_mutation`);
- 无进度字段(I-7):判题事件载荷只携带类别标签与序号(§1.5),不含命中计数、比例或谓词内容。

### 1.5 私有事件与载荷纪律

判题痕迹写 `privateEventLog`,类别 = `Internal`(**永不进入公开面**,WP-7 白名单外);阶段副作用 `grant_virtual_file` 复用 `FileGranted` 事件(与接口效果原语同形态)。载荷为引擎生成的定长标签 + 索引(值来源纪律对齐 I-10):

| 事件 | 载荷 |
|---|---|
| 成功条件达成 | `Internal{payload: [0x01]}` |
| 失败条件触发 | `Internal{payload: [0x02 ‖ 条件索引 LE u64]}`(题级与阶段级同标签,索引为各自声明序) |
| 阶段步数预算超限 | `Internal{payload: [0x04 ‖ 阶段索引 LE u64]}` |
| 阶段迁移 | `Internal{payload: [0x03 ‖ 目标阶段索引 LE u64]}` |
| 阶段副作用 | `FileGranted{byteLength: fileId 长度, payload: fileId 字节}`(与 WP-4 接口效果同形态) |
| 隐藏测试结果 | `Internal{payload: [0x05 ‖ 测试索引 LE u32 ‖ verdict 判别值 u8 ‖ 通过位 u8]}` |

## 二、内置谓词逐条规约(7 值封闭集)

求值输入 = 引擎当前状态(`&Engine`);判题视角**只读**,不产生事件、不改状态、不消耗执行步数预算。前置条件:谓词已过装配复验(§4.2);复验后不可达路径以引擎缺陷方向(`engine_error`)暴露。

| 谓词 | 语义 | 步耗 | 边界与异常 |
|---|---|---|---|
| `register_equals {register, value}` | `registers[register] == value`(掩蔽域等值;FLAG 命名寄存器可查,值永不进公开面) | 1 | 寄存器不存在 → 装配拒绝(XS-PRED-REFS 镜像);求值期不存在 = 引擎缺陷 |
| `register_bits_set {register, mask}` | `(registers[register] & mask) != 0`(位集合检查,掩码为 0 ⇒ 恒假) | 1 | 同上 |
| `memory_equals {regionId, offsetBytes, bytesHex}` | 区域 `[start + offset, start + offset + len)` 与定长字节切片**全量比对**相等(固定长度切片,§1.4) | 1 | 装配复验:区域存在 ∧ 权限含 `r` ∧ `[offset, offset+len) ⊆ [0, byteLength)`(XS-PRED-REFS 镜像 + 区域可读性扩展)∧ len ≤ 256 |
| `memory_contains {regionId, bytesHex}` | 区域内存在子串匹配(**全位置全长度扫描**,无提前退出) | 1 | 装配复验:区域存在 ∧ 可读 ∧ 1 ≤ len ≤ 64 ∧ len ≤ byteLength |
| `ret_target_equals {addressHex}` | **下一次 `ret` 将弹出并跳转的值** = 当前 `RSP` 指向的 8 字节栈槽(定宽小端读,掩蔽域比较,与 `ret` 指令的弹出语义同锚) | 1 | 栈槽读取失败(RSP 指向不可读位置)⇒ **假**(确定性:下一次 `ret` 本将以 `memory_fault` 失败);不产生异常 |
| `stack_canary_intact` | 全部 Canary 槽位当前内容与装载期期望一致(WP-4 期望值截取的同源查询) | 1 | 槽位读取失败按已破坏计(静态权限下不可达的防御性兜底);无 Canary 槽位 ⇒ 恒真 |
| `virtual_file_read {fileId}` | 私有事件日志存在对应 `FileRead` 事件(payload = fileId 字节;接口效果原语 `virtual_file_read` 的痕迹) | 1 | fileId 不在声明文件集 → 装配拒绝(XS-IFACE-REF 同立场镜像) |

## 三、条件结构(L1 / L2 / L3)与求值代数

### 3.1 结构(镜像 Schema `$defs`,深度静态封顶)

```text
L1: { all?: [L2] (0–4), any?: [L2] (0–4), not?: L2 }   // 至少一键(XS-NESTING 镜像)
L2: { all?: [L3] (0–4), any?: [L3] (0–4), not?: L3 }   // 至少一键
L3: { predicate: <内置谓词> }
```

- 引擎类型三层定深(L1 含 L2、L2 含 L3、L3 只含谓词实例),第四层结构性不可表达;
- `all: []` 恒真、`any: []` 恒假(Schema `minItems: 0` 语义);零键节点(`{}`)装配拒绝;
- 装配复验分支上限:每层 `all` / `any` 各 ≤ 4。

### 3.2 求值代数(不短路)

```text
eval(L1) = AND( ∀l2∈all: eval(l2), ∃l2∈any(析取): eval(l2), NOT(eval(not)) )   // 出现的键才参与
```

- **所有分支无条件全部求值**后布尔合并(§1.4 恒定成本);
- 步耗 = 树内谓词实例总数(静态函数 `predicate_count`,含 `not` 分支);
- 单条件树谓词实例上界:每层 ≤ (4 + 4 + 1) = 9 个子节点 ⇒ L1 ≤ 81;检查点总步耗上界 = 81 × (1 成功 + 8 题级失败 + 8 阶段失败 + 8 × (迁移 + 目标前置)) = 2 187,由 `maxPredicateEvalSteps` 全局承接。

## 四、多阶段状态机运行时(六要素落点)

### 4.1 运行时形态(D-J2)

- `stages` 为空 = 单阶段题:无阶段闸门、无迁移,仅题级成功 / 失败条件与全局预算;
- 阶段运行时状态(`Judge` 内部,不进 `VmState` 冻结 8 字段):当前阶段索引(装配 = 0)、本阶段已耗指令步数、本阶段已受理动作数——**每次进入阶段即清零**(重复进入同阶段亦然);快照承载归 WP-6;
- **前置条件 = 入场闸门**:迁移条件与目标阶段前置条件在同一检查点全量求值,**两者同时成立**才迁移(声明序首个成立者触发,一次检查点至多一次迁移,不级联);
- **副作用在进入阶段时触发**(含装配时的初始阶段):`grant_virtual_file` 记 `FileGranted` 事件,授予语义幂等(事件可重复,效果为集合并入);
- **失败条件**:题级与当前阶段级并存,任一触发即 `failed` 终态(D1 约束 5);
- **预算**:`maxInstructionSteps`(1–10 000 000)= 本阶段每次进入内的指令步数上限;`maxActions`(1–1 000 000)= 本阶段每次进入内的受理动作数上限。

### 4.2 装配镜像复验(`Judge::assemble`,方向 = challenge_invalid)

对判题面全量 fail-closed 复验(上游检查器 XS-* 的引擎镜像,防绕过编排器直装):

| 复验项 | 镜像规则 |
|---|---|
| 谓词引用 | 寄存器 ∈ 引擎寄存器集;区域存在 ∧ 权限含 `r` ∧ 切片几何在区域内;`memory_equals` ≤ 256 B / `memory_contains` 1–64 B;fileId ∈ 声明虚拟文件集(XS-PRED-REFS + 本文可读性扩展) |
| 条件形态 | 每层至少一键;`all` / `any` 各 ≤ 4(XS-NESTING 镜像) |
| 面上限 | `failureConditions` ≤ 8、`stages` ≤ 8、每阶段 `transitions` / `sideEffects` / 阶段级 `failureConditions` ≤ 8、`hiddenTests` ≤ 16、`allowedActions` ≤ 12 且无重复 |
| 阶段机 | stageId 唯一;迁移目标存在(XS-STAGE-REACH 前半);自 `stages[0]` BFS 全可达(XS-STAGE-REACH 后半);`maxInstructionSteps` ∈ [1, 10⁷]、`maxActions` ∈ [1, 10⁶](XS-STAGE-BUDGET 镜像);副作用 fileId ∈ 声明文件集 |
| 预算单源 | `constraints.predicate_evals.limit == judgingConfig.maxPredicateEvalSteps` |
| 初始前置 | `stages[0].preconditions` 在初始状态求值为真(作者错误 ⇒ 装配拒绝);求值按 §1.3 记账 |
| 隐藏测试 | testId 唯一;`predicate_probe` 载荷必须为空;`reference_payload` 非空载荷要求装配上下文已声明输入槽(§七);载荷 ≤ 4096 B;`expectedResult` ∈ 7 值可达判定枚举(D6:结构类型承载) |

装配通过即触发初始阶段副作用(§4.1)。

### 4.3 动作闸门(`Judge::gate`,每动作执行前)

按序:

1. 会话终态(`won` / `failed`)⇒ 拒绝一切 12 动作(D1 约束 5,确定性错误);
2. 当前阶段 `allowedActions` 不含该动作 ⇒ 拒绝(方向 `invalid_action`;单阶段题无此闸);
3. 当前阶段 `maxActions` 已达上限 ⇒ 拒绝(方向 `resource_limit`;计数在 settle 递增);
4. 通过 ⇒ 返回**步数窗口** = min(全局步数预算剩余, 当前阶段步数预算剩余),供执行层夹逼 `run_to_event`(窗口为 0 时执行层不得推进取指)。

### 4.4 检查点顺序(`Judge::settle`,每已执行动作后)

```text
① 阶段动作数 +1;阶段步数记账(steps_executed = 动作前后 constraints.steps.used 增量)
② 阶段步数超限(used > maxInstructionSteps)⇒ failed(resource_limit 方向);
   窗口夹逼下恰达上限不触发("恰好到限成功")
③ 会话已终态(引擎异常已 failed / 已 won)⇒ 不再求值
④ 管理类动作 ⇒ 不求值(D1 约束 5)
⑤ 预扣检查点谓词步耗(静态计数;耗尽 ⇒ challenge_invalid 方向上抛)
⑥ 失败条件:题级(声明序)→ 当前阶段级(声明序),全量求值;首个命中者上报 ⇒ failed
⑦ 成功条件 ⇒ won
⑧ 阶段迁移:全部迁移条件 + 全部目标前置全量求值,声明序首个(条件 ∧ 前置)者触发
   ⇒ 记迁移事件、阶段状态重置、触发新阶段副作用
```

### 4.5 迁移与副作用时序

- 迁移在⑥⑦之后:**先判终态、后判迁移**——本帧触发失败 / 成功的会话不再迁移;
- 新阶段的失败条件、迁移条件自**下一检查点**起生效(一次检查点至多一次状态变更,确定性);
- 副作用在迁移决定后立即触发(同帧);新阶段前置条件已在②入场闸门语义中求值(作为迁移条件的一部分)。

### 4.6 `reset` 的判题侧落点

`reset` 动作:引擎侧恢复初始状态(WP-4)+ **保留 `predicate_evals` 累计**(§1.3);判题侧阶段状态回到初始阶段(索引 0、预算清零、重新触发初始阶段副作用)。undo / checkout 的判题状态回退随 WP-6 快照内容承载(快照 payload 须含判题阶段状态与 seed 派生元数据——移交项)。

## 五、status 迁移权威时点

- `won` / `failed` **只在检查点**(§4.4 ⑥⑦)与引擎异常(WP-4 `fail()`)置位;指令执行中途不判题;
- 公开时点 = 动作响应同步携带(D1:无重询旁路、无进度字段);`PublicStatus` 粗化归 WP-7;
- 终态后:一切 12 动作以确定性错误拒绝;`sync-projection` / `submit` / 时间线查看不受终态影响(会话动作协议 §3.0);
- 公开 `won` / `failed` 不泄露隐藏条件:判定成本恒定(§1.4)、载荷纪律(§1.5)、预算耗尽走 `challenge_invalid`(非玩家可探测的 `resource_limit`)。

## 六、seed 策略与派生(D-J7)

- 策略二值(`SeedStrategy`):`fixed`(包内 `seedPolicy.seedHex`)与 `server_random_per_session`(编排器生成的 `sessionSeedHex`,D-F9:worker 只消费);
- **互斥解析**(`resolve_seed_state`,XS-SEED-POLICY 引擎镜像):`fixed` ⇒ 包内 seed 必填(8–32 字节)∧ 会话 seed 禁止;`server_random_per_session` ⇒ 会话 seed 必填 ∧ 包内 seed 禁止;长度界 8–32 字节;违反 ⇒ `challenge_invalid` 方向;
- 解析产物 = `SeedState { strategy, version: 1, state_bytes }`(seed 零驻留:只存在于 worker 进程内,无序列化路径);
- **随机数经注入 trait 派生**:`SessionRng`(注入面)+ 引擎内置确定性派生器 `SeedDeriver`(`splitmix64-stream-v1`:种子字节 FNV-1a 64 折叠 → splitmix64 流,第 k 次抽取仅由种子与 k 决定;确定性由 `vmEngineVersion` 锁定);
- **派生路径元数据**(不含 seed 值):`DerivationPathSummary { algorithm_id: "splitmix64-stream-v1", draws }`——写入回放元数据归 WP-6;
- v1 无作者声明的随机化应用面(`declaredSeedPublicPaths` 是判定基准不是应用点);派生器是随机化能力的引擎侧承载,属性测试锁定同种子同序列、异种子异序列(13.1"随机 seed 确定性")。

### 6.1 WP-42 增补登记(D-J8–D-J10;SeedDeriver 跨语言应用面)

ADR-DC1 条款 2 / §六 R2 的"同一套派生器、两个种子"自阶段四 WP-42 起产生首个应用面;以下三条为增补登记,不改变 §六既有语义(D-J7、`SeedState` / `resolve_seed_state` 互斥镜像、`SessionRng` 注入面、`DerivationPathSummary` 元数据形态均原样)。

- **D-J8(ASLR 基址派生应用面——调试侧已落地,真实实例侧登记为引擎契约演进项)**:`aslrEnabled = true` 时,`SeedDeriver` 的**首个 draw** 派生该实例基址——调试侧自本 WP 起经编译器产出的调试变体镜像落地(`buildDebugVariantBundle`:所有区域 `startAddressHex` 按同一基址 + 结构相对偏移重写,`derivation.baseAddresses` 逐区域登记,`draws` 如实含基址槽;映射算法定案见 D-J10)。**真实实例侧(真实种子基址派生进引擎装配)不在 WP-42 实现**,登记为引擎契约演进项,理由与耦合面:①引擎 `VmState` 装配需新增"基址注入"输入(区域几何由结构描述 + 派生基址合成),触碰 ADR-8"同一份引擎代码"的装配参数面;②权威动作日志的 `write_bytes` 等动作参数是**绝对地址**,基址派生后重放必须定义地址置换变换(或动作日志地址语义演进为结构相对地址),否则真实实例自身的 undo / 回放 / checkpoint 快照恢复在异基址间不可移植;③verifier(阶段六)复用同一回放引擎,基址派生使"判定基准 = 种子 + 结构"完全成立前,`replay_mismatch` 语义须先扩展派生路径复核;④`DerivationPathSummary` 已承载派生次数,无需 Schema 变更,但快照信封须新增基址登记位。**触发条件**:真实实例启用 ASLR 的产品决策(题目 `aslrEnabled = true` 作用于真实实例)进入实施排期;触发前,真实实例维持 v1 固定基址语义,ASLR 开启的题目仅调试实例呈"同结构、异基址"的兄弟形态(ADR-DC1 条款 3 / R1 的教学语义由 what-if 纪律呈现,verifier 零改动)。
- **D-J9(`declaredSeedPublicPaths` 完备性裁决——已裁决,沿用 WP-43 理由)**:不强制非空。v1 派生器无引擎侧应用面(本条登记后仍成立:首个应用面在编译器调试变体侧,输入是调试种子而非包内种子),作者声明面是判定基准而非派生输入;完备性由 **T-SC4 / ZR-P2 差分机检兜底**(同种子同序列逐字节可复现 + 语料扫描),非空强制会为未来应用面预留未经评审的语义位,与"封闭集、无预留字段"的契约纪律相悖。登记为已裁决,后续应用面(引擎侧随机化)落地时按 D-J 系增补流程另行走变更评审。
- **D-J10(基址映射算法定案)**:首个 draw 值 `raw` 到基址的映射**写死**为五步(与 `packages/challenge-compiler/src/debug-variant/build-debug-variant.ts` 的 `deriveAslrBaseAddress` 及黄金向量 `test/golden/seed-derivation-vectors.json` 的 `baseAddressVectors` 三方一致,跨语言一致性由 `vm-engine/vm-worker/tests/seed_derivation_conformance.rs` 对偶测试锚定 draw 值):`spaceBytes = 2^archBits` → `masked = raw & (spaceBytes − 1)`(位宽掩蔽)→ `alignedPage = masked div pageSize`(向下页对齐)→ `windowPages = (spaceBytes − span) div pageSize`(`span = max(relOffsetᵢ + byteLengthᵢ)`,结构总跨度,relOffset 锚定最低区域,与 WP-43 公开包结构描述语义同锚)→ `base = (alignedPage mod windowPages) × pageSize`。性质:base 页对齐、`base + span ≤ 2^archBits`(全部区域落位宽地址空间内)、结果仅为 `(raw, archBits, pageSize, span)` 的确定性函数。`span > spaceBytes` 或 `windowPages = 0` ⇒ 编译期确定性拒绝(XC-DEBUG-ASLR-SPACE);变更本算法 = 破坏性派生语义变更,走本文变更纪律 + 黄金向量同批换版。

## 七、隐藏测试执行(D-H1 / D-H2)

隐藏测试是(输入, 预期判定)对(WP-1 §12.3);执行语义 v1 裁决如下,供 verifier(阶段六)复用:

- **时机与基线**:在会话 settle 后由判题方驱动;基线 = 传入引擎的当前状态,**每个测试从同一基线的独立克隆出发**,互不影响、基线不动(仅追加判题事件与预算记账);
- **`reference_payload`**:载荷作为一次 `write_bytes` 动作写入**装配上下文声明的输入槽**(`JudgingContext.input_sink`),随后运行至程序终止(预算 = 基线剩余全局步数);
- **`predicate_probe`**:不应用载荷(载荷必须为空),在基线上直接求值 `successCondition`;
- **结局分类**(`classify_outcome`,7 值可达判定):

| 结局 | verdict |
|---|---|
| 载荷写入被拒(地址越权 / 越界)——动作级违规 | `invalid_action` |
| 运行异常:`invalid_rip`(含未知 token / 截断 / 弹出值不可执行)、未声明派发号、Canary 破坏 | `program_crash` |
| 运行异常:数据访问越权 / 越界 | `memory_fault` |
| 步数预算耗尽 | `resource_limit` |
| 正常 `exit`(或已终止后复核)∧ `successCondition` 真 | `success` |
| 正常 `exit` ∧ `successCondition` 假 | `wrong_answer` |
| wall-clock 超时(引擎无时钟,worker 看门狗补充) | `timeout` |

- 判定与 `expectedResult` 比对,通过与否**只写 Internal 私有事件**(§1.5);判题条件求值按 §1.3 记入基线预算;公开面只有结果类型(11 值,verifier 汇总);
- **D-H2(输入槽的装载层扩展点)**:双包 Schema v1 无输入槽声明字段;`input_sink` 由装载层从题目特定配置派生,未声明时 `reference_payload` 的载荷必须为空(装配拒绝非空)。契约面若需通用输入槽,走 WP-1 §1.3 契约变更流程增补,不在本 WP 私扩。

## 八·一、阶段六增补(WP-62):正式裁决 11 值汇总语义(verifier)

本节为阶段六 WP-62「隐藏测试裁决与正式裁决汇总」的增补登记:**本文 §一 ~ §七的运行时语义零改动**——隐藏测试驱动(`run_hidden_tests` / `classify_outcome`)、载荷纪律(§1.5)、预算记账(§1.3)原样复用,本节只定"重放终态 × 隐藏测试矩阵 → 11 值正式裁决"的**合成语义**与执行位置。权威定案记录 = `docs/adr/ADR-9-verifier进程形态决策.md` §四·一;实现锚点 = `vm-engine/vm-worker/src/session/verify.rs`(TS 侧零裁决逻辑,ADR-9 Q1 候选 (b))。

### 八·一.1 执行位置与基线(D-H1 的 verifier 面落点)

- **执行位置 = vm-worker `verify` 命令内**:重放(`vm_runtime::replay`,ADR-8 单一实现)逐项比对完成后,在**重放终态**上由引擎侧判题驱动执行——§七"会话 settle 后由判题方驱动"的时机语义在裁决面落为"重放 settle 完成后由 verify 命令驱动"。交互执行路径(SessionRuntime 动作循环)不执行隐藏测试;隐藏测试内容只存在于 vm-worker 进程内与 verdicts SERVER_ONLY 明细列(秘密零驻留);
- **基线 = 重放终态**:每测试从同一基线的独立克隆出发(§七原样);`predicate_probe` 在基线上直接求值 `successCondition`(记账落基线,§1.3);`reference_payload` 运行至终止(预算 = 基线剩余全局步数,§七原样)。终态基线(won / failed)上的克隆执行按 §七"已终止后复核"语义立即分类(引擎对终态状态返回 Halted);
- **引擎面 additive 登记**(零判题语义变更):`vm_runtime::replay` 增 `replay_with_final`(返回重放终态运行时;既有 `replay()` 委托之,逐项比对语义零改动)+ `SessionRuntime::engine_mut` 访问器;判题面 `JudgingContext` 与装配共用同一派生单点(v1 `input_sink` 恒 `None`,D-H2 边界维持,输入槽契约增补走 WP-1 §1.3,非目标)。

### 八·一.2 合成规则(失败方向优先 / fail-closed,§1.1)

设重放逐项比对一致后的终态为 S(交互期同构的 won / failed + 引擎结局标签),隐藏测试矩阵为 H(逐测试 classify 7 值判定与 `expectedResult` 比对):

1. **终态失败优先**:S = failed ⇒ 汇总 = 引擎结局标签粗化(ADR-9 §四既有映射)——交互期已失败的方向不被隐藏测试"救回"(fail-closed);
2. **隐藏测试失败方向**:S ≠ failed 且 H 中存在判定 ≠ `expectedResult` 的测试 ⇒ 汇总 = 首个失败测试 classify 值的映射(§八·一.3 表)——任一隐藏测试失败即否定 `success`(**交互 won ≠ 强制 success**,交互判定与正式裁决相互独立的独立性锚);
3. **成功合成**:H 全过 ∧ S = won ⇒ `success`;
4. **非终态 fail-closed**:H 全过 ∧ S ∈ {running, paused} ⇒ `wrong_answer`(未达成成功条件不判成功);
5. **汇总执行面异常**:隐藏测试驱动错误(基线谓词预算耗尽)⇒ `engine_error`(非成绩方向;与重放面谓词预算耗尽的 `challenge_invalid` 方向有意区分——耗尽发生在 verifier 汇总附加记账上而非重放自身,差异如实登记,§1.3 交互路径方向零改动);
6. 重放漂移 / 上下文错配 / 运行时故障 ⇒ 隐藏测试不执行,裁决走 ADR-9 §四既有映射(汇总语义不参与)。

### 八·一.3 7 值 × 汇总矩阵(失败测试 classify 值 → 11 值承载;逐格可测)

| 失败测试的 classify 值 | 汇总 verdict | v1 端到端可达性 |
|---|---|---|
| `success`(达成但 ≠ 期望) | `wrong_answer` | 可达 |
| `wrong_answer` | `wrong_answer` | 可达 |
| `invalid_action` | `invalid_action` | 结构性不可达(需输入槽 + 非空载荷,D-H2;映射格单测承载) |
| `program_crash` | `program_crash` | 可达 |
| `memory_fault` | `memory_fault` | 可达 |
| `resource_limit` | `resource_limit` | 可达 |
| `timeout` | `timeout` | 结构性不可达(分类器不产生,§七;映射格单测承载) |

### 八·一.4 报告面与公开面纪律(§1.5 的响应面延伸)

verify 响应的隐藏测试汇总面(`verify_report.hiddenTests`,additive,引擎进程协议 §4.9)仅含:逐测试**声明序索引 + classify 值 + expected 比对结论(passed)+ 总判定(allPassed)**;谓词内容、命中详情、testId、克隆终态不进报告(§1.5 载荷纪律的响应面延伸);汇总面整体 SERVER_ONLY(仅 verifier 受控日志 / 审计与 verdicts 明细列消费,零浏览器可达面)。公开裁决呈现只有 11 值结果类型(D-API-83)。
