# 前端交互需求拆解

- **需求来源**:`docs/develop/前端的交互和开发设计.md`(唯一需求源,下称"源文档")。本文将源文档拆解为编号化、可验收的需求条目,作为前端开发的验收基线与现状校验的输入。
- **拆解纪律**:条目描述忠实于源文档;凡为使条目可验收而补充的解释、或自仓库既有纪律(`CLAUDE.md`、`docs/项目计划书.md`、协议契约)派生的内容,一律以【解释】/【派生】标注。与源文档冲突时以源文档为准,并回改本文。
- **编号规则**:`FE-X`(横切架构)/ `FE-WS`(工作区)/ `FE-MV`(内存视图容器)/ `FE-ST`(栈视图)/ `FE-IN`(指令视图)/ `FE-RG`(寄存器视图)/ `FE-FV`(自由视图)/ `FE-PB`(payload 搭建)/ `FE-ED`(教学组件面,2026-09-11 阶段四回填增补,来源 = 计划书 §十二阶段四原文,见 §十三)。
- **配套文档**:各条目与现有仓库工作成果的匹配度校验见 `docs/develop/前端需求现状校验与不匹配清单.md`。

## 一、横切架构需求(FE-X)

| 编号 | 需求条目 | 验收要点 |
|---|---|---|
| FE-X-01 | **组件化封装,自具体组件起步**。前端开发采用组件化封装形式,先从具体组件启动开发,不先搭整体框架再填肉。 | 每个功能块(工作区、四类内存视图、payload 搭建)对应独立组件/组件包,可独立开发、独立测试;组件间无隐式全局依赖。 |
| FE-X-02 | **工作区唯一主体边界**。工作区是前端的最大唯一主体,负责容纳、管理、排布工作标签页;内存视图与 payload 搭建均以标签页形态存在于工作区内。 | 存在唯一的工作区根组件;标签页的创建/销毁/排布只由工作区管理;不存在游离于工作区之外的平行页面容器。 |

【派生】组件载体参照 `CLAUDE.md` 仓库结构的规划位:渲染组件归 `packages/vm-ui`,嵌入壳归 `packages/web-component` / `apps/plugin-dev`。规划位本身不是源文档需求,落地时可在不违反依赖方向(5.5)的前提下调整。

## 二、工作区组件需求(FE-WS)

来源:源文档「工作区组件」节。

| 编号 | 需求条目 | 验收要点 |
|---|---|---|
| FE-WS-01 | 工作区容纳、管理、排布工作标签页。 | 可打开多个标签页;标签页可被工作区排布、聚焦、关闭;标签页状态由工作区统一管理。 |
| FE-WS-02 | 标签页排布采用类似 Hyprland + Niri 的**滚动平铺结合**形式。 | 标签页以平铺方式排布,且具备滚动列/滚动条带的平铺行为(两布局范式行为的并集;具体交互细节见开放问题 Q1)。 |
| FE-WS-03 | 工作区顶部存在负责**管理工作区**的菜单。 | 顶部菜单常驻;菜单项可扩展;菜单操作作用于工作区/标签页整体而非单个标签页内部。 |
| FE-WS-04a | 运行选项:**指令步进运行**。 | 触发后 VM 恰好执行一条指令并暂停,界面反映执行后的最新投影。【解释】对应服务端 `step` 动作。 |
| FE-WS-04b | 运行选项:**积木步进运行**。 | 触发后 payload 积木程序推进一步(一块积木)并暂停,可观察中间状态。【解释】源文档未定义步进粒度与执行载体;按现有会话动作协议,唯一可行解释是客户端把积木图编译为原子动作序列、逐动作提交(见开放问题 Q3)。 |
| FE-WS-04c | 运行选项:**运行到断点**。 | 从当前状态持续运行,到达用户预设断点处暂停。【解释】"断点"的注册与命中机制源文档未指定(见 FE-IN-08、开放问题 Q4)。 |
| FE-WS-05 | 菜单可以**重启测试环境**。 | 触发后会话回到可重新测试的初始状态。【解释】"测试环境"按现有协议最接近 `reset` 动作(重置会话到题目初始状态);终态会话 `reset` 被服务端确定性拒绝,此时需新建会话(见开放问题 Q5)。 |
| FE-WS-06 | 菜单支持**解题模式与调试模式切换**(源文档 2026-09-10 增补)。 | 切换项常驻菜单;调试可用性由题目声明(默认启用、可显式关闭),未启用的题目隐藏切换项;切换后内存视图标签页换绑数据源(锚点/滚动状态重置),决议细节见 ADR-DC1 §五。**【2026-09-11 阶段四落地回填】**分级 = **A(已落地)**:工作区菜单「切换到调试模式 / 返回解题模式」(`packages/vm-ui/src/workspace/sm-workspace-menu.ts`),可用性门槛 = `debugModeAvailable` 属性(plugin-dev 开发壳经夹具描述包 `debugMode` 注入,未启用题目隐藏切换项);切换 = 组合根重绑数据源(`ProjectionDataSource ↔ DebugDataSource`,`packages/vm-ui/src/workspace/sm-workspace.ts` + `src/datasource/debug-data-source.ts`),字节视图换绑即重建 = 锚点/滚动状态重置(F5 既有行为);client 换绑(新会话)确定性退回解题模式。测试:`packages/vm-ui/test/workspace/sm-workspace-mode.test.ts`;调试可用性字段面 = WP-43 `debugMode`(opt-out,缺省 true)。 |
| FE-WS-07 | **payload 搭建标签页的状态两模式共用**(源文档 2026-09-10 增补)。 | payload 程序在模式切换后保留;断点积木为调试模式原生暂停点,解题模式档以步进暂停变通。**【2026-09-11 阶段四落地回填】**分级 = **A(已落地)**:payload 标签页元素状态不被模式切换/标签页切换销毁(workspace `#contents` 生命周期约定,`sm-workspace.ts`);断点积木双档 = 解题模式步进暂停点(`src/payload/executor.ts`,Q3 定案)、调试模式断点集合并入调试断点(挂点 = 内容元素 `breakpointAddresses()` 声明面,`sm-payload-tab.ts` 已实现;v1 编译器断点步骤无地址承载返回空,编译器演进携带 addressHex 后自动并入,零工作区改动)。测试:`packages/vm-ui/test/workspace/sm-workspace-mode.test.ts`(payload 元素保留与断点积木并入口)。 |

## 四、栈视图需求(FE-ST)

来源:源文档「内存视图标签页组件 → 栈视图」节。

| 编号 | 需求条目 | 验收要点 |
|---|---|---|
| FE-ST-01 | 默认显示模式:纵向排列、高处为低地址低处为高地址、以地址对齐的 8 字节为一行的 16 进制模式。 | 默认渲染即为该形态,无需用户配置;行与 8 字节边界对齐。 |
| FE-ST-02 | 行三段布局:左侧对齐;左段显示 8 字节中最低位字节的地址;中段显示 8 字节的 16 进制内存;右段为特殊显示。 | 每行三段齐备;左段地址 = 该行 8 字节中最低位字节的地址;三段各自对齐一致。 |
| FE-ST-03 | 可调整 8 字节对齐的偏移。 | 提供偏移调整手段;调整后行边界按 `对齐基址 + k×8 + offset` 重新划分,地址列与内容列同步移动。 |
| FE-ST-04 | 视角锚点:默认视角为 rsp 的位置;可切换到 rbp 的位置;视角被拖拽移动后可切换回 rsp/rbp 位置。 | 进入视图时视口锚定 rsp;可一键切到 rbp;拖拽离开锚点后可一键回锚(rsp 与 rbp 两锚点均可达)。 |
| FE-ST-05 | 支持输入地址跳转到任意地址的视角。 | 提供地址输入;提交后视口定位到该地址所在行;任意(可达内存的)地址均不因 UI 限制被拒绝。 |
| FE-ST-06 | 支持字节的检索。 | 可输入字节序列进行检索;命中处可定位呈现。【解释】检索范围应覆盖当前已获得的内存数据(范围边界见校验清单 M3,调试模式档口径见 §十二)。 |
| FE-ST-07 | 以行为单位在右段进行特殊显示(类似 pwndbg):若 8 字节为地址,则横向显示跳转链,跳转链最长显示三段,循环显示时箭头打回;超出三段可点击在下方展开成竖向,循环显示时箭头打回。 | 值形似地址的行右段出现跳转链;默认横向 ≤3 段;检测到循环时以回环箭头呈现;>3 段时提供展开为竖向完整链的操作。 |
| FE-ST-08 | 跳转链延伸到代码区时,后续多增加一个指令语句(伪汇编)的显示。 | 链中地址落入代码区时,链上追加该地址处一条伪汇编语句的展示。 |
| FE-ST-09 | 跳转链上点击地址后发生视角跳转。 | 链上每个地址可点击;点击后视口跳转到该地址所在行(栈/自由视图内的视角跳转)。 |
| FE-ST-10 | 若 8 字节均为可见字符,右段显示为可见字符;跳转链延伸的末尾满足可见字符条件时,多延伸出可见字符显示。 | 全可见字符的行右段出现字符渲染;链末地址指向的内容为可见字符时,链末追加该字符显示。 |

## 九、运行选项与现有协议动作的映射【解释】

源文档的运行选项需落到既有会话动作协议(`packages/protocol/src/session-action/`,12 动作)上。本节为解释性映射,不是源文档原文:

| 源文档运行选项 | 协议落点 | 说明 |
|---|---|---|
| 指令步进运行(FE-WS-04a) | `step` 动作 | 恰好执行一条指令后暂停,语义一致。 |
| 积木步进运行(FE-WS-04b) | 无直接对应 | 可行解释:客户端将积木图编译为原子动作序列(`write_bytes`/`push`/`pop`/`call`/`ret` 等),逐动作提交即"一步";步进粒度与积木程序语义(变量/循环/分支的求值数据源)需产品定义。 |
| 运行到断点(FE-WS-04c / FE-IN-08) | 无断点动作;近似 `run_to_event` | `run_to_event` 仅支持五类事件(read/write/call/ret/exception),不支持地址断点。变通:纯 `step` 步进 + 客户端比对 rip 与断点地址(受动作频率限流与往返延迟约束);原生支持需协议演进。**【2026-09-10 增注】**`ADR-DC1`(调试克隆通道,§十二;已评审接受)下,地址断点由调试通道原生承载,权威协议不增动作。 |
| 重启测试环境(FE-WS-05) | `reset` 动作 | 重置会话到题目初始状态;终态会话 `reset` 被确定性拒绝,需新建会话兜底。 |

## 十、工程与非功能约束【派生】

以下非源文档需求,但为本仓库既有纪律,前端实现必须一并满足(出处 `CLAUDE.md` 第十章与质量门禁):
