## 工作区组件

工作区是前端的最大唯一主体，负责容纳、管理、排布**固定窗口集**，并**占据整个页面**（整页布局：工作区自身即页面主体，不再依赖宿主给出的高度，也不再让溢出上浮到文档层）；
窗口集合 = 注册表登记的全部类型**各恰一实例、常驻**（固定窗口集，决议 D-MP-1）：窗口 id ≡ 类型键，**没有开 / 关状态**；无关闭入口、无空态引导，**视图类型名写在视图内的左上角，不设独立标题栏**；
窗口为**无边框、紧密贴合的矩形**：视图之间**不留间隙、不画描边、无分隔条**；
页面按**左右两分**（紧密贴合，无间隙）：

- **右半侧** = **payload 搭建窗口**（**固定**；不随左侧视图滚动而移动）；
- **左半侧** = **视图管理窗口**：在**上下两半**显示视图（任一时刻可见**两个视图位**），视图**纵向堆叠**、**上下滚动**，滚动带**丝滑动画**；左半侧内的视图类型同样写在视图内左上角。

**视图管理窗口的列表按钮**：可**展开 / 收起**；展开后可

1. **勾选**决定哪些视图在左半侧显示 —— 视图**仍全部常驻**，未勾选 = 不显示（这是「暂离」的**第二种成因**，第一种仍是滚出可视区），**不使用「打开 / 关闭」语义**（**D-MP-1 不变**：无开 / 关状态）；
2. **拖拽**列表项调整视图的排布顺序。

**键盘**：`Ctrl + ↑` / `Ctrl + ↓` 在左半侧**上下切换视图窗口**。

**可读性要求（不随任何几何改版废止）**：本版**窗口不再被压缩以塞进有限高度** —— 可读性由「左半侧**纵向滚动**承载溢出 + 每个视图位有确定高度」满足。
⇒ 上一版的**窗高下限**（D-API-152 的 `MIN_ROW_HEIGHT_PX` = 266px）与**列高下限**在本版中**废止**；
**但「不得把视图压到不可读」这条要求本身继续有效**，只是**改由滚动机制满足**。**若实现最终变成「压缩以适配」，即为对本条的违反** —— 历史证据见文末 2026-09-17 增补（窗口被压到 146px、连一行字节都看不见）。

**UI 风格**：**简洁的黑客 Linux 终端风格**；主题**只保留终端一种**，`light` / `dark` **退役**。**嵌入协议面已定案整体退役**（见下方已定案第 4 条）⇒ **`EMBED_THEMES` 随协议一并下线**，**不走「收窄枚举 + 递增 `EMBED_PROTOCOL_VERSION`」**（该路径作废）。

**已被本版取代的上一版内容（勿再按其实现）**：Niri 式列条带与列间水平滚动、列内二叉分割、视口宽预设 **P0 / P1 / P2** 三档与阈值表（`MIN_COLUMN_WIDTH` / `WIDE_MIN_PX` / `NARROW_MAX_PX`）、列宽五档调整、列间与窗间分隔条、三类拖拽落点（同列堆叠 / 跨列移动 / 列间空隙新建列位）、「重置布局」、焦点列居中相机。
`content-visibility` 视口外降级渲染**保留**（与布局形态无关）；`prefers-reduced-motion` 下**丝滑滚动动画降级**（由滚动动画承担，不再有相机滚动）；
工作区顶部存在负责管理工作区的菜单；
菜单分为「窗口」「布局」「模式」「运行」四组：「窗口」组按类型**聚焦**已存在的窗口实例（不创建实例）；
菜单包括运行选项，可以指令步进运行、积木步进运行、运行到断点等；
菜单还可以重启测试环境；
菜单支持解题模式与调试模式的切换；调试模式由题目声明启用（默认启用，可显式关闭，决议见 ADR-DC1）；
模式切换**只换绑数据源**：窗口集与布局零副作用；
两种模式共用 payload 搭建窗口的状态；内存视图窗口随模式切换绑定的数据源；

## 内存视图窗口组件

内存视图窗口组件拥有四种：栈视图、指令视图、寄存器视图和自由视图；
解题模式下内存视图以服务端公开投影为数据源，受公开投影字节窗口约束；调试模式下以调试通道为数据源，任意地址跳转、全内存检索、指令视图与指令断点等能力全量可用（能力分档见 ADR-DC1 与《前端需求现状校验与不匹配清单》）；

### 栈视图

显示模式默认为纵向排列、高处为低地址低处为高地址、以地址对齐的 8 字节为一行的 16 进制模式；
对于每一行，左侧对齐，左侧显示 8 字节中最低位字节的地址，中间显示 8 字节的 16 进制内存，右侧为特殊显示；
可以调整 8 字节对齐的偏移；
默认视角为 rsp 的位置、可切换到 rbp 的位置，若视角被拖拽移动可以切换回 rsp/rbp 位置；
支持输入地址跳转到任意地址的视角；
支持字节的检索；

会以偏移后地址对齐的 8 字节（一行）为单位在右侧进行特殊显示（类似 pwndbg）：
- 若为地址，则横向显示跳转链，跳转链最长显示三段（循环显示时箭头打回），超出三段可以点击在下方展开成竖向，循环显示时箭头打回；
- 对于跳转链，若延申到代码区，则后续多增加一个指令语句（伪汇编）的显示；
- 对于跳转链，点击地址后会发生视角跳转
- 若 8 字节均为可见字符，则在右侧显示为可见字符，且同理在跳转链中若延伸的末尾满足可见字符条件则会多延伸出可见字符显示；

### 指令视图

显示模式默认为纵向排列、高处为低地址低处为高地址、一条指令为一行；
对于每一行，左侧对齐，左侧显示指令中最低位字节的地址，中间显示指令的伪机器码（16 进制），右侧为指令语句显示（伪汇编），右侧单独对齐；
对于跳转语句（jmp、call），会向右延申跳转的目标地址，点击地址后会发生视角跳转；
存在一个函数列表（按地址排列），可以跳转到指定函数位置；
默认视角为 rip 的位置，若视角被拖拽移动可以切换回 rip 位置；
支持输入地址跳转到任意地址的视角；
支持字节、指令的检索；
可以在一条指令上添加断点，后续测试 payload 时运行到此处后会暂停；

### 寄存器视图

纵向显示所有的寄存器；
每一行从左到右为；寄存器名称、寄存器值（16 进制）、特殊显示；
特殊显示的形式和栈视图中的相同，但点击地址不会发生跳转，而会将地址复制到剪切板；

> 寄存器特殊处理：若寄存器储存的是一个地址，则会在任意视图中该地址对应的那一行的最左侧标注寄存器的名称，点击后会展开寄存器的值；

### 自由视图

显示模式默认为纵向排列、高处为低地址低处为高地址、以地址对齐的 8 字节为一行的 16 进制模式；
对于每一行，左侧对齐，左侧显示 8 字节中最低位字节的地址，中间显示 8 字节的 16 进制内存，右侧为特殊显示，特殊显示的形式和栈视图中的完全相同；
可以调整 8 字节对齐的偏移；
支持输入地址跳转到任意地址的视角；
支持字节的检索；
存在一个 VMA 列表（按地址排列），可以跳转到指定 VMA 头部位置；

## payload 搭建窗口组件

payload 搭建窗口的方位按 **D-MP-4** 以**帮助手册 §7.1「三区布局」为现状权威**登记为两栏：**左栏 = 积木画布**（内含工具箱分类与积木，通过拖拽、连接积木组成 payload）；**右栏自上而下三区 = 工具栏**（编译 / 运行 / 单步 / 暂停 / 复位步进 + 状态）、**程序区**（原子动作序列，当前步高亮）、**执行输出区**（动作摘要 + 状态 + 错误解释）；
基础通用积木应该包括：变量积木、列表积木、分支结构积木、循环结构积木、模块化积木（即函数，拥有返回值）、运算赋值积木、字符串操作积木、断点积木（用于观察内存变化）；
还有一个起始积木作为 payload 构建的入口，暂时设置为唯一，后续可以考虑多线程多起始积木的设计；
此外就是出题者提供的积木模块（交互接口），出题者提供的交互接口是关联 payload 搭建部分；
积木模块的技术选型可以考虑 Blockly；
payload 搭建窗口的状态在解题模式与调试模式之间共用；断点积木在调试模式下为原生暂停点，解题模式下以步进暂停变通；
鼠标移动到积木模块上后会显示积木功能；

> **机制（file:line 复核后的精确表述，勿沿用「百分比高度」的粗略说法）**：面板高度 = **弹性等分挤压**，不是百分比高度 —— `sm-workspace.ts:2755` 内联 `style="flex-grow: <窗高比例>; flex-shrink: 1; flex-basis: 0"`，受 `sm-workspace.ts:534-548` 的 `.tab-panel { min-block-size: <MIN_ROW_HEIGHT_PX>px; contain-intrinsic-size: auto <…>px }` 约束（值由常量插值，无魔数）。⇒ **高度下限一直在生效**；缺陷不在「有没有下限」，而在**下限的取值没有依据**（原值是裸的 `9rem` = **144px**；实测量到的 146px 即「贴着该下限 + 上下边框」）。
>
> **根因 = 两侧不对称：宽度下限有推导，高度下限没有**：宽度侧下限是**严格推导**出来的（`layout-presets.ts` 模块头：十六进制行不折行 = `58ch × 7.8px` ⇒ `MIN_COLUMN_WIDTH` = **452.4px**）；高度侧下限却是一个**无推导的裸 `9rem`** —— 而字节视图自身的面板 chrome（标题栏 + 字节视图边框 + 工具区 + 列头行）实测就有 **182.1px** ⇒ **144px 的下限连一行字节都装不下**。这条不对称叠加「固定窗口集（10 类常驻、窗口数不随视口变化）」，压扁即必然。**且因为下限存在（并非缺失），它一路躲过了 axe 9/9 面与全套 E2E** —— 这正是「下限有无依据」比「有无护栏」更隐蔽的地方。
>
> **订正落地（D-API-152）**：① 高度下限改为**按可读目标推导** —— `MIN_ROW_HEIGHT_PX = ceil(面板 chrome 182.1px + 4 行 × 行高 20.8px) = ` **266px**（`layout-divider.ts:53-55`；推导表与 N=4 的取值理由见 `layout-presets.ts` 的「块轴(高度)阈值推导」段），并**兼具「布局下限」与「拖拽下限」双重身份**；② 列获得内容盒高度下限 `columnMinHeightPx(n)`（`layout-divider.ts:73-81`），使**列盒 ≡ 内容高** —— 否则窗高拖拽的像素↔比例基准（`clientHeight`）整段偏小、列间分隔条与列视觉盒都短于内容；③ 两处**谎称「条带自身承担纵向滚动」的注释**被订正（该机制从未兑现，见下条形态差异）。
>
> **形态差异（必须两种都验，只在一种里「看起来对了」不算完成）**：① **开发壳页**（5173 根）`sm-workspace` 为 **auto 高度**；② **嵌入 iframe**（5174；`pwn-memory-vm` 只上报内容高、宿主 `MAX_EMBED_HEIGHT_PX = 960` 钳制）。⇒ **两种形态宿主的条带高度都是内容驱动**（`clientHeight ≡ scrollHeight`），溢出**上浮到文档层滚动**；条带自身成为滚动容器需要宿主给工作区定高（实测注入 `:host { block-size: 660px }` 即 `vScroll = true`）。用户验收走的正是 `/host-mock/` 嵌入页。
>
> **同一症状的第二个成因（已定位，数值见 D-API-152 伴生项）**：字节视图「特殊显示」列的 Lit 模板把**字面换行与缩进写在声明了 `white-space: pre` 的标签内部**（`src/render/special-display.ts:52-63` × `src/views/byte/byte-view.ts:744-747`），空白被当作内容渲染成额外行盒 ⇒ 数据行实测 **187.17px**（应为 **20.8px**）。**这才是「一屏看不见几行」的直接原因，并使 ① 的下限一度形同虚设**（266px 减 182.1px chrome 只剩 ≈86px，装不下一行 187px 的行）。该缺陷与 M3 已修的指令视图行高（**113.38 → 20.8px**，遗留第 5 项）属**同一家族**，字节视图这一处当时被漏掉。
