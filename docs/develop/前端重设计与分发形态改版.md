### 3.3 「独立来源 iframe」到底是什么保障(改版前必须回答)

`【已核实】` iframe 在本项目中**不只是布局手段**,它同时承担:
1. **来源隔离**(独立 origin)—— 宿主页不可直接触达插件 DOM;这是「浏览器完全不可信」下的边界形态;
2. **契约承载**(postMessage + V-1~V-13 校验)→ 所有跨边界输入都过同一套校验;
3. **解耦载体**(计划书 5.5:Core / UI / 协议 / 平台适配层解耦)。

## 五、分发形态设计(2026-09-18 定案:载体 / 授权 / 定位 / 迁移)

> **本节是解除「P0 缺口」的那一步。** 四项定案由主控现场选择(见 §四·补 第三批),其中两项以**自由文本**作答,本节按主控原文落定并显式标注解读依据。

### 5.1 定案摘要

| # | 决策点 | 定案 | 主控原话 / 依据 |
|---|---|---|---|
| 1 | **分发载体与同源关系** | **与 session-api 同源** —— 页面由 session-api 或**同域反代**提供(同域两路径,如 `/app` 与 `/api`) | 现场选择(选项 A) |
| 2 | **授权入口** | **服务端下发地址** —— 服务端为学习者**签发并下发一个地址**,学习者点开即用 | 原话:「**跟 CTF 平台一样服务端下发一个地址**」⇒ 落为「服务端签发票据 → 地址携带 → 页面服务端换票」 |
| 3 | **题目与租户定位** | **服务端分发,一题一址**;`challengeId` / `version` 为**公开导航信息**可进路径,**租户与授权由服务端绑定,不由 URL 自报** | 原话:「**服务端分发,和 CTF 平台一样的流程**」 |
| 4 | **迁移路径** | **硬切 + 迁移指引** —— 直接退役嵌入面,同批交付宿主迁移指引;**不留并存窗口** | 现场选择(选项 B) |

### 5.2 目标拓扑与流程

```
平台后端(持 SESSION_API_HOST_BACKEND_TOKEN)
   │  ① 调本服务「签发启动地址」端点(新契约面)
   ▼
session-api ──② 返回一次性启动地址(URL 携带一次性票据,绑定 租户+题目+版本)
   │
   │  ③ 平台把地址交给学习者(题目链接 / 跳转)
   ▼
学习者浏览器 ──④ 打开地址(顶层页面,同源)
   │
   ▼
页面(由 session-api / 同域反代提供)
   │  ⑤ 服务端用票据换取会话凭证(Cookie,同源可用)
   │  ⑥ 地址中的票据被剥离/失效(一次性)
   ▼
整页工作区开始运行(§六 的交互模型)
```

**要点**:
- **地址是导航,票据是授权** —— URL 里的 `challengeId` / `version` 只是「打开哪道题」;**租户与授权不由 URL 派生**(守住「不接受客户端自报身份」);
- **票据一次性 + 短时** —— 换取会话凭证后即失效,且**不在浏览器端做任何授权判断**;
- **无终端用户账号**:与现模型一致,身份来自**服务端签发的凭证**;新增的只是「签发入口从 postMessage 换票改为服务端下发地址」。

### 5.3 与既有面的关系(须注意的边界)

| 面 | 处置 | 说明 |
|---|---|---|
| 嵌入协议 / V-1~V-13 / `embed-runtime` / `react-wrapper` / `web-component` | **退役**(硬切) | 见 §四·补 (c);**清点 ≠ 现在可删**,须随实施同批 |
| `apps/plugin-dev`(宿主模拟页 / 5174 / token 签发面) | **退役** | 替代 = 页面分发的开发壳与服务端签发端点 |
| `MAX_EMBED_HEIGHT_PX` / `height_changed` / `auto_resize` | **退役** | `100dvh` 定高后无高度上报需求 |
| **`/host/scores`(WP-78 宿主成绩同步)** | **保留** | 它**不是嵌入协议的一部分**,是宿主面 REST;平台仍需要拉成绩 ⇒ **退役面 ≠ 全部宿主面** |
| `SESSION_API_HOST_BACKEND_TOKEN` | **保留并扩展用途** | 平台后端仍以它调用宿主面;新增「签发启动地址」端点也应由它鉴权 |
| `docs/contracts/嵌入协议.md` | **退役**,并**新增**启动票据 / 启动地址的契约面 | 新契约须走契约纪律 5.6(先契约后实现) |

### 5.4 迁移(硬切 + 迁移指引)

- **硬切**:嵌入面一次性退役,**不留并存窗口**;同批交付**宿主迁移指引**(落 `docs/user/宿主平台接入指南.md` 的改造);

- **不承诺**:不承诺 N-1 协议兼容窗口(因为协议是**退役**而非演进;契约纪律 5.6 的 N-1 规则适用于**演进**,退役走**下线公告 + 指引**)。

### 5.5 安全论证(逐条对照红线;须在实施前完成复核)
