# 前端需求现状校验与不匹配清单

- **校验对象**:《前端交互需求拆解.md》的 44 条需求(FE-X 2 / FE-WS 7 / FE-MV 1 / FE-ST 10 / FE-IN 8 / FE-RG 4 / FE-FV 6 / FE-PB 6)。
- **校验基准(现有工作成果)**:以 `9ffaff7` 时点的仓库为准——后端阶段三已收口(WP-0~WP-8:`packages/protocol` 冻结契约、`apps/session-api` 编排器、`vm-engine` Rust 引擎、Compose 拓扑、可观测与限流);**前端零代码**。
- **校验方法**:逐条核对两件事——①前端实现是否存在;②协议/契约/题目包面是否具备该需求所需的数据与能力承载(前端无法凭空渲染服务端未下发的数据)。证据均给出来源文件。

## 一、总体结论

1. **前端实现整体缺位(G-M1)**:需求涉及的全部前端载体(`packages/vm-ui`、`packages/web-component`、`packages/embed-runtime`、`packages/react-wrapper`、`apps/plugin-dev`,见 `CLAUDE.md` 仓库结构规划)在仓库中不存在;`apps/` 仅有 `session-api`,`packages/` 仅有 `protocol` / `challenge-schema` / `challenge-compiler` / `session-core`。44 条需求无一有前端实现。
2. **协议面对需求的支撑分层明显**:19 条(A 类)协议面已支撑、可直接实现;15 条(B 类)可前端变通但有明确约束;8 条(C 类)协议/契约面无数据承载、前端无法变通,需服务端或 Schema 演进;**2 条(D 类)与已冻结决策直接冲突,须先做需求或协议决策**。
3. **最高优先级决策项**:FE-ST-05 / FE-FV-04(输入地址跳转任意地址视角)与投影决策 D3(字节窗口锚定区域起点、不支持玩家任选偏移)正面冲突;它同时制约 B 类中 8 条条目的完成度。在决策"需求降级还是协议演进"之前,栈/自由视图的核心交互形态无法定稿。
4. **正向面**:会话通道与动作面(12 动作、5 命令、认证 WSS、Cookie 凭证、断线 sync-projection、心跳/踢旧/背压/限流)与初始投影下发均已就绪,寄存器视图、VMA 列表、rip 锚点、指令步进、会话重置等条目的后端前提全部成立。

## 二、匹配分级定义

| 级别 | 含义 |
|---|---|
| **A 已支撑·待实现** | 协议/契约面已具备数据与能力,仅缺前端实现。 |
| **B 部分支撑·需变通** | 可在前端变通实现,但有明确约束/局限,或需对需求做语义解释。 |
| **C 无支撑·需演进** | 协议/契约面无数据或能力承载,前端无法变通,需服务端或 Schema 演进。 |
| **D 决策冲突** | 与已冻结决策直接冲突,须先决策(修改需求形态,或走协议版本演进推翻/扩写决策)。 |

## 四、全局缺口与重点不匹配项详述(M1~M14)

### M1 前端包整体零落地【全局】

- **关联**:全部 44 条。
- **现状**:规划中的 `packages/vm-ui`(投影渲染)、`packages/web-component`、`packages/embed-runtime`、`packages/react-wrapper`、`apps/plugin-dev` 均不存在;TS 侧仅有协议与后端包。
- **性质**:实现缺位,非设计冲突。
- **处置**:按 FE-X-01 自具体组件起步;依赖方向纪律(`lint:deps` 已在 CI 强制)对前端包落位已有既有轨道,无需新决策。

### M2 公开描述包的浏览器交付通道缺失【全局】

- **关联**:FE-PB-04 及一切需要题目静态面(标题/简介/VM Profile/encodingTable/hintLadder)的前端渲染。
- **现状**:`create_session` 响应仅含 `sessionId / revision / projection`,不含公开描述包(`session-command-response.ts`);嵌入协议消息为封闭五类型 hello/ready/height_changed/theme_changed/language_changed,无描述包载荷(`embed-message.ts`);iframe 嵌入面整体归阶段五(D-API-66)。
- **性质**:交付通道缺位(阶段五未启动),非契约冲突。
- **处置**:与阶段五嵌入面统筹;前端先行期可在 `plugin-dev` 开发壳内以测试夹具注入描述包。

### M3 任意地址视角 vs 投影决策 D3(字节窗口锚定区域起点)【D 类,最高优先级】

- **关联**:FE-ST-05、FE-FV-04(D 类直接冲突);FE-ST-03/04/06/09、FE-FV-03/05、FE-RG-04(B 类受限)。
- **现状**:可见区域的字节窗口**锚定区域起点,不支持玩家任选偏移窗口**(`visible-memory-region.ts` bytesHex 注释;`投影语义规约.md:73`:`window_bytes = min(region_len, maxBytesPerRange)`);窗口默认 256 字节、单策略上限 4096、单 revision 投影总预算 8192(`数据分类与秘密零驻留清单.md:351`)。这意味着:①地址跳转/拖拽到窗口外**无任何数据可渲染**;②rsp/rbp 锚点随执行移动,锚点处内容不保证在窗口内;③检索、偏移调整、跳转链延伸全部以窗口为界。
- **性质**:需求形态(自由探索内存)与已冻结的脱敏简化决策(D3,WP-3 冻结)正面冲突。
- **处置方向**(需决策,二选一或组合):
  1. **需求降级**:视角/跳转/检索限定在可见区域已下发窗口内,VMA 列表跳转(FE-FV-06,天然匹配)成为主要导航手段;
  2. **协议演进**:引入"窗口重锚定"类只读查询动作(读取指定窗口),须重做 D3 的脱敏面论证(地址是否构成侧信道、字节预算、ZR 机检影响),走协议版本演进 + golden fixture 跨语言同步。

### M4 指令流展示数据缺失(仅单条 currentInstruction)【C 类】

- **关联**:FE-IN-01/02/06/07、FE-ST-08。
- **现状**:投影代码面仅 `controlFlow.currentInstruction`(地址 + 服务端生成的伪指令文本,`public-control-flow.ts`;D5:该展示由服务端从展示数据单独生成,非可执行 IR 形态)。无指令列表、无伪机器码字节序列、无按地址取指令的通道。
- **性质**:数据承载缺失;演进受两条既有纪律约束——展示数据必须维持"非可执行 IR"边界(D5、ZR-B 系机检),且受单 revision 投影字节总预算 8192 约束。
- **处置方向**:协议演进新增"代码区展示窗口"(服务端生成的一段伪反汇编),或公开描述包预置静态代码区展示数据(代码区 MVP 恒公开,D5 前提成立);两者都需走契约版本演进。

### M5 跳转目标地址缺失【C 类】

- **关联**:FE-IN-03、FE-ST-08 的跳转目标。
- **现状**:投影不含指令跳转目标的解析结果;客户端可从伪汇编文本自解析,但该文本来源仍是 M4 的缺失面。
- **处置**:随 M4 一并演进(展示数据附结构化目标地址字段)。

### M6 函数列表缺失【C 类】

- **关联**:FE-IN-04。
- **现状**:投影无函数符号面;公开描述包内存布局仅 region 粒度(`public-types.ts` `PublicRegionSpec`),无函数边界/名称。
- **处置方向**:公开描述包扩展函数表(7.1 字段分类 + 双包 Schema + golden fixture),或服务端从展示数据生成;注意函数名值来源须满足 I-10(公开符号表/服务端静态模板)。

### M7 断点机制不存在【C 类(原生)/ B 类(变通)】

- **关联**:FE-IN-08、FE-WS-04c、FE-PB-02 断点积木。
- **现状**:12 动作与全部协议文档中无断点概念;`run_to_event` 仅五类事件(read/write/call/ret/exception,`action-args.ts` `PauseEventSchema`)。
- **变通**(现协议内可行):payload 执行若采用纯 `step` 客户端编排,每步后比对 rip 与断点地址即可暂停——语义成立,但每条指令一次 WSS 往返,受每会话动作频率限流(D-API-50~53)与延迟约束,且与 `run_to_event` 的连续运行语义不兼容(连续运行中无法插入客户端检查)。
- **原生演进方向**:新增地址断点动作;须论证断点对动作日志与回放等价性的影响(6.3 确定性、verifier 复用同一回放引擎)、`allowedActions` 公开面与协议版本演进。

### M8 积木步进运行无执行语义承载【B 类】

- **关联**:FE-WS-04b。
- **现状**:积木程序不是协议概念;唯一可行解释是客户端把积木图编译为 12 动作的原子序列逐步提交。"一块积木 = 一步"的粒度、分支/循环在步进中的呈现均无定义(拆解文档 Q3)。
- **处置**:产品定义步进语义后按客户端编排实现;须与限流默认值对表(循环类积木可能展开大量动作)。

### M9 积木程序语义无协议对应【B 类】

- **关联**:FE-PB-02(变量/列表/分支/循环/模块化/运算赋值/字符串操作积木)。
- **现状**:动作协议只有 12 个原子动作,无表达式求值、无变量承载;积木程序的求值数据源只能是公开投影(`visibleRegisters` / 窗口内 `bytesHex`),隐藏数据天然不可用(这是底线约束而非缺陷)。展开后动作数量受动作频率限流与资源预算约束。
- **处置**:前端实现积木→动作编译器;在题目包 `allowedActions` 现有裁剪机制内声明可用动作;编译器行为先写测试(TDD)。

### M10 出题者积木模块无题目包承载【C 类】

- **关联**:FE-PB-04。
- **现状**:公开描述包(`public-types.ts` `PublicChallengeDescriptor`)无积木/交互接口字段;最接近的锚点是 `vmProfile.encodingTable` 的 `interface` 操作数(`public-types.ts:48-51`),但那是编码表 token 语义(字节权威执行模式的接口调用 token),与"积木交互接口"不是同一概念,仅可作设计参考。
- **处置方向**:公开描述包 Schema 演进新增交互接口声明(积木形态、能力边界、展示文本);走 7.1 字段分类、双包 Schema 校验、golden fixture 与版本演进;同时须回答拆解文档 Q7(下发通道随 M2)。

### M11 "重启测试环境"与 reset 动作的语义缝隙【B 类】

- **关联**:FE-WS-05。
- **现状**:`reset` 动作=重置会话到题目初始状态,但**终态会话确定性拒绝**(D1 约束,`action-args.ts`);提交(`submit`)后会话进入终态,菜单项若直接调 `reset` 将被拒绝。
- **处置**:产品定义边界(拆解文档 Q5):运行中= `reset`;终态= `close_session` + `create_session` 新建;前端按会话状态启用/禁用菜单项。

### M12 跳转链/字符延伸的数据边界【B 类,受 M3/M4 支配】

- **关联**:FE-ST-07/09/10、FE-FV-02、FE-RG-03。
- **现状**:链首段可由客户端解析 8 字节 `bytesHex` 得到(端序按题目 `vmProfile.endianness`);延伸段需要读**目标地址**的内存(受 M3 窗口限制)或指令(M4 缺失)。`semanticHighlights`(buffer_start / return_address_slot 等,上限 32)可增强特殊显示的教学标注,现成可用。
- **处置**:B 类范围内先实现"窗口内跳转链";延伸能力随 M3/M4 决策跟进。

### M13 rsp/rbp 锚点内容不保证在窗口内【B 类,受 M3 支配】

- **关联**:FE-ST-04。
- **现状**:rsp/rbp 当前值来自 `visibleRegisters` ✓,锚点跳转机制可行;但栈区域窗口锚定区域起点(默认 256 字节),执行推进后 rsp/rbp 指向的位置可能已在窗口之外,锚点行将无内容。
- **处置**:随 M3 决策;短期可在 UI 明示"该地址内容不在可见窗口"而非空白渲染。

### M14 "所有寄存器"与白名单裁剪【B 类,需求需按纪律解释】

- **关联**:FE-RG-01、FE-RG-04。
- **现状**:仅 `ProjectionPolicy.visibleRegisters` 白名单寄存器进入投影(上限 64,`limits.ts:61`);FLAG 保留区命名结构性排除(`投影语义规约.md:61`),秘密寄存器经编译期污点推导禁止入白名单。
- **性质**:这是安全底线的预期行为,不是缺陷;需求文字"所有寄存器"应按"白名单内全部寄存器"解释(拆解文档已按此口径标注)。
- **处置**:无需协议改动;UI 不得为白名单外寄存器保留占位(与隐藏区域"无占位"纪律同构)。
