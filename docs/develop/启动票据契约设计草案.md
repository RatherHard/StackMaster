## 〇、为什么这条链是当前最该先钉死的

§五 定案「**服务端下发地址**」后,系统里**新增了一个把授权物放进 URL 的动作**。而计划书 §8.1 自己立过一条纪律:

> 「iframe 应使用最小化的 `sandbox` 权限…;**不应把长期凭证放入 iframe URL**。」

⇒ **启动票据必须正面回答这条纪律**:它是「长期凭证」吗?不是 —— 但**它仍然进了 URL**,而 URL 会进**浏览器历史、Referer、各级访问日志(含反代)**。**本草案的核心就是把这条暴露窗口关上**,而不是绕开它。

**已确认可复用的既有先例**(设计时直接沿用,不另造):

| 先例 | 位置 | 复用于 |
|---|---|---|
| **单次消费令牌** `token:{jti}`(fail-closed、**不可降级**) | 计划书 `:427`;`persistence/idempotency-window.ts:8` | 票据的单次消费语义 |
| **宿主凭证校验单份实现** `hostBackendTokenMatches` | `apps/session-api/src/auth/plugin.ts:111` | 签发端点鉴权(**复用,不另写第二套**) |
| **固定窗口限流 + 429 冻结形态** `rate:{锚租户}:{维度}` / `FixedWindowRateGate` / `{budget_exhausted, "rate limit exceeded"}` | `rate-gate.ts`、D-API-50 / D-API-125 | 签发端点限流(**逐字节同形态**) |
| **凭证 × 租户白名单** `SESSION_API_HOST_TENANTS`(**凭证 → 租户集合,查询参数不得派生租户**) | O-MP-6 / D-API-122~126 | 票据的租户绑定 |
| **失败统一形态** 「过期 embed token / 已消费 jti 重放 / 绑定不符 / 未认证」**全部 401 统一形态** | 阶段三 `:483` | 换票失败语义 |

### ⚠ 一处必须说明的取舍(第 4 项:它与第 1 项不相容)

§九 第 4 项原本并列了「基线缓解」与「换票改 POST + 同站校验」两条 —— 但**二者与 D1 = A 在结构上不相容**:

> **换票走 POST ⇒ 必须由页面 JS 发起** ⇒ 而那正是 **D1 选 A 要避开的**(票据不在不可信侧被处理、零 JS 依赖)。

⇒ 故本次**采纳基线缓解**:票据**一次性** + **TTL 300 s** + **平台侧「地址只发给对应学习者」的交付纪律** + **`Sec-Fetch-Mode: navigate` 校验**(拒绝子资源 / 嵌入式换票,**纯请求头校验,不需要 JS**),
**并显式登记残留风险**(§八「会话固定」行 = **中低**)。

**若主控认为该残留不可接受,则必须回到 D1 = B**(fragment + JS 换票)—— **第 1 项与第 4 项必须一致取舍,不能各取一半**。

## 一、目标时序

```
平台后端 ──① POST /auth/launch-tickets(Authorization: host backend token;body: challengeId+version)
             │  鉴权(hostBackendTokenMatches)→ 租户 = SESSION_API_HOST_TENANTS 绑定集合 → 限流闸
             ▼
session-api ──② 201 { launchUrl, expiresAt }   // launchUrl 携带一次性票据
             │
平台后端 ──③ 把 launchUrl 作为**题目链接**下发给学习者
             ▼
学习者浏览器 ──④ GET launchUrl(顶层、与 API 同源)
             ▼
session-api(页面服务端) ──⑤ 校验票据 → 原子消费(单次)→ 签发会话凭证(Set-Cookie)
             │
             └──⑥ 302 到**不含票据**的干净路径(票据即刻脱离地址栏 / 历史)
             ▼
   页面以「已认证」态加载(§六 的整页工作区)
```

**设计要点**:⑤⑥ 都在**服务端**完成 ⇒ **不需要页面 JS 参与换票**,票据不在不可信的浏览器里被处理。

## 三、【核心决策 D1】票据在 URL 中的承载方式

**这是本草案唯一必须由主控拍板的安全岔路。**

| 方案 | 不进 Referer | 不进访问日志 | 需页面 JS | 说明 |
|---|---|---|---|---|
| **A · query + 服务端立即消费 + 302 抹除**(推荐) | 否(但**首屏无子资源**,且 302 后地址栏即净) | **否** ⇒ 需**强制日志脱敏** | **不需要** | 服务端在 `GET` 时原子消费票据 → `Set-Cookie` → 302 到无票据路径。**零 JS 依赖**,与「服务端权威」姿态一致 |
| **B · fragment(`#t=…`)** | **是** | **是** | **需要**(页面 JS 读 fragment 后 POST 换票) | 暴露面最小;**代价 = 换票回到浏览器**,且多一次往返、依赖 JS |
| **C · POST 自动提交表单** | 是 | 是(请求体,但仍入日志) | 需一段引导 JS | 平台侧多一步;不改善日志面 |
| **D · 短时票据 + 长期凭证分离**(票据只换一次性入场券) | —— | —— | —— | 复杂度翻倍,建议不做 |

**推荐 A**,理由:
1. **零 JS** ⇒ 换票不依赖浏览器执行,票据不在不可信侧被处理(与底线「服务端权威」一致);
2. **首屏无子资源** ⇒ 302 之前不存在可泄漏 Referer 的外链请求;
3. 消费与抹除**在同一次请求内完成**,窗口 = 一次请求处理时间。

**A 的代价必须写清并由主控确认**:票据**会进服务端访问日志**。⇒ 强制要求:
- **应用侧日志脱敏**(查询串中的票据字段一律不落);
- **反代侧同义务** —— 而反代**不在本项目控制内**(D-API-104 定案为「反代准入」)⇒ **须写入部署指南作为运维硬要求**,并加**机检**:CI 扫描确认应用侧零票据落日志。

> **若主控判定「无法保证反代侧脱敏」,则应改选 B(fragment)** —— 用一次 JS 换票与一次往返,换「票据永不进任何日志与 Referer」。**这是一个可以论证的等价取舍,不是一个"更安全的默认"。**

**主控裁定 = A**(2026-09-18;**见 §〇.1**,该节同时载明本项与会话固定缓解项的相容性取舍)

## 四、【D2】票据的生成与生命周期

| 参数 | 建议值 | 理由 |
|---|---|---|
| 熵 | **≥ 128 bit CSPRNG**,base64url 编码(22 字符) | 与「不可预测」要求匹配;不低于既有令牌强度 |
| 有效期 | **缺省 300 s**(5 分钟),配置键 `SESSION_API_LAUNCH_TICKET_TTL_SECONDS`,天花板 3600 | 足够平台下发与学习者点击;短到泄漏后基本无用 |
| 单次消费 | **原子单次**(Redis Lua CAS,同 `RateLimitCounter` 载体) | 重放 ⇒ 第二次必失败 |
| 重放防护 | 消费即删除(或置为已消费标记至 TTL 到期) | 与 `token:{jti}` 同纪律 |
| 绑定 | 票据**绑定**(tenantId, challengeId, version, expiresAt) | 换票时逐字段校验;**不绑定 IP / UA**(教学场景会移动网络,且绑定会引入新侧信道) |

**不绑定 IP/UA 是一个有意的取舍**:绑定可提升抗窃取,但会误伤移动端与共享出口,且引入「绑定不匹配」这一可探测的差异面(与「统一 401」冲突)。

## 五、【D3】存储与可用性

| 项 | 决定 |
|---|---|
| 载体 | **Redis**,键 **`launch:{jti}`**(新键域,带 TTL) |
| 为何不用 PG | 票据是**瞬时引导物**,不值得新表 / 迁移(与 O-MP-6「不引入新表」姿态一致) |
| 可用性语义 | **fail-closed**:Redis 不可用 ⇒ 换票 **503 `store_unavailable`**,**不降级、不静默放行**(与 `token:{jti}` / `route:{sessionId}` 同纪律 —— 计划书 `:427` 注明**这两者不可降级**) |
| 丢失语义 | **Redis 掉电/刷库 ⇒ 未消费票据失效** ⇒ 学习者看到「地址已失效」,须由平台**重新签发**。**这是可接受的**:票据可无限重签,不承载不可重建状态 |
| 绝不入库的东西 | 票据明文**不进 PG、不进审计账、不进指标标签** |

> **键域登记义务**:新键域须同批写入计划书 §5.7 的 Redis 键域清单与 `docs/develop/权威API语义规约.md` 的键域表(**不得静默新增键域**)。

## 六、【D4】签发端点

| 项 | 决定 |
|---|---|
| 路由 | `POST /auth/launch-tickets` |
| 鉴权 | **`hostBackendTokenMatches`(复用,单份实现)**;失败 **401 统一形态** |
| 租户 | **只由凭证 × `SESSION_API_HOST_TENANTS` 白名单派生**;白名单缺失/为空 ⇒ **404 同形 fail-closed**;**请求体 / 查询参数永不派生租户** ⇒ **机检:URL 与 body 参数不得进入租户派生路径** |
| 题目 | `challengeId` / `version` 取自请求体(**公开信息**),须**校验存在且已发布**,否则 **404 同形**(与「不存在」同形,零探测信号) |
| 限流 | 新维度 `RateLimitDimension += "launch_ticket_rate"`,键 **`rate:{锚租户}:launch_tickets`**(锚租户 = 绑定集合字典序最小项,D-API-125 同法);缺省 **60 次/分**,天花板 100000;触顶 **429 逐字节沿冻结常量** |
| 护栏 | 请求体恰两键(多余 400);字符串长度上限;`version` 须为合法 semver 字面 |
| 响应 | `{ launchUrl, expiresAt }`;**不返回票据本身**(票据只在 `launchUrl` 内) |

## 七、【D5】换票(页面服务端内完成)

| 项 | 决定 |
|---|---|
| 触发 | `GET /app/c/:challengeId/:version?t=<ticket>` |
| 校验 | ⓪ **`Sec-Fetch-Mode: navigate` 校验**(拒绝子资源 / 嵌入式换票;**纯请求头校验,不需要 JS**);① 票据存在且未过期;② **未消费**;③ 绑定字段与路径字段**逐字一致**(tenant / challengeId / version);任一不满足 ⇒ **401 统一形态** |
| 消费 | **原子消费成功后才签发凭证**(先消费后签发;失败不得留下半态) |
| 签发 | 既有会话凭证 + `Set-Cookie`;**同源** ⇒ `SameSite` 可保持既有策略(不因本改版放宽);`credentialCookiePath` 沿用既有装配(`"/"`) |
| 响应 | **302 → 不含票据的干净路径**;失败 ⇒ 冻结 `PublicError` 页面(401 统一形态),**不泄露失败原因分类** |
| 幂等 | **不幂等**(单次消费即设计):重复打开 ⇒ 401 ⇒ 提示「地址已失效,请向平台重新获取」 |
| 日志 | 该路由的访问日志**必须脱敏 `t` 参数**(与 D1 的机检同一条) |

## 八、攻击面与红线对照

| 攻击面 | 处置 | 残留风险 |
|---|---|---|
| **票据经 Referer 外泄** | D1 方案 A:首屏无子资源 + 302 即净;并设 `Referrer-Policy: no-referrer` | **低**;若选 B 则结构性为零 |
| **票据进访问日志 / 反代日志** | 应用侧脱敏机检 + 部署指南硬要求 | **中** —— 反代不在本项目控制内(D-API-104);**这正是 A 的主要代价** |
| **票据进浏览器历史** | 302 到干净路径(历史里留的是原 URL) | **低** —— 条目仍在历史里;可加 `Cache-Control: no-store` |
| **重放** | 原子单次消费 | 低 |
| **枚举票据** | ≥128 bit 熵 + 限流 | 极低 |
| **枚举题目 / 租户** | 404 同形(白名单外与不存在同形) | 低 |
| **会话固定(session fixation)** | ⚠ **已正面处置**:攻击者可把**自己的** launchUrl 诱使受害者点击 ⇒ 受害者在**攻击者的会话**里答题,攻击者事后读取成绩。**已采纳缓解**(§〇.1 第 4 项):票据**一次性** + **TTL 300 s** + 平台侧「**地址只发给对应学习者**」交付纪律 + **`Sec-Fetch-Mode: navigate` 校验**(纯请求头,不需 JS)。**未采纳**「换票改 POST + 同站校验」—— **它与 D1 = A(零 JS)在结构上不相容** | **中低**(教学场景可接受);**已登记**;若主控判定不可接受,**须回到 D1 = B** |
| **侧信道(过期 vs 已消费 vs 不存在)** | **统一 401 形态**,三者不可区分 | 低 |
| 红线:身份不由客户端自报 | 租户/题目由**服务端签发的票据**绑定;URL 仅导航 | 满足 |
| 红线:浏览器不可信 | 票据一次性短时;页面不做授权判断。**注意:这与"URL 里的东西不可信"不矛盾** —— 票据是**服务端签发的持有证明**,不是客户端自报声明 | 满足 |
| 红线:ADR-7 投影脱敏 | **零改动** | 满足 |

## 十一、机检与验收建议(实施时)

| # | 机检 | 说明 |
|---|---|---|
| 1 | **URL / body 参数不得进入租户派生路径** | 结构性断言(比照既有「查询参数不得决定租户」) |
| 2 | **应用侧日志零票据** | 扫描日志输出,含 `t=` 的查询串必须被脱敏 |
| 3 | **401 三态同形** | 过期 / 已消费 / 不存在,响应**逐字节一致** |
| 4 | **单次消费原子性** | 并发两次换票,恰一次成功(真实 Redis) |
| 5 | **429 逐字节同形态** | 沿 D-API-50 冻结常量 |
