## 一、总则

### 1.1 COW 分页快照(6.3"内存按固定大小分页,COW 快照")

COW 承载在 vm-core 页存储层:页以 `Rc<[u8]>` 引用计数持有,写入路径经 `Rc::make_mut` **写时复制**——共享组内首个写入者复制整页,其余持有人(快照、`initial_state`、隐藏测试基线克隆)保持冻结视图。推论:

- `VmState::clone()` 即 O(脏页) 的 COW 快照;`Engine::initial_state`(reset 恢复源)与判题隐藏测试的基线克隆同享此机制,**行为语义不变**(D4.4 译码缓存透明性、WP-5 基线隔离均有既有红灯锁定);
- 权限语义(I-9 统一拒绝路径)不因 COW 改变:COW 是存储面,不是访问面;
- **有界性**:跨(活体 + 全部快照)的页存储分配数只随脏页增长,不随"快照数 × 总页数"增长(集成测试 `cow_snapshot_memory_growth_is_bounded_by_dirty_pages` 以页存储身份指针去重计数锁定);
- **快照隔离**:快照内容在活体继续写入下逐字节不变(同测试逐轮断言)。

已知 MVP 界(教学规模、正确性优先):快照对 `privateEventLog` 为深拷贝,事件日志长度随动作增长时,快照成本 O(事件日志);T2 前不做持久化事件日志优化(阶段二任务分解 §六:性能不是本阶段优化对象)。

### 1.2 页访问器与恢复原语(vm-core 增补面)

| API | 语义 |
|---|---|
| `page_ids()` / `page_bytes(no)` / `page_identity(no)` | 页号升序遍历、页内容、页存储身份(`Rc` 指针地址)。身份相等 ⇔ 共享同一页存储(内容必然一致);身份不同 ⇒ 内容是否变化需逐字节比对——差分与有界性统计的观察面 |
| `shared_page_count()` | 强引用 > 1 的页数(正被共享的页;有界性观察面) |
| `restore_page(no, bytes)` | **存储面恢复**(不走权限检查,与装载期页物化同类):整页替换、恰页长、页必须已物化;替换(而非原地写)使恢复页脱离既有共享组 |

### 1.3 会话快照(`SessionSnapshot`)

```text
SessionSnapshot { state: VmState, judge_stage: Option<StageState>, halted: bool, revision: u64 }
```

- `state`:冻结 8 字段整体(含 `constraints` 可回退预算与 `seedState`);
- `judge_stage`:判题阶段运行时状态——**判题语义规约 §一"快照须承载判题状态"的落点**(规约 §4.4 ①"受理即计数"的管理类增量随恢复一并回退);
- `halted`:程序 `exit` 标记随快照回退——undo 可撤销一次已发生的 exit;
- `revision`:快照点的权威 revision(内容版本;恢复后新动作在其上 +1)。

### 1.4 checkpoint(引擎进程协议 D-F7)

- `create_checkpoint` 动作成功时快照入**本进程 checkpoint 表**;`checkpointId` 由 worker(运行时)**确定性签发**:`cp-{签发序 4 位}-{快照规范化形态 SHA-256 前 16 hex}`,满足服务端标识符字符集 `^[A-Za-z0-9_-]{1,128}$`;同内容重复创建因签发序而 ID 唯一;
- **归属校验**(6.3)= `checkout_checkpoint` 时在本进程表内按 ID 解析;解析不到 = 执行前确定性拒绝;
- 崩溃后旧 checkpoint 引用随进程消失(协议 §4.7 如实记录的退化):新进程只持"最近服务端快照"的内容,checkpoint 粒度恢复归编排器账本(WP-8 / 阶段三)。

### 1.5 快照导出 / 导入(阶段三持久化的对接面)

载荷形态 `stackmaster-session-snapshot/1`(规范化 JSON):

```json
{"engineBuildId":"…","form":"stackmaster-session-snapshot/1","halted":false,
 "judgeStage":null|{"actionsUsed":0,"index":0,"stepsUsed":0},
 "revision":0,"state":{…stackmaster-vmstate/1…},"vmEngineVersion":"…"}
```

- 信封(`snapshotFormatVersion` / 双版本 / `payload` 为对象)由 worker 协议层校验(WP-1 已冻结);本规约定 **payload**;
- 导入 = 形态标识 + **引擎双版本绑定复验**(版本策略 §四"verifier 与交互执行同锁"的引擎侧落点;`vmEngineVersion` 必须一致、声明了 `engineBuildId` 就必须一致)+ 状态重建;
- 状态重建以**当前装载布局为锚**:架构 / 页大小 / 执行模式 / 区域面 / 寄存器与 FLAG 名集 / 预算上限 / seed 策略与版本必须与锚一致,任一不符 = `challenge_invalid` 方向整体拒绝——快照只承载内容状态,不携带布局(布局由两步恢复的 `load` 步装载,引擎进程协议 D-F8)。

## 二、状态规范化形态与状态哈希(6.3"前后状态哈希")

### 2.1 形态定位:不是契约,是引擎内部确定性编码

`VmState` 是 SERVER_ONLY 类型,**没有契约,只有禁令**(数据分类清单 §3.1 规则 1:无 serde 派生、无契约 JSON)。`stackmaster-vmstate/1` 是引擎内部确定性编码,只服务于:

1. **状态哈希**:规范化序列化(§三文法:UTF-16 键序、最短转义、整数十进制、零空白)的 UTF-8 字节序列的 SHA-256(64 hex;规范化序列化 §3.2);
2. **快照载荷状态段**与回放日志的哈希比对——只在信任域 3 / 4(执行域、verifier)内流转,**永不跨越进程边界下发给浏览器或编排器**。

形态漂移 = 引擎语义变更 = `vmEngineVersion` 演进(版本策略:确定性由引擎版本锁定);三形态标识常量与版本绑定关系见本文头部"变更纪律"。

### 2.2 形态内容(冻结 8 字段全覆盖)

顶层键(form / archBits / status / instructionPointer / registers / flags / callFrames / memory / privateEventLog / constraints / seedState)。值层规则(规范化序列化 §四,发射面):地址 / 架构值 = 小写 `0x` 前缀按位宽左补零(32 位 → 8 位数字);字节序列 = 小写偶长 hex;整数全部经安全整数域(±(2^53 − 1))守卫,超界 fail-closed(引擎_error 方向——上游资源预算使正常值远不可达)。

内存段:区域面(权限权威单元,装载布局)+ 页表(存储粒度;页号十进制字符串 → 整页 hex)。区域与页均在装载期固定,形态侧逐项对照锚拒绝漂移。

### 2.3 哈希输入面与秘密(9.2)

哈希输入包含完整冻结 8 字段——含 `seedState` 状态字节。理由:状态哈希须覆盖一切参与状态转换的分量(undo 回退的确定性比对要求);SHA-256 单逐且只在服务端流转,不构成 seed 泄露面。版本策略 §三记录项 #5 的"不含 seed 值"约束作用于回放**元数据**(`ReplayContext.seed_policy`:只有策略与派生路径声明),不是单逐哈希的输入面。

### 3.2 append-only 与拒绝不入账(§4.1)

- 条目只追加;`undo` / `checkout_checkpoint` / `reset` / `create_checkpoint` 本身也是条目——**内容回退、版本前进**,日志永远完整表达时间线;
- 进入执行前被拒绝的动作(参数 / 终态 / 归属 / 预算闸门)**不入日志**,revision 不动——日志长度 = 已执行(非拒绝)动作数 = revision;
- 序列化先验:越界数值在入账前拒绝(`append` 返回错误),日志永远可序列化。

### 3.3 内存 / 寄存器差分

- 寄存器:名集相同(装载固定)、按键序配对,值不同即记录;
- 内存:**先按页存储身份过滤**(`page_identity` 相同 ⇒ 共享 ⇒ 内容必然一致,零比对),身份不同者逐字节比对,连续地址合并为区间,再按区域归属切分(跨界写入产生两条记录)。

## 四、revision 与回退语义(会话动作协议 §4.1 的引擎侧实现)

### 4.1 revision:唯一权威序号

- `revision` = 已执行(非拒绝)动作数;被接受的动作(含 undo / checkout / reset / pause / create_checkpoint)恒 +1,被拒绝的动作不推进——**增量 ∈ {0, +1}**(ZR-P5 运行时断言,测试 `revision_monotonic_with_delta_zero_or_one`);
- 拒绝是 `(输入, 会话状态)` 的确定性函数(I-4):同输入两次拒绝结论逐字段一致(测试 `terminal_session_rejects_all_twelve_actions_deterministically`);
- 终态会话(won / failed)拒绝一切 12 动作(D1 约束 5),undo / checkout / reset 与之一致拒绝。

### 4.2 执行链路(D-J1 引擎侧接线)

```text
① gate(终态 / 阶段允许动作 / 阶段动作数预算)──拒绝 ⇒ ② ③ 不发生
② 执行前结构闸门(动作日志长度结构上限;回退类另查回退累计预算)
③ 执行:执行类 → 引擎动作原语 / step / run_to_event;
   管理类 → 内容恢复(undo / checkout / reset)或快照入表(create_checkpoint)
④ settle(检查点:阶段记账 → 失败优先 → 成功 → 迁移;管理类不求值)
⑤ 差分(前后状态哈希、寄存器、内存、事件序)→ append-only 日志追加
⑥ revision += 1
```

执行类动作在执行前把动作前快照压入历史栈(COW 页共享,压栈廉价);教学性失败(引擎层拒绝:`memory_fault` / `invalid_rip` / Canary 等)**已执行**:照常入账(+1、有日志条目、结局标签 = `EffectFailed{reason}`),会话继续(§4.1"失败但已执行的动作同样 +1")。

### 4.3 undo / checkout / reset 的内容回退(§3.2 / §4.1)

| 动作 | 内容效果 | 历史栈 | 判题阶段状态 |
|---|---|---|---|
| `undo` | 弹出栈顶快照恢复内容(= 前一内容,哈希可证) | **弹出且不压**——连续 undo 沿内容时间线继续回退;空历史 = 确定性拒绝(`NothingToUndo`) | 随栈顶快照恢复(`Judge::restore_stage`) |
| `checkout_checkpoint` | 恢复 checkpoint 快照内容(新 revision 旧内容) | 先压当前快照——**checkout 可被后续 undo 撤销** | 随 checkpoint 快照恢复 |
| `reset` | `Engine::reset`(回初始状态)+ `Judge::reset`(回初始阶段、重触发初始副作用) | 先压当前快照 | 权威 reset 路径 |
| `create_checkpoint` | 内容不变;快照入表、ID 回执 | 压当前快照 | settle ①"受理即计数"**不被恢复覆盖**(无恢复发生) |

- **累计预算跨回退不重置**(D1 约束 5,防回退神谕):`predicate_evals` 由 `Engine::restore_session` / `Engine::reset` 保留当前累计(与 reset 同规则);checkpoint 表中恢复动作的回退亦同;
- `halted` 随快照回退:undo 撤销已发生的 `exit`(测试 `undo_rolls_content_back_and_revision_forward` 锁定)。

### 4.4 快照替换恢复(引擎进程协议 D-F8 的运行时落点)

`replace_from_snapshot(规范化载荷文本)`:导入并整体替换当前内容(状态 + 判题阶段 + halted + revision),清空历史栈 / checkpoint 表 / 动作日志,回退累计计数随新进程重开。语义要点:

- **累计预算自快照续算**(替换恢复后 `predicate_evals.used` = 快照携带值):同一逻辑会话的续命——若保留"当前"(新进程为 0),崩溃恢复即成预算重置的后门,违反 D1 约束 5;交互回退(undo / checkout / reset)仍保留当前累计,两条路径语义不同、方向一致(测试 `snapshot_roundtrip_and_replace_recovery` 锁定);
- 回退累计计数是**进程级**结构护栏,跨进程锚定归阶段三持久化(以重放日志复核)——本规约如实记录该边界;
- 版本绑定复验失败 / 形态非法 → `challenge_invalid` 方向拒绝,进程状态不被污染(拒绝后可重试合法载荷,测试 `snapshot_import_enforces_version_lock`)。

## 五、回放一致性(完成标准;ADR-8 单一实现)

- **同一份代码**:回放不在别处另写执行器——`replay(config, log)` 以日志条目驱动 `SessionRuntime::apply`(与交互执行同一代码路径),verifier 复用(ADR-8:禁止第二套实现);
- **逐项比对**:上下文一致性(§三 #1–#5 错配 = `ContextMismatch`)、受理性(交互期受理、重放期拒绝 = 语义漂移)、revision 序列、**状态哈希序列(逐字节一致)**、引擎 / 判题结局标签;
- **黄金回放 fixture**:13 动作确定性脚本(执行 / 暂停 / checkpoint / undo 链 / checkout / reset)的活体哈希序列 = 日志重放一次 = 重放两次 = 规范化序列化→解析→再重放,三路逐项一致(测试 `golden_replay_hash_sequence_identical_across_three_runs`);checkpoint 的确定性 ID 保证 checkout 在重放侧解析到同一目标;
- **篡改检测**:任一字段漂移在对应条目被捕获(`state_hash` / `revision` / `engine_outcome` / `judge_outcome` / `acceptance`),不静默通过(测试 `replay_detects_tampered_log` / `replay_mismatch_fields_and_fault`)。

## 六、私有包版本锁定与资源计数

### 6.1 版本锁定(版本策略 §四;引擎进程协议 §2.3)

- 自报常量归 worker 进程层(`VM_ENGINE_VERSION` = crate 版本;`ENGINE_BUILD_ID` = 编译期注入,缺省 `dev`);运行时经 `EngineIdentity` 注入;
- 锁定判定:`verify_bundle_lock(declared, identity)`——`vmEngineVersion` 必须一致;`engineBuildId` 声明了就必须一致;不一致 = `challenge_invalid` 方向拒绝装载(宁可拒绝,不近似执行);
- 装配一致性:运行时上下文中的引擎双版本必须与身份一致,矛盾 = 装配缺陷(`engine_error` 方向);快照导入同锚(§4.4)。

### 6.2 资源计数(9.1 引擎侧落点;WP-8 消费约束值)

| 约束 | 强制点 | 说明 |
|---|---|---|
| 执行步数 / 调用深度 | vm-core(`constraints.steps` / `call_depth_limit`) | WP-4 既有 |
| 谓词求值 | vm-core(`predicate_evals` 累计) | WP-5 既有;耗尽 = `challenge_invalid` 方向安全终止 |
| 动作日志长度 | **本规约**:追加上限 = `action_log.limit` | 结构护栏以日志**真实长度**为准——预算 `used` 是可回退状态量,回退博弈不放大日志 |
| 回退 / 重置次数 | **本规约**:进程级累计 ≤ `rollback_ops.limit` | 可回退预算 used 之外的反神谕兜底;超限 = `resource_limit` 方向确定性拒绝 |
| 内存总量 | **本规约**:装载静态护栏 `memory_bytes_limit` | 区域字节总量超限拒绝装配(`challenge_invalid` 方向) |
| wall-clock / 单动作超时 / 输入输出字节 | worker 进程层(WP-8) | 引擎 crate 无时钟(ENG-2);`judgingConfig.timeoutMsPerAction` / `maxTotalActionBytes` 的消费归 WP-8 |

| # | 决策 | 内容与理由 |
|---|---|---|

| D-W6-3 | 历史 = 每动作前 COW 快照栈 | undo 精确恢复(事件日志随状态回退),无重放式回退的复杂度;页共享使栈增长有界(§1.1);事件日志深拷贝为已知 MVP 界 |
| D-W6-4 | undo 自身不压历史栈 | 连续 undo 沿内容时间线走(撤销也是一步的 timeline 语义,§4.1),undo 不可被 undo(无 redo 动作);checkout / reset / create_checkpoint 压栈(可被 undo) |
| D-W6-5 | 管理动作的阶段计数随快照恢复 | 判题语义规约 §4.4 ①"受理即计数;管理类动作的阶段状态随后由快照恢复"的忠实实现:settle 先行(不改求值),恢复覆盖计数(规约 §4.6) |

| D-W6-7 | 日志长度 / 回退次数取结构护栏 | 可回退预算 `used` 随内容回退,直接用它闸 append / 回退会被回退博弈绕过(§六表);结构护栏以不可回退的真实占用 / 进程累计为准,方向 resource_limit |
