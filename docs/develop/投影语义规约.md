## 一、总则

### 1.1 crate 定位(ADR-7 / 驻留三原则 2)

投影的白名单过滤与脱敏在数据离开执行域之前完成:本 crate 消费 `vm-core` 的权威状态(`VmState` / 私有事件 / 调用帧),按 `ProjectionPolicy` 白名单生成 `PublicStateProjection` / `ProjectionDelta` / 公开事件与粗化错误——它们是唯一允许离开 worker 进程的状态形态。`VmState` 及其子类型无任何序列化路径(WP-1 §3.1 规则 1:SERVER_ONLY 类型只有禁令);策略对象整体 `SERVER_ONLY`(WP-1 §五),浏览器只接收它的脱敏效果。

依赖面:`projection → vm-core`(计划书 5.5 Rust 侧依赖方向;零外部依赖,ENG-4 允许清单)。无 serde、无 JSON 解析路径——跨进程序列化由 vm-worker 的出站转换承担(`contract::outbound`,见 §六)。

### 1.2 生成面三入口(全部是确定性纯函数,I-4)

| 入口 | 语义 | 消费场景 |
|---|---|---|
| `full_projection` | `PublicStateProjection` 全量(7 字段) | 会话创建初始投影;`sync-projection` 重同步取数(9.1 sanctioned 路径) |
| `delta_projection` | `ProjectionDelta` 增量 | 已执行动作的响应(可选字段存在性 = 可观察变化) |
| `rejected_action` / `executed_action` | `ActionResponse` 投影面五字段 | 响应装配(§五);拒绝形态由构造器结构性保证 §4.4 耦合 |

全部生成函数是 `(策略, 静态声明面, 状态, 动作观察)` 的纯函数:相同(可见状态, 动作)必然产生字节相同的公开响应(I-4)——由差分测试套件锁定(§八;T-SC1 / T-SC4)。

### 1.3 规范化输出文本(生成面第三处落点)

仓库内 `stackmaster-canonical-json/1` 有三处落点,同一冻结文法(键 UTF-16 码元序、最短转义、零空白、整数十进制),角色不同:

| 落点 | 输入域 | 角色 |
|---|---|---|
| `vm-runtime::canon` | 引擎内部值树(状态形态 / 日志 / 快照) | 值树写入器 + 严格解析器 |
| `vm_worker::contract::canonical` | 入站契约文本 | 文本消费侧规范化 |
| `projection::canon` | **本 crate 的投影输出类型** | 生成面输出文本(差分测试 / 哈希锚定) |

本 crate 不提供通用值树:投影输出的对象键集合全部是契约冻结的字面量集合,每个类型的 `to_canonical` 是直线写入函数;键序在编译期固化为该键集的 UTF-16 码元序,由专测逐类型断言(`frozen_key_orders_are_utf16_sorted`),手写键序漂移即红灯。文法风险收敛到字符串转义与十六进制编码两处原语,金面向量与 `vm-runtime::canon` 的测试向量同源。

**缺席语义**(从 Schema 形态严格导出,是本次实现的关键判定):契约的 `.optional()` 字段拒绝 `null`——"字段缺席 = 键整体缺席",不存在"显式 null 占位"形态;唯二例外是契约明确 `nullable` 的两处:`ActionResponse.projectionDelta`(拒绝动作恒 `null`)与 `PublicControlFlow.pausedOn`(可空表达"未因事件暂停"),以及 `PublicError.addressHex` 的 `null-only` 形态(`inaccessible_address` 恒 null,I-9 / M-3 抉择)。presence-only 截断标记建模为 `bool`,false 时键整体缺席(契约 `z.literal(true).optional()` 拒绝显式 false)。

## 二、ProjectionPolicy 求值器(`policy.rs`;WP-1 §五 / D3)

### 2.1 装配期 fail-closed(引擎侧镜像复验)

策略装配(`ProjectionPolicy::assemble(spec, sinks)`)执行全量校验,任一约束不满足即拒绝,方向 = `challenge_invalid`(宁可拒绝不近似执行;沿 WP-5 `judge/spec.rs` 装配镜像纪律):

| 校验 | 规则 | 上游锚点 |
|---|---|---|
| 白名单护栏 | 区域 ≤ 64、对象 ≤ 64、寄存器 ≤ 64 | `MAX_VISIBLE_REGIONS` / `MAX_VISIBLE_OBJECTS` / `MAX_VISIBLE_REGISTERS`(D3.1:32→64) |
| 标识符形态 | 非空、≤ 128、`A-Za-z0-9_-`(契约 `OpaqueIdSchema` 同则) | 会话动作协议语义 §2.1 |
| 唯一性 | 各白名单内重复成员即拒绝 | 存在即歧义 |
| **FLAG 结构性排除** | `visibleRegisters` 中 FLAG 保留区命名(`^FLAG[A-Z0-9_]*$`)拒绝;一般名过 `^[A-Z][A-Z0-9_]{0,15}$` 校验 | WP-3 裁决"FLAG 值永不进入公开面(引擎侧结构性保证 + WP-7 投影白名单执行)" |
| **I3-VISIBLE-REG 引擎镜像** | `sinks`(`flagRegisterNames ∪ secretSinkRegisters ∪ FLAG 命名初始寄存器` 的并集,装载侧组装传入)与白名单交集非空即拒绝 | I-3 编译期污点推导漏检的纵深防御;作者显式声明仅作补充,不得放宽 |
| 窗口域 | `maxBytesPerRange` ∈ [1, 4096];`None` 取默认 256 | D3 数值冻结(默认 256 / 单策略上限 4096 / 单 revision 总预算 8192) |

每条校验带必触发红灯样例(`policy.rs` 测试:FLAG 拒绝、小写名拒绝、秘密汇相交拒绝、重复 / 超护栏 / 标识符形态、窗口域三向)。

### 2.2 求值面

| API | 语义 |
|---|---|
| `is_region_visible(id)` / `is_register_visible(name)` | 白名单成员资格(区域布局本身是公开描述包声明的公开信息;隐藏区域的存在性只由"名单不下发"保证) |
| `is_address_visible(memory, addr)` | 地址所在区域 ∈ 白名单;未映射同判(I-9) |
| `window_bytes(region_len)` | `min(region_len, maxBytesPerRange)`(D3:窗口锚定区域起点,不支持玩家任选偏移) |
| `classify_write_range(memory, addr, len)` | 写入目标三分类(§2.3;玩家写动作执行前判定的依据) |
| `error_detail_level()` | 错误粗化粒度(`coarse` / `educational`,10.1) |

### 2.3 写入目标三分类(执行前判定;I-9 / E-2 / E-3 的判定依据)

| 分类 | 判定 | 运行时动作(闸在 WP-8,分类函数在本 crate) | 公开错误 |
|---|---|---|---|
| 全覆盖 `Covered` | `[addr, addr+len)` 逐字节落在可见区域覆盖内(允许横跨相邻可见区域) | 放行到引擎;权限不足由引擎教学性失败 | `permission_denied`(required-real 可满足) |
| 越界 `CrossesBoundary` | 起点可见,可见覆盖前缀 < len(前缀尽头是隐藏区域或未映射空洞,同形态) | **执行前拒绝**(杜绝把跨边界写入漏进隐藏区域——邻接隐藏区域的写入会被引擎接受,预检必须先于引擎) | `offset_out_of_range`;`expectedBytesLength` = 可见覆盖字节数(来源 = 可见区域边界,E-3)、`actualBytesLength` = 请求长度 |
| 不可见 `Invisible` | 起点不在可见覆盖内 | **执行前拒绝** | `inaccessible_address`(null-only;隐藏映射与未映射不可区分,I-9) |

零长度写入按起点可见性归类。判定基准(ZR-P5):三分类拒绝发生在**进入执行前**,revision 不推进(增量 0);全覆盖但权限不足的教学失败已进入执行,revision +1(增量 +1)。

## 三、投影生成(`project.rs`;WP-1 §4.1 / §4.3、D2 / D3 / D5)

### 3.1 完整投影(7 字段,不增不删)

| 字段 | 生成规则 |
|---|---|
| `revision` | 调用方账本注入(已执行非拒绝动作数,I-5;投影面不做算术) |
| `visibleRegions` | **白名单序 = 输出序**(公开布局序);每区域:标签取静态声明面(缺失即 `challenge_invalid`,fail-closed)、窗口字节 = 存储面读回前缀 `min(byteLength, maxBytesPerRange)`、`truncated` = 窗口 < 区域长(常态布尔字段:完整展示也是显式教学事实,投影与错误契约语义 §2.2) |
| `visibleRegisters` | 白名单寄存器当前值,大写变长十六进制(`ArchValue::format_hex` 同形态);白名单引用未声明寄存器即 `challenge_invalid` |
| `callStackSummary` | §3.2 |
| `controlFlow` | §3.3 |
| `semanticHighlights` | 静态声明面逐条复核:目标区域存在且 ∈ 白名单、几何 `[start, start+len)` 落区域界内——任一违反即 `challenge_invalid`(I-2 引擎侧 fail-closed;编译期检查的上游) |
| `status` | `VmStatus → PublicStatus` 一一映射(D1 粗化;`rejected` 结构性不在枚举中;won / failed 的公开时点由 WP-5 检查点判定承载,本映射零增益) |

### 3.2 调用栈摘要(D2;截断方向裁决 D-P3)

内容裁剪为 `{index, functionLabel, returnAddressHex}`:帧基址不下发(玩家从可见 RSP/RBP 推导,教学价值),`args` 不下发(私有布局信息)。`functionLabel` 值来源 = 引擎静态模板(`{:#X}` 目标地址;公开符号表来源归 WP-8 装载面增强,模板类不变)。

- **index 0 = 最内帧**(当前函数;引擎 `call_frames` 栈顶);
- 深度上限 `CALL_STACK_MAX_DEPTH = 64`:超限时**保留最内 64 帧、裁剪最老帧**,presence-only `truncated` 打在展示的最后一帧(index 63)上——"其后还有帧未展示",不含省略帧数(D2:计数是隐藏控制流深度的信号)。裁决记录:契约未指明裁剪端,取"保留内层"符合教学语境(玩家需要当前调用链);标记落点"最后一帧"两端一致;
- 深度 ≤ 64:全量展示,无标记。

### 3.3 控制流展示(D5)

`currentInstruction` 必填非空:MVP 代码区恒公开,RIP 展示恒可行。

- **文本来源**:与执行共用层 1 表示——IR 模式按指令索引直取;字节模式按 RIP 取指译码(与 `Engine::fetch_decode` 同一编码表与译码纯函数,取指窗口 65 字节余量)。渲染为 `助记符 操作数, 操作数` 静态模板(寄存器名 / 大写立即数 / `[base±0xN]` 补码位移 / 接口号地址形态);自定义指令使用 `displayText`(层 3 展示面,编译期已过 XS-CUSTOM-DISPLAY 的 E-4/E-6 扫描,静态模板类)。文本不是可执行 IR 的任何形态(7.3);
- **不可译码形态**(IR 索引出界 / 字节截断 / 未知 token):统一占位文本 `<undecodable>`,地址照显——地址是玩家自供值或公开布局(E-3 允许源);地址与文本一起呈现,不存在"只藏地址留文本"(D5 占位规则的 MVP 对偶);
- `pausedOn`:仅 `status = paused` 时携带暂停原因(与 `run_to_event.pauseOn` 同源枚举);其余状态恒 `null`(nullable 形态)。

### 3.4 增量生成(§4.3;存在性确定性 I-4)

| 字段 | 存在性规则 | 内容 |
|---|---|---|
| `revision` | 恒在 | = 信封 revision(生成侧同值注入,superRefine 跨字段规则的引擎侧保证) |
| `dirtyRanges` | 恒在(可空数组,I-8) | §3.5 |
| `changedRegisters` | 恒在(可空数组,I-8) | 白名单序前后比对(前后同策略 ⇒ 同序),仅携带变化者的新值 |
| `controlFlow` | 地址 / 文本 / pausedOn 任一可见面变化 | 整体替换形态 |
| `status` | 状态变化(`PublicStatus::delta_field`) | 整体替换形态 |
| `callStackSummary` | 摘要比较变化 | 整体替换形态 |
| `semanticHighlights` | 恒缺席 | 静态声明面,运行期恒不变化(存在性规则的退化情形) |

### 3.5 脏范围合并(D3;§4.3 冻结规则的完整判定序)

输入 = 本动作新增私有事件段中的 Write 事件(地址 + 宽度;拒绝不入账 ⇒ 拒绝动作天然无脏范围):

1. **可见覆盖裁剪**:每次写保留其可见覆盖前缀(复用 §2.3 分类:`Covered` 全保、`CrossesBoundary` 保前缀、`Invisible` 丢弃)——相邻隐藏区域的写入段被裁剪,与未映射空洞同形态(I-9);越界段永不进入 `bytesHex`(I-10:字节来源 ⊆ 可见区域内容);
2. **地址升序排序**(承载顺序 = 契约规则);
3. **同区域相邻 / 重叠归并**为极大连续区间(range 有单一 `regionId`,永不跨区域);
4. **单 range 窗口上限**:归并段 > `maxBytesPerRange` 时窗口裁剪(锚定 range 起点);
5. **条数上限**:≤ 256(`MAX_DIRTY_RANGES_PER_DELTA`,地址升序保留);
6. **单 revision 字节总预算 8192**:按地址升序承载至预算耗尽,预算边界段部分承载;
7. **内容读回**:承载段字节 = 动作后权威内存存储面读回(D-P2)与写事件载荷同源;
8. **截断标记落位(D-P6)**:任何不完整承载(窗口裁剪 / 条数上限 / 预算耗尽)⇒ presence-only `truncated` 打在**最后一个已承载 range**上;恰好承载完毕(总字节 = 8192)无标记。不含省略字节数;客户端收到标记后以 `sync-projection` 重新对齐(9.1)。

边界红灯:恰 8192 字节无标记、8193 字节预算段部分承载 + 标记(`revision_budget_*` / `exactly_at_budget` 测试)。

## 四、公开事件管线(`events.rs`;WP-1 §4.2 / D4)

管线五步(全部确定性纯函数;输入 = 本动作新增私有事件段,由调用方从 `privateEventLog` 切片承载):

1. **类别白名单**:六公开类(read / write / call / ret / syscall / exception)保留;`Internal` / `FileGranted` / `FileRead` **永不进入公开面**(结构上无映射路径);
2. **可见性过滤**(整事件丢弃,无占位无条目——D4;序号空洞不可利用,因 §4 步稠密重编号):
   - read / write:访问范围必须**完全**落在可见覆盖内(`classify_write_range = Covered`),部分覆盖即整事件丢弃(可见部分仍以脏范围承载;事件面不留"部分可见"探测形态);
   - call / ret:地址为代码地址(MVP 公开),不可见即丢弃;
   - syscall:无地址,恒保留;
   - exception:异常本身是玩家可观测事实(响应错误同源),恒保留;地址仅在可见时携带——隐藏映射与未映射地址的异常事件字节形态一致(I-9);
3. **载荷承载**:write 事件 `payloadHex` = 动作后权威内存存储面读回(与脏范围同源,D-P2);生成保证 `payloadHex` 字节长度 == `byteLength`(superRefine 一致性的引擎侧结构性保证,契约层只校验形态);read 事件只携带 `byteLength`(读值随时间线变化,不承载误导快照);读回失败(理论不可达:成功写入必已物化目标页)按无载荷形态下发;
4. **稠密编号**:`seq` 从 0 起、动作内独立(D4:禁止沿用私有序号——序号空洞即隐藏事件计数侧信道;跨动作连续性不承担语义,避免与 undo / 回退产生序号耦合);
5. **确定性聚合(D-P4)**:公开事件 > 256 时保留前 255 + 一个聚合事件(`seq = 255`、`truncated: true`、`kind` = 首个被聚合事件的类别、无地址 / 长度 / 载荷)。聚合只读取公开事件列表自身,不读取任何私有状态(WP-1 v1.2);聚合类别是玩家动作的公开语义,无隐藏信息。

## 五、错误粗化(`error.rs`;WP-1 §4.4 / §6.3 E-1–E-6 / 10.1;ZR-P6)

### 5.1 能力矩阵生成侧强制(矩阵是构造期结构,不是约定)

16 错误码枚举(`PublicErrorCode`,与协议冻结枚举同串)逐 code 承载 `addressHex` 四形态(`forbidden` / `null-only` / `free` / `required-real`)与 explanation 允许面(与 `@stackmaster/protocol` 的 `ERROR_CODE_CAPABILITIES` 一一对应,漂移由 vm-worker Schema 闭环测试锁定)。`ErrorDraft` 草稿构造 + `finish` 裁决是**唯一出口**:

- 矩阵外组合在构造期即 `CapabilityViolated`(方向 `engine_error`)——引擎侧缺陷以 fail-closed 暴露,不静默剥离、不近似下发;
- **地址形态裁决**:`forbidden` 携带即违规(含显式 null);`null-only` 恒 null(真实地址即违规);`required-real` 必须真实**且可见**(`finish` 期对照内存布局复核);`free` 在 educational 携带真实可见地址、在 **coarse 整体缺席**(10.1 coarse 列"目标地址 ✗"的落实;不可见地址在任何级别都是 Null——统一占位不进入 free 分支);
- **coarse 零解释**(10.1 / ZR-P6):coarse 级 explanation 整体剥离——"coarse 载荷只含 code + message"由生成侧结构性保证(机检见 §八 ZR-P6 测试);`forbidden` 码(`objective_not_met` / 预算 / 协议级拒绝 / 内部错误)在任何级别携带解释字段即违规(E-4 / I-7);
- **静态模板**(E-5 / I-10):`message` 按 `f(code)` 常量模板(1–512,无控制字符);`hints` 逐 code 静态教学提示(≤ 4 条、单条 ≤ 256、无控制字符)。参数化是允许面而非义务——常量模板使 ZR-P6 的"相同 (code, 可见状态, 级别) 载荷字节一致"平凡成立。

### 5.2 引擎错误映射(教学性失败面;已执行,revision 前进)

| 引擎错误 | 可见性裁决 | 公开形态 |
|---|---|---|
| `MemoryFault` | 故障地址不可见(隐藏映射 / 未映射 / 回绕) | `inaccessible_address`(null-only;`valueHex` 回显目标地址——玩家自供;隐藏区域的权限事实与类别零外泄) |
| `MemoryFault::PermissionDenied` | 故障地址可见 | `permission_denied`(required-real 真实地址;`regionId` + 区域权限事实 + hints) |
| `MemoryFault::Unmapped / AddressOverflow` | 故障地址可见 | 构造性不可达(可见 = 已映射;跨界段首地址不可见已被上一分支统一)→ `EngineDefect` 防御性安全终止 |
| `InvalidRip` | — | `invalid_rip`(free:可见地址携带真实地址,不可见 null;`valueHex` + `interpretedAs` 位宽×端序) |
| `InvalidSyscallDispatch` | — | `invalid_call_argument`(forbidden 地址;`valueHex` = 派发号回显——玩家自供;未声明派发号是调用参数面错误) |
| `CanaryViolation` | 槽位必须在可见区域 | `canary_violation`(required-real;`valueHex` = 槽位当前内容回显 = 玩家写入值,canary 期望值零外泄);不可见槽位无法满足 required-real → `challenge_invalid`(装载面漏检的纵深防御) |
| `ResourceLimit` | — | `budget_exhausted`(forbidden / forbidden) |
| `InvariantBroken` | — | `internal_error`(engine_error 公开兜底,E-6 零细节) |

判定结局投影:检查点置 `failed` → 响应错误 `objective_not_met`(**恒零解释**——不含已匹配/未匹配计数、谓词标识、部分匹配结果,E-4 / I-7);`won` → 无错误。判定失败的失败来源标签(`challenge_condition:N` 等)只入私有事件与受控日志,公开面只有 `status = failed`(D1)。

### 5.3 执行前拒绝映射(响应 `status = rejected`;revision 不动)

`RejectionReason` 中性枚举(vm-runtime / worker 侧映射到本枚举,粗化单点在本模块):

| 拒绝原因 | 公开码 |
|---|---|
| 终态会话(D1 约束 5) | `session_terminal` |
| 阶段不允许动作 / 空历史 undo / 未知 checkpoint / 标签非法 | `invalid_input_format`(hints 静态) |
| 阶段动作预算 / 动作日志满 / 回退预算耗尽 | `budget_exhausted` |
| `baseRevision` 过期 / `clientSeq` 乱序 / 幂等冲突 | `stale_base_revision` / `stale_client_seq` / `idempotency_conflict` |
| 写越可见边界(§2.3) | `offset_out_of_range`(educational 携带 free 地址 + expected/actual) |
| 写起点不可见(§2.3) | `inaccessible_address`(null-only;`valueHex` 回显) |
| 装配 / 版本锁定拒绝(challenge_invalid 方向)、判题谓词累计预算耗尽 | `internal_error`(公开兜底,零细节;challenge_invalid 不是玩家可及错误码,题目缺陷细节只进受控日志) |

### 5.4 响应面装配(`response.rs`;§4.4 耦合的结构性保证)

- `executed_action`:已执行(含教学性失败)——`projectionDelta` 恒存在、`publicEvents` 承载本动作公开事件、`userVisibleError` 可携带;`delta.revision == 信封 revision` 由同值注入保证;
- `rejected_action`:执行前拒绝——`status = rejected`、错误必有、增量恒 `null`、事件恒空;构造器是拒绝形态唯一入口,"拒绝却带增量"不可表达(§4.4 耦合的生成侧结构性保证,Schema `if/then` 注入形态在 worker 出站自检承接)。

## 六、出站契约闭环(`vm_worker::contract::outbound`)

出站面的字段集合**单一来源就是 `projection` crate 的生成类型**:worker 只提供生成类型 → `serde_json::Value` 的 1:1 保形转换,**不另立镜像类型**——入站面用 serde 镜像 + schemars 漂移冒烟,出站面以"转换 + 双路字节等价"替代,镜像漂移结构性不可能。三重闭环(全部机检):

1. **Schema 闭环**:全部生成形态(完整投影 / 空与满增量 / 16 码 × 零解释与满解释两形态 / 已执行与拒绝信封)通过阶段一冻结 JSON Schema(`public-state-projection` / `projection-delta` / `public-error` / `action-response`,后两者本次接入 `ContractValidators`);未知字段拒绝由 Schema `additionalProperties: false` 承担(I-1 / ZR-P1);
2. **双路字节等价**:转换产物经 `contract::canonical` 规范化 == `projection` 生成类型的规范化输出文本,逐字节相等——生成面文本与出站 JSON 是同一内容的两种序列化路径;
3. **rejected 耦合**:Schema `if/then` 注入形态(语义文档 §六)校验"delta null + events 空 + error 必有"。
