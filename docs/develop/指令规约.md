## 一、总则

### 1.1 三层结构与统一执行入口(G5/D6)

```text
层 1  执行语义   20 基线 opcode ∪ 大写自定义助记符(本规约 §二~§五;引擎解释的权威)
层 2  表层机器码  token 字典(公开包 encodingTable;字节模式取指译码到层 1)
层 3  汇编显示   displayText / 助记符文本(不参与执行)
```

两程序形态共享同一执行语义,只差**取指方式**:

| | IR 模式 | 字节模式 |
|---|---|---|
| 程序来源 | 私有包 `compiledIr.instructions[]`(编译产物直读) | 代码区 `contentHex`(表层机器码即唯一权威执行空间,D4.4) |
| 执行位置(`instructionPointer` / `RIP`) | **指令索引**(0..len−1) | **代码区字节地址**(任意字节边界,gadget 一等公民) |
| 取指 | 索引界内直读;出界 → `invalid_rip` | 按 `encodingTable` 取指译码(§1.6);未知 token / 截断 / 不可执行 → `invalid_rip` |
| 跳转 / `call` 立即数与返回地址 | 指令索引 | 绝对字节地址 |
| 预算 / 谓词 / 编排 / 判题链路 | 完全同一 | 完全同一 |

跨模式一致性(完成标准):同一逻辑程序两形态的事件类别序列、Read/Write 事件地址、通用寄存器终值、栈区字节、步耗逐项一致;RIP 与调用帧标签因地址域不同属构造性差异。

### 1.2 值域与位宽(G1/D1)

- 架构值 = archBits 位宽的值,64 位容器承载,高位按位宽掩蔽;立即数**无符号**,位移**有符号**(二进制补码承载于同一掩蔽域容器);
- **有效地址(EA)** = base 寄存器值(缺省 0)+ 位移,按模 2^archBits 加法(掩蔽域回绕是定义语义,非溢出);
- **内存操作数宽度** = `archBits/8` 字节(32 位 4 字节、64 位 8 字节),小端;
- 移位量按 archBits **取模**(shl/shr;量 = 操作数值 mod archBits);
- 算术在掩蔽域内进行:`add`/`sub` 的模回绕是定义语义,进位 / 借位以原始量输出置 `cf`;**未定义域内的意外溢出**(Rust 算术 panic,ENG-3)按 `engine_error` 安全终止——引擎内一切指针 / 地址算术均以模运算完成,panic 只可能是引擎缺陷。

### 1.3 栈语义

- **栈槽定宽 8 字节**(冻结于最小DSL范围 §三.1 "`RSP -= 8` 后写栈"),与 archBits 无关;`push`/`pop`/`call`(压返回地址)/`ret`/`leave`(弹 saved RBP)全部使用 8 字节槽;
- 槽内值为掩蔽域架构值,小端落盘(32 位题目高 4 字节为零);
- `RSP` 的增减为模 2^archBits 运算;栈访问的权限检查与其他内存访问同路径(统一拒绝路径 I-9)。

### 1.4 标志模型(v1 三标志)

| 标志 | 语义 |
|---|---|
| `zf` | 最近一次置标志运算的结果为零 |
| `cf` | 无符号进位(`add`)/ 借位(`sub` / `cmp`) |
| `sf` | 结果符号位(第 archBits−1 位) |

- 归属:冻结表 `registers` 行"寄存器全集到架构值的映射 **+ FLAG 位**"——标志承载于 `RegisterFile`,随寄存器文件进入快照与回退,不是 `VmState` 新字段;**永不进入公开面**(WP-7 白名单只覆盖命名寄存器);
- 置位规则(冻结表标志列):`add`/`sub`/`cmp` 置 zf cf sf;`and`/`or`/`xor`/`shl`/`shr` 只置 zf sf(**cf 不动**);
- `cmp` 只置标志不写回;条件跳转只消费标志;装载时全清。

### 1.5 步数预算

| 执行对象 | 步耗 | 性质 |
|---|---|---|
| 基线指令 | 1 | — |
| 自定义指令 | = 微算子条数 | 恒定,与操作数值无关(T-SC2) |
| 接口效果序列(每次派发) | = 效果原语条数 | 恒定(声明序全量计费,即使 `exit` 提前终止) |

全部计入 `constraints.steps`(可回退预算,随快照回退);取指在记账之前,取指失败不记账。超限 → `resource_limit`,状态 `failed`。

### 1.6 取指与译码(D4.4 / D4.6 / D4.7)

字节模式逐指令执行:

1. 自 `RIP` 取 1 字节 token(执行权限,统一路径);
2. 查编码表得表项 → 指令总长 = 1 + 内联操作数 × `archBits/8`(寄存器 / 接口号烘焙,立即数 / 位移内联小端);
3. 整体取指 `[RIP, RIP+总长)`(执行权限)→ 纯函数译码 `(表, 字节, 地址) → 指令`;
4. 按层 1 语义执行。

- 译码是纯函数,无时钟 / 随机 / IO(6.3);**译码缓存**(键 = 指令首地址)是性能优化不是状态:W^X(D4.5)保证代码区内容会话内不变,缓存永不失效、不进快照、跨 `reset` 恒有效;
- 内联操作数任意位型都在掩蔽域内(`XS-ARCH-WIDTH` 在译码中结构性不触发,D4.6);
- 取指可从任意字节地址开始(指令中间 gadget 合法,ROP 教学底座);取指失败(未映射 / 无执行权限 / 未知 token / 截断)统一 `invalid_rip`——与 `ret` 弹出不可执行值同规则。

### 1.7 事件模型(私有事件 → 公开事件的全集来源)

每条指令至多产生**一个主事件类别**(call / ret 的栈访问并入 Call / Ret 事件,不另发 Read / Write):

| 指令 / 操作 | 私有事件 | address | byteLength | payload |
|---|---|---|---|---|
| `mov R,M`、`pop`、`leave`(弹 saved RBP)、`jmp M`、算术 M 形态、`load_mem` 微算子 | `read` | 访问地址 | archBits/8 | — |
| `mov M,R`、`push`、`store_mem` 微算子、动作 `write_bytes` | `write` | 访问地址 | 写宽 | — |
| `call`(真实 / 接口)、动作 `call` | `call` | 真实调用 = 目标;接口调用 = `None` | — | 接口调用 = 接口号 LE8 |
| `ret`、动作 `ret` | `ret` | 弹出的返回地址 | — | — |
| `syscall` | `syscall` | — | — | 派发号 LE8 |
| 一切异常(§1.8) | `exception` | 故障地址(如有) | — | — |
| 效果 `grant_virtual_file` / `virtual_file_read` | 内部事件 `FileGranted` / `FileRead`(永不进公开面) | — | fileId 长度 | fileId 字节 |
| 无暂停类事件的指令(算术 / 跳转 / 寄存器传送) | 无 | — | — | — |

- 事件 append-only,`seq` 引擎内单调(公开事件的稠密编号是 WP-7 生成面的另一序列);
- 失败的访问不产生 read / write 事件(异常以 `exception` 事件记录);
- `syscall` 事件**不属于** `pauseOn` 枚举(伪 syscall 不作为暂停事件提供,协议 PauseEventSchema 同源)。

### 1.8 异常面(方向映射)

| 引擎异常 | 触发 | 公开方向 | 状态 |
|---|---|---|---|
| 取指位置不可执行 | 未映射 / 无执行权限 / 未知 token / 指令截断 / IR 索引出界 / `ret`·`leave` 弹出值不可作为执行位置 | `invalid_rip` | `failed` |
| 数据访问越权 / 越界 | 统一拒绝路径 I-9(Unmapped / PermissionDenied / AddressOverflow) | `memory_fault` | `failed` |
| Canary 破坏 | `ret` / `leave` 前置检测,槽位字节 ≠ 期望值 | `canary_violation` | `failed` |
| 步数 / 调用深度超限 | `constraints.steps` / `call_depth_limit` | `resource_limit` | `failed` |
| 运行期派发号不可解析 | 字节模式探测译码外的 `syscall` gadget 路径 | `invalid_action` | `failed` |
| Rust 算术溢出 panic | ENG-3(理论不可达:引擎算术全在模域内) | `engine_error`(宿主层安全终止) | 进程级 |
| 引擎不变量破坏 | 装载校验后理论不可达(防御性) | `engine_error` | 进程级 |

公开错误码 / 消息模板 / 能力矩阵合规由 WP-7 生成侧保证;`resource_limit` 的结果类型方向见协议 11 结果类型。

### 1.9 程序终止与执行位置视图

- `syscall exit(I)`(保留带内置)与接口 `exit` 效果(等效 `exit(0)`)终止程序执行:引擎置 `halted`,状态保持 `running`(won / failed 的权威判定归 WP-5);`undo` / `reset` 可回退;
- 已 `halted` 或状态终态(won / failed)时 `step` / `run_to_event` 不执行(返回 `Halted`);动作层的终态拒绝(`session_terminal`)归 WP-8;
- `RIP` 寄存器与 `instructionPointer` 是同一执行位置的两个架构视图:装载即同步,此后引擎统一维护(公开面可经 `visibleRegisters` 见到真实 RIP,不产生双真相源)。

## 二、基线 20 opcode 逐条规约

操作数类别:`R` 寄存器、`I` 立即数、`M` 内存(base + 有符号位移)、`F` 作者接口引用。事件列见 §1.7;异常列仅列指令特有路径,统一拒绝路径(I-9)适用于一切内存访问。

| opcode | 操作数形态 | 位宽行为 | 异常 | 事件 | 步耗 |
|---|---|---|---|---|---|
| `mov` | `R,I` / `R,R` / `R,M` / `M,R` | 传送掩蔽域架构值;M 形态读写 `archBits/8` 字节小端;EA 模加(§1.2) | M 形态 → `memory_fault` | `R,M` → read;`M,R` → write | 1 |
| `push` | `R` / `I` | `RSP −= 8`(模);8 字节槽小端写入掩蔽值(§1.3) | 栈写越权 → `memory_fault` | write(addr = 新 RSP, len 8) | 1 |
| `pop` | `R` | 读 `[RSP]` 8 字节;`RSP += 8`;值掩蔽 | 栈读越权 → `memory_fault` | read(addr = 旧 RSP, len 8) | 1 |
| `leave` | 无 | ① Canary 检查 → ② `RSP ← RBP` → ③ 弹 saved RBP(`pop RBP`,§1.3)→ ④ 返回地址槽校验(§三) | Canary → `canary_violation`;③/④ 访问 → `memory_fault`;④ 校验失败 → `invalid_rip` | read(addr = ② 后的 RSP, len 8) | 1 |
| `add` | `R,R` / `R,I` / `R,M` | 掩蔽域模加;进位原始量置 `cf`;zf / sf 按结果 | M 形态 → `memory_fault` | M 形态 → read | 1 |
| `sub` | `R,R` / `R,I` / `R,M` | 掩蔽域模减;借位置 `cf` | 同上 | 同上 | 1 |
| `cmp` | `R,R` / `R,I` / `R,M` | 同 `sub`,**不写回**,只置 zf cf sf | 同上 | 同上 | 1 |
| `and` / `or` / `xor` | `R,R` / `R,I` | 掩蔽域按位运算;只置 zf sf(cf 不动,§1.4) | — | 无 | 1 |
| `shl` / `shr` | `R,R` / `R,I` | 移位量 = 操作数值 mod archBits(§1.2);`shr` 高位补零;只置 zf sf | — | 无 | 1 |
| `jmp` | `I` / `R` / `M` | 目标写入执行位置(IR = 索引 / 字节 = 地址) | M 形态读 → `memory_fault`;目标不可执行由**下一次取指**判 `invalid_rip` | `M` 形态 → read | 1 |
| `je` / `jne` | `I` | `zf` 为真 / 假则跳转;未跳落下一位置 | — | 无 | 1 |
| `jb` / `jae` | `I` | `cf` 为真 / 假则跳转(无符号域序) | — | 无 | 1 |
| `call` | `I` / `R` / `F` | `I`/`R`:真实调用(§三);`F`:接口派发(§五,D4.2 ①) | 真实调用:栈写越权 → `memory_fault`、深度超限 → `resource_limit` | call(真实 = 目标地址;接口 = payload 接口号) | 1 + 效果条数(F 形态) |
| `ret` | 无 | ① Canary 检查 → ② 弹返回地址(`RSP += 8`)→ ③ 弹影子调用帧 → ④ 目标执行位置校验(§三) | Canary → `canary_violation`;② → `memory_fault`;④ → `invalid_rip` | ret(addr = 目标) | 1 |
| `syscall` | `I` | 派发号 ∈ [0x00,0xFF] → 内置 `exit(I)`(终止,退出码 = I);≥ 0x0100 → 接口派发(§五) | 派发号不可解析(运行期 gadget 路径)→ `invalid_action` | syscall(payload = 派发号 LE8) | 1 + 效果条数(接口) |

装载校验(引擎镜像复验,方向 `challenge_invalid`):操作数形态冻结表(XC-OPCODE-SHAPE 镜像)、寄存器 / 基址引用可解析(XC-OPERAND-REF)、自定义助记符声明(XS-CUSTOM-REF)、`syscall` 派发号声明(XS-SYSCALL-DECL,IR 模式静态全量)、`interface` 引用声明(XS-IFACE-REF)、编码表自检(XS-ENC-TOKEN 镜像:token 唯一 / 形态匹配 / FLAG 不可编码 R11 / 空表失败关闭 R13)、入口落可执行代码区(XS-ENC-PROBE)。

## 三、调用与栈帧语义

### 3.1 `call`(真实调用,`I` / `R` 形态)

1. 深度检查:`call_frames.len() + 1 > call_depth_limit` → `resource_limit`(协议 `CALL_STACK_MAX_DEPTH`);
2. 压返回地址(下一执行位置)入栈(8 字节槽;栈写并入 Call 事件);
3. 影子调用帧入栈:`{function_label = "0x" + 目标十六进制(确定性静态模板), return_address, saved_rbp = 当前 RBP, args = []}`;
4. `RIP ← 目标`;Call 事件。

`call_frames` 是**引擎侧影子栈**,不是玩家栈:与内存栈独立维护,被劫持的 `ret` 不因影子栈状态被拒——栈帧劫持教学(RSP 劫持后 `ret` 弹攻击者地址)正是要在影子栈"看不见"的前提下成立。公开调用栈摘要(presence-only)由 WP-7 从影子栈生成。

### 3.2 `ret`

1. Canary 检查(§3.4,先于一切栈语义);
2. 自 `[RSP]` 读 8 字节返回地址(数据读;越权 → `memory_fault`),`RSP += 8`;
3. 影子帧非空即弹(与玩家栈不对应时不追责);
4. **执行位置校验**:目标在 IR 模式须为界内索引、字节模式须整体取指译码成功;失败 → `invalid_rip{目标}`(RIP 保持未跳转);
5. `RIP ← 目标`;Ret 事件。

无 `call` 配对的 `ret` 合法(弹出的地址有效即成功)——ROP 教学核心路径。

### 3.3 `leave`

语义 = `mov rsp,rbp; pop rbp` + 两项栈帧安全检查:

1. Canary 检查(§3.4);
2. `RSP ← RBP`;
3. 弹 saved RBP(read 事件);`RBP ← 弹出值`;
4. **返回地址槽校验**:读当前 `[RSP]`(即将被随后 `ret` 弹出的 8 字节),按 §3.2 第 4 步同规则校验;失败 → `invalid_rip{槽值}`。

**G4 裁决落点说明**:冻结表 leave 行"弹出值不可执行时报 `invalid_rip`(与 `ret` 同规则)"——若按字面把检查施加于**弹出的 saved RBP**(帧指针,恒为栈地址、天然不可执行),一切合法函数序言都会误报,指令不可用;本实现取唯一自洽读法:**"后续将被弹出的值"**(返回地址槽)以 `ret` 同规则校验,在 `leave` 即报,早于其后的 `ret`,与教学注记(saved RBP 被覆写 → `leave` 劫持 `RSP` → 随后 `ret` 弹攻击者地址)完全相容:被劫持的 `RSP` 使槽位读出攻击者数据,`leave` 阶段即得 `invalid_rip` 教学反馈。`leave` 不弹影子帧(帧销毁由配对的 `ret` 完成)。

### 3.4 Canary 破坏检测

- 槽位来源:私有包 `privateObjects` 中 `kind = "canary"` 的对象(装载管线换算为 `{address, byteLength}`,期望值在引擎初始化时自初始内存截取,只存在于引擎内);
- 检测时点:`ret` 与 `leave` 的**第一步**(先于栈语义,使 canary_violation 优先于 invalid_rip / memory_fault 报出);
- 判定:槽位当前字节逐字节比对期望值;不等 → `canary_violation{address, byteLength}`,状态 `failed`(数据分类清单 v1.1:Canary 破坏触发 failed);
- 无 canary 对象的题目零开销(空槽位集)。

## 四、自定义指令解释器(微算子封闭集 v1)

`op` 为大写自定义助记符时,按 `customInstructions[]` 声明的微算子序列**直线**执行(封闭集内无控制转移,D4.3;恒定步耗 = 条数,T-SC2;`displayText` 属层 3 展示,不参与执行):

| 微算子 | 字段 | 语义 | 事件 | 异常 |
|---|---|---|---|---|
| `load_imm` | `dst`(一般寄存器)、`valueHex` | `dst ← 立即数`(掩蔽) | 无 | — |
| `mov_reg` | `dst`、`src`(一般寄存器) | 寄存器间传送 | 无 | — |
| `load_mem` | `dst`、`baseRegister`、`displacementHex` | `dst ← [base + disp]`(archBits/8 小端;EA 模加;统一权限路径) | read | `memory_fault` |
| `store_mem` | `baseRegister`、`displacementHex`、`src` | `[base + disp] ← src`(同上) | write | `memory_fault` |
| `set_flag` | `flagRegister`(FLAG 保留区)、`valueHex` | FLAG 汇寄存器置位(FLAG 写入唯一微算子;值永不进公开面,I-3) | 无 | — |
| `bit_mask` | `dst`、`src`、`maskHex`、`logic ∈ {and,or,xor}` | `dst ← src ⊕ mask`(掩蔽域) | 无 | — |

- 微算子**中途异常**:已执行微算子的效果保留(寄存器 / 内存已写、事件已记),状态 `failed`(序列无原子性承诺,回放按同一序重放一致);
- 装载校验:数据寄存器可解析且落一般命名空间(FLAG 只可作 `set_flag` 目标)、`set_flag` 目标必须是声明 FLAG、序列 1..=16 条。

## 五、接口派发(`syscall` / `call F`;D4.2 ①)

### 5.1 派发规则

- `syscall I`:I ∈ [0x00,0xFF] → 内置 `exit(I)`(唯一内置,无宿主副作用);I ≥ 0x0100 → 按 `interfaces[]` 精确匹配派发——IR 模式装载即校验声明(XS-SYSCALL-DECL),字节模式探测译码外的运行期路径未声明 → `invalid_action`;
- `call {interfaceId}`:结构化引用,装载即校验声明(XS-IFACE-REF);
- **引擎管理调用**(D4.2 ①):执行效果后**返回下一条指令**——不压返回地址、不占玩家栈、不建调用帧(RSP 不动),教学上区分"真实 `call`(栈帧)"与"接口 `call`(教学接口)"。

### 5.2 效果原语封闭集 v1

| 原语 | 字段 | 语义 |
|---|---|---|
| `exit` | — | 程序终止(等效内置 `exit(0)`);**其后声明序的剩余效果跳过**,步耗仍按声明全量计费(恒定) |
| `grant_virtual_file` | `fileId` | 授予虚拟文件 capability → 内部事件 `FileGranted`(WP-5 谓词与编排账本的私有记录) |
| `virtual_file_read` | `fileId` | 标记虚拟文件已读 → 内部事件 `FileRead`(衔接谓词 `virtual_file_read`) |
| `set_flag` | `flagRegister`、`valueHex` | 置 FLAG 汇寄存器(经 I-3 污点检查落点:FLAG 值永不进公开面) |
| `noop` | — | 无操作 |

grant / read 状态经 append-only 私有事件承载(事件随 `VmState` 快照回退,谓词求值与回退语义天然一致)。

## 六、暂停事件与动作原语

### 6.1 `run_to_event` 与 `pauseOn`

- `pauseOn ∈ {read, write, call, ret, exception}`(协议 PauseEventSchema;伪 `syscall` 不作为暂停事件提供);
- 循环执行至:命中 `pauseOn` 类主事件(状态置 `paused`,暂停在事件后指令边界)/ 程序 `exit` / 异常(恒 `failed`)/ 预算耗尽;
- `exception` 作为停止条件的语义:异常本就终止运行;该枚举值约束的是动作层响应面(以异常为停止条件的运行,其 `ActionResponse` 生成归 WP-7 / WP-8);
- 指令级暂停由 `step` 动作承载("单步执行恰好一条指令",步数不作为动作自由度)。

### 6.2 引擎动作原语(WP-8 接线面)

| 原语 | 语义 |
|---|---|
| `action_write_bytes(addr, bytes)` | 统一权限写 + write 事件(越权 → `memory_fault`) |
| `action_push(v)` / `action_pop()` | 与 `push` / `pop` 指令同语义 |
| `action_call(target)` | 与 `call I/R` 同语义(返回地址 = 当前执行位置;含深度检查与 Call 事件) |
| `action_ret()` | 与 `ret` 同语义(含 Canary 检查与执行位置校验) |
| `pause()` | `running` → `paused`(当前指令边界) |
| `reset()` | 恢复装载时初始状态(事件清空、`halted` 清除;revision / 投影 / 预算外记账归 WP-6 / WP-8) |
