## 一、Q3 定案:workspace 依赖 + 自包含打包(「分层同源」的装配面延伸)

**任务分解 §六 Q3**(web-component 与 vm-ui 装配形态)定案:**workspace 依赖 + vite 库模式自包含打包**,占位期「不得依赖 vm-ui」边界解除。具体:

1. **依赖面**:`packages/web-component` 新增两条工作区依赖——`@stackmaster/vm-ui`(Q3 装配:挂载 `<sm-workspace>` 承接公开投影渲染 / 断线横幅 / sync-projection 重连)与 `@stackmaster/embed-runtime`(Q4 复用:esid 校验 `validateEmbedSessionId`、`TypeRateLimiter`、违规计数键 `VIOLATION_COUNTER_KEYS`——Q4「分层同源」定案的插件侧消费面)。`@stackmaster/protocol` 为既有公开入口依赖(EmbedMessage 解析器;**浏览器绝不解析 token**,`EmbedTokenClaims` 解析器不经本包消费)。
2. **自包含产物**:vite 库模式单入口(`src/index.ts`)单产物(`dist/index.js`,约 1.5 MB,lit / vm-ui / protocol / embed-runtime 全部内联);`codeSplitting: false` 压平动态分块保证「单产物」形态。机械断言:`test/artifact.test.ts`(零外部导入、零相对 chunk、组件注册面完整)。
3. **非根路径部署**:插件文档页以 `<script type="module" src="./pwn-memory-vm.js">` **相对路径**引用产物,整目录拷贝即可部署于任意路径前缀。
4. **受限 CSP 兼容**:零 `eval`、插件文档页零内联脚本(唯一 `<script>` 为空体 + 相对 src)、零内联事件处理器——`test/artifact.test.ts` 静态自测 + demo 服务器以 `Content-Security-Policy: script-src 'self'` 头真实运行证明(plugin-site-server.mjs)。
5. **dependency-cruiser 规则修订**(随规则修订必带反例自检):`browser-package-cross-dependency-*` 规则族的放行边从一条扩为两条——既有 `react-wrapper → embed-runtime`(WP-51)+ 新增 `web-component → embed-runtime`、`web-component → vm-ui`;`→ web-component` / `→ react-wrapper` 方向仍全禁(web-component 是装配叶子)。`tooling/dependency-boundary-self-test.mjs` 同步扩展至 16 组边期望(新增红灯:vm-ui→web-component、embed-runtime→web-component;新增正控:web-component→embed-runtime / vm-ui / protocol 零违规;既有反例全数保留绿灯)。

**跨源引导取回的演示语义**:`/host-api/embed-tokens`(宿主页面签发代理)保持同源-only(WP-51 姿态不变);`/host-api/embed-bootstrap`(插件面取回端点)对 `PLUGIN_SITE_ORIGIN` 白名单回显精确 ACAO——这是 D-API-75 默认形态(插件跨源 POST 体取回)在 dev 替身上的必要对应物,生产部署由宿主后端按其插件来源清单配置。

## 三、主题 / 语言接线点接口(WP-53 直接消费)

1. **唯一接线点 = `EmbedAppearanceController`**(`src/plugin/appearance.ts`,经包入口导出):
   - `apply({ theme?, language? })`:ready.config 初始下发与 `theme_changed` / `language_changed` 运行时切换的**统一幂等入口**(元素内已接线,WP-53 无需改动消息消费路径);
   - 三值状态保持:`snapshot.theme` 恒为宿主下发的三值原样(`light` / `dark` / `auto`);`snapshot.resolvedTheme` 为解析后二值(`auto` = 跟随插件自身 `prefers-color-scheme`,matchMedia 注入,`matchMediaImpl` 为注入缝);
   - `snapshot.language`:BCP-47 字符串;内置默认 `zh-CN`(非法取值按冻结 `EmbedLanguageSchema` / `EmbedThemeSchema` 拒绝并保持原值);
   - `onChange(listener)`:状态变化订阅(元素据此外落 attribute)。
2. **元素级落地面(WP-53 的 CSS/i18n 锚)**:host 元素 `data-sm-theme`(二值 light/dark)+ `data-sm-language` + 内联 `color-scheme`;三值状态与语言经 `element.appearanceSnapshot` 可读。WP-53 的主题双套 CSS 变量在 `data-sm-theme` 锚上挂接,i18n 抽取面消费 `snapshot.language`(缺语言 → `zh-CN` 确定性降级已在本层)。
3. **未授予降级(§4.4)已在本层闭合**:theme/language 未授予时对应消息按 V-8 丢弃 + 计数,外观保持内置默认——WP-53 的「未授予禁用实现」与 WP-52 降级矩阵共用本测试锚(`test/pwn-memory-vm.test.ts` 能力降级矩阵组)。

## 四、插件侧协议实现定案(嵌入协议 §四 / §五的插件角色)

1. **hello 窗口语义(D-API-77 `helloMaxRetries` 的插件侧解释)**:窗口内总发送次数 = 1(首发)+ `helloMaxRetries`(重试预算,默认 3 → 至多 4 发),固定间隔 = `T_handshake / (helloMaxRetries + 1)`(默认 2500 ms);窗口到期未就绪 → 降级显示(§4.3),**不向宿主重试风暴**;每次发送 seq 严格递增。`retry()`(用户可见重试入口,§4.5)= 同会话重开窗口与预算、seq 不清零;已就绪 / 已释放为 no-op。
2. **降级态的迟到 ready**:超时降级后,通过全部校验(V-1'/V-2~V-8)的 ready 仍完成握手并撤除降级 UI(慢网韧性;迟到不是校验失败,不违 V-12)。决策登记理由:降级显示是 UI 状态而非会话终结,宿主侧超时路径(§4.5 宿主侧)才是会话不可用的权威面。
3. **入站校验序**(与 embed-runtime 宿主侧登记序同构):port 转移识别 → V-1'(source === window.parent,恒核)→ V-1(钉住后核 origin)→ V-2(结构化对象[WP-51 wire 形态]与字符串 JSON 双形态受理;字节上限 + JSON 对象)→ V-3(受理集 [1])→ V-4(strictObject)→ V-5(esid 全等)→ V-6(方向集)→ 分发(ready:V-7 → 防御性 V-8[granted ⊆ 本端声明集] → 钉住 origin → 幂等重放;控制消息:V-7 → V-8 → 高水位 → V-10 入站外圈 → 事件)。
4. **V-10 插件侧双闸**:入站控制消息外圈(默认 10/s,`TypeRateLimiter` 复用)+ 出站 height_changed 管道自限(默认 30/s)。`negotiateEmbedProtocolVersion` 在插件侧无自然消费点(宿主是 max-wins 的裁决方,插件侧 V-3 受理集校验即覆盖),故不复用——Q4 复用面以 esid 校验 / TypeRateLimiter / 计数键三项落地。
5. **本地计数键词汇**:协议违规与宿主侧同键(`VIOLATION_COUNTER_KEYS`,快照全键稳定补 0)+ 插件本地两键:`pwn-height-oversize`(内容高度超 `MAX_EMBED_HEIGHT_PX` 整条不发)、`pwn-height-rate-limit`(出站 V-10 命中)。元素 `violationCounters` getter 合并两源可读;一切失败丢弃 + 计数,零反馈(V-12)。
6. **port 路径(WP-51 wire 形态)**:`event.ports.length > 0` 即绑定为控制面 port(转移消息 data=null 零载荷零绑定值,V-13 前置形态);绑定后宿主控制面消息可经 port 到达(免 origin/source 校验,端点已绑定),插件出站消息改走 port;凭证信封 `{kind: "stackmaster:embed-credential", credential}` 触发 `pwn-embed-credential` 事件——元素只保留布尔面(`portCredentialReceived`,**凭证值零回显零解析**);默认路径 a(引导配置)为主,port 信封不携带题目上下文与 sessionApiOrigin,单凭它无法建会话。
7. **装配时序**:esid(fragment 一次性读取)→ hello 立即发出(握手不依赖 token)∥ 引导配置取回并行 → ready + 引导配置双就绪 → `SessionClient.createSession`(embedToken 随 create_session 命令体、embedSessionId = esid、challengeId/Version 来自引导配置;`credentials: "include"` 冻结契约)→ `connect()` → 挂载 `<sm-workspace>` 注入 client。create_session 失败 → 静态文案降级(零反射面:PublicError 细节不进 DOM,重试入口重建会话;token 单次消费语义由服务端裁决)。
8. **iframe 重载(§4.5)**:重载 = 新文档 = 新元素实例,全部状态从零(esid 重读、seq 自 1、外观回内置默认、无任何持久化写入);测试锚 `test/pwn-memory-vm.test.ts`「iframe 重载 = 从空状态重新握手」组。
9. **工作区终态引导**:`<sm-workspace>` 的 `new-session-request` 事件 → close_session(如未关)+ 以既有引导配置重建会话;iframe 形态下真正的新会话 = 宿主重载 iframe(§4.5 新 esid),归宿主 UI(WP-55 E2E 面)。

## 七、纪律自查(硬门槛对照)

- embed token:不进 URL query(POST 体取回)、不经 `targetOrigin: "*"` 的裸 postMessage 承载(出站信封仅 hello/height_changed;port 路径经转移后的绑定端点)、浏览器不解析(元素对凭证零回显,`portCredentialReceived` 仅布尔);
- fragment 只放 esid、读后零持久化(无任何 storage 写入面);
- 一切校验失败丢弃 + 本地计数,零反馈零中断(V-12;冒烟第六步 = 全链路计数清零);
- 断线呈现与重连 = vm-ui 既有能力(断线横幅 + sync-projection),本包只保证 iframe 形态贯通,零本地 VM 降级;
- 静态文案零反射面:降级文案为常量表,不回显任何响应内容(集成测试含 `bootstrap_not_found` / `challenge_invalid` 零回显断言)。
