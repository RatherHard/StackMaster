> 状态:实现期草稿(2026-09-11,WP-54 交付时成文)。**本文不是权威决策记录**:正式 D-API 增补、校验清单 M2 关闭、文档回填由 WP-56 统一收尾;本文供 WP-55(E2E 收口与门禁接线)消费接口面,并作为 WP-56 回填的事实来源。

## 一、加载器(题目描述客户端获取):API 与失败语义

**落点 = `packages/vm-ui/src/descriptor/challenge-descriptor.ts`**(供插件与 dev 壳共用;依赖边界:只依赖 `@stackmaster/protocol` 公开入口与自身——冻结标识符字符集 / `PUBLIC_ERROR_CODES` / `SESSION_ACTION_TYPES` 直接引用 protocol,零新契约)。不落 web-component 的理由:dev 壳(夹具形态之外的正式通道)与未来宿主面都要消费;vm-ui 已是两方的装配依赖(Q3 定案),且与 ed-types 本地结构类型先例同域。

- **输入**(`FetchChallengeDescriptorInput`):`sessionApiOrigin`(绝对 http(s) origin)+ `challengeId` + `challengeVersion`(来自引导配置或 dev 壳显式给定);注入缝:`fetchImpl` / `sha256Hex`(jsdom 无 `crypto.subtle`,测试注入 Node webcrypto;浏览器缺省走 `globalThis.crypto.subtle`)/ `guards`。
- **获取序**(每步确定性拒绝,折叠为布尔结果 + 原因码,**不抛错**):
  1. 定位参数闸(origin 形态 / challengeId 冻结字符集 / version 客户端路径卫生,禁穿越)→ `invalid-input`,零请求;
  2. `GET {origin}/descriptors/{challengeId}/{version}`(无凭证,D-API-76);**网络失败至多一次显式重试**(不重试风暴)→ 仍失败 `network`;
  3. 非 200:404 → `not-found`(与未登记 / 参数违规服务端同形,客户端不区分);其余 → `http-status`;
  4. **尺寸护栏第一闸**:Content-Length 显式超限(不读体)或响应体字节超限 → `over-limit`;
  5. **完整性闸**:`ETag`(= 登记摘要,剥 `W/` 前缀与引号)缺失或不可读 → `etag-missing`;WebCrypto SHA-256 复算与 ETag 比对不符 → `digest-mismatch`(篡改红灯);
  6. JSON 解析失败 → `invalid-json`;**尺寸护栏第二闸**(嵌套深度 / 数组长度 / 字符串长度,深度优先结构巡检,session-api request-guards 同则的客户端镜像)→ `over-limit`;
  7. **轻量结构校验**(`parseDescriptorView`,对齐锚 = challenge-schema 公开 Schema 16 字段:顶层 13 必需 + 3 可选、未知顶层字段拒绝、枚举封闭集[revealPolicy / region kind / archBits / errorCode 16 值 / allowedActions / semanticHighlights]、`after_n_failures ⇒ failureThreshold` 必填、minItems 面与 Schema 同值)→ 坏形态 `bad-shape`;摘要原语不可用 → `digest-unavailable`;
  8. 产出强类型 `ChallengeDescriptorView`(`hintLadder` / `publicErrorMapping` 直接复用 ed-types 结构类型 = ED 组件注入面零转换;**`debugMode` / `aslrEnabled` 归一化为布尔**:opt-out 缺省 true / 缺省 false,消费方不再各自解释缺席)。
- **失败呈现纪律**(FE-ED 缺席形态):全部失败折叠进 `descriptorStatus = "absent"` → 工作区「题目描述未加载」静态明示面板;原因码属诊断面(测试 / 诊断读出),**不进玩家可见 DOM**;不中断会话、零降级。

## 二、客户端护栏数值(与服务端 §8.3 护栏成对的双闸;登记)

`DESCRIPTOR_CLIENT_GUARDS`:`maxBodyBytes = 262144`(= 服务端 `SESSION_API_MAX_DESCRIPTOR_BYTES` 默认值,D-API-76 配置表)、`maxJsonDepth = 16` / `maxArrayLength = 256` / `maxStringLength = 4096`(= D-API-31 请求护栏与 D-API-76 结构巡检同值)。测试可注入收紧,生产缺省即此表。

## 三、装配时序(web-component 插件侧;不阻塞 workspace 就绪)

`esid 读取 → hello 发出(握手)∥ 引导配置取回 → 引导配置就绪即刻**并行发起描述包获取**(与 create_session 并行;challengeId / version / origin 来自引导配置,`descriptor-origin` attribute 可覆盖 origin)→ create_session 成功即挂载 workspace(描述包**晚到即注入**:`hintLadder` / `publicErrorMapping` / 静态面 / `debugModeAvailable` 到达即补写属性,`descriptorStatus` loading → loaded | absent);失败 → 缺席明示终态,无重试入口(网络重试在加载器内;重载 iframe 重新走管线,§4.5)。选此形态的理由:workspace 就绪的等待面只剩握手 + create_session(既有路径),描述包网络慢不拖累首屏;教学面晚 1~2 RTT 到达属可接受的渐进增强。

**ETag 跨源可读性(端点缺口发现,只登记不改动)**:加载器把「ETag 不可读」作为确定性失败(`etag-missing`)。session-api CORS 装配(D-API-16)未配置 `Access-Control-Expose-Headers`,故**跨源**插件 iframe(如 demo 拓扑 5174 → 13000)读不到 `ETag`,描述包将确定性缺席明示(会话不受影响);同源消费(vite 反代形态)不受影响。生产 / demo 若需插件 iframe 跨源直取,须在 session-api CORS 装配增补 `exposeHeaders: ["ETag"]`(一行配置,归 WP-55/56 统筹;本 WP 按边界纪律不改 session-api 源码)。

## 十、本机实跑记录与环境处置(2026-09-11;WP-55 复跑须知)

**结果:全绿**——`descriptor.spec.ts` 3 用例 PASS + `plugin-dev` E2E 全套件 **9/9 PASS**(既有 6 用例零回退),compose 全拓扑(外部托管形态,`readyz` 探测跳过拉起)。

**实跑期发现并就地处置的三件环境事项**(均非本 WP 交付物缺陷,复跑者注意):

1. **陈旧 dev server 占用 5173**:一次旧形态 vite dev server(PID 30096,不带 e2e 重定向中间件)存活导致 playwright `reuseExistingServer` 复用 → `import("/index.js?import")` 500 → 全壳引导失败。处置 = 结束陈旧进程后复跑。复跑前自查:`curl -s -o /dev/null -w "%{http_code}" "http://localhost:5173/index.js?import"` 应非 500(新起的 e2e webServer 自带 302 重定向)。
2. **session-api 容器镜像早于 WP-50 提交**:容器内 `dist/` 无 descriptor 路由 → `GET /descriptors/*` 恒 404(应用级 404 同形,与"未登记"不可区分)。处置 = `docker compose -f compose/deps.yaml -f compose/app.yaml up -d --build session-api`(本地 `pnpm build` 先行)。
3. **正式下发语料 × 私有包的程序模式配对(G5/D6 实战确认)**:公开包携带 `vmProfile.encodingTable`(字节权威执行模式声明)⇒ 私有包必须字节模式(`compiledIr` 省略 + `entrypointAddressHex`,XS-PROG-MODE);且代码区自入口线性取指的每一字节都须落编码表(XS-ENC-PROBE 探测译码)——语料以 `0x00 → mov RAX,RAX`(无副作用填充,4096 条恰达 `MAX_IR_INSTRUCTIONS` 上界)承载填充 token 化。`seed-formal-challenge.mjs` 的私有包按此形态构造,已验证 `create_session` 201。
