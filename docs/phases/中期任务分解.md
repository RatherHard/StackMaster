### 1.2 边界裁决(执行期不得越界;越界即按 WP-1 §1.3 另评)

1. **冻结契约零改动为默认基线**:12 动作、16 错误码、嵌入协议 v1(V-1~V-13、`EMBED_THEMES = ["light","dark","auto"]` 三值)、调试通道协议(ADR-DC1)、投影七字段、11 值裁决结果类型、审计 kind 十值封闭集。终端主题与固定窗口工作区**不引入**任何协议面变更(D-MP-2 口径:terminal 以 `data-sm-theme` 扩展值承载,宿主侧 appearance 映射为 dark + 变量覆盖)。
2. **浏览器零权威**:本计划全部前端改动只消费公开投影与 UI 状态;固定窗口工作区、终端主题、布局交互均为**呈现层**改造,不得引入本地 VM、本地判题、本地计分(D3 投影窗口边界与 D5「非可执行 IR」边界不动)。
3. **视觉改造零新增运行时依赖**:纯 CSS token + 既有 Lit 组件;主 chunk(≈1.2MB)拆分列为可选增量,不绑定义务;超过 1.3MB 触发拆分(可选增量转义务)。
4. **布局持久化不在本计划义务内**(中期计划 §2.2 第 8 条):布局状态随会话内存保持;「重置布局」是逃生门;IndexedDB 持久化与布局持久化一并评估、不入本计划。
5. **T2 / T3 面不引入**:多实例编排器、Redis Streams、WSS 网关分离、二进制投影编码、K8s、堆 / ROP / 防护机制深化 / 更完整指令集 / 后端 WASM / 真实 ELF 维持不实现(中期计划 §三.3、计划书 5.1 路线纪律);D-J8(真实实例 ASLR)维持「不启用」登记不变。
6. **admin 面按 D-MP-5 二选一**:只读最小面落地,或移出本中期并登记;**二者必居其一**,`README.md` / `CLAUDE.md` 的 `apps/admin/` 目录声明必须与磁盘一致(当前磁盘无 `apps/admin/`,属「声明了但没有」)。
7. **文档回填是交付物而非附加品**:WP-77 与 WP-82 的文档项与代码项同批验收(E-4、中期计划 §八)。

### 1.3 硬门槛(实现期逐条自查)

> **安全红线逐条维持**(计划书十六章):黑客氛围只存在于视觉与文案层,不新增任何攻击能力;不绕过 D3 投影窗口边界、不绕过 D5「非可执行 IR」边界;浏览器任何位置(主线程 / Worker / IndexedDB)只保存公开投影与 UI 状态。
>
> **可读性优先于氛围**:终端主题色值以 axe 真机 color-contrast 门禁为唯一口径(WP-55 先例);字号下限 13px;light 主题保留可切换;学习可读性判断高于视觉效果。
>
> **无障碍与动效纪律**:动画只用 transform / opacity;`prefers-reduced-motion` 必须被尊重;屏幕阅读器信息不得只存在于视觉效果中(扫描线 / 光标闪烁为纯装饰,`aria-hidden`);字节视图维持语义化 DOM + 虚拟列表,控制流关系用 SVG / DOM 而非 Canvas。
>
> **门禁不降级**:typecheck / lint / lint:deps / 覆盖率 ≥80% / fixture manifest / `smoke:contract` / `scan:public` / Rust 双 profile / 引擎确定性 lint 全部必过;新 UI 逻辑 TDD、行为命名;错误反馈断言覆盖「可解释性」而非仅状态码。
>
> **契约先行**:凡涉及嵌入协议值域、公开描述包字段、宿主成绩接口、canary 可见性语义的改动,一律先改分类论证 → 改契约包与 golden fixture → 评审 → 再改实现;TS 与 Rust 双语言必须同时接受或拒绝同一语料。

### 1.4 已冻结、本阶段直接消费的能力(不得绕开重造)

`data-sm-theme` 锚 + CSS 自定义属性穿透 shadow DOM 的主题机制(WP-53);`LocaleController` / i18n 双目录同键集机制(WP-53,`test/i18n/i18n.test.ts` 机检);`WorkspaceLayoutModel` 的列式平铺不变量与 `moveTab` 落点语义(WP-F5);`scrollToColumn` / `ensureTabVisible` 滚动基建;自研行级虚拟列表 `sm-window-list`(WP-F7 裁决);`DebugDataSource` / `DebugChannelClient` 与调试通道协议(ADR-DC1);`PayloadStep` 编译产物与 `PayloadStepExecutor`;`VerdictPoller` 与裁决呈现横幅(D-API-83 / 84);`ChallengeDescriptorView` 归一化视图(WP-54);`crossAnnotateRegisters` / `sm-register-annotation` 交叉标注面;`sm-jump-chain` 跳转链形态;契约单一来源 `packages/protocol`(Zod → JSON Schema)与手写落盘的 `challenge-schema` 双包 Schema(防漂移靠测试);`tooling/contract-smoke` 的夹具发现与规范化摘要机制;`PgAuditSink` / RLS 租户政策 / 最小授权角色(阶段六)。

2. **deps-only 拓扑无角色引导(同根因的第二条路径)**:IT 门禁的 `globalSetup`(`test/persistence/compose-lifecycle.ts`)只 `up -d --wait` `deps.yaml`,而 `deps.yaml` 自始只有 postgres / redis / minio(**零 init 服务**)⇒ 全新 deps 卷上「完整门禁形态」必然红(实测 9 files / 4 tests 失败,根因 `error: role "session_app" does not exist`,code 42704 / `acl.c` `get_role_oid`);长期「看似绿」的原因是收尾是 `down`(**不带 `-v`**)、deps 卷跨轮次留存着早年角色。修复 = 角色引导**下沉为 deps 面单一来源**(`db-roles-init` 定义移入 `deps.yaml`,app.yaml 只引用),并删除两个治理脚本里的 `CREATE ROLE` 兜底守卫(**授权面语义零变化**)⇒ 角色缺席即显式红灯;连带修正:① 该服务形态为「引导 + 健康锚」(deps-only 形态下它无下游依赖方,compose `up --wait` 对「无依赖方的一次性容器」判失败 —— 原文 `container session-api-deps-db-roles-init-1 exited (0)` → exit 1;健康探针 = 两角色在场且非 `rolsuper` / 非 `rolbypassrls`),`session-api` 用更强的 `service_healthy` 前置;② host 形态两条红灯用例的降级判据由「角色能否连接」改为「授权面是否就位」(查 `has_table_privilege`,断言体零变化)—— 附带事实:此前 host 形态「35/35 全跑」其实是**卷状态依赖**,修后行为确定。
3. **MinIO 建桶 check-then-act 竞态(独立预存缺陷,已修复)**:`MinioChallengeBundleStore.ensureBuckets()` 在 `bucketExists` 为 false 后直接 `makeBucket`,不区分「桶已被他人刚创建」这一正常并发结果 ⇒ 全新卷上并行引导时败者抛 `S3Error: … you already own it`,随机打红 1 个集成文件(`minio` / `descriptor-publish` 之间轮换)。受控复现 = 全新卷 8 路并发 `OK | ERR×7`,**3/3 轮命中**(桶已存在时 8/8 OK ⇒ 窗口 = 桶缺失期);修复角色引导缺陷后暴露面变大。**修复** = `makeBucket` 拒绝分支显式容忍 `BucketAlreadyOwnedByYou` / `BucketAlreadyExists`(引导目标已达成、幂等成立),其余错误仍 fail-closed 且由**裸 `Error` 直穿**改为转成契约错误类型 `PersistenceError("store_unavailable", …)`。**证据** = 新增单元层红灯(内存替身 `MinioLike`,零容器)`test/persistence/minio-bucket-bootstrap.test.ts`:实现前 **3 failed | 2 passed**(两类竞态 + fail-closed 类型),修复后 **5 passed**;真机全新 deps 卷复跑覆盖率套件时**该竞态未再出现**(唯一失败为既有的 debug 通道负载抖动,隔离复跑 2/2 绿)。
