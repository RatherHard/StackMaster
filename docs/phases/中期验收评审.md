1. **WebKit 跨源 WS 认证面缺陷(= E-3 唯一剩余阻塞)** · **仍开放** · 触发条件 = 在**独立来源 iframe** 内、向**跨源** API 发起**认证 WSS** 升级(现拓扑必现:矩阵稳定 `29 passed / 12 failed`,12 格逐条为 webkit 连接面)· 归属 = **须先定案修法方向**(① 短时一次性 ticket 走 query;② `Sec-WebSocket-Protocol` 携带 token;③ 先 fetch 换 ticket 再升级),且因涉及**冻结凭证语义**(`authenticateSessionCredential` / Cookie `Path=/sessions`)与 golden fixture,**必须走契约更新 + 安全审查** · **两个未定分项**:WebKit 该策略的具体分支(ITP / SameSite / WS 握手专属省略)、HTTP 面同凭证在 webkit 是否可用(决定方案 ③ 是否可行) · **已逐项核对 WP-78~83:无实现 WP 覆盖认证 / 传输面** ⇒ 本清单承接,不虚构承接面。
   **机制已读盘取证为 file:line 锚点(2026-09-17 M3 收口期复核,零代码改动)**:升级认证走凭证 preHandler 的 Cookie 呈递 —— `apps/session-api/src/wss/wss-plugin.ts:104-116`;通道 URL 由公开 API `baseUrl` 派生 —— `packages/vm-ui/src/client/transport.ts:145`(`WSS_CHANNEL_PATH = "/sessions/channel"`)+ `:148` 起的 `resolveWebSocketUrl`。二者合起来即「插件页 `:5174` 的独立来源 iframe → 跨源 API `:13000` 的认证 WSS 升级,握手需带 API 源 Cookie」;WebKit 第三方 Cookie 策略使握手不带凭证 ⇒ preHandler 判无凭证返回 **401**(与 run 31 起服务端日志取证一致:六次 `GET /sessions/channel` 全 401、`responseTime ≈ 0.3ms`)。
