# 阶段三任务分解:实现投影层与权威 API

本文件是计划书第十二章"阶段三"的执行层拆解,与计划书冲突时以计划书为准。上游依据还包括:阶段二任务分解 §三(范围边界裁决)与 §六、阶段二验收评审 §六(移交项)、`docs/develop/会话编排语义规约.md`(D-W8-9 / D-W8-11 移交面)、`packages/protocol/docs/会话动作协议语义.md`(§一边界声明、§5.1、§5.2)、`docs/contracts/嵌入协议.md`(§六 token 签发流程)、`docs/develop/秘密零驻留CI检查项映射.md`(🔜 项接线)。

## 一、阶段定位

**目标**(计划书 §十二阶段三原文):完成 ProjectionPolicy、脱敏器、`ProjectionDelta`、认证 WebSocket 通道、断线同步、服务端 COW 快照和规范化动作日志。

**边界裁决**(沿袭阶段二任务分解 §三,已随阶段二验收评审确认):ProjectionPolicy / 脱敏器 / `ProjectionDelta` 的**生成面**已在阶段二 WP-7 交付(执行域内,ADR-7);COW 快照与规范化动作日志的**引擎面**已在 WP-6 交付。本阶段交付其**网络承载面与持久化面**:认证 WSS 通道、断线同步下发、快照落库与加密静止、动作日志落库,以及承载它们的权威 API(apps/session-api,信任域 2)。

**产出物性质**:行为实现——Fastify 会话编排器、认证与凭证链路、持久化适配层、Compose 部署面、测试与证据;**加一组契约冻结**(会话级命令 Schema、WSS 传输信封、会话凭证 claims——唯一新增契约面,走 WP-1 §1.3 契约变更流程)。动作 / 投影 / 错误契约**零新增字段**,只做消费;`vm-engine` 零预期改动(引擎进程协议 v1 不变,实现期若发现协议缺陷走引擎进程协议 D-F 增补流程)。

**主要目标(计划书原文精神)**:投影只在执行域内生成——编排器零投影合成、零增量合流;通道上只有公开投影;身份只来自认证上下文。

**硬门槛(实现期逐条自查)**:

> 通道上只有公开投影:编排器、网络通道任何位置不出现 `VmState`、私有包内容、seed、完整事件日志;跨域载荷录制机检证明(WP-7)。
>
> 快照加密静止(D-W8-11):快照为 worker 所有 SERVER_ONLY blob,编排器只存取、不解析、不派生,落盘必须加密。
>
> 一切校验失败响应面 = 冻结 `PublicError` 形态,零校验器细节透出(会话动作协议 §七 #8);一切拒绝路径确定性(I-4)。

**已冻结、本阶段直接消费的契约**(不得绕开重造):

- `ActionRequest`(12 动作)/ `ActionResponse` / 16 错误码 + 能力矩阵 / 11 结果类型 / `VerdictResult`(`SESSION_ACTION_PROTOCOL_VERSION = 1`);
- `embed-message` 与 `EmbedTokenClaims` 七字段冻结面(嵌入协议 §二;签发 / 消费实现归本阶段);
- 会话级命令在生命周期中的位置、前置条件与失败语义(协议 §5.1)——本阶段冻结其请求 / 响应 Schema;
- 规范化序列化 `stackmaster-canonical-json/1`(幂等负载比较)、快照信封 `stackmaster-session-snapshot/1`、引擎进程协议 v1(D-F1~D-F10);
- 版本策略(四类版本、生产锁定语义)与 ADR-2 / ADR-3 / ADR-4 / ADR-5 / ADR-7;
- 阶段二交付的 `packages/session-core`(生命周期状态机、串行队列、幂等缓存、账本、崩溃替换恢复)——本阶段在其上装配网络与持久化,不重写。

**与计划书阶段六的边界裁决**:计划书 §十二阶段六含"审计日志、租户隔离和限流"。本阶段交付**会话路径上的执行机制**(限流执行点、租户作用域列与查询层校验、审计最小写入面),阶段六完成**全面租户隔离、行级策略、审计归档与 verifier 侧裁决**;该裁决与阶段二任务分解 §三"请求限流 → 阶段三"一致。

## 六、决策点与风险

| 决策点 / 风险 | 说明 | 应对 |
|---|---|---|
| WSS 信封与版本协商形态 | 消息帧字段集、协商结果承载方式(协议 §5.2"传输层信封携带会话级版本协商结果") | WP-0 决策记录 D-API-*;先冻结再实现;fixture 锁定 |
| 动作通道形态 | WSS-only vs REST 镜像 12 动作端点 | 推荐 WSS-only(5.3 拓扑:WSS 承载动作与增量;REST 面最小化);决策记 D-API-*;变更走 WP-0 契约流程 |
| 会话凭证载体 | JWT vs PASETO vs 自有格式;密钥轮换 | 沿 embed token 纪律(claims 冻结 + 载体为实现决策);密钥仅域 2;决策记 D-API-* |
| token 消费失败响应面 | 三方比对失败是否区分原因(过期 / 已消费 / 绑定不符) | 统一失败形态防枚举;细节仅入受控日志与审计;决策记 D-API-* |
| 断线保持窗口与回收 | 保持多久、回收什么(worker / 会话行 / route 键) | 教学场景默认值 + 配置化;回收动作与会话表 / route 键生命周期一致;决策记 D-API-* |
| 多连接与背压 | 同会话第二连接、慢消费者 | 服务端串行不变性是底线;有界缓冲 + 断开走恢复路径;决策记 D-API-* |
| 编排器重启恢复粒度 | 恢复到最近快照丢尾(客户端 sync-projection 对齐)vs 动作日志重放追尾 | 推荐前者(实现小、语义与崩溃替换恢复同构);日志重放追尾列为演进项;决策记 D-API-* |
| 自动快照策略 | 周期间隔(6.3"周期性 COW 快照")与存储预算的平衡 | 每 N revision 触发 + 显式 checkpoint 双轨;间隔配置化;决策记 D-API-* |
| 快照加密层级 | 应用层字段加密 vs 存储级加密;密钥轮换 | MVP 取实现最简且满足 D-W8-11 的层级;密钥环境变量 + 密钥服务,启动校验;决策记 D-API-* |
| action_log append-only 强制层 | 应用纪律 vs 数据库权限 / 触发器 | 决策记 D-API-*;两者取其一必须有红灯反例(更新 / 删除被拒) |
| Redis 不可用降级分级 | 幂等窗口(可降级)vs token / route(fail-closed) | 分级语义成文;降级不破坏协议正确性(§4.3 窗口是效率设施);决策记 D-API-* |
| 限流默认值与确定性 | 教学规模默认值;超限形态 | 默认值保守 + 配置化;超限 = 确定性拒绝 + 冻结错误形态;阶段六全面租户隔离时复核 |
| 指标标签基数 | 租户 / 会话粒度标签的 Prometheus 基数爆炸 | 标签纪律决策(会话 ID 不入标签,聚合维度受限);决策记 D-API-* |
| Compose 在 Windows dev 的 worker 构建产物路径 | 本地开发与 CI(linux)产物差异 | 沿用 ensureWorkerBinary 的产物解析;Compose 仅承诺 linux 环境全功能;本地 Windows 降级路径记录在开发文档 |
| k6 基线的位置 | 质量门禁 9 要求 benchmark 任务,但阈值未定 | 首采归档不设阈值(10.3 / 13.6);T2 触发判据的数据源自此建立 |
