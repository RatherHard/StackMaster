# 阶段二任务分解:实现后端 VM Core 与会话编排

本文件是计划书第十二章"阶段二"的执行层拆解,与计划书冲突时以计划书为准。上游依据还包括:`docs/develop/Vm 模块设计冲突与整改方案.md`(P4/P5 批次与 D1–D7 裁决)、阶段一各冻结契约(contracts/ 与包内语义文档)。

## 一、阶段定位

**目标**:交付可运行的权威执行域——Rust VM 引擎(vm-core / vm-runtime / projection / vm-worker)与最小会话编排核心,使"私有题目包 + 动作 → 状态转换 → 脱敏投影"的端到端链路在进程边界内闭环;阶段三的权威 API、阶段六的 verifier 复用全部建立在这一层上。

**产出物性质**:行为实现——引擎 crate、worker 二进制、TS 编排核心、测试与证据;契约本身不再新增字段,只做**消费**(引擎进程协议版本登记是唯一例外,见 WP-1)。

**主要目标(计划书原文)**:先以**正确性和确定性**为主要目标——性能与容量在 MVP 验收前不是优化对象。

**硬门槛(沿袭阶段一,实现期逐条自查)**:

> 秘密不出执行域:`VmState`、私有题目包、隐藏测试和 seed 只存在于 VM Worker 进程内(ADR-7);白名单 + 脱敏在数据离开执行域之前完成。
>
> 引擎不实现到一套注定变更的机器模型上:P1–P3/P5 契约变更已完成冻结(整改方案 §五),阶段二严格按已定稿契约实现(G 系列 + D1–D7 裁决)。

**阶段一已冻结、本阶段直接消费的契约**(不得绕开重造):

- `VmState` 8 字段集合与 `PublicStateProjection` / `ProjectionPolicy` 字段面(WP-1 数据分类清单);
- `ActionRequest`(12 动作)/ `ActionResponse` / 11 结果类型 / 16 错误码 + 能力矩阵 / `VerdictResult`(protocol 包,JSON Schema 为权威);
- 双包 Schema v2:双程序形态恰一(IR / 字节模式)、`customInstructions` / `interfaces` 声明面、`seedPolicy` 互斥、`judgingConfig`;
- 规范化序列化 `stackmaster-canonical-json/1`(幂等负载比较、状态哈希、摘要纪律)与 golden fixture 摘要清单;
- ADR-8 决策(维持 Rust)与版本策略(引擎自报版本、生产锁定语义)。

- [ ] TS 会话编排核心(进程内服务,HTTP / WSS 网络面归阶段三):9.1 生命周期状态机(create-session → action / step / run-to-event / pause → undo / checkout / reset → create-checkpoint → sync-projection → submit → close-session);单会话串行队列;worker 进程管理(按会话 spawn、池化、僵尸回收);

- [ ] revision 与投影会话账本:revision 单调、`projectionDelta.revision === 信封 revision` 的生成侧保证、`sync-projection` 重同步语义;
- [ ] 提交面最小实现:`submit` 引用规范化动作日志并产出内部裁决引用(verifier 独立部署与最终裁决归阶段六,本阶段只保证日志完整可重放)。

**交付物**:`vm-worker` 二进制 + TS 编排核心包(apps/session-api 领域层或独立包,网络路由除外)+ 集成测试(进程级:TS 编排器 spawn 真实 worker 全链路)。

**完成标准**:Compose 外的最小集成闭环可演示:创建会话 → 动作 → 投影增量 → undo → checkpoint → checkout → reset → submit(内部引用动作日志);崩溃替换恢复与幂等重放语义有集成测试;编排器进程内不出现 `VmState` / 私有包 / seed(秘密零驻留断言)。

## 六、决策点与风险

| 决策点 / 风险 | 说明 | 应对 |
|---|---|---|
| ADR-8 tripwire 中期复核 | 阶段二中期评审(引擎 crate 首个可运行里程碑)是产能 tripwire 检查点 | WP-4 完成时显式复核;触发即按回退预案评估 TS vm-core,契约与 fixture 不变 |
| 进程帧协议形态 | stdio 行分隔 JSON vs 长度前缀帧;单帧上限与半包语义 | WP-1 决策记录;样例走 golden fixture;先冻结再实现 |
| 超时的实现层 | 引擎 crate 禁时钟,`timeoutMsPerAction` / wall-clock 只能在 worker / 编排器层实现 | worker 进程层看门狗 + 编排器外层兜底;语义文档写明两层职责 |
| seed 生成归属 | `server_random_per_session` 的 CSPRNG 在编排器生成传入 worker(推荐)vs worker 内生成 | 编排器生成、按会话锁定并记入回放元数据(策略 + 派生路径,不含 seed 值);worker 只消费;决策记入 WP-6 |
| COW 分页粒度与内存预算 | 页粒度过细增加元数据、过粗放大写时复制成本 | 以教学规模内存(每会话个位数 MB)为准做基线测试;T2 前不做压缩 / 去重优化 |
| 双模式取指一致性 | IR 与字节模式双前端的执行语义漂移 | 统一取指译码层共享执行入口(WP-4);跨模式一致性测试进 WP-9 必过项 |
| 谓词求值 DoS | 恶意题目包的谓词在编译期合法但运行期组合爆炸 | `maxPredicateEvalSteps` 运行时硬预算(WP-5)+ fuzz(WP-9) |
| worker 池与僵尸进程 | 强制终止后的残留进程 / 句柄泄漏;池复用造成跨任务残留 | 9.1 强制终止 + 状态清理 + 不复用;集成测试含反复 kill 场景 |
| Rust 产能节奏 | 引擎学习曲线影响里程碑(ADR-8 已复核维持 Rust) | 语言面锁死为纯同步状态机子集;AI 辅助产能 + clippy / miri 审查兜底;tripwire 兜底 |
| 编排器与引擎的版本错配 | 编排器升级先于 worker 部署导致协议不兼容 | 引擎进程协议独立版本号 + worker 自报版本;窗口期双受理语义沿用 5.6 |
