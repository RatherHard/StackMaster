# 阶段五任务分解:实现 iframe 插件与嵌入安全

本文件是计划书第十二章"阶段五"的执行层拆解,与计划书冲突时以计划书为准。上游依据还包括:`docs/contracts/嵌入协议.md`(阶段一 WP-5 v1:消息契约、handshake 五路径与 V-1~V-13 校验规则已冻结,实现归本阶段)、阶段三任务分解 §三(移交表:embed-runtime SDK、postMessage 协议实现、token 交付通道、自适应高度/主题/语言、公开描述包 CDN 发布链路与签名 URL)、阶段三 WP-7(13.3 iframe 面条目登记 D-API-66)、阶段四任务分解 §一裁决 3 与 §三(嵌入面整体归本阶段)、阶段四验收评审 §六(移交清单 1~4)、`docs/develop/前端需求现状校验与不匹配清单.md`(M2)、`docs/develop/权威API语义规约.md`(D-API-1~74 既有决策面)、`docs/contracts/数据分类与秘密零驻留清单.md`。

## 一、阶段定位

**目标**(计划书 §十二阶段五原文):完成独立构建产物、postMessage 宿主协议、embed token、自适应高度、主题和语言、静态公开描述包加载、断线重连和错误恢复。

**边界裁决**:

1. **契约零新增为基线**:嵌入协议 v1(`EmbedMessage` 六字段五类型、`EmbedTokenClaims` 七字段、handshake 五路径、V-1~V-13)与公开描述包 Schema(阶段四 WP-43 演进后 16 字段)均为冻结面,本阶段只实现不修改。唯一可能的新契约面 = 公开描述包**发布清单**(§8.3"发布清单应有内容哈希或签名")——是否立为新契约在 WP-50 走 WP-1 §1.3 流程定案,不定案不实现。
2. **主题与语言是嵌入协议冻结面的实现义务,不是视觉美化工程**(UI 美化不排期,2026-09-11 定案):插件须具备 light/dark/auto 三值主题机制与 BCP-47 语言切换机制(含 `prefers-color-scheme` 跟随与未授予降级);视觉风格零重设计,主题层只做功能对比度(以 axe 真机门禁为唯一口径)。
3. **与阶段六边界**:verifier 独立判题、隐藏测试裁决与正式裁决结果展示、审计归档、全面租户隔离与行级策略,归阶段六;submit 响应面维持 `{submissionId, revision}` 冻结形态零改动。
4. **CDN 为生产部署面关注,不在本阶段**:dev/MVP 拓扑以 MinIO `public-descriptors` 桶(阶段三 WP-3 落点)+ 签名 URL 或 session-api 端点(WP-50 定案)承接;CDN 厂商挂接与生产缓存策略为部署期后续项。
5. **产出物性质**:`packages/web-component` 正式实现(插件 Shell,占位退场)、`packages/embed-runtime`(宿主侧 SDK,新包)、`packages/react-wrapper`(薄封装,新包)、M2 描述包下发通道服务端面、宿主模拟页与 E2E 扩展、测试与证据。**既有冻结面(WSS 通道、12 动作、16 错误码、会话凭证链路、调试通道协议)零改动**;vm-ui 零破坏性改动(主题/语言/描述包消费为增量接线)。

**硬门槛(实现期逐条自查)**:

> embed token 不进 URL query、不经 `targetOrigin: "*"` 的裸 postMessage 承载(V-13);iframe URL fragment 只放 `embedSessionId`(无权限语义、一次性、重载即轮换),不进浏览器历史之外的任何持久化。
>
> 浏览器对 token 保持不透明:不解析、不校验、不在会话期外留存;`EmbedTokenClaims` 解析器只在 `@stackmaster/protocol/server-only` 子路径(既有导出纪律,dependency-cruiser 兜底)。
>
> 静态公开描述包加载:只接受已登记题目 ID 派生的获取路径(禁任意 URL,SSRF 纪律,§8.3),哈希/签名校验 + 响应体/嵌套深度/数组/字符串长度护栏;描述包数据形态以公开 Schema 为唯一对齐锚。
>
> postMessage 通道零权威语义(V-9:不承载结果/分数/通过状态,宿主不得经本协议修改插件内部 DOM 或 VM 状态);一切校验失败 = 丢弃 + 本地计数,零反馈、零中断(V-12);断线只展示最近一次公开投影、重连走 `sync-projection`,零本地 VM 降级。

**已冻结、本阶段直接消费的契约**(不得绕开重造):`EmbedMessage` 信封与五消息类型 / `EMBED_PROTOCOL_VERSION = 1` / 方向集常量 / `EmbedTokenClaims` 七字段 / V-1~V-13 逐条规则与失败处理 / handshake 五路径(嵌入协议 §4.1~4.5)/ 能力枚举(`theme` / `language` / `auto_resize`)与主题三值;embed token 签发端点与三方比对消费(阶段三 WP-2 已实现,D-API-10~15);`SessionCredentialClaims`(阶段三 WP-0);公开描述包 Schema 16 字段(含 `debugMode` / ASLR 语义);公开投影七字段与会话五命令;限流 429 冻结形态;`public-descriptors` 对象存储落点。

**工作包编号约定**:WP-50~56(取"阶段五"义,沿阶段四 WP-40 先例;与阶段一~四工作包编号无继承关系)。
