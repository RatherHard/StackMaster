## 一、阶段定位

**目标**(计划书 §十二阶段六原文):完成 verifier 重放规范化动作日志、隐藏测试裁决、审计日志、租户隔离和限流。在前述闭环稳定后,再评估堆、ROP、防护机制、信息泄露、更完整指令集、后端 WASM 或真实 ELF 实验模式。是否扩展以及优先级由实际教学数据、性能基准和安全评审共同决定。

**边界裁决**:

1. **T0 收口与 T1 进入的次序**:MVP 验收(11.1 清单、13.6)在阶段六收口——11.1 中"独立 verifier 与审计日志"正是本阶段交付面,"6—10 道渐进式题目"纳入本阶段承接(阶段二 / 三移交口径"题目内容批量制作(MVP 期)"的落点);容器级 Worker 隔离的**交付面**(执行形态、配置开关、compose 拓扑)在本阶段交付,**缺省启用形态**仍为进程池(dev / CI 拓扑零回退),容器池切换以 MVP 验收通过为前置并按 ADR-3"赛事弹性与租户预算"触发(5.1:T1 进入条件 = MVP 上线试用);
2. **契约面基线**:submit 响应面 `{submissionId, revision}` 冻结形态零改动(阶段五边界裁决 3 延续);12 动作、16 错误码、嵌入协议 v1、调试通道协议、会话 WSS 通道零改动。本阶段候选新契约面恰两处,均"不定案不实现"(WP-1 §1.3 流程):(a) **裁决呈现通道**(浏览器获取正式裁决的查询 / 帧面,WP-60 定案);(b) **引擎进程协议重放命令面**(仅当 Q1 定案选择进程协议路线时启用;否则引擎进程协议"verifier 进程内复用、不经本协议"登记维持,零改动);
3. **v1 seed 无应用面的裁决重放语义**:真实实例 v1 固定基址、`SeedDeriver` 无引擎侧应用面(D-J7 / D-J8),动作日志重放不摄入 seed 即可逐字节复现——verifier 对 seed 保持零驻留(不取快照、不持有快照密钥),`replay_mismatch` 语义**不**扩展派生路径复核;D-J8(真实实例 ASLR)触发时裁决面随行演进(判题语义规约 §6.1 已登记),本阶段只做产品决策登记(WP-68);
4. **与 T2 边界**:多实例编排器、Redis Streams、WSS 网关分离、投影二进制编码、K8s 不引入(5.1 路线纪律);裁决队列形态受同一纪律约束(以 PG 承载,禁 Redis Streams);Redis 键域(幂等 / route / rate)的 T1 演进面只复核登记、不实现(D-API-24 / 36 / 49 / 50);
5. **与 T3 边界**:堆、ROP、防护机制、信息泄露、更完整指令集、后端 WASM、真实 ELF 实验模式**只评估不实现**(WP-68 评估报告成文;是否扩展与优先级由教学数据、性能基准、安全评审共同决定,计划书阶段六原文);
6. **admin 管理后台不在本阶段**:5.5 `apps/admin` 为预留位;管理后台独立凭证与部署归后续,裁决运营面本阶段以受控查询与审计承接,不建后台;
7. **产出物性质**:`apps/verifier` 新服务(信任域 4)、裁决域落库(`verdicts` / `verifier_runs` 预留表启用,004 迁移)、审计 PG 落库与归档、行级租户策略(RLS)、容器化 Worker 执行形态、MVP 题目集、裁决呈现 UI 增量(vm-ui,零视觉重设计延续)、测试与证据。**vm-engine 零语义变更为基线**(Q1 路线若触进程协议演进,按契约流程另评;判定原则 = 复用优先,回放 / 判题 / 投影代码零第二实现)。

**硬门槛(实现期逐条自查)**:

> 正式裁决唯一出处 = 信任域 4 verifier 对规范化动作日志的独立重放;编排器、通道与浏览器任何位置不得预判、缓存或改写裁决;交互会话 `won` / `failed` 与正式裁决相互独立(清单 §五:前端显示与权威结果彻底解耦)。
>
> verdict 细节零公开面:浏览器只获得 11 值结果类型与契约字段;隐藏测试内容、谓词、命中详情、重放中间态只进受控日志与审计;裁决重询走限流(429 冻结形态);宿主不得经嵌入协议承载或转述权威结果(V-9),裁决呈现通道必须端到端来自 session-api / verifier 链路。
>
> 审计是安全事件账不是运维事件账:append-only 端口语义 + 库层强制;kind 集合扩展走 WP-64 统一论证一次定案,不逐次漂移(D-API-59)。
>
> 行级策略是查询层校验之外的第二道结构闸:跨租户与"不存在"同形态;容器形态下强制终止、崩溃替换恢复、秘密零驻留语义零回退,容器无网络出口。

**已冻结、本阶段直接消费的契约**(不得绕开重造):`VerdictResultSchema` 11 值结果类型(protocol,WP-2 冻结);`stackmaster-session-submit/1` 内部裁决引用(D-W8-9,`submissions.reference` 内含完整规范化动作日志,D-API-56);`submissions` / `verdicts` / `verifier_runs` 表结构(004 迁移预留,裁决域两表本阶段启用写入);判题语义规约 §七隐藏测试执行(基线独立克隆 / `reference_payload` / `predicate_probe` / `classify_outcome` 7 值);快照与回放语义规约 §五(`replay(config, log)` 单一实现与逐项比对语义);版本策略 §三(六记录项,缺项裁决无效)/ §四(verifier 与交互执行同锁);AuditSink append-only 端口与 kind 七值集合(D-API-18 / 33 / 59);PG 表域与查询层租户校验(D-API-20)、快照密文信封与 action_log append-only 触发器(D-API-21 / 22);限流 429 冻结形态与七配置键(D-API-50~54 / 58);compose 拓扑与 CI 编排(D-API-64 / 65);指标面纪律(D-API-70~72)。

**工作包编号约定**:WP-60~68(取"阶段六"义,沿阶段四 WP-40 / 阶段五 WP-50 先例;与阶段一~五工作包编号无继承关系)。
