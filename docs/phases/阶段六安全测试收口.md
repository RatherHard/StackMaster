## 二、13.5 秘密零驻留:四类检查逐条取证

### 1. 构建产物检查

- **`pnpm scan:public` 实跑**:`tooling/scan-public-artifacts.mjs` 对五浏览器可达包(protocol / vm-ui / web-component / embed-runtime / react-wrapper)dist 全量 JS 产物(注释剥离后)扫描——**0 违规,3 条既有豁免**(protocol server-only 同构字段名,带原因与到期日的 ALLOWLIST 形态)。本机实跑输出见 §八。
- **verifier 产物不进浏览器可达面(结构性论证)**:`apps/verifier` 是服务端包(信任域 4 独立进程),不在 `PUBLIC_PACKAGES` 五包之列;dependency-cruiser 边界(ZR-B3 `no-ts-dependency-on-vm-engine` + 浏览器可达包禁反向依赖服务端包)使 verifier 与 vm-engine 都不可出现在任何浏览器构建图——`pnpm lint:deps` 0 violations + 反例自检(`lint:deps:self-test`)必触发反例同 CI;verifier 产物只进其独立镜像 / 宿主进程,无静态面下发路径。
- 既有登记不变:ZR-B3 / B4 / B5 / B8 / B9 / B10 构建与通道面逐条见《秘密零驻留CI检查项映射》§三(v1.12 同步更新)。

## 四、侧信道论证(9.2 侧信道约束在裁决链上的延伸)

1. **裁决时延 = 队列深度函数,非载荷函数**。裁决链为异步解耦:submit 只落提交行 + pending run 行即返回 `{submissionId, revision}`(冻结形态);裁决由 verifier 以轮询节奏(SUBMIT 认领批 + poll interval)推进——单提交从提交到裁决的时延由**队列深度与 verifier 消费吞吐**决定,与提交载荷内容(动作日志字节、是否含隐藏判定相关内容)无函数关系。verifier 对单日志的重放耗时差异(指令数多寡)不构成秘密信号:动作日志本身是玩家提交内容可见面(BOUNDARY,清单 §六),其长度玩家自知。
2. **呈现通道零进度泄露(D-API-84)**:pending 期响应 = 恒定三字段 `{submissionId, revision, status:"pending"}`,零进度 / 零队列位置 / 零预计等待;重复重询字节确定(I-4)。**本包新增最小断言**(`verdict-routes.test.ts` 侧信道用例):三提交最终分别落 success / wrong_answer / engine_error 三个不同方向,其 pending 期载荷仅 submissionId 不同、其余逐字节一致——pending 可观察面不承载裁决方向的任何函数;若呈现实现引入任何与裁决相关的信号(长度 / 字段 / 字节),该用例逐字节对齐断言即红灯。
3. **verdicted 期载荷 = 成绩本身**(11 值字面 + decidedAt),是最终必须公开给选手的结果,非隐藏状态;非成绩方向与成绩方向同构呈现(同键集,零语义附加字段,既有 `verdict-routes.test.ts` 矩阵)。
4. **ZR-P4 统计面延伸论证**:交互通道的统计不可区分面(帧数 / 帧长分布逐位置 / 归一化载荷)由 `zr-p4-frame-statistics.test.ts` 承载(WP-6);呈现通道(GET /verdicts 族)为 REST 单响应形态,其统计面退化为本节第 2 点的字节确定性断言——pending 字节与裁决方向零相关 + 429 冻结形态逐字节,即呈现通道版"无可区分差异"。重询限流的 429 计数窗口为 (tenant, user) 维度固定窗口,与裁决状态零耦合(风暴用例:pending 重询触顶不改变任何裁决侧状态)。
