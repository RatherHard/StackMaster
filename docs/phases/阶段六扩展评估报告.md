## 二、逐项评估

> 每项四格:①教学数据(待观察形态 + 观察点 + 启动判据);②性能基准(既有数字与增量论证);③安全评审(威胁面增量与前提条件);④触发条件建议(何时值得进入实施排期)。**七项均"暂不进入实施排期"**;评估不改变任何冻结契约与引擎语义。

### 2.1 堆利用(复杂堆模型)

**能力概述**:为引擎引入堆分配器语义模型(堆区域、分配 / 释放元数据、堆溢出的元数据破坏教学),支撑 heap overflow / 堆布局操纵类教学。11.2 明确"复杂堆和多架构支持"为 MVP 不交付项,本项是其中最常被要求的第一扩展。

- **①教学数据(待观察)**:观察点 = 八题集的完成率 / 放弃率与进阶信号(CH-04~08 的溢出因果链观察点是前置阶梯:D-API-107 CH-04"溢出因果链首次成功"、CH-05"溢出越界长度"、CH-08"收官完成率")+ 十五章"各题完成率和放弃率""错误类型分布""学习前后概念理解变化"。**观察启动判据**:MVP 上线试用启动采集后,若栈序列(CH-01~06)完成率显著高于放弃率、且 CH-08 收官完成率与"重复错误比例"显示学习者已消化返回地址模型,堆即是最自然的下一站;反之栈模型尚未消化,堆扩展无教学收益。
- **②性能基准**:堆模型 = 引擎区域类型与元数据的语义扩展,不是新执行引擎——COW 分页存储与步数预算机制原样承载,预期单动作成本与栈区域同量级(结构性论证;无实测,实现期以既有 proptest / miri / fuzz 门禁为回归闸)。verifier 侧:堆重放仍走 `vm_runtime::replay` 单一实现(ADR-8),动作日志预算(`ACTION_LOG_LIMIT` 10 000 条)不变,裁决时延增量与指令数线性。既有基线(§1.2)无任何指向当前执行域瓶颈的信号。
- **③安全评审(9.2 延伸)**:威胁面增量 = ①堆元数据是新隐藏状态面,须入数据分类清单逐字段分类(隐藏元数据不下发的既有纪律直接适用,ZR-P 字段白名单机检扩展);②新谓词面(堆条件谓词)走判题语义规约版本演进(`verdictRuleVersion` 递增),7 值分类与 11 值汇总矩阵逐格扩展;③投影泄漏差分套件(T-SC1~T-SC4)对新公开面逐题重跑。**前提条件**:数据分类与投影语义的扩展论证先行(阶段一流程重演),引擎纪律门禁(miri / fuzz / 确定性)不豁免。
- **④触发条件建议**:①十五章栈序列完成率 / 放弃率数据支持"进阶需求"(采集启动后一个完整试用周期的数据);②出题人制作需求登记(M10 出题人积木触发面同源观察);③安全评审前提(分类论证 + 谓词词汇演进流程)具备排期窗口。三条同时满足再进入实施排期。

### 2.2 ROP

**能力概述**:面向 ROP(return-oriented programming)链构造的教学——多 gadget 组合、栈转 pivoting、`ret` 链接力。引擎现状已承载 ROP 的最小形态:字节模式真实地址语义 + `ret` 劫持(CH-06 ret2win 即单 gadget ROP)。

- **①教学数据(待观察)**:观察点 = D-API-107 CH-06"字节模式过渡首次成功 / 提示等级 / 投影传输量"与 CH-08"两阶段状态机 + 组合闭环"(CH-08 的阶段闸门重试观察点即多步利用链的教学前测)。**观察启动判据**:CH-06 → CH-08 的过渡完成率与提示使用等级——若学习者能在少量提示下完成多步组合,ROP 链教学(更多 gadget / 栈布局设计)有真实承接面;若 CH-06 本身高放弃,ROP 扩展为时过早。
- **②性能基准**:ROP 题目 = 更大代码区(gadget 密集布局)与更长动作日志。既有预算充裕:动作日志天花板 10 000 条 / verify 帧预检 4 MiB(帧硬顶 16 MiB)(ADR-9 §三),投影增量直方图(k6 双轮归档:write_bytes 全量样本落于 ≤ 512 B 档,`k6/results/2026-09-09T223628898Z` 与 `2026-09-12T134452996Z` metrics-after 快照)有 1 MiB 档位余量;引擎解释器恒定步数语义不变。零新基础设施需求。
- **③安全评审**:威胁面增量**低**——ROP 教学仍在 VM 抽象封闭域内(无新权限面、无新边界跨域);所需主要是题目语料(公开 / 私有双包管线既有)与可能的指令词汇增补(见 §2.5 共同前提)。隐藏测试面:`predicate_probe` 形态直接承载 ROP 终态判定,零输入槽需求(D-H2 边界不动)。
- **④触发条件建议**:CH-06~08 观察点数据支持进阶(同 §2.1 判据)+ 指令词汇增补清单经最小DSL范围版本演进定案(新 opcode = 版本演进流程,非本阶段)。ROP 依赖 §2.5(指令集)作为前置,建议两者合并评估排期。

### 2.3 防护机制深化(NX·ASLR·Canary)

**能力概述**:三项防护机制的教学深化。现状与差距逐项核实:

| 机制 | 现状 | 深化空间 | 前提与耦合 |
|---|---|---|---|
| NX(不可执行) | **已有**——区域权限 rw / rx,不可执行区域拒执行、可解释错误;语料承载(verdict-closed-loop:"写入只读代码区被拒并给出解释") | 教学呈现面(执行位置视图)已就绪(指令规约 §1.9);基本无引擎深化需求 | 无 |
| ASLR | 真实实例**固定基址**(D-J8 不启用,D-API-108);调试实例兄弟形态(D-J10,ZR-B13 draws = 514) | 真实实例 ASLR = D-J8 演进四件套:①动作日志绝对地址的置换变换(或地址语义演进为结构相对);②`replay_mismatch` 语义扩展派生路径复核;③快照信封新增基址登记位;④(`DerivationPathSummary` 已就绪,Schema 零变更) | D-API-108 已登记:**触发条件 = 产品决策进入实施排期(当前无排期)**;触发则 verifier 裁决面随行演进(判题语义规约 §6.1) |
| Canary | 检测已有(`stack_canary_intact` + `build_canary_slots`);**契约缺口如实登记**:XS-CANARY-CORR(检查器:启用 canary ⇒ 隐藏 + containsSecret 的 canary 对象)与引擎装配(可见性公开)在冻结契约下结构性不相容 ⇒ 交互可玩题暂不能启用引擎 canary 槽(CH-05 以守护标记谓词承担教学) | 契约收口(canary 槽可见性语义两侧对齐)后,canary 启用题进入题目集 | **契约收口归 WP-1 §1.3 流程另行登记**(D-API-109;阶段六验收评审 §遗留同项挂账)——收口完成是 canary 深化的硬前置 |

- **①教学数据(待观察)**:观察点 = D-API-107 CH-05"溢出越界长度 / 防护机制概念前后测 / 回退次数"与 CH-07"隐藏区域概念完成率 / 探针行为"。**观察启动判据**:CH-05 概念前后测变化量与"溢出越界长度"分布——若学习者普遍能精准绕过守护标记(越界长度分布集中于恰好在位长度),则 canary / ASLR 的真实随机化教学(而不是固定布局记忆)有明确增量价值;若连守护标记概念都未建立,深化无收益。
- **②性能基准**:NX 已有(零增量);canary 启用 = 每栈帧 canary 槽写入与检查,单动作常数级增量,步数预算内;真实实例 ASLR = 基址派生一次(种子首 draw),运行时零增量,裁决面派生复核为重放期一次性成本。既有 k6 基线无压力信号(§1.2)。
- **③安全评审**:ASLR 真实实例是本项中唯一的**高耦合演进**——触碰 ADR-8 同一装配参数面、重放语义与快照信封,安全评审要求 = ①派生路径复核与 `replay_mismatch` 的边界重论证(拒绝"重放需 seed 摄入"方向,保 v1 零驻留纪律);②快照信封基址登记位的分类论证(SERVER_ONLY);③ZR-B13 复算面扩展。canary 契约收口的安全评审 = 可见性语义对齐后隐藏性论证重跑(containsSecret 对象的 I-9 面)。
- **④触发条件建议**:分轨——**canary 契约收口**:短平快,建议作为最近的登记动作(挂账 WP-1 §1.3,教学价值已在 CH-05 观察点预备);**真实实例 ASLR**:维持 D-API-108 登记(产品决策 + 上述安全评审前提,当前无排期);**NX**:已交付,无动作。

### 2.4 信息泄露类

**能力概述**:以"泄露"为核心机制的教学题——利用读越界 / 格式化缺陷等泄露 canary、基址、机密后再构造利用。引擎现状的雏形已具备:虚拟文件 flag(作者接口,CH-07 / CH-08 判定面)、隐藏区域不可探测(I-9)与探针行为机检、`containsSecret` 秘密对象面(ZR-B13 / XS-CANARY-CORR 语料)。

- **①教学数据(待观察)**:观察点 = D-API-107 CH-07"隐藏区域概念完成率 / 探针行为 / inaccessible_address 分布"与 CH-08"阶段闸门重试"。**观察启动判据**:CH-07 探针行为数据(学习者是否自发尝试越界读取)与 inaccessible_address 错误分布——自发探针行为密集 = 泄露机制教学有承接;零探针 = 先补栈模型基础。
- **②性能基准**:泄露链题目 = 读动作 + 后续利用的组合,动作日志更长但预算充裕(同 §2.2 论证:10 000 条 / 4 MiB 预检);投影侧:泄露动作的返回值是**提交内容可见面**(BOUNDARY,清单 §六),投影增量受既有直方图档位约束,零新机制。
- **③安全评审**:威胁面增量**中**——信息泄露题目的"可泄露秘密"全部必须留在服务端私有面(隐藏 flag / 秘密对象的既有分类),教学呈现 = 服务端裁决字面(11 值)而非秘密本体;关键评审项 = ①泄露面(读越界的返回值语义)与投影白名单的交叉论证(返回值进动作响应 = 玩家提交内容,不触 ZR-P 字段白名单;但涉及秘密对象值的读取须走虚拟文件 / containsSecret 的既有服务端判定路径,不得让引擎把秘密值直接放进公开投影);②T-SC1 逐题必过义务对泄露变体题天然加重(秘密变体 × 泄露路径差分),题目发布管线义务量增。
- **④触发条件建议**:CH-07 探针行为 / 完成率数据支持 + 虚拟文件 / 秘密对象语义的教学化封装设计定案(零契约变更的题目语料形态优先尝试——现状管线已能承载单步泄露教学,无需引擎演进即可试点)。

### 2.5 更完整指令集

**能力概述**:基线 20 opcode 之外的词汇扩展(算术 / 访址 / 串操作 / 标志位利用等),支撑更丰富的题目设计与 ROP / 泄露类教学(§2.2 / §2.4 的共同前置)。

- **①教学数据(待观察)**:观察点 = 出题侧与学习侧双向——十五章"出题人制作、校验和调试一题所需时间"(指令词汇不足会表现为题目设计的绕行 workaround 成本)与八题集错误类型分布(学习者因词汇面受限而绕行的信号)。**观察启动判据**:MVP 试用期的出题人侧反馈登记(当前出题人面 = 仓库内题目作者,M10 积木未启动)与题目集制作期的词汇约束实录(8 题集制作已在构造式 DSL 内沉淀语料,制作期未出现词汇阻塞——如实登记:这不是教学数据,是制作侧观察)。
- **②性能基准**:解释器为直线语义(每 opcode 常数步数),词汇扩展对执行成本零结构性影响;步数预算模型不变。真实成本在**工程面**:每新 opcode = 指令规约逐条规约 + 编译器 / 装配管线 + 投影事件面 + fixture(跨语言契约)+ miri / fuzz 门禁扩展——阶段二的产能证据(10 WP 一次通过全门禁)表明工艺可行,但词汇扩展是线性人力成本,应严格由题目需求牵引而非一次性铺开。
- **③安全评审**:每新 opcode = 新异常 / 事件面 → 投影白名单机检扩展(ZR-P1)+ 指令纪律门禁(无控制转移的自定义指令、恒定步数)逐条复检;位宽 / 掩蔽算术在 32 / 64 双位宽的行为矩阵翻倍(13.1 既有覆盖形态)。词汇面演进走最小DSL范围版本(`verdictRuleVersion` 联动),破坏性变更递增版本并保 N-1 窗口——**这不是本阶段可"顺手"做的事,是完整契约演进流程**。
- **④触发条件建议**:题目设计需求清单(具体 opcode × 教学场景)积累至批量门槛 + 一次完整的版本演进排期窗口;建议与 ROP / 泄露类扩展合并为一个"教学能力扩展"工作包统一评估,避免逐 opcode 碎片化演进。

### 2.6 后端 WASM

**能力概述**:VM Core 的 WASM 化(计划书 5.1 路线纪律明列"T2/T3 选项,触发条件满足前不得引入")。候选动机两分:①浏览器侧执行(教学沙箱预览 / 离线形态);②后端可移植性(非 x86-64 / ARM64 环境的执行面)。

- **①教学数据(待观察)**:**无直接教学指标关联**——十五章指标中唯一可能相关的是"低端设备上的投影渲染、内存占用和断线重连性能"(若 WASM 化动机是浏览器本地预览,受低端设备指标牵引;但投影传输量小、渲染面轻,既有数字(k6 投影直方图 ≤ 512 B / 动作)不构成任何"必须本地执行"的压力信号)。**观察启动判据**:无——本项的牵引力不在教学数据维,评估为三项中最低。
- **②性能基准**:动机面无信号——后端侧 k6 三轮基线(§1.2)无 CPU 瓶颈证据(动作 med 3 ms、24 并发稳态);可移植性由既有 cross-platform 确定性矩阵覆盖(cross-platform.yml:x86-64 + ARM64 × debug / release 黄金向量),ARM64 容器化部署是平台问题而非引擎形态问题。
- **③安全评审**:**负向**——①浏览器 WASM 执行与 11.2 非目标("浏览器本地权威 VM、离线完整执行或本地判题")直接冲突,修订该非目标 = 产品层边界变更而非技术演进;②WASM 运行时是新信任边界(运行时逃逸面 / 线性内存模型与引擎位宽语义的交互),9.2 四边界须重评;③ADR-8 单一实现纪律要求 WASM 构建与原生构建同源(同一份 Rust 源的双 target 构建可满足,但确定性 / miri / fuzz 门禁需逐 target 重验)。
- **④触发条件建议**:**维持"触发前不得引入"纪律不变**。触发条件 = 产品决策修订 11.2 边界(浏览器教学沙箱预览成为明确需求)或出现真实后端可移植性需求(当前零信号);任一触发时按本节③重做安全评审。当前**不建议排期**。

### 2.7 真实 ELF 实验模式

**能力概述**:以真实 ELF 二进制为执行对象的实验模式(解析 ELF、真实系统调用语义、真实 Linux 环境容器)。11.2 明确"真实 ELF、容器和完整 Linux 环境"为 MVP 不交付项;现阶段字节模式 + 虚拟文件是受控替代。

- **①教学数据(待观察)**:观察点 = 进阶需求信号——八题集收官(CH-08)完成率、十五章"学习前后概念理解变化"(若学习者完成栈 → ROP 全序列且表达进入真实二进制教学的需求)。**观察启动判据**:八题集全序列完成 + §2.1~2.4 扩展(堆 / ROP / 泄露)在虚拟域内消化后仍有进阶缺口——真实 ELF 是 T3 链条的**末端**而非起点。
- **②性能基准**:真实 ELF 执行域与现有 VM 抽象域**不可比**——现有基线(k6 动作 med 3 ms、冷启动 0.26 s、镜像 145 MiB、2 GiB / 租户)全部基于封闭解释器;ELF 模式 = 系统调用仿真 / 真实进程 / QEMU 或同等设施,冷启动、镜像预算、单动作时延的量级完全改写,既有量化判据面(D-API-105 / 106)不适用,须全新 baseline。当前无任何可引用的实测数字(如实声明)。
- **③安全评审**:**七项中威胁面重写量最大**——从"封闭解释器 + 禁网络 + 只读 fs + cgroup"的抽象执行域,进入"真实二进制执行"域:①选手提交内容的攻击面从"动作日志字节"扩大到"任意 ELF 语义"(解析器 fuzz 面剧增:ELF 解析、重定位、动态链接均成不可信输入面);②9.2 后端交互边界须重写(容器内执行真实二进制 = 容器逃逸面回归评审);③秘密零驻留面(13.5)在真实执行域的语义重定义。**前提条件**:独立信任域 / 独立集群形态(不与交互执行域共享拓扑)+ 显式的"实验模式"产品边界(知情、限流、零成绩效力或独立成绩域)。
- **④触发条件建议**:**当前无排期,如实维持 11.2 非目标边界**。触发条件 = 高阶课程产品决策(栈 → ROP → 堆全链路教学已被真实学习者消化并产生明确需求)+ 上述安全评审重做 + 独立部署形态预算;三者均为长周期前提,本报告登记性质为"远期实验方向"而非可排期项。

1. **七项全部暂不进入实施排期**;是否扩展以及优先级的最终决策不在本阶段产出(分解 §三),本报告提供的是三维判据与触发条件。
