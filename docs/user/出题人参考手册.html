1. 快速开始：15 分钟一道题

StackMaster 的题目不是手写 JSON，而是用 TypeScript 构造一对包对象。 最快的路径是"抄一道既有题，改内容"：

  1. 打开参考实现：apps/session-api/test/mvp-challenges/corpus.ts（MVP 八题的构造源，每题都过了全部门禁）；扩展题集活例在 apps/session-api/test/extended-challenges/（ret2win / 最小 ROP / 整数截断）。
  2. 复制其中一道题的 buildPair 构造块，改：challengeId、题面文案、内存布局、IR 程序、判题条件、语料脚本。
  3. 写一个门禁测试（模板见 §15），跑： 
    pnpm --filter @stackmaster/session-api exec vitest run test/<你的目录>
  4. 装载器（四层校验管线）会逐条告诉你哪里违规（规则 ID + 消息 + 路径）。修到全绿，再补裁决回归语料（真实 vm-worker 重放验证你的解法真的能赢）。
心智模型：你交付的不是"一个文件"，而是一对包 + 一组可重放的解法脚本。 公开包发给选手浏览器；私有包只在服务端判题；解法脚本证明题目可解且判分正确。

2. 出题工作流与文件清单

2.1 一个题目由哪些文件组成

文件谁产出进 git？作用
语料模块（如 corpus.ts，TS）出题人手写是 题目的"源代码"：以构造式代码生成公开包 + 私有包对象、解法动作脚本、预期终态与裁决。私有内容只在运行时构造，不落盘。
公开描述包（JSON 对象）语料模块构造形态样例可入 git 发给选手浏览器：题面、VM 元数据、可见内存布局、允许动作、提示阶梯、初始投影。不允许出现任何秘密（检查器强制）。
私有判题包（JSON 对象）语料模块构造永不 只在服务端：flag、种子、隐藏区域、完整程序、判题条件、隐藏测试。整体 SERVER_ONLY，进浏览器即违规。
门禁测试（*-set.test.ts）出题人手写是 每题跑 loadChallengePair 四层校验管线；登记摘要（规范化 JSON SHA-256）确定性检查。
裁决回归测试（verdict-closed-loop.test.ts）出题人手写是 用真实 vm-worker 进程逐条执行解法脚本 → 导出动作日志 → 一次性 verifier 进程重放 → 断言 11 值裁决。证明"题目可解、判分正确"。
登记 / 发布演示（compose 集成测试，可选）出题人手写可选 ChallengeRegistrar.register 真实登记 + Ed25519 签发链路演示（compose 门控 SESSION_API_COMPOSE=1）。

2.2 从语料到发布的流水线

语料模块(构造式 TS)
  └─> buildPair() 每次现场构造 { publicDescriptor, privateBundle }
        └─> loadChallengePair() 四层装载管线（fail-closed，任一层违规即整体拒绝）：
             第0层 严格 JSON 扫描（仅文本入口；重复键拒绝）
             第1层 Ajv 双包 Schema 校验
             第2层 XS-* 字段分类检查器（跨包一致性 / 秘密不外泄 / 词汇封闭）
             第3层 XC-* 编译期校验（逐 opcode 形态 / 可达性 / 回边⇒预算）
        └─> canonicalDigests() 规范化 JSON SHA-256（登记哈希输入，D-API-23）
              └─> ChallengeRegistrar 登记发布（dev/CI 经 compose；Ed25519 签发链路）
装载失败的方向恒为 challenge_invalid：不产出部分程序、不带病装载。 你拿到的违规列表（规则 ID + 消息 + 路径）是内部诊断，只给出题人和发布管线看；玩家侧永远只看到笼统的 internal_error。

hintLadder 必填0–8 项，见 §12.2提示阶梯。

3.2 vmProfile（虚拟机画像）

字段类型与约束写法与效果
registers[] 必填1–64 项 × {name, displayLabel?}；name ^(?!FLAG)[A-Z][A-Z0-9_]{0,15}$本题寄存器集的定义性声明：自由命名（如 RDI、RSI、RCFG），大写。必含 RSP/RBP/RIP（XS-REG-CORE）。名字会出现在选手的寄存器视图里，建议起有教学含义的名字并配 displayLabel。
flagRegisterNames[] 可选1–32 项 × ^FLAG[A-Z0-9_]*$秘密标志寄存器的名字清单（如 FLAG0、FLAG_WIN）。只公开名字，值永不公开：不得出现在 registers[]，必须存在于私有初始寄存器集（XS-REG-FLAG）。用于"到达胜利态置一个秘密标志"的判题写法。
archBits 必填enum 32 | 64位宽。所有架构值（寄存器初值、立即数、位移、公开镜像值）按此校验域（XS-ARCH-WIDTH）：立即数无符号 [0, 2^archBits−1]，位移有符号 [−2^(archBits−1), 2^(archBits−1)−1]，越界即拒。值以 64 位容器承载、高位掩蔽。
endianness 必填const "little"固定小端，没有选择。教学上这就是"值在内存里倒着躺"。
pageSizeBytes 必填integer，4096–65536，4096 的倍数VMA 页大小。
canary 必填{enabled, sizeBytes?}；enabled=true ⇒ sizeBytes 必填（1–8）注意交互可玩题当前请填 {enabled:false}：检查器要求"启用 ⇒ 存在隐藏的、含秘密的 canary 对象"，而引擎要求 canary 槽公开——两者在冻结契约下结构性不相容（D-API-109 如实登记，契约收口挂账中）。金丝雀教学用"守护标记 + memory_equals 谓词"替代（见 MVP CH-05）。
encodingTable[] 可选1–64 项 × {tokenHex, op, operands?}；tokenHex ^0x[0-9a-fA-F]{2}$声明即进入字节模式（与私有包 compiledIr 恰一，XS-PROG-MODE）。详见 §6。

3.3 memoryLayout.regions[]（可见布局）

字段类型与约束写法与效果
regionId 必填^[a-z][a-z0-9-]{0,62}$区域标识，全局唯一。公开/私有同名区域互为镜像（regionId 是公开私有共享的豁免标识）。
kind 必填enum code|global|stack|heap|key|custom六类。code 区域至多 1 块、不得隐藏、必须出现在初始投影（D2-CODE-PUBLIC）；custom 需 publicLabel 承载类型名。
startAddressHex 必填^0x[0-9a-fA-F]{1,16}$起始地址。aslrEnabled=true 时变为相对布局描述。
byteLength 必填1–16 MiB，4096 的倍数区域长度（页对齐只约束 VMA 边界，区域内的对象如 canary 不受约束）。全部区域合计 ≤ 64 MiB。
permissions 必填^r?w?x?$（规范序子集）如 "rw"（栈/数据）、"rx"（代码，字节模式下代码区禁止含 w，W^X）。
publicLabel 必填1–128 字符区域在 UI 的展示名（如 "栈"、"全局配置"）。
隐藏区域怎么声明？公开包结构上不存在"隐藏"表达位（D2-NO-HIDDEN-IN-PUBLIC）。 想藏的区域只写进私有包 initialState.memoryRegions[]（isHidden: true），地址不得与任何公开区域重叠。 选手侧的效果：该区域"不存在"——探测它和对未映射地址探测的可见结果完全一致（I-9 防侧信道）。

3.4 initialProjection（初始投影，部分镜像）

字段类型与约束写法与效果
visibleRegions[] 必填1–64 项 × {regionId, label, startAddressHex, byteLength, permissions, bytesHex, truncated}；bytesHex ≤512 hex 字符与 memoryLayout.regions[] 按 regionId 双射，几何+标签逐项相等（XS-PROJ-GEOM）。bytesHex = 私有区域 contentHex 的同长前缀切片（XS-PROJ-VALUES），选手首屏看到的就是它；truncated = 前缀是否被截断（诚实标记，必须与长度自洽）。
visibleRegisters[] 必填1–64 项 × {name, valueHex}；valueHex 大写 ^0x[0-9A-F]{1,16}$初值镜像私有初始寄存器；FLAG 寄存器与秘密汇禁止出现（I3-VISIBLE-REG）。想给学员看哪些寄存器就列哪些（如教学题公开 RCFG/RBUF 让学员能算地址）。
semanticHighlights[] 可选0–32 项 × {kind, targetRegionId, startAddressHex, byteLength, label}；kind enum buffer_start|return_address_slot|saved_rbp_slot|canary_slot|custom结构视图的语义标注（"这里是 buffer 起点 / 返回地址槽"）。目标区域必须可见且跨度在区域内（I2-HIGHLIGHT）。栈教学题建议至少标 buffer 与返回地址槽。

4. 私有判题包 · 逐字段参考

整体 SERVER_ONLY。顶层 13 必填 + 条件字段（compiledIr / entrypointAddressHex 恰一）+ 4 可选。

字段类型与约束写法与效果
schemaVersion / challengeId / challengeContentVersion / vmProfileVersion 必填同公开包四项与公开包逐项同值（XS-ID-CORR）。
dslSchemaVersion 必填const 2DSL 词汇版本（v2 = 20 opcode + 自定义指令/接口声明面）。
vmEngineVersion 必填semver锁定执行环境的引擎版本（回放按它选解释器）。照抄当前引擎实际版本（参考语料里的值）。
engineBuildId 可选^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$构建 ID（正式判题记录项）。缺省时 bundle-lock 跳过构建级比对。
declaredSeedPublicPaths 必填0–32 项；每项 段1.段2…（≤8 段，段 ^[A-Za-z][A-Za-z0-9_]{0,31}$）声明"seed 会影响哪些公开投影叶子"（侧信道审计基准，T-SC4/ZR-P2）。空数组 = 显式声明"无公开随机化面"——固定 seed 的静态题就填 []。路径必须可解析到 initialProjection 的具体叶子（XS-SEED-DECL）。
seedPolicy 必填{strategy, seedHex?}；strategy enum fixed|server_random_per_session互斥（Schema if/then/else + XS-SEED-POLICY 双闸）：fixed ⇒ seedHex（16–64 hex 字符）必填；server_random_per_session ⇒ 禁止携带 seedHex。seed 值永不进公开面。教学题用 fixed + 手选固定值（回放可复现）。
initialState.registers 必填对象 ≤256 键；键 = 一般名或 FLAG 名；值 ^0x[0-9a-fA-F]{1,16}$ 落 archBits 域完整初始寄存器（含 FLAG 值、含程序要用的全部寄存器——XC-OPERAND-REF 要求 IR 里引用的寄存器都在初始集内）。
initialState.memoryRegions[] 必填1–64 项 × {regionId, kind, startAddressHex, byteLength, permissions, contentHex, isHidden}全部区域（含隐藏）。contentHex 长度必须 = 2×byteLength（XS-MEM-CONTENT，一字节都不许少）。非隐藏区域与公开布局双射镜像（I2-PUB-MIRROR）。区域内容合计 ≤ 2 MiB（XS-MEM-TOTAL）。
secretSinkRegisters[] 可选1–256 项补充声明"这些寄存器是秘密汇"（仅收紧不放宽；FLAG 命名恒为秘密汇）。被声明的寄存器不得出现在公开投影。
secrets.flag 必填8–128 字符本题 flag。永不发往浏览器；教学期用占位格式（如 FLAG{...}）。
secrets.virtualFiles[] 可选0–8 项 × {fileId, content(≤4096 字符)}虚拟文件（"读文件拿 flag"教学）。fileId 是私有标识，禁止出现在公开包任何字符串里（XS-ID-NO-PRIVATE / ZR-B8-CAP-SCAN）。经作者接口授予/读取（§7.2）。
privateObjects[] 必填0–64 项 × {objectId, kind, addressHex, byteLength, visibility, containsSecret}；kind enum buffer|canary|saved_rbp|return_address|file|other语义对象登记（给判题/审计看）。规则：containsSecret ⇒ visibility:"hidden"（I3-SINK-HIDDEN）；hidden 对象地址不得与公开区域相交（I2-OBJ-NOT-PUBLIC）。栈教学题照惯例登记 input-buffer / saved-rbp-slot / return-address-slot。
judging 必填见 §8成功条件 / 失败条件 / 隐藏测试。
judgingConfig 必填见 §11.2判题配置（规则版本 + 谓词预算必填）。
stages[] 可选0–8 项多阶段状态机，见 §9。
compiledIr 条件必填{irFormatVersion:2, entrypointIndex?, instructions(1–4096), labels(0–512)}IR 模式（公开包无 encodingTable）时必填；字节模式必须省略。见 §5。
entrypointAddressHex 条件必填hex 地址字节模式必填：执行入口字节地址，必须落在代码区内（允许不在首字节——"入口即 gadget"）。IR 模式不得出现。
customInstructions[] 可选0–16 项自定义指令，见 §7.1。
interfaces[] 可选0–16 项作者接口，见 §7.2。

5. 指令集（IR 模式）

IR 模式是默认程序形态：私有包 compiledIr.instructions 是一个指令数组， 控制流立即数与 ret 弹出的目标都是"指令索引"（第 0 条 = 索引 0）。没有表层机器码，内存里的字节只是数据。

5.1 基线指令集（20 opcode，封闭枚举）

操作数记号：R=寄存器，I=立即数（无符号，archBits 域），M=内存（base 寄存器 + 有符号位移），interface=结构化接口引用。每指令 ≤4 操作数。标志：zf（零）/ cf（无符号进位借位）/ sf（符号）。

opcode操作数形态语义标志
movR,I / R,R / R,M / M,R架构值传送（按 archBits 掩蔽）—
pushR / I压栈（RSP −= 8 后写栈）—
popR出栈（RSP += 8）—
leave—RSP←RBP 后 pop RBP。栈帧教学核心：saved RBP 被溢出覆写后，leave 劫持 RSP、随后的 ret 弹攻击者值。要求初始寄存器集含 RBP（XS-IR-LEAVE）—
addR,R / R,I / R,M加法。溢出走引擎错误安全终止（不静默回绕）zf cf sf
subR,R / R,I / R,M减法（可产生借位回绕，置 cf）zf cf sf
cmpR,R / R,I / R,M减法比较，不写回，只置标志zf cf sf
and / or / xorR,R / R,I按位逻辑zf sf
shl / shrR,R / R,I移位（移位量按 archBits 取模——shl 64 ≡ shl 0，这也是个教学点）zf sf
jmpI / R / M无条件跳转—
je / jneIzf=1 / zf=0 跳转—
jb / jaeI无符号低于 / 不低于跳转（只有无符号条件跳转，没有有符号跳转——signed 教学要靠位技巧）—
callI / R / interface压返回地址后跳转；interface 形态走作者接口（§7.2，引擎管理调用，不占玩家栈）。深度 ≤64—
ret—弹出栈顶作为新执行位置；弹出值不可执行时报 invalid_rip。动态目标（编译器无法静态判定落点）—
syscallI教学伪操作：I ∈ [0x00,0xFF] 只有内置 exit(I)；I ≥ 0x0100 走作者接口派发（未声明即拒，XS-SYSCALL-DECL）。无宿主副作用—
IR 书写三规则（编译器 XC-* 强制）： ①每条指令的操作数个数与形态必须符合上表（XC-OPCODE-SHAPE）； ②引用的寄存器必须在私有初始寄存器集里（XC-OPERAND-REF）； ③立即数跳转目标必须是界内索引（XC-IR-TARGET）；纯静态程序不允许死代码（XC-IR-REACH）—— 但只要程序里有 ret/jmp R 等动态目标，编译器保守地认为全图可达，所以"只能被 ret 劫持到达的 win 块"是合法的。

5.2 IR 指令的 TS 写法

// compiledIr.instructions 的元素（裸对象，无特殊 DSL）：
{ op: "mov", operands: [
    { kind: "register",  name: "RSIZE" },
    { kind: "memory",    baseRegister: "RCFG" }                      // [RCFG]
]}
{ op: "mov", operands: [
    { kind: "register",  name: "RVAL" },
    { kind: "memory",    baseRegister: "RCFG", displacementHex: "0x8" }  // [RCFG+8]
]}
{ op: "cmp", operands: [{ kind: "register", name: "RTMP" },
                        { kind: "immediate", valueHex: "0x10" }] }
{ op: "jne", operands: [{ kind: "immediate", valueHex: "0xd" }] }    // 目标 = 指令索引 13
{ op: "mov", operands: [{ kind: "memory", baseRegister: "RDST" },   // [RDST] = RVAL
                        { kind: "register", name: "RVAL" }] }
{ op: "syscall", operands: [{ kind: "immediate", valueHex: "0x0" }] } // exit(0)

// labels 是元数据（给人和工具看的锚点），控制流目标一律写内联索引：
labels: [ { labelId: "entry", instructionIndex: 0 },
          { labelId: "win",   instructionIndex: 12 },
          { labelId: "lose",  instructionIndex: 13 } ]
需要"用标签写控制流"的作者形态时，可用编译器生成面 compileProgram(AuthorProgram, publicDescriptor) （操作数第四种 {kind:"label", labelId}），它会消解标签并产出 compiledIr 或字节流； 产物必须再过一遍 loadChallengePair 才能进私有包。MVP 语料全部直接手写内联索引（程序短，索引可控）。

6. 字节模式（表层机器码）

公开包声明 vmProfile.encodingTable 即进入字节模式：代码区 contentHex 就是可执行空间， 入口 = 私有包 entrypointAddressHex（字节偏移）。这是 ret2win / ROP 教学的地基：任意 token 边界取指， RIP 可以落在指令中间。

6.1 编码表（公开，ISA 公开立场）

字段约束说明
tokenHex^0x[0-9a-fA-F]{2}$，表内唯一定宽 1 字节 token（变长 token 挂 T2/T3，v1 不允许）
op20 基线小写枚举 ∪ 大写自定义助记符与 IR 同词汇；自定义助记符必须在私有包声明（XS-ENC-TOKEN），且自定义条目零操作数
operands[]≤4 项，四种形态声明{kind:"register", name}（寄存器烘焙进 token：同一助记符不同寄存器 = 不同 token；FLAG 寄存器不可编码）/ {kind:"immediate", width:"arch"}（内联 archBits/8 字节小端）/ {kind:"memory", baseRegister, displacementWidth:"arch"} / {kind:"interface", interfaceId}。width/displacementWidth 必填且恒 "arch"（R12：机器码长度不得依赖隐式推断）

教学立场：编码表放公开包（真实 pwn 里 ISA 与二进制都是选手可见的，谜题在 gadget 构造不在解码）。 选手能看到"字节 ↔ 助记符"，但自定义指令的语义仍在私有包。

6.2 代码区约束

约束内容机检
纯指令流从入口到区域尾 = 已声明 token + 内联操作数 + 填充 token 连续构成；数据放 global/key 等其他区域XS-ENC-PROBE 探测译码
W^X代码区权限不得含 w；写代码区运行时报 memory_faultXS-CODE-WRX
入口必填entrypointAddressHex 必须落在某代码区（允许非首字节）XS-ENC-PROBE
填充 token 化尾部填充不能用任意字节，必须落表（惯用自定义 NOP0）XS-ENC-PROBE
恰一代码区字节模式：恰一个公开代码区 + 恰一个非隐藏私有代码区（R10）检查器

探测译码（XS-ENC-PROBE）：发布管线从入口线性取指译码 ≤4096 条或区域尾止，未知 token / 截断即拒； 不可达字节不判罚（运行时取指到坏字节 → invalid_rip 兜底）。 4096 字节区域用 1 字节 NOP0 填充时全量解码 ≈ 4080 条 < 4096 上限，可行。

6.3 字节模式最小工作例（摘自 MVP CH-06 的构造手法）

// 公开包 vmProfile.encodingTable：
[ { tokenHex: "0xc3", op: "ret" },
  { tokenHex: "0x90", op: "NOP0" } ]        // NOP0 = 私有包声明的零操作数自定义指令

// 私有包：entrypointAddressHex: "0x400010"
// 代码区 contentHex = 前 0x10 字节 00 + 0x90 填充 + 补丁：
//   0x400010: c3                    （入口即 ret）
//   0x400200: c3                    （win gadget：跳到这就算到）
// 解法：buffer 写 24 字节填充 + le64("0x400200")，然后 ret 动作。

7. 自定义指令与作者接口

两者都是声明式映射表（数据），由引擎按封闭原语解释执行——没有函数、没有控制转移、 步数恒定（= 序列长度），不存在"注入逻辑"的语法位置。≤ 各 16 条。

7.1 自定义指令 customInstructions[]

形态：{mnemonic, displayText, semantics[]}。 mnemonic 大写 ^[A-Z][A-Z0-9_]{0,15}$（与基线小写结构性不相交，不得与基线冲突）； IR 引用方式：op 直接写助记符，且自定义指令必须零操作数（XS-CUSTOM-REF / 编码表同规则）。 semantics = 微算子有序组合（1–16 步，直线语义，无控制转移）：

微算子参数语义
load_immdst（一般寄存器）、valueHex立即数装载
mov_regdst、src寄存器间传送
load_memdst、baseRegister、displacementHex（有符号）内存读
store_membaseRegister、displacementHex、src内存写
set_flagflagRegister（FLAG 名）、valueHex唯一能写 FLAG 寄存器的微算子
bit_maskdst、src、maskHex、logic ∈ and|or|xor位掩蔽（截断/取位/拼位的教学工具）
// 例：填充 NOP（MVP 惯例）与"胜利置位"指令
customInstructions: [
  { mnemonic: "NOP0", displayText: "nop",
    semantics: [ { op: "bit_mask", dst: "RAX", src: "RAX",
                   maskHex: "0xFFFFFFFFFFFFFFFF", logic: "and" } ] },
  { mnemonic: "WINFLAG", displayText: "win: 置胜利标记",
    semantics: [ { op: "set_flag", flagRegister: "FLAG0", valueHex: "0x1337" } ] },
]

7.2 作者接口 interfaces[]

形态：{interfaceId, displayText, effects[]}。interfaceId 整数 [0x0100, 0xFFFF] （与保留系统号带 [0x00,0xFF] 不相交）。效果原语 1–16 步：

效果原语参数语义
exit—程序终止
grant_virtual_filefileId授予虚拟文件能力（fileId ∈ secrets.virtualFiles）
virtual_file_readfileId标记虚拟文件已读（衔接判题谓词 virtual_file_read）
set_flagflagRegister、valueHex置 FLAG 寄存器
noop—占位

派发方式二选一：syscall 0x0201（立即数 ≥0x0100 精确匹配 interfaceId）；或 call {kind:"interface", interfaceId}。接口调用由引擎管理（记录返回地址→执行效果→回下一条）， 不占玩家调用栈——教学中"真实 call（栈帧）"与"接口 call（教学接口）"泾渭分明。

// 例：CH-07"看不见的宝库"的 flag 接口
interfaces: [ { interfaceId: 0x100, displayText: "vault: 读取密档",
                effects: [ { effect: "grant_virtual_file", fileId: "vault-flag" },
                           { effect: "virtual_file_read", fileId: "vault-flag" } ] } ]
// 判题侧配谓词 { type: "virtual_file_read", fileId: "vault-flag" }
// 公开侧 encodingTable 可加 { tokenHex: "0xd4", op: "call",
//   operands: [{ kind: "interface", interfaceId: 0x100 }] }（接口号是公开 ISA 引用）

8. 判题面

8.1 条件结构：7 谓词 × 三级布尔

判题逻辑 = 三级固定深度的布尔组合（第 4 层 Schema 直接拒，XS-NESTING）。all/any 每层 ≤4 分支；空 all = 恒真。

L1: { all?: L2[](≤4), any?: L2[](≤4), not?: L2 }    // 至少一个键
L2: { all?: L3[](≤4), any?: L3[](≤4), not?: L3 }
L3: { predicate: { type: "<谓词>", ...参数 } }

// 例：RIP 到达 win 且栈帧守护完好（MVP CH-03~05 同款）
{ all: [ { all: [ { predicate: { type: "register_equals", register: "RIP", valueHex: "0x1" } },
                  { predicate: { type: "stack_canary_intact" } } ] } ] }
谓词参数语义
register_equalsregister（一般名或 FLAG 名）、valueHex寄存器值等于目标
register_bits_setregister、maskHex按位掩码测试
memory_equalsregionId、offsetBytes、bytesHex（≤256 B）区域内固定切片相等（"守护标记"教学就是它）
memory_containsregionId、bytesHex（≤64 B）区域内子串匹配
ret_target_equalsaddressHexret 弹出目标等于给定值
stack_canary_intact—栈守护完好（canary 未启用时恒真，可放心与其他条件合取）
virtual_file_readfileId虚拟文件已被读（配合作者接口）
判题视角寄存器只读；谓词引用的一切（寄存器 / regionId / fileId / 切片范围）必须在题目里可解析 （XS-PRED-REFS：切片 offset+长度 ≤ 区域长度）。超出"三级布尔 + 七谓词"的判题需求，正确姿势是沉淀为新内置谓词走审计，不是绕。

8.2 judging 三件套

字段约束说明
successCondition 必填L1判胜条件。何时求值：交互判定在检查点触发（如程序结束 / 目标达成）；正式裁决时 verifier 重放到终态后复核。
failureConditions[] 可选0–8 × L1触发即 failed 终态。
hiddenTests[] 可选0–16 × {testId, kind, payloadHex?, expectedResult}隐藏测试（选手不可见）。kind：predicate_probe（终态探针，无输入字节）/ reference_payload（参考输入重放；v1 输入槽未开放，MVP 全部用 probe）。expectedResult ∈ 7 值可达枚举：success|wrong_answer|invalid_action|program_crash|memory_fault|resource_limit|timeout。惯用：一条 final-state-probe 复核 successCondition（答案册语义）。

8.3 正式裁决怎么合成（11 值）

交互终态（won/failed）与正式裁决相互独立（篡改前端 won 拿不到成绩）。verifier 重放你的动作日志 + 跑隐藏测试，按规则合成：failed 粗化优先；非终态提交记 wrong_answer；交互 won ∧ 隐藏测试全过 才 success；驱动出错记 engine_error；重放与在线记录不一致记 replay_mismatch（完整性保护）。 完整 11 值语义见 docs/develop/判题语义规约.md §八·一。出题人的义务：保证参考解在隐藏测试下也过、 失败路径的预期裁决值在语料里钉死。

9. 多阶段状态机（stages[]）

0–8 个阶段；有循环（回边）的 IR 程序必须声明 stages（XC-IR-TERMINATE），每阶段预算必填——这是"循环必须有上限"的落位。

要素约束说明
stageIdobjectId 模式，唯一阶段标识；stages[0] 为首阶段。
allowedActions≤12，⊆ 公开包 allowedActions（XC-STAGE-ACTIONS）本阶段允许的动作。
preconditionsL1，必填进入前置（恒真写 {"all":[]}）。
transitions[]≤8 × {toStageId, onCondition}迁移；目标必须存在且自首阶段全部可达（XS-STAGE-REACH）。
sideEffects[]≤8；v1 仅 {type:"grant_virtual_file", fileId}有限副作用（fileId 必须真实存在，XC-STAGE-SIDE-EFFECT）。
failureConditions[]≤8 × L1触发即 failed 终态。
resourceBudgetmaxInstructionSteps 必填（1–10,000,000）；maxActions?循环上限：无预算的状态 Schema 直接拒（XS-STAGE-BUDGET）。

阶段自身不可再套子状态机；自定义指令/接口效果不引入新编排面（在指令预算内恒定步数求值）。

10. 随机化与 seed

  • seed 永不进公开面。策略二选一（互斥，双闸机检）：fixed（配 seedHex，教学/测试推荐——回放可复现）或 server_random_per_session（每会话服务端随机，禁止携带 seedHex）。
  • declaredSeedPublicPaths 必须老实填：列出 seed 会影响的公开投影叶子（如 visibleRegions.0.bytesHex 形态的点分路径 ≤8 段）；静态题填 []（显式声明无公开随机化面）。 这是侧信道审计的判定基准（T-SC4/ZR-P2），乱填会在发布管线的派生复算里被抓（ZR-B13 检查）。
  • aslrEnabled（公开包，缺省 false）：开启后 startAddressHex 变为镜像内相对布局， 真实基址会话期由种子派生（调试实例与真实实例各自派生——学员会看到"调试地址 ≠ 真实地址"的教学事实）。 开启时必须给 randomizationNotice。MVP 全部缺省关闭（D-J8）。

14. 完整出题实例 ×4

四个实例按难度递增；①②给出可直接照抄的结构，③④指向仓库内活例（全部过门禁 + 真实 worker 裁决回归）。

实例 1 · 最小"写字节"题（入门）

教学目标：认识内存表 + 完成第一次 write_bytes + 认识权限错误。程序只有一个 ret； 判胜条件 = 栈上出现标记字节。（结构 = MVP CH-01 同款）

// 关键面（省略题面文案）：
allowedActions: ["write_bytes", "call", "step", "ret", "run_to_event"],
frame: { buffer: "0x7ffff7f0", savedRbp: "0x7ffff800", retSlot: "0x7ffff808",
         rsp: "0x7ffff800", rbp: "0x7ffff800" },
irProgram: { instructions: [ { op: "ret", operands: [] } ],
             labels: [ { labelId: "entry", instructionIndex: 0 } ] },
successCondition: {                       // 栈底 4 字节 == "STAC"
  all: [ { all: [ { predicate: { type: "memory_equals", regionId: "stack",
                                  offsetBytes: 0, bytesHex: "53544143" } } ] } ] },
// 语料：
//  success:       write_bytes(stack, "53544143")                     → won / success
//  wrong_answer:  write_bytes(stack, "53544145")（差一字节）          → failed / wrong_answer
//  教学失败:       write_bytes(code区, ...)                           → paused / permission_denied
//  crash:         写 8 字节值 + step（ret 弹出非指令索引）             → failed / program_crash

实例 2 · ret2win（IR 模式）

教学目标：栈帧算术——找到返回地址槽，用 payload 覆写它，把控制流劫持到永远不会被正常执行的 win 块。 （仓库活例：apps/session-api/test/extended-challenges/ 的 sm-x01-ret2win-ir；骨架 = MVP CH-04）

// 帧几何：buffer 0x7ffff7f0(16B) | saved RBP 0x7ffff800 | 返回地址槽 0x7ffff808
// buffer → 返回地址槽偏移 = 24 字节。
irProgram:
  0: push RBP            // 序章
  1: mov  RBP, RSP
  2: cmp  RAX, 0x0       // 正常路径判定（RAX 初值 0）
  3: jne  0x8            // 异常 → lose
  4: leave               // ★ 教学：RSP←RBP 后 pop RBP
  5: ret                 // ★ 劫持点：弹出攻击者写入的索引
  [win] 6: mov FLAG0, 0x1337
         7: syscall 0x0   // exit(0)
  [lose] 8: syscall 0x1   // exit(1)
labels: entry=0, win=6, lose=8
// 初始返回地址槽内容 = le64(8)（正常执行只会到 lose；win 只能靠劫持到达）。
// 程序含 ret（动态目标）→ 编译器保守全图可达，win 块合法（XC-IR-REACH）。
successCondition: RIP == win索引(0x6) ∧ stack_canary_intact

// 参考解 payload（一次 write_bytes，24+8 字节）：
//   "41"×16        16 字节填充（刚好漫过 buffer）
//   "42"×8         覆写 saved RBP
//   le64(0x6)      覆写返回地址槽 = win 的指令索引
// 然后执行 step ×2（leave、ret）→ ret 弹出 6 → RIP=6 → won。
// 语料矩阵：success（上面） / wrong_answer（不写 payload 走 lose，exit(1)）
//           / program_crash（返回地址槽写 0xdead → invalid_rip）
//           / 教学失败（向代码区写 → permission_denied）。

学员怎么知道 win 的索引？调试模式（题目默认开启）的指令视图能看到全部指令与地址； 这本身就是教学点：真实 pwn 里找 win 地址靠逆向，这里靠"调试器"。

实例 3 · 最小 ROP（字节模式）

教学目标：gadget 思维——在既有代码里找 pop RDI; ret，栈上串一条链，带着"密钥"调用 win。 （仓库活例：apps/session-api/test/extended-challenges/ 的 sm-x02-rop-minimal；手法 = MVP CH-06 的 bytePatches 形态）

// 编码表（公开）：0xc3=ret  0x90=NOP0  0x5f=pop RDI  0x81=cmp RDI,imm
//                0x75=jne imm  0xcd=syscall imm  0xd0=WINFLAG(自定义零操作数)
// 代码区（0x400000，4KB，rx；0x90 填充）：
//   0x400010: c3                       入口即 ret（"门开着，等你来劫持"）
//   0x400200: 81 EFBE000000000000      win: cmp RDI, 0xDEADBEEF
//             75 0024000000000000           jne fail(0x400220)
//             d0                            WINFLAG（密钥对上才置胜利标记 FLAG0=0x1337）
//             c3                            ret
//   0x400220: cd 0100000000000000       fail: syscall exit(1)
//             c3
//   0x400300: 5f c3                    gadget: pop RDI; ret（"工具函数 load_arg 的收尾"）
// 链布局（写在 buffer，漫过 24 字节到达返回地址槽）：
//   [0x400300][0xDEADBEEF][0x400200]
// 参考解：ret 动作弹出 gadget（会话 ret 只弹一次，不续跑）→ 之后 step×5 推进链：
//   pop RDI 吃进密钥 → ret 弹出 win → cmp 密钥对上 → jne 不跳 → WINFLAG 置 FLAG0。
// successCondition: register_equals FLAG0 "0x1337"     ← 为什么不是 RIP==win？见下方警示框
// 语料：success（带密钥的链）/ wrong_answer（错密钥 → jne 走 fail，exit(1)）
//      / program_crash（链尾端序反转 → invalid_rip）/ wrong_answer（只写填充 → 原入口空转）。
// 学员可见性：编码表公开 + 代码区字节公开（栈/自由视图直接看）→ 可自行"逆向"出 gadget 地址与密钥。
出题人必懂：判定时点（settle）语义。成功条件在每个动作之后即时求值。 如果 ROP 题把判胜写成"RIP 到达 win"，那么 ret 落到 win 地址的那一瞬就已经判胜—— win 块里的 cmp/密钥校验永远来不及执行，"错密钥"的失败语料将无法构造。 正确姿势：判胜条件挂在 win 块内的副作用上（如自定义指令 WINFLAG 置 FLAG0），让块内的门先拦、标记后置。 ret2win（实例 2）没有块内校验，用 RIP == win 才是简洁的正确形态。

实例 4 · 隐藏区域 + 作者接口 flag 题（进阶）

教学目标：存在看不见的内存；"系统调用"是题目定义的接口。仓库活例：MVP CH-07 （corpus.ts 内 sm-ch07-hidden-vault）与扩展题集 sm-x03-int-truncation-ir（整数截断）。

// 隐藏区域：只在私有包声明（公开包无此区域）
initialState.memoryRegions += { regionId: "vault", kind: "key",
  startAddressHex: "0x20000000", byteLength: 4096, permissions: "r",
  contentHex: "<头部放 VAULT_MARKER，正文放 flag 字节>", isHidden: true }
// 作者接口：读密档（§7.2 例）
interfaces: [ { interfaceId: 0x100, displayText: "vault: 读取密档",
  effects: [ { effect: "grant_virtual_file", fileId: "vault-flag" },
             { effect: "virtual_file_read", fileId: "vault-flag" } ] } ]
// 判题：{ type: "virtual_file_read", fileId: "vault-flag" }（＋栈守护等合取）
// 学员侧效果：对 vault 的任何探测与未映射地址完全一致（I-9）；接口调用后有事件/谓词反馈。

16. 边界与 FAQ

问题回答
能用 JavaScript/Python 写题目逻辑吗？不能，永远不能。F-1~F-5 五项禁止由 Schema 结构性保证：没有函数形态、没有代码字符串、没有宿主 IO 原语。你的全部表达力 = 三个封闭词汇面（§5/§7/§8）。
能启用 canary 吗？交互可玩题当前不能（检查器与引擎的契约冲突，挂账收口中）。用"守护标记 + memory_equals"教学替代（MVP CH-05 先例）。
隐藏测试能给输入吗？v1 输入槽未开放，用 predicate_probe（终态探针）。reference_payload 形态已在 Schema 里，等输入槽契约开放。
有汇编文本语法吗？还没有。作者程序当前以编程形态输入（TS 构造）；文本语言另行立项走契约流程。
flag/seed 放哪？flag 在私有包 secrets.flag；seed 在 seedPolicy（fixed 时）。两者永不进公开包、私有语料永不写盘入 git。
学员能看到隐藏区域吗？永远不能——区域不下发即"不存在"，且探测隐藏地址与探测未映射地址的可见结果逐字节一致（I-9）。
我的题判分和我想的不一样？检查三处：successCondition 是否会在"程序结束"时成立；隐藏测试与参考解是否一致；语料里失败路径的预期裁决是否钉对。裁决合成规则见 §8.3。
改了题目要动什么版本？见附录 C：内容改动递增 challengeContentVersion；判题谓词集变化递增 verdictRuleVersion；双包身份三元组必须两侧一致。

动作语义
write_bytes向目标地址写字节（payload 构造的主动作；单次上限见 resourceLimits）

reset重置到题目初始状态

附录 D · 发布前检查清单

  • ☐ 双包身份三元组一致；vmEngineVersion 与当前引擎一致
  • ☐ 公开包零秘密：无 flag/seed/fileId/隐藏区域痕迹（ZR-B8-CAP-SCAN 过）
  • ☐ 初始投影逐字节镜像私有初始态；truncated 标记自洽
  • ☐ FLAG 寄存器只在私有面；秘密汇不出现在公开投影
  • ☐ IR：无死代码；有循环则有 stages 且预算填了；win 块经动态目标可达
  • ☐ 字节模式：代码区 W^X、纯指令流、填充 token 化、入口落代码区
  • ☐ 判题：参考解能过 successCondition + 隐藏测试；失败路径预期裁决在语料钉死
  • ☐ 教学面：题面/目标/提示阶梯/错误注解齐备且为中文
  • ☐ 语料 ≥3 且覆盖 success / wrong_answer / 非平凡失败方向（program_crash 或 memory_fault）
  • ☐ 门禁 + 裁决回归 + （可选）compose 登记全绿；canonicalDigests 确定性通过
