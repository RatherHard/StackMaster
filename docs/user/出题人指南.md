## 一、出题人能做什么、不能做什么

StackMaster 的题目 DSL **不是脚本语言**:它是"结构化题目描述格式 + 封闭指令集白名单"。你的全部表达能力分布在三个**封闭词汇面**上:

| 面 | 词汇上限 | 载体 |
|---|---|---|
| 指令面 | 20 个基线 opcode + 自定义指令(微算子封闭集 v1) | 私有包 `compiledIr` / `customInstructions` |
| 谓词面 | 7 个内置谓词 + 三级布尔组合 | 私有包 `judging` / `stages[]` 条件 |
| 编排面 | 多阶段状态机六要素(≤ 8 阶段) | 私有包 `stages[]` |

因此:

- **可以**:自由命名寄存器与内存区域、定义你自己的虚拟指令集(指令"作用 ↔ 机器码表现"的映射由你定)、定义判题条件与隐藏测试、编排多阶段题目;
- **不能**:注入任何代码(JS/Python/Lua 回调、eval、WebAssembly)、访问宿主环境(文件/网络/进程)、留下无限循环(每个状态必须有指令预算)。这些都由 Schema 结构性拒绝,不存在"绕一下"的写法。

**重要现状(如实)**:作者程序的**文本语言尚未立项**。当前制作路径是**编程形态**——用 TypeScript 构造双包对象(或构造 `AuthorProgram` 交编译器生成),像 `corpus.ts` 那样。文本语法与解析器会随题目制作需求另行立项并走契约流程;在那之前不要期望"写汇编文本出题"。

## 二、双包模型与红线

每道题是**一对** JSON 包:

- **公开描述包(Public Descriptor)**:发给选手浏览器。题面、VM 元数据、可见内存布局、允许动作、提示阶梯、错误教学注解、初始投影;
- **私有判题包(Private Bundle)**:只存在于服务端。完整初始状态(含 flag 值与种子)、隐藏区域、隐藏对象、完整程序(IR 或机器码)、判题条件、隐藏测试。

四条红线(检查器机检,违反即拒绝装载):

1. **flag / seed / 隐藏测试内容 / 虚拟文件内容永不进入公开包**;
2. **隐藏区域和隐藏对象只能在私有包声明**——公开 Schema 结构上不存在"隐藏"表达位;
3. **公开包的初始投影值必须逐字节镜像私有初始态**(否则 `XS-PROJ-VALUES` 拒绝)——"公开值是私有值的白名单切片",不是两套数据;
4. **私有包样例永不入 git**:私有语料一律在代码里现场构造(`corpus.ts` 就是这么做的),仓库里只有公开形态的 fixture。

## 三、制作流程总览

```text
① 构造式 TS 语料(公开包 + 私有包成对构造,公开值镜像私有初始态)
      ↓
② loadChallengePair 装载管线(四层,fail-closed):
   严格 JSON 扫描 → Ajv 双包 Schema → XS-* 检查器全量 → XC-* 编译期校验
      ↓  任一层违规即整体拒绝(方向恒为 challenge_invalid)
③ 语料门禁测试(参考 mvp-challenge-set.test.ts:门禁 + 裁决回归 + 逐题变体)
      ↓
④ 登记 / 发布:经 ChallengeRegistrar 真实登记(compose 套件演示含 Ed25519 签发链路)
```

- 装载失败时你拿到的是**内部诊断**(`CompilerViolation`:规则 ID + 消息 + 路径),面向出题人反馈;玩家侧只会看到笼统的 `internal_error`,不会泄漏你的私有细节;
- 生成面产物(`compileProgram` 产出的 `compiledIr` 或字节流)**必须再过一遍 `loadChallengePair`** 才能进私有包——编译器也要被同一道门检查。

## 四、定义虚拟机(`vmProfile`,公开包)

| 字段 | 你的选择 |
|---|---|
| `archBits` | `32` 或 `64`。所有架构值(寄存器初值、立即数、位移)按此位宽校验域,64 位容器承载、高位掩蔽 |
| `endianness` | 固定 `little`,没有选择 |
| `pageSizeBytes` | 4096 的倍数(4096–65536) |
| `registers[]` | **双命名空间自由命名**:一般寄存器 `^[A-Z][A-Z0-9_]{0,15}$`;FLAG 保留区 `^FLAG[A-Z0-9_]*$`(放你的秘密标志寄存器,值永远私密)。1–64 个,**必须含 `RSP` / `RBP` / `RIP`**;每个可带 `displayLabel` |
| `flagRegisterNames?[]` | 你打算秘密使用的 FLAG 寄存器名单(只公开名字,值私密;名字本身不得出现在 `registers[]` 里) |
| `canary` | `{enabled, sizeBytes?}`(1–8 字节)。**交互可玩题当前请勿启用**,见第十五章已知边界 |
| `encodingTable?[]` | 声明即进入**字节模式**(第七章);不声明 = IR 模式(第六章,默认) |

## 五、内存布局(`memoryLayout` + 私有 `initialState`)

- 区域 1–64 块;每块 `byteLength` 为 4096 的倍数(1–16 MiB);全部区域合计 ≤ 64 MiB,内容合计 ≤ 2 MiB;地址区间不得越过 2^64;
- 区域类型六选一:`code` / `global` / `stack` / `heap` / `key` / `custom`(custom 需 `publicLabel` 承载类型名);
- **可见性规则**:公开包的布局 = 你想让选手看到的全部区域;想藏的区域只写进私有包 `initialState.memoryRegions[]`(`isHidden: true`),且地址不得与任何公开区域重叠;`kind: code` 区域至多一块、不得隐藏、必须出现在初始投影;
- **私有对象**(`privateObjects`,≤ 64 个):给 buffer、canary、saved RBP、返回地址槽等打语义标(`kind`),`visibility: public|hidden`、`containsSecret: boolean`。规则:`containsSecret ⇒ hidden`(`I3-SINK-HIDDEN`);
- 公开包 `initialProjection`:`visibleRegions`(与布局双射,`bytesHex` 是私有内容的同长前缀切片 + `truncated` 标记)、`visibleRegisters`(值必须等于私有初值;FLAG 与秘密汇寄存器禁止出现)、`semanticHighlights`(≤ 32 条,比如"buffer 起点""返回地址槽",选手的结构视图靠它)。

## 六、写程序:IR 模式(默认)

私有包 `compiledIr` = `{irFormatVersion: 2, entrypointIndex?, instructions[](1–4096), labels[]}`。

### 20 个基线 opcode

| 类别 | opcode | 备注 |
|---|---|---|
| 数据传送 | `mov`(R,I/R,R/R,M/M,R)、`push`、`pop` | |
| 栈帧 | `leave` | `RSP←RBP` 后 `pop RBP`;教学核心:溢出覆写 saved RBP 后,`leave` 劫持 RSP、`ret` 弹出攻击者地址。要求初始寄存器集含 `RBP` |
| 算术 | `add` / `sub` / `cmp` | 三标志 `zf`/`cf`/`sf`;`cmp` 只置标志不写回;`add` 溢出走引擎安全终止(不静默回绕) |
| 位运算 | `and` / `or` / `xor` / `shl` / `shr` | |
| 控制流 | `jmp` / `je` / `jne` / `jb` / `jae` / `call` / `ret` | 标签操作数等价于立即数槽(取地址语义);`call` 深度 ≤ 64 |
| 教学 IO | `syscall` | 保留号带 [0x00, 0xFF] 只有内置 `exit`;≥ 0x0100 走作者接口(第八章) |

规则要点:

- 立即数 = **无符号**架构值;内存位移 = **有符号**(base 寄存器 + 位移);越位宽即拒(`XS-ARCH-WIDTH`);
- 编译器校验(`XC-*`):逐 opcode 操作数形态、寄存器引用必须在私有初始寄存器集内、立即数跳转目标必须界内、**纯静态程序不允许死代码**(`XC-IR-REACH`)、**存在回边就必须声明 `stages[]`**(`XC-IR-TERMINATE`——循环必须有预算,见第九章);
- `ret` / `jmp R` / `jmp M` / `call R` 是动态目标:gadget 语义,运行期落点不静态校验,由资源预算兜底。

## 七、写程序:字节模式(可选,机器码形态)

在公开包声明 `vmProfile.encodingTable`(≤ 64 条 `{tokenHex, op, operands?}`)即进入字节模式:代码区 `contentHex` 就是可执行空间,入口 = 私有包 `entrypointAddressHex`(字节偏移)。

- **ISA 公开立场**:编码表放公开包——选手看到"字节 ↔ 助记符 ↔ 展示文本",但自定义指令的**语义**仍在私有包;谜题在 gadget 构造,不在解码;
- token 定宽 1 字节,表内唯一;寄存器烘焙进 token(同一助记符不同寄存器 = 不同 token);立即数 / 位移内联在指令流中,定宽 `archBits/8` 字节小端;立即数 `width` / 位移 `displacementWidth` 必须显式声明为 `"arch"`;
- 代码区约束:**纯指令流**(数据放其他区域)、**W^X**(代码区权限不得含 `w`,写代码区运行时报 `memory_fault`)、尾部填充必须用表内 token;字节模式代码区恰为"一个公开 + 一个非隐藏私有";
- **任意 token 边界取指是第一等能力**:RIP 可以落到指令中间——这是 ret2win / ROP 风格教学的地基;
- 发布管线会做**入口探测译码**(`XS-ENC-PROBE`):从入口线性译码 ≤ 4096 条,未知 token / 截断即拒;不可达字节不判罚,运行时 `invalid_rip` 兜底。

## 八、自定义指令与作者接口(私有包声明面)

两者都是**声明式映射表**(数据),由引擎按封闭原语解释执行——不是函数,没有控制转移,步数恒定。

### 自定义指令 `customInstructions[]`(≤ 16 条)

`{mnemonic(大写助记符,与基线小写结构性不相交), displayText, semantics[](1–16 步)}`,微算子六选一:

| 微算子 | 语义 |
|---|---|
| `load_imm` | 立即数装载 |
| `mov_reg` | 寄存器间传送 |
| `load_mem` / `store_mem` | 基址 + 位移内存读 / 写 |
| `set_flag` | 置 FLAG 寄存器(**唯一**能写 FLAG 的微算子) |
| `bit_mask` | 位掩蔽(and/or/xor) |

### 作者接口 `interfaces[]`(≤ 16 条)

`{interfaceId(整数 0x0100–0xFFFF,与保留系统号带不相交), displayText, effects[](1–16 步)}`,效果原语五选一:

| 效果原语 | 语义 |
|---|---|
| `exit` | 程序终止 |
| `grant_virtual_file` | 授予虚拟文件能力 |
| `virtual_file_read` | 标记虚拟文件已读(衔接判题谓词) |
| `set_flag` | 置 FLAG 寄存器 |
| `noop` | 占位 |

派发方式:`syscall N`(N ≥ 0x0100)或 `call {kind:"interface", interfaceId}`。**接口调用由引擎管理**(记返回地址 → 执行效果 → 回到下一条),不占玩家调用栈——教学中"真实 `call`(栈帧)"与"接口 `call`(教学接口)"泾渭分明。这是"题目定义自己的系统调用"的正规通道(CH-07 的虚拟文件 flag 就是这么做的)。

## 九、判题面(`judging` / `judgingConfig` / `stages[]`)

### 判定条件:7 谓词 × 三级布尔

谓词七选一:

| 谓词 | 用途 |
|---|---|
| `register_equals` / `register_bits_set` | 寄存器值 / 位判定 |
| `memory_equals` / `memory_contains` | 定长切片相等 / 有界子串匹配(≤ 64 字节) |
| `ret_target_equals` | 返回地址目标判定 |
| `stack_canary_intact` | 守护标记完好判定 |
| `virtual_file_read` | 虚拟文件已读(配合作者接口) |

组合结构固定三级(深度即 Schema 属性,第四层直接拒):

```text
L1: { all?[](≤4) / any?[](≤4) / not? }   // 至少一键;空 all = 恒真
L2: 同形,元素为 L3
L3: { predicate: ... }
```

- `successCondition`(必填):判胜条件;
- `failureConditions[]`(0–8):触发即判负;
- 超出这套词汇的判题逻辑,正确姿势是沉淀为新内置谓词走审计,不是想办法绕。

### 隐藏测试 `hiddenTests[]`(0–16)

`(输入, 预期判定)` 对:`kind: reference_payload | predicate_probe`,`expectedResult` ∈ 7 个可达判定值(`success / wrong_answer / invalid_action / program_crash / memory_fault / resource_limit / timeout`)。

**v1 现状(如实)**:输入槽(D-H2)尚未开放,当前隐藏测试实际形态为 `predicate_probe`(终态探针,类似"答案册"):对 `successCondition` 的终态做独立复核。需要"给定输入应得什么"的题目请等输入槽契约开放。

### 多阶段状态机 `stages[]`(0–8 个)

每个阶段六要素(缺一不可的预算是反无限循环的关键):

| 要素 | 约束 |
|---|---|
| `allowedActions` | 12 动作的子集,且 ⊆ 公开包 `allowedActions` |
| `preconditions` | L1 条件,必填(恒真写 `{all: []}`) |
| `transitions[]` ≤ 8 | 目标必须存在且自首阶段全部可达 |
| `sideEffects[]` ≤ 8 | v1 仅 `grant_virtual_file` |
| `failureConditions[]` ≤ 8 | 触发即 `failed` 终态 |
| `resourceBudget` | `maxInstructionSteps` **必填** > 0(这就是循环预算) |

### 判题配置 `judgingConfig`(必填)

`verdictRuleVersion`(semver)、`maxPredicateEvalSteps`(1–10,000,000)、可选 `timeoutMsPerAction`(≤ 60,000)、`maxTotalActionBytes`(≤ 1 MiB)。

正式裁决怎么合成(给你建立预期):交互终态与隐藏测试汇总成 11 值之一——交互 `failed` 优先粗化、非终态提交记 `wrong_answer`、交互 `won` ∧ 隐藏测试全过才 `success`、驱动出错记 `engine_error`。语义权威见 `docs/develop/判题语义规约.md` §八·一。

## 十、教学面(公开包)

- `briefing`:`title`(≤ 128)+ `summary`(≤ 2048)+ `learningObjectives[]`(1–8 条)+ 可选 `teachingNotes[]`(≤ 8 条);
- `hintLadder[]`(0–8 级):`{order, revealPolicy: on_request | after_n_failures, failureThreshold?, hintText}`——按请求揭示或失败 N 次后揭示;
- `publicErrorMapping[]`(0–16 条):按 16 个错误码配 `teachingNote`,玩家的错误解释器据此教学;
- `authorBlocks`(公开包,M10 新增,可选):**出题者积木**——见下方小节。

### 出题者积木 `authorBlocks[]`(M10 新增,公开包可选)

**它解决什么**:初学者不该先学汇编才能动手。你可以在公开包里声明若干**积木模板**,学习者在"程序"窗口里拖积木、填参数,再单步运行;每个模板被编译成**你声明的 12 个公开动作**的固定序列,由服务端权威执行。它**不是**判题面(判题永远只看私有包),也**不是**授权放大(服务端仍逐个动作重新校验)。

**最小形状**(每项 = 一个模板,最多 16 个):

```jsonc
"authorBlocks": [
  {
    "id": "overwrite-return",          // 1–63 字符,小写 + 数字 + 连字符,题目内唯一
    "displayText": "覆写返回地址",       // 积木上显示的文字(≤ 128)
    "interfaceId": 512,                 // 指向你私有包 interfaces[] 里已声明的接口(256–65535)
    "slots": [                          // 最多 4 个"槽"= 学员要填的空
      { "key": "target", "label": "目标地址", "kind": "address" }
    ],
    "actions": [                        // 最多 8 个动作,按下单顺序展开
      { "type": "write_bytes",
        "args": { "addressHex": { "slot": "target" }, "bytesHex": "4141414141414141" } },
      { "type": "call", "args": { "targetHex": { "slot": "target" } } }
    ]
  }
]
```

**规则(写错会被拒)**:

1. `actions[].type` 只能是 12 个公开动作之一(与 `allowedActions` 同一枚举),参数名必须用该动作的冻结参数名;值要么是字面量字符串,要么是 `{ "slot": "槽键" }` 的**结构化引用**;
2. `slots[].kind` ∈ `address` / `immediate` / `length`(决定学员输入框的形态);槽键题目内模板内唯一,引用了不存在的槽、或声明了槽却没人用,都会被拒;
3. `interfaceId` **必须**在私有包 `interfaces[]` 里声明过——这是唯一"公开引私有"的许可面,未声明即拒(所以它不会泄露隐藏接口的存在性);
4. **公开面不许出现效果语义**:不要写 `effects` / `semantics` / `flagRegister` / `fileId` 这类私有键,也不要把隐藏区域名 / 隐藏对象名 / 秘密汇或 FLAG 寄存器名写进 `displayText` 或槽标签(`XS-BLOCK-NO-EFFECT` 递归扫描)——效果原语序列只存在于私有包 `interfaces[].effects`;
5. **`allowedActions` 是权威**:模板里写了、但题目 `allowedActions` 没放开的动作,学员运行时会被裁剪并以 `unauthorized_action` 拒绝(报错会带上积木 id,便于定位);
6. **不声明 `authorBlocks` 的题目包行为完全不变**(工具箱与编译面与 M10 之前一致)——这是向后兼容的**可选**字段,`schemaVersion` 仍是 1;
7. 积木**非图灵完备**:没有变量、循环、条件、表达式。要表达逻辑就多声明几个模板,或把逻辑放回 `interfaces[]` 的私有效果序列。

## 十一、资源预算与随机化

- 公开包 `resourceLimits`:`predicateEvalBudgetPerSession`(≤ 1,000,000)、`rollbackBudgetPerSession`(≤ 10,000)、`maxWriteBytesPerAction`(≤ 4096,协议硬上限);
- **seed 策略**(`seedPolicy`,私有包,二选一互斥):`fixed` ⇒ `seedHex`(16–64 hex 字符)必填;`server_random_per_session` ⇒ 禁止携带 seed 值。seed 是秘密,永不进公开面;
- `declaredSeedPublicPaths`(必填,可空数组):声明"随机化会影响哪些公开投影叶子"(点分路径 ≤ 8 段);空数组 = 显式声明"无公开随机化面"。这是侧信道审计的判定基准,老实填;
- `aslrEnabled`(公开包,缺省 false):true 时 `startAddressHex` 变为结构描述(相对布局),真实基址会话期派生,且**必须**同时给出 `randomizationNotice`(文案只声明"存在随机化",禁写策略与熵上界)。

## 十二、校验会拒绝你什么(高频规则速查)

| 你可能犯的错 | 拒绝你的规则 |
|---|---|
| 忘了声明 `RSP`/`RBP`/`RIP` | `XS-REG-CORE` |
| FLAG 寄存器值出现在公开投影 | `I3-VISIBLE-REG` / `XS-REG-FLAG` |
| 公开初始值与私有初始态不一致 | `XS-PROJ-VALUES` / `XS-PROJ-GEOM` |
| 公开包里出现 `fileId` / `objectId` / capability 字符串 | `XS-ID-NO-PRIVATE` / `ZR-B8-CAP-SCAN` |
| 立即数 / 位移超出 archBits 域 | `XS-ARCH-WIDTH` |
| 区域大小 / 页大小不是 4KB 倍数 | `XS-MEM-PAGE-ALIGN`(Schema 层也拒) |
| IR/字节两种程序形态双给或双缺 | `XS-PROG-MODE` |
| 字节模式代码区可写 / token 不在表内 / 入口不在代码区 | `XS-CODE-WRX` / `XS-ENC-TOKEN` / `XS-ENC-PROBE` |
| 自定义指令语义里想加跳转 | 微算子封闭集结构性拒绝(没有控制转移微算子) |
| 死代码(纯静态程序) | `XC-IR-REACH` |
| 有循环没声明 stages(或 stages 没写 `maxInstructionSteps`) | `XC-IR-TERMINATE` / `XS-STAGE-BUDGET` |
| 阶段动作超出题目允许面 / 副作用引用不存在的虚拟文件 | `XC-STAGE-ACTIONS` / `XC-STAGE-SIDE-EFFECT` |
| `displayText` 里夹带隐藏区域名 / 测试 ID / fileId | `XS-CUSTOM-DISPLAY` |
| 积木引用了私有包里没声明的接口 `interfaceId` | `XS-BLOCK-IFACE-REF` |
| 积木槽键重复 / 超过 4 个 / `kind` 写错 / 引用了不存在的槽 | `XS-BLOCK-SLOT-FORM` |
| 积木动作不是 12 个公开动作之一 / 参数名写错 / 少写必填参数 | `XS-BLOCK-ARG-ALLOW` |
| 积木里夹带 `effects` 等私有键、或展示文本含隐藏区域名 / FLAG 寄存器名 | `XS-BLOCK-NO-EFFECT` |
| 两个积木模板 `id` 重名 | `XS-ID-UNIQUE` |

## 十三、登记与发布

- 题目经 `ChallengeRegistrar` 登记进 session-api(规范化摘要 `canonicalDigests` 作为登记哈希输入,发布演示含 Ed25519 签发链路)——参考 compose 套件 `mvp-challenge-set` 的真实登记路径;
- **如实边界**:CDN 分发、生产密钥管理属生产部署面,MVP 范围内未做;当前发布形态 = dev/CI 拓扑内登记。**管理后台(admin)**:`apps/admin` 的**只读最小面已落地**(D-MP-5 分支 A:题目登记列表 / 裁决查询 / 成绩导出,独立凭证 + 独立只读角色 `admin_ro`,全部 GET、零业务写路由);**完整管理后台**(写面 / 运营功能)仍不在 MVP 范围。对出题人的直接影响:登记与发布链路**不变**,admin 面只是**只读查看**已登记题目与裁决的运维入口。

## 十五、已知边界与坑(制作前必读,均为如实登记)

1. **交互可玩题不要启用 canary**:`XS-CANARY-CORR`(启用 ⇒ 私有包须有隐藏的、含秘密的 canary 对象)与引擎装配(canary 槽必须 public)在冻结契约下结构性不相容。金丝雀教学的正确姿势 = CH-05 的"守护标记 + `memory_equals` 谓词"。契约收口已挂账(WP-1 §1.3),收口前请勿启用;
2. **ASLR 缺省关闭**(D-J8 定案):MVP 题目集全部 `aslrEnabled` 缺省;真实实例固定基址,ASLR 只在调试实例兄弟形态;
3. **隐藏测试暂无输入槽**(见第九章),`predicate_probe` 形态;
4. **文本 DSL 未立项**(见第一章),别按"汇编文本"设计制作流程;
5. 私有包样例**永不入 git**——语料全部代码内构造,fixture 只放公开形态;
6. **积木(`authorBlocks`)的校验是两层的,且客户端那层更弱**:权威校验在服务端 / 编译前置(双包检查器,含"接口是否真的声明过"),而浏览器端只做形状闸(键集封闭 + 动作枚举 + 参数名禁令)——因为浏览器只依赖协议、拿不到你的私有包。所以"本地看着能拖出来"不等于"服务端一定受理";发布前请以服务端校验结果为准。

## 十六、最好的学习材料

按难度递增读 MVP 八题的构造源(`apps/session-api/test/mvp-challenges/corpus.ts`):CH-01 教你最小公开/私有对;CH-03/04 教栈帧布局与溢出判题;CH-05 教"守护标记"替代 canary;CH-06 教字节模式与编码表;CH-07 教隐藏区域 + 作者接口 + 虚拟文件;CH-08 教两阶段状态机。每一题都通过了全套装载门禁与裁决回归——抄结构,改内容,是你的最快路径。
