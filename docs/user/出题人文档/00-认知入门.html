0.1 出题人视角的 StackMaster（3 分钟）

传统 pwn 出题：你写一个二进制、藏一个 flag、丢到服务器上，选手 nc 连上来盲打。StackMaster 把这套流程换成 "看得见内部的服务端虚拟机"：选手在浏览器里能看到内存的每一个字节、用受限的动作（写字节、单步、压栈……）亲手操作虚拟机， 而每一个动作都在服务端的权威虚拟机里执行并被记录；提交时由独立的裁决服务把操作日志从头重放一遍来打分—— 所以选手改浏览器、伪造界面都拿不到成绩。

作为出题人，你产出的不是二进制，而是一对 JSON 包，外加一组"证明这道题可解、判分正确"的自动化语料：

你交付什么给谁看 / 用类比传统 pwn
公开描述包（一个 JSON）选手浏览器：题面、可见的内存布局、提示阶梯、错误教学注解题面 + 二进制文件（但内存布局是明牌）
私有判题包（一个 JSON，只在服务端）服务端：flag、随机种子、完整程序、判题条件、隐藏测试服务器上的 flag 文件 + 判题脚本
语料模块（TypeScript 代码）发布管线：程序化地构造上面两个包 + 解法脚本 + 预期结果出题的"源代码"
一句话：你设计一个"透明的栈实验室"（公开包决定选手看到什么），再配一套"自动判分规则"（私有包决定怎么算赢）， 最后用代码把它们构造出来、测试通过、登记发布。

这套模型的直接推论（后面所有章节都会反复回到这三条）：

  • 选手看到的每一个字节，都是你主动下发的——没下发的东西（flag、隐藏区域、窗口外内存）结构上就不在浏览器里，不存在"被找到"；
  • 题目逻辑不能写代码——你的全部表达能力是三个封闭词汇表：20 条指令、7 个判题谓词、1 种状态机写法； 想写 JavaScript/Python 注入逻辑？语法上不存在这个位置。这保证了题目本身永远不会成为攻击面；
  • 判分是重放，不是信任——成绩由"重放操作日志 + 跑隐藏测试"合成，你只需要保证：参考解真能赢、失败路径的预期分值钉得对。

0.2 一道题的一生（全局地图）

从你动笔到选手拿到成绩，一道题走完这 9 站。每一站在第 1 层都有对应的概念详解，在第 2 层有照着做的任务指南：

 ① 构造        你写一个 TS 语料模块，进程内构造出 公开包 + 私有包 对象
               （私有内容只在内存里，永不写盘入 git）
                   │
 ② 装载校验    loadChallengePair 四层管线：JSON 扫描 → Schema 校验
               → XS 检查器（安全与一致性）→ XC 编译器（程序语义）
               任一层违规 = 整体拒绝，你收到规则ID+消息+路径
                   │
 ③ 门禁与回归  门禁测试（装载全绿 + 登记摘要确定性）
               + 裁决闭环测试（真实 vm-worker 重放你的解法 → 断言 11 值裁决）
                   │
 ④ 登记        ChallengeRegistrar：规范化 JSON 落桶 + Ed25519 签名验签 + PG 建档
               （登记版本不可变；内容版本号区分迭代）
                   │
 ⑤ 游玩        选手浏览器拿到公开包 → 创建会话 → 逐动作操作内存
               （每个动作服务端权威执行、记录，revision 单调 +1）
                   │
 ⑥ 交互判定    动作后即时求值 successCondition → 界面显示 running/paused/won/failed
               （这只是"即时反馈"，不是成绩）
                   │
 ⑦ 提交        选手点提交 → 服务端把规范化操作日志入队
                   │
 ⑧ 独立裁决    verifier 复用同一引擎重放日志 → 跑隐藏测试 → 合成 11 值裁决
                   │
 ⑨ 成绩        verdict 落库并呈现（success / wrong_answer / program_crash / …）

0.3 术语速查卡（先混个脸熟）

每条一句话。看完有个印象即可，第 1 层会把每个词展开讲透。

术语一句话解释
公开描述包发给选手浏览器的 JSON：题面、可见内存布局、允许动作、提示、初始投影
私有判题包只在服务端的 JSON：flag、种子、完整程序、判题条件、隐藏测试
双包模型一道题 = 这两个包成对出现，身份三元组必须一致
投影服务端按白名单发给浏览器的"状态照片"——浏览器里的一切都来自它
初始投影选手打开题目看到的第一屏（区域前缀字节 + 寄存器初值 + 语义高亮）
寄存器虚拟机的存储单元；RSP=栈顶指针、RBP=当前栈帧基址、RIP=执行位置，三者必选
FLAG 命名空间FLAG 开头的保留寄存器名——值永远私密，用于"到达胜利态置标记"
位宽 archBits32 或 64；所有数值按此宽度截断掩蔽
小端序低位字节放低地址——数值写入内存后看起来"倒着"
内存区域 region一段连续内存（code/global/stack/heap/key/custom 六类），页对齐
隐藏区域只在私有包声明的区域；选手探测它与探测"不存在的地址"结果完全一致
私有对象给 buffer / 返回地址槽等打的语义标签，供判题与审计用
IR 模式程序 = 指令数组；跳转目标是"第几条指令"；内存里的字节只是数据
字节模式程序 = 真实机器码字节；内存里的代码区可执行，任意位置可开始取指（gadget 语义）
opcode指令名；基线封闭 20 条（mov/push/pop/leave/add/…/syscall）
标志位zf/cf/sf 三个一位寄存器，cmp 比较、条件跳转消费
栈帧函数调用在栈上的记录：局部 buffer + saved RBP + 返回地址
返回地址劫持溢出覆写返回地址槽，让 ret 跳到攻击者指定位置——pwn 教学核心
canary / 守护标记栈保护哨兵；交互题用"守护标记 + memory_equals 谓词"替代真 canary
谓词判题的最小判断单元，共 7 个（寄存器等于/内存相等/……/虚拟文件已读）
三级条件谓词的三层布尔组合（all/any/not，每层 ≤4 分支）
隐藏测试选手不可见的复核用例；v1 为"终态探针"（对照答案册）
交互终态界面上的 won/failed——即时反馈，与成绩无关
正式裁决verifier 重放日志 + 隐藏测试合成的 11 值成绩（success 等）
stages 状态机多阶段题目编排；每个阶段必须带指令预算（循环的上限）
种子 seed随机化的确定性来源；策略二选一，值永不公开
检查器 XS-*安全与一致性规则集（"公开包不得含秘密"等），装载时全量执行
编译器 XC-*程序语义规则集（操作数形态、死代码、循环⇒预算）
装载管线四层 fail-closed 校验；装载失败方向恒为 challenge_invalid
规范化 JSON同一 JSON 的确定性字节写法；登记摘要 = 其 SHA-256
语料模块你写的 TS 代码：构造双包 + 解法脚本 + 预期结果
