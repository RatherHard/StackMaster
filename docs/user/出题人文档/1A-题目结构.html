A1 · 双包模型 概念 · 题目结构

一句话：一道题 = 公开描述包 + 私有判题包两个 JSON；公开包决定选手看到什么，私有包决定服务端怎么判， 两个包必须同声明同一个题目身份（challengeId / 内容版本 / VM 版本）。

为什么是两个包。为什么是"两个包"而不是"一个包加权限控制"？因为 StackMaster 的安全模型是结构性不可达， 不是访问控制。传统思路是"敏感字段加 secret: true 标记，服务端下发时过滤"——过滤逻辑一旦有漏洞就泄漏。 StackMaster 直接把公开包的 Schema 写死：里面根本不存在"隐藏区域""flag""种子"这类字段（additionalProperties: false + 元检查禁止私有属性名出现）。你想泄漏都没有语法位置。私有包则整体 SERVER_ONLY：只被后端装载， 浏览器构建图在 CI 里被依赖规则禁止接触它，公开产物扫描还会扫描发布物确认零泄漏。

两个包各自的"户口"：

信息放哪理由
题面、学习目标、提示阶梯、错误教学注解公开包选手要读
可见内存布局、寄存器名、允许动作、初始投影公开包选手界面据此渲染
flag、随机种子、虚拟文件内容私有包泄漏 = 题目作废
完整初始状态（含隐藏区域）私有包隐藏性即谜题
程序（IR 或机器码）与自定义指令语义私有包（字节模式的编码表例外，见 D6）语义即答案的一部分
判题条件、隐藏测试私有包判题标准不能让选手看到

为什么这样设计。这是"后端权威 VM + 浏览器公开投影"信任模型在题目层的落位：浏览器完全不可信， 所以一切秘密留在服务端；跨域只传投影；题目包是版本化的序列化格式而不是共享代码——TS 与 Rust 两侧只共享 JSON Schema 这一份契约。

例子。同一道题的两个包（示意，只列关键差异）：

公开包（选手可见）                     私有包（仅服务端）
{                                      {
  "challengeId": "sm-x01-ret2win-ir",    "challengeId": "sm-x01-ret2win-ir",   ← 身份必须一致
  "briefing": { "title": "幕间收尾…"},    "secrets": { "flag": "FLAG{...}" },  ← 秘密
  "memoryLayout": { "regions": [          "seedPolicy": { "strategy": "fixed",
    { "regionId": "stack", … } ]},                      "seedHex": "0011…" },
  "initialProjection": { …可见前缀… },     "initialState": { …完整状态,含隐藏… },
  "hintLadder": [ … ]                    "judging": { "successCondition": …,
}                                                      "hiddenTests": [ … ] }
                                       }
常见误解。 ①"隐藏区域可以在公开包里标 isHidden: false"——公开包 Schema 里没有 isHidden 字段，写了直接拒绝； ②"私有包里也放一份题面方便服务端用"——可以但不该：题面的唯一真源在公开包，两份会漂移； ③"两个包是同一份数据的不同视图"——不是，它们是镜像关系（见 A4）：公开值必须逐字节等于私有值的对应切片。

A2 · 公开描述包里有什么 概念 · 题目结构

一句话：公开包回答四个问题——这是道什么题（briefing）、机器长什么样（vmProfile）、 内存哪些可见（memoryLayout + initialProjection）、选手能做什么、做错了我教什么（allowedActions + 提示与错误注解）。

逐块说明。逐块看（完整字段表在 R1）：

块回答什么关键约束
身份四字段这是谁、第几版challengeId 小写连字符；内容/VM 版本 semver；与私有包同值
briefing题面：标题/摘要/学习目标/教学备注长度上限 128/2048/8×256/8×512；禁控制字符
vmProfile虚拟机画像：寄存器集、位宽、端序、页大小、canary、（字节模式）编码表必含 RSP/RBP/RIP；详见 1B / D6
memoryLayout可见区域布局（选手能看哪些内存）≤64 块；每块 4KB 对齐 1–16MiB；无隐藏表达位
allowedActions选手能用 12 个会话动作中的哪几个子集选择；教学建议最少 ["write_bytes","step"]
resourceLimits会话级预算（谓词求值/回滚/单次写字节）全可选，上限见 F4
hintLadder提示阶梯（≤8 级）按请求揭示或失败 N 次自动揭示
publicErrorMapping错误码 → 教学注解（≤16 条）错误码从 16 值冻结枚举里选
initialProjection第一屏：区域前缀字节、寄存器初值、语义高亮必须逐字节镜像私有初始态（A4）
randomizationNotice / debugMode / aslrEnabled三个可选开关ASLR 开 ⇒ 必须带随机化声明文案；debugMode 缺省开

为什么这样设计。注意公开包里没有任何"判题"信息——选手不该从题面推断出成功条件的措辞； 也没有任何"隐藏"表达位——这是 A1 说的结构性不可达。提示与错误注解放公开包，是因为它们本来就是给选手的教学服务， 且由选手本地渲染（提示揭示的失败计数也在本地进行，不发网络请求，不产生侧信道）。

常见误解。①"提示阶梯的服务端会拦着不让看"——揭示策略在界面本地执行，公开包本来就把提示发给选手了， "藏"只藏后面的级别；②"debugMode 关了更安全"——它只控制沙盘功能开关，与安全无关；③"错误注解会泄漏判题逻辑"—— 注解是纯教学文案，经 E-4/E-6 扫描禁止夹带隐藏区域名、测试 ID、fileId。

A3 · 私有判题包里有什么 概念 · 题目结构

一句话：私有包 = 这道题的答案与判卷标准——完整初始状态、程序本体、判题条件、隐藏测试、秘密与种子， 整体 SERVER_ONLY，永不离开服务端，也永不写入 git。

七个组成部分。七个组成部分（完整字段表在 R2）：

部分内容概念链接
身份 + 版本锚与公开包同值的身份三元组；dslSchemaVersion（词汇版本）；vmEngineVersion（锁定执行引擎）R6 版本表
seedPolicy + declaredSeedPublicPaths随机化策略 + "随机化影响哪些公开面"的声明F2
initialState完整寄存器初值（含 FLAG 值）+ 全部内存区域（含隐藏，contentHex 逐字节）C2
secretsflag（8–128 字符）+ 虚拟文件（≤8 个，每个 ≤4096 字符）D5
privateObjects语义对象登记（buffer / saved_rbp / return_address / canary / file / other）C3
程序compiledIr（IR 模式）或 entrypointAddressHex（字节模式）——恰一；可选 customInstructions / interfaces / stages1D / 1F
judging + judgingConfig成功条件 / 失败条件 / 隐藏测试 + 判题配置1E

为什么这样设计。注意 vmEngineVersion 是必填：题目程序会在引擎上重放（游玩一次、裁决再重放一次）， 把执行环境版本钉死是"重放确定性"的前提。同理 contentHex 要求长度一字节不差等于 2×byteLength—— 内存是稠密定义的，不存在"未初始化"的字节，重放才能逐字节一致。

常见误解。①"私有包是加密存储的"——纪律是不落盘、不进 git：语料在代码里现场构造， 存储层另有快照加密，但你的责任是"别把它写进任何文件"；②"测试时可以用假 flag，上线再换"——flag 长度参与变体测试， 正式发布用真实占位格式（如 FLAG{...}）并在内容版本递增时替换。

A4 · 镜像原则与秘密零驻留 概念 · 题目结构

一句话：公开包里每一个值，都必须逐字节等于私有初始态的对应切片——公开包是私有包的"白名单前缀拷贝"， 不是两套独立数据。

三条强制规则。镜像原则由三条检查器规则强制：

  • 几何镜像（XS-PROJ-GEOM / I2-PUB-MIRROR）：公开布局的每块区域，在私有包里有一块同名、同起点、同长度、同权限的非隐藏区域对应——公开区域是私有非隐藏区域的全集；
  • 值镜像（XS-PROJ-VALUES）：初始投影的 bytesHex 必须等于私有区域 contentHex 的同长前缀切片；寄存器公开值必须等于私有初值；
  • 反向排除（I3-VISIBLE-REG / XS-REG-FLAG）：FLAG 寄存器与声明为秘密汇的寄存器，禁止出现在公开投影；containsSecret 的对象必须 hidden 且不与公开区域重叠。

为什么这样设计。如果允许两套数据，"公开显示 A、私有实际是 B"会造成两类灾难：判题与展示不一致（选手做对了却判负）； 或者更糟——两者的差集本身就是泄漏信道（T-SC1 差分测试专门断言"响应是可见状态的确定性函数"）。 镜像原则让"初始投影 = 函数(私有初始态)"成为可机检的恒等式。

私有: contentHex = "53544143 4B4D 0000 …"（32 B）
公开: bytesHex   = "53544143 4B4D"（前 6 B）, truncated: true   ← 前缀切片 + 诚实截断标记
常见误解。①"我可以在公开包里放一份'美化过的'初始值"——拒绝（XS-PROJ-VALUES）； ②"隐藏区域反正看不到，地址随便放"——隐藏区域地址不得与公开区域重叠（I2-HIDDEN-NOT-PUBLIC），否则重叠部分既是"隐藏的"又"可见的"，自相矛盾；③"秘密汇只是建议"——是硬检查，FLAG 命名寄存器永远进不了公开投影。
