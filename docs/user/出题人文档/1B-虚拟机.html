1B 虚拟机 概念组 · 4 个概念

本页目录　B1 · 位宽、端序与页　B2 · 寄存器与双命名空间　B3 · 栈、栈帧与劫持　B4 · canary 与守护标记

B1 · 位宽、端序与页 概念 · 虚拟机

一句话：你声明 archBits（32/64）决定所有数字多宽；端序固定小端决定数字在内存里"倒着放"； 页大小固定 4KB 的倍数决定内存的分配粒度。

展开。

  • 位宽（archBits）：真实 CPU 的寄存器是 32 或 64 位宽，溢出与回绕都发生在这个宽度上。StackMaster 里你选 32 或 64， 之后所有架构值——寄存器初值、指令立即数、内存位移、公开镜像值——都按这个宽度校验： 立即数是无符号数，范围 [0, 2^archBits−1]；内存位移是有符号数，范围对称。越界直接被拒（XS-ARCH-WIDTH）。 一个 64 位题里写 0x1FFFFFFFF（33 位）的立即数 = 装载失败，没有"自动截断"的暧昧。数值内部以 64 位容器承载、 高位按位宽掩蔽——这保证 32 位题的行为与真 32 位机器一致。
  • 小端序（little-endian）：多字节数值写入内存时，低位字节放低地址。例如 64 位值 0x0000000000400200 写入内存后的字节序列是 00 02 40 00 00 00 00 00——"看起来倒着"。选手在字节视图里看到的正是这个顺序， 所以"把地址写进返回地址槽"必须自己按小端排列字节（这是栈教学的第一道坎，MVP 语料的 le64() 辅助函数就是干这个的）。 端序在 StackMaster 里是冻结常量，你不可选——真实 x86 就是这样。
  • 页（pageSizeBytes）：内存按页管理，页大小 4096–65536 且为 4096 的倍数。区域长度必须是页的倍数 （VMA 对齐）；区域内部的对象（如 8 字节的 canary）不受此限。

为什么这样设计。位宽与端序是"数值语义"的根基：pwn 的一切把戏（截断、回绕、端序错位）都建立在它们之上。 把它们做成题目级声明而不是全局常量，是为了让你能出一道 32 位题教"指针是 4 字节"、再出一道 64 位题教"地址变长了"。

常见误解。①"add 溢出会回绕"——不会：基线 add 溢出走引擎安全终止（教学上明确暴露）， 静默回绕只出现在 sub 的借位与移位取模里；②"位移和立即数一样是无符号的"——内存位移是有符号的（[rbp−8] 需要负偏移），写错符号域直接被拒。

B2 · 寄存器与双命名空间 概念 · 虚拟机

一句话：寄存器名字由你自由定义（1–64 个，大写），分两个结构性不相交的命名空间——一般名（选手可见） 与 FLAG 保留区（名字可公开、值永远私密）；RSP/RBP/RIP 三个核心寄存器必须存在。

展开。寄存器是虚拟机的"工作变量"。真实 x86 的名字（RAX/RDI…）只是惯例，StackMaster 把命名权交给你： 模式 ^[A-Z][A-Z0-9_]{0,15}$，想叫 RDI 贴近真实、叫 RSIZE 贴近教学，都行。 两个命名空间：

命名空间模式可见性用途
一般寄存器^(?!FLAG)[A-Z][A-Z0-9_]{0,15}$（负向前瞻排除 FLAG 开头）值可进公开投影题目的一切工作变量；教学题常暴露 RCFG/RBUF 这类"带含义"的名字帮选手算地址
FLAG 保留区^FLAG[A-Z0-9_]*$（如 FLAG0、FLAG_WIN）名字可出现在 flagRegisterNames 清单，值永不公开"到达胜利态置一个秘密标记"——判题谓词可以读它，选手永远看不到它

关键约束：RSP/RBP/RIP 必须在你声明的集合里（XS-REG-CORE）——它们是会话动作 （push/pop/call/ret）、栈语义指令和整个 MVP 栈帧教学的公共底座。FLAG 名不得混进一般寄存器声明（两空间结构性不相交）， 且必须真实存在于私有初始寄存器集（XS-REG-FLAG）。

为什么这样设计。双命名空间解决一个两难：判胜需要"一个选手看不到的状态位"（否则选手从投影反推成功条件）， 但又希望把"存在胜利标记"这件事公开（题面可以提示"置位 FLAG0"）。保留区让名字公开、值私密成为可机检的静态事实 ——秘密汇可以静态枚举，泄漏检查才有确定的判定基准。

常见误解。①"FLAG 寄存器藏在寄存器列表里，选手看不到名字"——名字通过 flagRegisterNames 是公开的， 隐藏的只是值；②"我可以在运行时动态加寄存器"——寄存器集是题目的定义性声明，静态封闭（扩展走 VM Profile 版本演进，不靠预留）。

B3 · 栈、栈帧与劫持 概念 · 虚拟机（教学核心）

一句话：栈是从高地址向低地址生长的内存区；函数调用在栈上留下"栈帧"= 局部 buffer + saved RBP + 返回地址； buffer 写过头会淹没返回地址，ret 一弹出就跳到攻击者指定的位置——这就是 StackMaster MVP 要教的全部核心。

展开。三个核心寄存器各司其职：RSP 指向栈顶（当前栈的尽头）；RBP 指向当前函数栈帧的基址 （帧的"锚点"）；RIP 指向下一条要执行的指令。一次典型调用：

   高地址
   ┌──────────────┐
   │ 调用者的栈帧  │
   ├──────────────┤ ← retSlot：call 压入的返回地址（ret 弹这里跳回去）
   │ saved RBP    │ ← 调用者的 RBP 存档（leave 时弹回 RBP）
   ├──────────────┤ ← RBP（当前帧基址）
   │ 局部 buffer  │ ← 函数的局部变量（向下生长；这就是"往低地址"读写的窗口）
   ├──────────────┤ ← RSP（栈顶）
   低地址

劫持的完整链条（MVP CH-03~06 与扩展题 x01/x02 教的就是它）： ①程序从 buffer 读入超出其长度的数据（或选手直接用 write_bytes 向 buffer 写）； ②多余的字节向高地址漫延，依次覆盖 saved RBP、返回地址槽； ③函数收尾执行 leave——RSP←RBP 再 pop RBP，此时 saved RBP 已是攻击者的值，RSP 被带歪； ④执行 ret——弹出攻击者覆写过的返回地址进 RIP； ⑤控制流跳到任意攻击者指定的位置（win 函数、一条 gadget 的中间）。这就是"缓冲区溢出"四步， 每一步都对应界面里可观察的字节变化——这正是"可视化 pwn 实验室"的教学价值。

为什么这样设计。MVP 把指令集收窄到恰好覆盖这条链：push/pop 移数据、call/ret 构成调用、 leave 补全帧收尾（它被从真实 x86 单独拎出来，因为"saved RBP 被覆写后 leave 劫持 RSP"是最教科书式的教学时刻）。 出题人的题目只要布局出 buffer→返回地址槽的几何，就能承载这套教学。

常见误解。①"栈向上生长"——方向反了，向低地址生长，所以"溢出"是向高地址淹没返回地址； ②"ret 之后程序就结束"——ret 只是跳转，跳到的位置继续执行；跳到非法位置才报 invalid_rip； ③"选手必须拖慢节奏逐步覆盖"—— write_bytes 一次最多写 4096 字节（题目可再收紧），一条 payload 一次写穿是常态。

B4 · canary 与守护标记 概念 · 虚拟机

一句话：canary（金丝雀）是放在 buffer 与返回地址之间的哨兵值——被溢出碰坏就报警； StackMaster 的交互题当前不能启用真 canary（契约冲突，挂账收口中），标准替代方案是"守护标记 + memory_equals 谓词"。

展开。真实系统的栈保护原理：函数 prologue 在 buffer 上方放一个随机值（canary），epilogue 检查它是否完好—— 连续溢出必然路过并破坏它，从而在被劫持之前终止进程。StackMaster 的 vmProfile.canary 字段与 stack_canary_intact 谓词就是这套语义。但当前版本存在一个如实登记的契约冲突：检查器要求"启用 canary ⇒ 存在隐藏的、含秘密的 canary 对象"（XS-CANARY-CORR），而引擎装配要求 canary 槽公开（build_canary_slots）—— 两个冻结规则对同一对象提出了矛盾的可见性要求。收口走契约变更流程（挂账中），在那之前：

守护标记替代方案（MVP CH-05 先例）：在 buffer 与返回地址槽之间放一段固定标记字节（公开可见即可）， 判胜条件合取 memory_equals(区域, 标记偏移, 标记字节)——溢出写穿标记则判负，"精准绕过"（算准偏移跳过标记）则放行。 教学效果等同，还能让选手看到哨兵长什么样，更直观。

常见误解。①"canary.enabled=true 试试呗"——装载直接拒绝（XS-CANARY-CORR），不要浪费时间； ②"守护标记必须保密"——恰恰相反，公开的哨兵 + 严格的判负条件才是教学点：选手能看见墙，才要学"绕过"而不是"撞墙"。
