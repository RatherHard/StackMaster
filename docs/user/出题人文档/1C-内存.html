C1 · 区域六类与页对齐 概念 · 内存

一句话：内存由若干区域（region）组成，每块有类型（六选一）、起点、长度（4KB 的倍数）、权限（rwx 子集） 和展示名；类型是给选手的"这是什么"暗示，权限才是硬约束。

六类区域与护栏。六类区域的传统语义（引擎不强制用途，但权限与惯例决定玩法）：

kind传统用途典型权限出题要点
code程序代码rx（IR 模式可为 r——内存字节只是数据）至多 1 块、不得隐藏、必须出现在初始投影（D2-CODE-PUBLIC）；字节模式下还有额外规则（D6）
stack栈rw栈帧、buffer、返回地址槽的家
global全局数据rw（只读数据可 r）教学题的"输入区"（选手 write_bytes 的目标）
heap堆rwMVP 无分配器语义，纯数据区
key关键区r常配合隐藏（如"密库"）
custom你自定义的类型任意publicLabel 必填承载类型名

数量与尺寸护栏：区域 1–64 块；每块长度 1–16MiB 且 4096 的倍数；全部区域合计 ≤64MiB；初始内容合计 ≤2MiB （内容是稠密定义的——每块都有完整的 contentHex，长度一字节不差等于 2×byteLength）。 地址是 64 位空间里的半开区间 [start, start+length)，不得越过 2^64（XS-ADDR-SPACE）。

常见误解。①"权限是装饰"——写只读区域是已执行的教学失败（permission_denied，revision +1）， 这正是"权限错误可解释"的教学点；②"区域可以部分隐藏"——可见性是整块区域的属性，不存在"半块隐藏"； ③"内容可以偷懒不写全"——XS-MEM-CONTENT 逐块校验长度。

C2 · 可见与隐藏 概念 · 内存

一句话：可见性在 StackMaster 里是布局问题而不是标志位问题——公开包里列出的区域就是可见的； 只在私有包里声明（isHidden: true）的区域就是隐藏的，选手侧"不存在"。

三层机制。三层机制：

  • 布局即可见性：公开包 memoryLayout 列出的区域进入初始投影，选手的字节视图能看； 隐藏区域只在私有包 initialState.memoryRegions[] 里出现（带 isHidden: true）。 公开 Schema没有任何隐藏表达位（D2-NO-HIDDEN-IN-PUBLIC 元检查），这不是"下发时过滤"，是"想写都写不出"；
  • 隐藏 ⇒ 不相交：隐藏区域与任何公开区域的地址区间不得重叠（I2-HIDDEN-NOT-PUBLIC）——否则同一地址既可见又隐藏，自相矛盾；
  • 不可区分原则（I-9）：选手对"隐藏区域的地址"做任何操作（读、写、调用），其可观察结果与操作"一个谁也没映射的地址"完全一致 ——同样的错误码、同样的占位符、同样不推进 revision、响应字节相同。扫描探测得不到任何边信息。

为什么这样设计。"窗口 + 隐藏 + 不可区分"三者合起来构成内存面的完整防侧信道：可见的部分是真数据（镜像自私有态）， 不可见的部分在浏览器里不存在，试探行为得不到 1 bit 的区别对待。选手的"看不见"是数学意义上的看不见。

常见误解。①"把隐藏区域地址设在可见区域旁边，选手相邻探测能摸到边界"——摸到的只有统一的 inaccessible_address，窗口边界与区域边界是两套正交的机制；②"隐藏区域内容可以留空"——内容仍须稠密定义 （XS-MEM-CONTENT），verifier 重放时它真实存在。

C3 · 私有对象 概念 · 内存

一句话：私有对象是你给内存里的"有意义片段"打的语义标签（这是 buffer、这是返回地址槽、这里含秘密）， 它不改变内存内容，但驱动判题引用、审计与检查器的一致性判定。

字段与两条硬规则。每个对象 = {objectId, kind, addressHex, byteLength, visibility, containsSecret}。 kind 六选一：buffer / canary / saved_rbp / return_address / file / other。 两条硬规则：containsSecret ⇒ visibility = "hidden"（I3-SINK-HIDDEN，"含秘密却公开"直接拒）； hidden 对象不得与公开区域重叠（I2-OBJ-NOT-PUBLIC）。惯例：栈教学题登记 input-buffer、 saved-rbp-slot、return-address-slot 三个对象（公开、不含秘密），让审计与测试有稳定的语义锚点。 注意对象与"语义高亮"（公开包 semanticHighlights）是两回事：高亮是给选手看的结构视图标注， 对象是给判题/审计的登记——两者地址通常一致，但服务对象不同。

常见误解。①"对象会改变引擎行为"——不会，它是纯登记；改变行为的是你的程序与判题条件； ②"file 对象就是虚拟文件"——虚拟文件的真身在 secrets.virtualFiles，对象只是指向它的语义标签之一。
