D1 · IR 模式与字节模式 概念 · 程序

一句话：程序有两种载体——IR 模式（一个指令数组，跳转目标"第几条指令"，内存字节只是数据） 与字节模式（真实机器码字节躺在内存里，代码区可执行，任意字节位置都可以开始取指）——二者恰选其一，执行语义层完全同一。

一张对照表看懂。用两个类比建立直觉：

IR 模式字节模式
类比汇编伪代码清单：程序是编号指令表，"跳到第 7 条"真实二进制：程序是一段字节，CPU 从某地址开始取指译码
程序在哪私有包 compiledIr.instructions（1–4096 条）公开代码区的 contentHex 字节流 + 私有包入口 entrypointAddressHex
地址是什么指令下标（0,1,2,…）代码区内的字节偏移
内存里的字节只是数据（想当数据用）就是程序本身（取指译码执行）
RIP 是什么指令下标代码区字节地址
教学定位栈帧/溢出/判题教学（MVP CH-01~05、x01、x03）真实地址语义、ret2win、ROP/gadget（CH-06~08、x02）
互斥机制公开包声明 encodingTable ⇒ 字节模式（私有 compiledIr 必须省略）；不声明 ⇒ IR 模式。双给/双缺都拒（XS-PROG-MODE）

为什么这样设计。两种形态服务两种教学：IR 把"指令语义"从"编码细节"里剥离出来，初学者先学"ret 会弹出返回地址"； 字节模式再把"程序就是字节"这层真实感加回来——而且它是 gadget 教学的地基：取指可以从任意 token 边界开始， 跳到指令的第二个字节是合法执行路径。两层共享同一套执行语义（同一 20 opcode）、同一判题链路、同一资源预算， 所以从 IR 升级到字节模式，题目逻辑不用重写。

常见误解。①"IR 模式没有代码区"——必须有公开 code 区域（展示"当前指令"用），只是它不可执行、纯展示； ②"字节模式的程序也是私有包里那份 IR"——不是，字节模式的唯一程序就是公开代码区的字节流（ISA 公开立场，见 D6）； ③"两种模式可以混用"——恰一（XS-PROG-MODE），引擎只认一个程序真源。

D2 · 指令、操作数、标志位 概念 · 程序

一句话：基线指令封闭 20 条；每条指令的操作数最多 4 个、形态四选一（寄存器 R / 立即数 I / 内存 M / 接口引用）； 三个标志位 zf/cf/sf 由算术比较置位、只被条件跳转消费。

操作数四类与三个标志位。操作数四类（写语料时就是四种 JSON 形态）：

{ "kind": "register",  "name": "RAX" }                       // 寄存器
{ "kind": "immediate", "valueHex": "0x40" }                  // 立即数（无符号，archBits 域）
{ "kind": "memory",    "baseRegister": "RBP",
  "displacementHex": "-0x8" }                                // 内存：基址+有符号位移，即 [RBP-8]
{ "kind": "interface", "interfaceId": 256 }                  // 作者接口引用（见 D5）

每条 opcode 允许的操作数形态组合是冻结表（完整表在 R3），例如 mov 允许 R←I / R←R / R←M / M←R 四种， cmp 只置标志不写回，leave/ret 零操作数。形态不符在装载期被 XC-OPCODE-SHAPE 拒绝。

标志位（理解条件跳转的钥匙）：

标志含义谁置位
zf结果为零add / sub / cmp / and / or / xor / shl / shr
cf无符号进位/借位add / sub / cmp
sf符号位（最高位）同 zf 那组

cmp A, B 内部做 A−B 但丢弃结果、只留标志；随后 je/jne 看 zf、jb/jae 看 cf 决定跳不跳。注意：条件跳转只有无符号四种（jb=低于跳、jae=不低于跳）——没有"小于则跳"的有符号跳转。 想做有符号判断需要位技巧（比如 xor 符号位后用 jne），这个"缺口"本身是整数表示教学的一部分（扩展题 x03 的截断盲区正是利用"检查只看低字节"）。

为什么这样设计。20 条指令是计划书 6.1 能力清单（"push、pop、mov、基本算术与位运算、有限跳转、call、syscall、ret"） 的封闭实例化：恰好够教栈帧/溢出/劫持/简单 ROP，又少到每条指令的语义都能在一页纸里讲清。 add 溢出走引擎安全终止而非静默回绕——"数值溢出"在这个虚拟机里是响亮的教学事件，不是埋在内存里的暗坑。

常见误解。①"mov 可以内存到内存"——形态表里没有 M,M（真实 CPU 也没有）；②"sf 置位就能跳"——没有消费 sf 的跳转； ③"syscall 是系统调用"——它是教学伪操作：0x00–0xFF 保留带只有 exit(n)，≥0x100 走作者接口（D5），没有宿主副作用。

D3 · 控制流、标签与死代码 概念 · 程序

一句话：IR 模式的跳转目标就是"指令下标"；labels 数组只是给人看的锚点元数据；编译器会检查 目标界内、无死代码、有循环就必须配阶段预算。

编译器的三条控制流规则。写一个带分支与"不可达 win 块"的程序（ret2win 的标准骨架）：

下标  指令                        说明
 0    push RBP                    序章（教学展示面）
 1    mov RBP, RSP
 2    cmp RAX, 0x0
 3    jne 0x8                     ← 立即数 8 = "跳到下标 8"（lose）
 4    leave                       ← 教学核心：RSP←RBP 后 pop RBP
 5    ret                         ← 劫持点：弹出攻击者覆写的值
[win] 6  mov FLAG0, 0x1337
      7  syscall 0x0              ← exit(0)
[lose]8  syscall 0x1              ← exit(1)

labels: [ {entry,0}, {win,6}, {lose,8} ]   ← labels 只是元数据，
                                            控制流目标一律写内联下标

编译器的三条控制流规则（XC-*）：

  • 目标界内（XC-IR-TARGET）：立即数跳转目标必须 0 ≤ 目标 < 指令数；
  • 无死代码（XC-IR-REACH）：纯静态程序（全部跳转都是立即数）里每条指令必须从入口可达。 但只要程序含动态目标（ret / jmp R / jmp M / call R）， 编译器保守地认为"任何指令都可能被跳到"——所以上面 win 块（只能被劫持到达）是合法的；
  • 循环⇒预算（XC-IR-TERMINATE）：存在回边（往回跳的边）就必须声明 stages[]， 且每个阶段 maxInstructionSteps 必填——"循环必须有上限"由 Schema 强制（F1）。

为什么这样设计。"死代码非法 + 动态目标全图可达"这对规则精确刻画了 pwn 的现实：你可以（也应该）放一个 正常执行永远不会到达的 win 函数——因为 ret 的落点编译期无法判定，编译器选择相信运行期预算而不是拒绝你的题目。 标签消解成下标这件事，如果你嫌手工算下标烦，可以用编译器生成面的 {kind:"label"} 操作数让工具代劳（生成产物仍要过全量装载校验）。

常见误解。①"win 块会被当死代码删掉/拒绝"——不会（动态目标保守可达）；②"labels 数组能当控制流用"——不能， 引擎只读 instructions；③"leave 不写也行"——可以，但"溢出后 leave 劫持 RSP"的教学时刻就没了，ret 直接从 RSP 弹，教学链条少一环。

D4 · 自定义指令 概念 · 程序

一句话：自定义指令 = 你用六种微算子拼出的"新指令"（≤16 条，每条 1–16 步直线语义）， 给选手一个助记符和一句展示文本——它是"题目自定义指令集"的实现机制，本质是声明式数据，不是代码。

六种微算子怎么拼。六种微算子：装载立即数（load_imm）、寄存器传送（mov_reg）、内存读（load_mem）、内存写（store_mem）、 置 FLAG（set_flag——唯一能写 FLAG 寄存器的算子）、位掩蔽（bit_mask，支持 and/or/xor）。 拼法是有序组合、无控制转移、步数恒定等于序列长度：

customInstructions: [
  { mnemonic: "NOP0", displayText: "nop",                        // 经典填充位
    semantics: [ { op: "bit_mask", dst: "RAX", src: "RAX",
                   maskHex: "0xFFFFFFFFFFFFFFFF", logic: "and" } ] },
  { mnemonic: "WINFLAG", displayText: "win: 置胜利标记",
    semantics: [ { op: "set_flag", flagRegister: "FLAG0", valueHex: "0x1337" } ] },
  { mnemonic: "TOLOW8", displayText: "取低 8 位",                 // 整数截断教学的好帮手
    semantics: [ { op: "bit_mask", dst: "RAX", src: "RAX",
                   maskHex: "0xFF", logic: "and" } ] }
]

引用方式：IR 里 op 直接写大写助记符（与基线小写结构性不相交），自定义指令零操作数—— 它需要的输入输出全在语义序列里写死。字节模式下编码表同样引用助记符、同样零操作数。

为什么这样设计。"题目自定义指令集"是计划书的核心卖点（教学 IO 不存在、`syscall` 是题目定义的）， 但绝不能让题目携带代码。封闭微算子集 + 直线语义 + 恒定步数，把"可表达的"限制在"可审计的"： 每条自定义指令的执行步数编译期可知（侧信道审计 T-SC2 逐条可断言），没有循环、没有跳转、没有第二实现。 displayText 经扫描禁止夹带隐藏区域名/测试 ID/fileId（XS-CUSTOM-DISPLAY）。

常见误解。①"自定义指令能带操作数"——不能，零操作数是硬规则（语义序列里写死）； ②"能拼出一个循环"——微算子集里没有控制转移，结构性不可能；③"NOP0 是系统指令"——它是 MVP 语料自定的填充位，你也可以叫 PAD0。

D5 · 作者接口与虚拟文件 概念 · 程序

一句话：作者接口 = 题目自定义的"系统调用"——每个接口一个编号（0x0100–0xFFFF）、一句展示文本、 一段效果原语序列（终止 / 发虚拟文件 / 标记已读 / 置 FLAG / 空操作）；程序里用 syscall N 或 call {接口引用} 触发，由引擎管理调用、不占玩家栈。

以虚拟文件 flag 为例。"flag 放在一个要靠能力才能读的文件里"是经典 pwn 叙事，作者接口就是它的正规实现通道：

// 私有包两处配合：
secrets: { flag: "FLAG{...}",
           virtualFiles: [ { fileId: "vault-flag", content: "FLAG{v4ult}" } ] },
interfaces: [ { interfaceId: 0x100, displayText: "vault: 读取密档",
                effects: [ { effect: "grant_virtual_file", fileId: "vault-flag" },
                           { effect: "virtual_file_read", fileId: "vault-flag" } ] } ]

// 判题条件里挂上"文件已被读"：
{ "predicate": { "type": "virtual_file_read", "fileId": "vault-flag" } }

触发方式二选一：syscall 0x100（立即数落在接口号域）或 call {kind:"interface", interfaceId:0x100}。 两种派发的关键区别：接口 call 由引擎管理——记录返回地址、执行效果、回到下一条指令， 不占用玩家的调用栈。这让教学中"真实 call（栈帧教学）"与"接口 call（教学外设）"泾渭分明： 选手劫持栈帧不会误触接口，接口调用也不会污染他要练习操作的栈。

为什么这样设计。效果原语封闭五枚（exit / grant_virtual_file / virtual_file_read / set_flag / noop）—— 没有"读写任意文件""发网络包"这种原语，题目结构上碰不到宿主。fileId 是私有标识，公开包里出现即拒 （XS-ID-NO-PRIVATE / ZR-B8 扫描），杜绝"选手从公开面猜出文件名"。接口号域 [0x0100, 0xFFFF] 与保留系统号带 [0x00, 0xFF]（内置 exit）结构性不相交，未声明的派发号直接 invalid_action。

常见误解。①"接口调用会像真实 call 一样压栈"——不会（引擎管理调用），ret 弹回的是它自己的返回点； ②"选手可以随便 syscall 探测接口号"——可以试，但未声明的号统一 invalid_action，且 displayText 扫描保证展示文本不泄露接口语义之外的秘密；③"虚拟文件内容会进投影"——不会，grant_virtual_file 只授予能力，内容经独立通道按需交付。

D6 · 字节模式深潜 概念 · 程序

一句话：字节模式让代码区字节流成为程序本体——你在公开包里发布一张"token 字典" （哪个字节值 = 哪条指令），选手能在内存里直接看到自己的程序；任意 token 边界取指是合法的，gadget 教学由此成为可能。

四块新知识。四块新知识：

  • 编码表（公开）：≤64 条 {tokenHex, op, operands?}。tokenHex 定宽 1 字节且表内唯一； 寄存器烘焙进 token（pop RDI 和 pop RAX 是两个不同 token，FLAG 寄存器不可编码）； 立即数/位移内联在指令字节流里，定宽 archBits/8 字节小端；内联宽度必须显式声明 "arch"。 表在公开包——ISA 公开是刻意的教学立场（真实 pwn 里二进制和指令集都是选手可见的，谜题在构造不在解码）； 自定义指令的语义仍留私有包，选手看到"字节↔助记符↔展示文本"，看不到语义序列；
  • 代码区纪律：纯指令流（数据放别的区域，沿 .text/.rodata 分离先例）；W^X——代码区权限不得含 w， 写代码区运行时报 memory_fault（自修改代码挂 T2/T3，与 DEP/NX 教学叙事一致）；尾部填充必须用表内 token （惯例：自定义一条零副作用 NOP0）；字节模式代码区恰为"一个公开 + 一个非隐藏私有"；
  • 探测译码（XS-ENC-PROBE）：发布管线从 entrypointAddressHex 起线性取指译码（≤4096 条或区域尾止）， 未知 token / 指令跨区域尾截断即拒。不可达字节不判罚——运行时取指碰到坏字节由 invalid_rip 兜底 （这正是 gadget：合法执行路径不保证从入口开始）；
  • 字节权威：地址 = 代码区字节偏移，没有"第二套指令索引"；出口/跳转目标都是内联的绝对字节地址； 立即数变长（archBits/8 字节）意味着"改一个立即数宽度，后面所有地址自动顺移"——字节偏移语义天然自洽。
// MVP CH-06 的最小布局（4096B 代码区，0x90 填充）：
//   0x400010: c3                入口即 ret（"门开着，等你来劫持"）
//   0x400200: c3                win gadget——跳到这就算到
// 参考解：向返回地址槽写 24 字节填充 + le64("0x400200")，然后 ret。
// 选手侧：代码区字节在栈/自由视图直接可见，编码表在题面——自己"逆向"出 win 地址。
常见误解。①"编码表放公开包会泄漏答案"——泄漏的是编码不是谜题：教学立场是解谜在 gadget 构造； ②"NOP 填充可以用 0x00"——填充字节必须落在编码表内（纯指令流约定），全零未登记就是未知 token； ③"flag/数据可以藏在代码区尾部"——纯指令流约定禁止（数据进 global/key 区域）；④"4096 字节区域装不下 4096 条 NOP0"——装得下（1 字节/条 ≈ 4080 条 < 4096 上限），但要心里有数。
