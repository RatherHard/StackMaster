T1 · 从零做一道最小题（~30 分钟）

步骤 1 · 建语料文件。新建 apps/session-api/test/my-challenges/corpus.ts， 照抄 MVP corpus 的骨架（导出面：interface Challenge / CHALLENGES 数组 / loadChallenge() / canonicalDigests()）。核心是 buildPair()—— 每次调用现场构造 { publicDescriptor, privateBundle } 两个对象。
步骤 2 · 定教学目标与几何。本题：选手向栈区写 4 字节标记 "STAC" 即胜。 帧几何照抄 MVP 惯例：buffer 0x7ffff7f0、saved RBP 0x7ffff800、返回地址槽 0x7ffff808；区域 code 0x400000、stack 0x7ffff000（各 4KB）。
步骤 3 · 填最小双包。公开包：vmProfile（寄存器 RAX/RSP/RBP/RIP + FLAG0，64 位， canary disabled）→ memoryLayout（两块可见区域）→ allowedActions: ["write_bytes","step"] → hintLadder 3 条 + publicErrorMapping 2 条 → initialProjection （公开值从私有初值切片生成——先写私有，再镜像）。 私有包：身份同值 + dslSchemaVersion: 2 + vmEngineVersion（照抄 MVP 值）+ seedPolicy: fixed + initialState（寄存器初值 + 两块区域完整 contentHex）+ secrets + privateObjects（buffer/retSlot 登记）+ 程序 compiledIr: { instructions: [{op:"ret",operands:[]}], labels:[{entry,0}] } + judging: { successCondition: memory_equals(stack,0,"53544143") } + 一条终态探针隐藏测试 + judgingConfig。
步骤 4 · 写语料矩阵。≥3 条：success（write_bytes "53544143" → won/success）、 wrong_answer（写 "53544145" → wrong_answer）、教学失败（写 code 区 → permission_denied）、 crash（写 8 字节值 + step → program_crash）。每条 = 动作脚本 + 预期终态 + 预期裁决。
步骤 5 · 写门禁 + 裁决回归测试。照抄 mvp-challenge-set.test.ts 与 verdict-closed-loop.test.ts 的结构（后者跨目录复用 ../mvp-challenges/helpers/verify-driver.js）。跑： pnpm --filter @stackmaster/session-api exec vitest run test/my-challenges。 红灯按 [规则ID] 逐条修——症状对照表见 T4。
步骤 6 · 全量回归。pnpm --filter @stackmaster/session-api test 确认零回归 → 按 T5 登记。

T2 · 做一道 ret2win（栈帧教学主力）

在 T1 骨架上升级四步（完整活例：sm-x01-ret2win-ir）：

① 程序换 ret2win 骨架。6 指令 + win/lose 块（B3 的图）：push RBP / mov RBP,RSP / cmp RAX,0 / jne lose / leave / ret / [win] mov FLAG0,0x1337; syscall 0x0 / [lose] syscall 0x1。 初始返回地址槽写 lose 下标（防"瞎跑赢"）；RIP 初值 = leave 的下标。win/lose 下标登记进 labels。
② 判胜条件换 RIP 型。RIP == win下标 ∧ stack_canary_intact（win 块无门，RIP 型正确； 若 win 块有密钥门，改用 FLAG 型——见 E1 的坑）。
③ 结构视图标注。semanticHighlights 标 buffer_start / saved_rbp_slot / return_address_slot—— 选手靠它对出 24 字节偏移。
④ 语料矩阵换 ret2win 矩阵。success（41×16 + 42×8 + le64(win下标) 一次写入 + step×2）、 wrong_answer（不写直接走 lose）、program_crash（返回地址槽写 0xdead → invalid_rip）、 教学失败（写 rx 代码区 → permission_denied）。

T3 · 隐藏区域 + 作者接口 flag 题（进阶）

活例：MVP CH-07（sm-ch07-hidden-vault）。四个新要素：

① 隐藏区域。私有包追加 {regionId:"vault", kind:"key", isHidden:true, …}， 内容头部放标记字节；公开包什么都不加。选手探测 vault 地址只会得到与未映射一致的 inaccessible_address。
② 虚拟文件。secrets.virtualFiles 加 {fileId:"vault-flag", content:"FLAG{…}"} （fileId 是私有标识，公开包任何字符串出现即拒）。
③ 作者接口。interfaces: [{interfaceId:0x100, displayText:"vault: 读取密档", effects:[grant_virtual_file, virtual_file_read]}]；字节模式再往编码表加一条 {tokenHex:"0xd4", op:"call", operands:[{kind:"interface",interfaceId:0x100}]}（接口号是公开 ISA 引用）。
④ 判题。successCondition 合取 virtual_file_read("vault-flag")（+ 其余条件）。 选手流程：触发接口 → 能力授予 → 文件已读 → 判胜。

T4 · 装载失败排查手册（症状 → 规则 → 修法）

症状规则修法
多写/写错字段名Ajv strict对照 R1/R2 字段表；公开包顶层恰 16 字段
缺 RSP/RBP/RIPXS-REG-COREvmProfile.registers 补齐
FLAG 值出现在公开投影I3-VISIBLE-REG / XS-REG-FLAGFLAG 名不进 registers/visibleRegisters
公开值与私有初值不一致XS-PROJ-VALUES / XS-PROJ-GEOM公开 = 私有前缀切片，逐字节对齐
公开包出现 fileId/objectId/capability 字符串XS-ID-NO-PRIVATE / ZR-B8-CAP-SCAN私有标识只留私有包
立即数/位移超域XS-ARCH-WIDTH按 archBits 掩蔽；位移记得有符号
contentHex 长度 ≠ 2×byteLengthXS-MEM-CONTENT补零到等长（内存稠密定义）
encodingTable 与 compiledIr 双给/双缺XS-PROG-MODE恰一：IR 删表 / 字节删 IR
代码区可写 / token 未登记 / 入口不在代码区XS-CODE-WRX / XS-ENC-TOKEN / XS-ENC-PROBEW^X、补表、入口落代码区、填充用表内 token
IR 引用未声明助记符 / syscall 号没着落XS-CUSTOM-REF / XS-SYSCALL-DECL补 customInstructions / interfaces
用了 leave 但没有 RBPXS-IR-LEAVE初始寄存器集加 RBP
操作数个数/形态错XC-OPCODE-SHAPE对照 R3 形态列
纯静态程序有死代码XC-IR-REACH删掉，或让 win 块经 ret 等动态目标到达
有循环没 stages / 阶段没预算XC-IR-TERMINATE / XS-STAGE-BUDGET补 stages + maxInstructionSteps
引用了不存在的寄存器/区域/fileIdXC-OPERAND-REF / XS-PRED-REFS引用必须落在私有初始集与已声明对象里
启用 canary 被拒XS-CANARY-CORR交互题改"守护标记 + memory_equals"（B4）

裁决回归阶段的红灯不是装载错误：按五元组（终态/拒绝/错误码/重放一致/隐藏测试）逐项对—— 先实跑观察实际行为，再钉语义正确的预期值（exit(1) 的败 path 钉 wrong_answer，不要为了让测试绿而钉 success）。

T5 · 语料测试与发布上线

① 本地全绿。pnpm --filter @stackmaster/session-api exec vitest run test/<你的目录> + pnpm --filter @stackmaster/session-api test（全量回归）+ pnpm lint。
② 登记。起依赖（compose:deps:up）后运行登记脚本/测试—— 语料 → canonicalize 落桶字节 → 摘要自证 → Ed25519 签名 → ChallengeRegistrar.register （模板：test/compose/mvp-challenge-set.compose.integration.test.ts； 登记脚本活例：k6/seed-challenge.mjs）。记住登记租户——发 token 要用同一个。
③ 验证下发。curl -sI http://127.0.0.1:13000/descriptors/<id>/<version> → 200 + ETag（= 公开包摘要）。
④ 浏览器实测。签 token → 开发壳/插件页创建会话亲手玩一遍（参考 apps/session-api/test/extended-challenges/README.md 的浏览器联调节）。
⑤ 过一遍发布检查清单。见 R6 末尾；CDN 与生产密钥属生产部署面（MVP 未做，如实边界）。
