0 · 设计稿：四个决定

决定内容为什么
程序骨架9 条指令：序章 4 条（push RBP / mov RBP,RSP / cmp RAX,0 / jne lose）+ leave + ret + win 块（mov FLAG0,0x1337; exit(0)）+ lose 块（exit(1)）leave;ret 是栈帧收尾的完整教学链（B3）；含 ret（动态目标）→ win 块合法（XC-IR-REACH 保守全图可达）
执行起点RIP 初值 = 0x4（leave 处）；序章 0–3 为"已执行完"的展示面选手从收尾开始，两步引爆
判胜条件RIP == 0x6（win）∧ stack_canary_intact——RIP 型win 块无内部校验，落点即胜利；若要加密钥门，改 FLAG 型（见 E1 的坑）
初始返回槽写 lose 下标（0x8）防"不写 payload 瞎跑也能赢"
失败路径wrong：不写直接 step×3 → lose / crash：返回槽写 0xdead → invalid_rip / 教学失败：写 rx 代码区 → permission_denied三个方向覆盖门禁要求

选手怎么知道 win 的下标？题目默认开启调试模式，指令视图能看到全部指令与地址——这本身就是教学点（真实 pwn 靠逆向，这里靠"调试器"）。

1 · 语料模块：类型与工具（完整代码）

与 T1 同构（接口名换成 T2 前缀）。直接替换 T1 语料文件的头段即可：

/**
 * T2 样例:ret2win(IR;出题人文档 T2 的配套语料——与扩展题集 sm-x01 同构)。
 */
import type { ActionObject } from "@stackmaster/protocol";
import { canonicalize } from "@stackmaster/protocol";
import { createHash } from "node:crypto";
import { loadChallengePair, type ChallengeLoadResult } from "@stackmaster/challenge-compiler";

export interface T2CorpusEntry {
  readonly name: string;
  readonly description: string;
  readonly expectedFinalStatus: "running" | "won" | "failed";
  readonly expectedVerdict: "success" | "wrong_answer" | "invalid_action" | "program_crash" | "memory_fault" | "resource_limit" | "timeout";
  readonly actions: readonly ActionObject[];
  readonly expectedLastError?: string;
}

export interface T2Pair {
  readonly publicDescriptor: unknown;
  readonly privateBundle: unknown;
}

export interface T2Challenge {
  readonly meta: { readonly challengeId: string; readonly title: string; readonly mode: "ir" | "byte" };
  readonly buildPair: () => T2Pair;
  readonly corpora: readonly T2CorpusEntry[];
}

export function canonicalDigests(pair: T2Pair) {
  return {
    publicDescriptorSha256: createHash("sha256").update(canonicalize(pair.publicDescriptor), "utf8").digest("hex"),
    privateBundleSha256: createHash("sha256").update(canonicalize(pair.privateBundle), "utf8").digest("hex"),
  };
}

export function loadT2Challenge(challenge: T2Challenge): ChallengeLoadResult {
  return loadChallengePair(challenge.buildPair());
}

2 · 几何常量与辅助函数（完整代码）

比 T1 多两个工具：le64（小端编码——把 win 下标写进返回地址槽用）与 overflowPayload（拼装 16+8+8 的连续 payload）：

const CODE_BASE = "0x400000";
const STACK_BASE = "0x7ffff000";
const REGION_BYTES = 4096;
const PAGE_SIZE = 4096;
const ARCH_BITS = 64;

const FRAME = {
  buffer: "0x7ffff7f0",
  savedRbp: "0x7ffff800",
  retSlot: "0x7ffff808",
  rsp: "0x7ffff808", // T2:RSP 初始指向返回地址槽(leave;ret 收尾从这里弹)
  rbp: "0x7ffff800",
} as const;

const WIN = "0x6"; // win 块指令下标
const LOSE = "0x8"; // lose 块指令下标

function le64(valueHex: string): string {
  let value = BigInt(valueHex);
  const bytes: string[] = [];
  for (let index = 0; index < 8; index += 1) {
    bytes.push((value & 0xffn).toString(16).padStart(2, "0"));
    value >>= 8n;
  }
  return bytes.join("");
}

function offsetOf(address: string): number {
  return Number(BigInt(address) - BigInt(STACK_BASE));
}

function stackContent(writes: readonly { readonly offset: number; readonly hex: string }[]): string {
  const bytes = Buffer.alloc(REGION_BYTES, 0);
  for (const write of writes) {
    Buffer.from(write.hex, "hex").copy(bytes, write.offset);
  }
  return bytes.toString("hex");
}

function zeroRegion(): string {
  return "00".repeat(REGION_BYTES);
}

function flagFor(challengeId: string): string {
  return `FLAG{my-${challengeId.slice(4, 6)}}`;
}

function seedFor(challengeId: string): string {
  const serial = challengeId.slice(4, 6);
  if (!/^[0-9a-f]{2}$/.test(serial)) throw new Error(`bad serial: ${challengeId}`);
  return `00112233445566778899aabbccdd${serial}ee`;
}

function writeAction(addressHex: string, bytesHex: string): ActionObject {
  return { type: "write_bytes", args: { addressHex, bytesHex } };
}

function steps(count: number): ActionObject[] {
  return Array.from({ length: count }, () => ({ type: "step", args: {} }) as ActionObject);
}

function pubHex(valueHex: string): string {
  return `0x${BigInt(valueHex).toString(16).toUpperCase()}`;
}

/** 连续 payload:16 填充 + 8 saved RBP + 8 返回槽(小端目标)。 */
function overflowPayload(tailHex: string): string {
  return "41".repeat(16) + "42".repeat(8) + tailHex;
}

4 · 测试与运行

  • 门禁/裁决测试沿用 T1 的两个文件，把导入与规模断言改成你的题目即可；IR 布局断言建议加一条： entrypointIndex === 初始 RIP、labels 含 entry/win/lose（T1 门禁已有同款）；
  • 运行：pnpm --filter @stackmaster/session-api exec vitest run test/<你的目录>；
  • 预期：success 语料 = 写 payload → step×2（leave、ret）→ won；crash 语料在 leave 处即报 invalid_rip （引擎对返回槽做前置校验，早于 ret——如实的教学锚点）。
出题人必懂（E1 的坑）：判胜写成 RIP == win 时，ret 落到 win 的一瞬就判胜—— win 块内部的任何校验都来不及执行。要"密钥门"就必须用 FLAG 型条件（本页 x01 无门，RIP 型正确；扩展题 x02 有门，用 FLAG 型）。
