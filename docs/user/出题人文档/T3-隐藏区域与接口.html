T3 · 隐藏区域 + 作者接口 flag 题 任务指南

0 · 设计稿：题目叙事与机制

要素设计概念
叙事实验室藏着一间"密库"，里面有 flag 文件；程序定义了「读取密档」接口（接口号 0x100），只有配置区的密钥正确时程序才会调用它—
隐藏区域vault（kind key，0x20000000，r，isHidden:true），内容 = flag 文本字节选手探测它与探测未映射完全同形（I-9）
虚拟文件secrets.virtualFiles: [{fileId:"vault-flag", content:"FLAG{v4ult}"}]fileId 私有，公开包出现即拒
作者接口interfaces: [{interfaceId:0x100, effects:[grant_virtual_file, virtual_file_read]}]；程序内 call {interface 0x100} 触发引擎管理调用，不占玩家栈
程序IR 6 条：读配置区密钥 → cmp 0x5EC5AB1E → jne lose → call 接口 → exit(0) / lose: exit(1)判胜 = virtual_file_read（密钥门在 call 之前，天然不会被 E1 的即时求值绕过）
配置区cfg（global，0x600000，rw，公开）——选手把 8 字节小端密钥写进 0x600000RCFG 寄存器公开，选手可算地址
失败路径错密钥 → lose；探测密库地址 → 执行前拒绝（rejected，与未映射同形）；写 rx 代码区 → permission_denied四个方向全覆盖

1 · 语料模块：类型与工具（完整代码）

/**
 * T3 样例:隐藏区域 + 作者接口 flag 题(IR;出题人文档 T3 的配套语料)。
 */
import type { ActionObject } from "@stackmaster/protocol";
import { canonicalize } from "@stackmaster/protocol";
import { createHash } from "node:crypto";
import { loadChallengePair, type ChallengeLoadResult } from "@stackmaster/challenge-compiler";

export interface T3CorpusEntry {
  readonly name: string;
  readonly description: string;
  readonly expectedFinalStatus: "running" | "won" | "failed";
  readonly expectedVerdict: "success" | "wrong_answer" | "invalid_action" | "program_crash" | "memory_fault" | "resource_limit" | "timeout";
  readonly actions: readonly ActionObject[];
  readonly expectedFirstRejected?: boolean;
  readonly expectedLastError?: string;
}

export interface T3Pair {
  readonly publicDescriptor: unknown;
  readonly privateBundle: unknown;
}

export interface T3Challenge {
  readonly meta: { readonly challengeId: string; readonly title: string; readonly mode: "ir" | "byte" };
  readonly buildPair: () => T3Pair;
  readonly corpora: readonly T3CorpusEntry[];
}

export function canonicalDigests(pair: T3Pair) {
  return {
    publicDescriptorSha256: createHash("sha256").update(canonicalize(pair.publicDescriptor), "utf8").digest("hex"),
    privateBundleSha256: createHash("sha256").update(canonicalize(pair.privateBundle), "utf8").digest("hex"),
  };
}

export function loadT3Challenge(challenge: T3Challenge): ChallengeLoadResult {
  return loadChallengePair(challenge.buildPair());
}

2 · 布局、区域与辅助（完整代码）

注意：公开布局 = code + stack + cfg 配置区；vault 不在公开布局，只在私有 regions 里带 isHidden: true。 密库内容是稠密定义的（flag 文本字节 + 全零填充到 4096）：

const CODE_BASE = "0x400000";
const STACK_BASE = "0x7ffff000";
const CFG_BASE = "0x600000";
const VAULT_BASE = "0x20000000";
const REGION_BYTES = 4096;
const PAGE_SIZE = 4096;
const ARCH_BITS = 64;

const FRAME = {
  buffer: "0x7ffff7f0",
  savedRbp: "0x7ffff800",
  retSlot: "0x7ffff808",
  rsp: "0x7ffff800",
  rbp: "0x7ffff800",
} as const;

/** 密钥(教学值;选手从题面/提示得知)。 */
const VAULT_KEY = "0x5ec5ab1e";
const VAULT_FLAG_FILE_ID = "vault-flag";
const VAULT_FLAG_CONTENT = "FLAG{v4ult}";

function le64(valueHex: string): string {
  let value = BigInt(valueHex);
  const bytes: string[] = [];
  for (let index = 0; index < 8; index += 1) {
    bytes.push((value & 0xffn).toString(16).padStart(2, "0"));
    value >>= 8n;
  }
  return bytes.join("");
}

function stackContent(writes: readonly { readonly offset: number; readonly hex: string }[]): string {
  const bytes = Buffer.alloc(REGION_BYTES, 0);
  for (const write of writes) {
    Buffer.from(write.hex, "hex").copy(bytes, write.offset);
  }
  return bytes.toString("hex");
}

function zeroRegion(): string {
  return "00".repeat(REGION_BYTES);
}

/** 密库内容:flag 文本字节 + 全零填充(稠密定义)。 */
function vaultContent(): string {
  const bytes = Buffer.alloc(REGION_BYTES, 0);
  Buffer.from(VAULT_FLAG_CONTENT, "utf8").copy(bytes, 0);
  return bytes.toString("hex");
}

function flagFor(challengeId: string): string {
  return `FLAG{my-${challengeId.slice(4, 6)}}`;
}

function seedFor(challengeId: string): string {
  const serial = challengeId.slice(4, 6);
  if (!/^[0-9a-f]{2}$/.test(serial)) throw new Error(`bad serial: ${challengeId}`);
  return `00112233445566778899aabbccdd${serial}ee`;
}

function writeAction(addressHex: string, bytesHex: string): ActionObject {
  return { type: "write_bytes", args: { addressHex, bytesHex } };
}

function steps(count: number): ActionObject[] {
  return Array.from({ length: count }, () => ({ type: "step", args: {} }) as ActionObject);
}

function pubHex(valueHex: string): string {
  return `0x${BigInt(valueHex).toString(16).toUpperCase()}`;
}

3 · 题目本体与语料矩阵（完整代码）

4 · 三个真实红灯（本页代码开发时逐一踩到，必读）

红灯 1 · invalid_action 不是公开错误码。publicErrorMapping 想为"未声明接口号"配教学注解， 选了 invalid_action——它是 11 值裁决，不在 16 值错误码枚举里，Schema 直接拒。 修法：换枚举内的 objective_not_met（错误码与裁决值是两套词汇，对照 R6）。
红灯 2 · displayText 不得含隐藏区域名。接口展示文本写了 "vault: 读取密档"，而隐藏区域 regionId 恰好叫 vault——XS-CUSTOM-DISPLAY 拒绝（展示文本是公开面，不能泄露私有标识）。修法：展示文本改纯中文 "读取密档(密钥正确时授权)"。给隐藏区域起 regionId 时就避开你将在展示文本里用的词。
红灯 3 · RCFG 指向的区域忘了建。寄存器 RCFG 指向 0x600000，但布局里根本没有 cfg 区域—— 选手写密钥得到 inaccessible_address，程序读配置区直接引擎失败。修法：cfg 作为 global/rw 公开区域加入布局 （公开包 + 私有镜像同步）。寄存器指向的地址必须有真实区域背书。
