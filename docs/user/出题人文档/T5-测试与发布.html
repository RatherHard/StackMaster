2 · 起联调拓扑

# ① 先构建页面产物 —— compose 把宿主 apps/page-app/dist 只读挂进容器(镜像不构建 page-app)
pnpm --filter @stackmaster/vm-ui build
pnpm --filter @stackmaster/page-app build
# ② 再起全拓扑(PostgreSQL/Redis/MinIO + session-api:13000 + verifier:13100;需 Docker Desktop)
pnpm --filter @stackmaster/session-api compose:app:up

只想要依赖容器、应用跑宿主进程时:compose:deps:up 起依赖,再 pnpm --filter @stackmaster/session-api dev:host (session-api:13000 + verifier:13100,开发联调启动器;本地合成凭证只用于联调)。 ⚠ 该形态的 SESSION_API_PUBLIC_ORIGIN 取自 compose/integration.env(测试用 origin,不是页面开发服务器), 其签发的 launchUrl 不能直接贴进浏览器 ⇒ 浏览器实测请走上面的 compose 形态。

页面(apps/page-app)由 session-api 同源托管:SESSION_API_PAGE_APP_DIR 未设时用仓库内 apps/page-app/dist(存在即启用); 显式配了却指不到目录会拒绝启动;compose 形态该键指向容器内 /app/apps/page-app/dist(由 bind mount 承载)—— 宿主没构建页面时那里是空目录,容器照常起、换票照常,但页面打不开(静态面零路由)。

两个与启动链同批登记的键:SESSION_API_PUBLIC_ORIGIN(页面 origin;未配 ⇒ 签发面一律 404)必须与 SESSION_API_ALLOWED_ORIGINS 里的同一个值成对出现 —— 页面上的变更请求带 Cookie 与 Origin,CSRF 闸按白名单精确比对,不登记就是 401。

3 · 登记题目（完整代码，拓扑就绪后执行）

新建 apps/session-api/test/my-challenges/register-my-challenge.compose.integration.test.ts （与扩展题集登记测试同构：规范化 JSON 落桶 + 摘要自证 + Ed25519 签名验签 + PG 建档；复跑自带清理）：

/**
 * 我的题目登记(联调拓扑;T5 配套。与 extended-challenges/register-extended 同构,单题版)。
 *
 * 运行(依赖容器须已 compose:deps:up;拓扑见 extended-challenges/README.md):
 *   SESSION_API_COMPOSE=1 pnpm --filter @stackmaster/session-api exec vitest run test/my-challenges/register-my-challenge.compose.integration.test.ts
 *
 * 登记链路:规范化 JSON 落桶 → 摘要自证 → Ed25519 签名验签 → PG 建档(版本不可变,
 * 重跑前清理旧行/旧对象)。登记租户必须与后续签发启动地址时服务端派生的租户一致。
 */
import { generateKeyPairSync, sign as cryptoSign } from "node:crypto";
import { afterAll, beforeAll, describe, expect, it } from "vitest";
import type { Pool } from "pg";
import { canonicalize } from "@stackmaster/protocol";

import { MY_CHALLENGE, canonicalDigests } from "./corpus.js";
import {
  ChallengeRegistrar,
  MinioChallengeBundleStore,
  PostgresChallengeRegistry,
  createMinioClient,
  createPostgresPool,
  registrationSignatureBasis,
  sha256Hex,
} from "../../src/persistence/index.js";
import { ensureMigrated, IT_CONFIG } from "../persistence/helpers/it.js";

const COMPOSE_ENABLED = process.env["SESSION_API_COMPOSE"] === "1";
const SKIP_REASON = "跳过原因:SESSION_API_COMPOSE != 1(先 compose:deps:up 起依赖服务)";
const DEV_TENANT_ID = process.env["EXT_DEV_TENANT_ID"] ?? "tenant-dev-0001";
const CONTENT_VERSION = "1.0.0";
const VM_PROFILE_VERSION = "1.0.0";

describe.skipIf(!COMPOSE_ENABLED)(`我的题目登记(联调租户 ${DEV_TENANT_ID};${SKIP_REASON})`, () => {
  let pool: Pool | null = null;
  let bundles: MinioChallengeBundleStore | null = null;

  beforeAll(async () => {
    pool = await createPostgresPool(IT_CONFIG.postgresUrl, 3);
    await ensureMigrated(pool);
    const registry = new PostgresChallengeRegistry(pool);
    const minio = await createMinioClient({
      endpoint: IT_CONFIG.minioEndpoint,
      port: IT_CONFIG.minioPort,
      accessKey: IT_CONFIG.minioAccessKey,
      secretKey: IT_CONFIG.minioSecretKey,
    });
    bundles = new MinioChallengeBundleStore(minio, {
      bucketPrivate: IT_CONFIG.minioBucketPrivate,
      bucketPublic: IT_CONFIG.minioBucketPublic,
    });
    await bundles.ensureBuckets();

    const challengeId = MY_CHALLENGE.meta.challengeId;
    await pool.query(`DELETE FROM challenge_versions WHERE challenge_id = ANY($1::text[])`, [[challengeId]]);
    const cleanup = minio as unknown as {
      removeObject(bucket: string, objectName: string): Promise<void>;
    };
    for (const objectName of [
      `${challengeId}/${CONTENT_VERSION}/bundle.json`,
      `${challengeId}/${CONTENT_VERSION}/descriptor.json`,
    ]) {
      await cleanup.removeObject(IT_CONFIG.minioBucketPrivate, objectName).catch(() => undefined);
      await cleanup.removeObject(IT_CONFIG.minioBucketPublic, objectName).catch(() => undefined);
    }

    const pair = MY_CHALLENGE.buildPair();
    const digests = canonicalDigests(pair);
    const privateBundle = Buffer.from(canonicalize(pair.privateBundle), "utf8");
    const publicDescriptor = Buffer.from(canonicalize(pair.publicDescriptor), "utf8");
    expect(sha256Hex(privateBundle)).toBe(digests.privateBundleSha256);
    expect(sha256Hex(publicDescriptor)).toBe(digests.publicDescriptorSha256);
    const { privateKey, publicKey } = generateKeyPairSync("ed25519");
    const signature = cryptoSign(
      null,
      Buffer.from(
        registrationSignatureBasis({
          challengeId,
          contentVersion: CONTENT_VERSION,
          vmProfileVersion: VM_PROFILE_VERSION,
          privateBundleSha256: digests.privateBundleSha256,
          publicDescriptorSha256: digests.publicDescriptorSha256,
        }),
        "utf8",
      ),
      privateKey,
    ).toString("base64");
    await new ChallengeRegistrar({ bundles, registry, signingPublicKey: publicKey }).register({
      tenantId: DEV_TENANT_ID,
      challengeId,
      contentVersion: CONTENT_VERSION,
      vmProfileVersion: VM_PROFILE_VERSION,
      privateBundle,
      publicDescriptor,
      signature,
    });
  }, 120_000);

  afterAll(async () => {
    if (pool !== null) await pool.end().catch(() => undefined);
  }, 30_000);

  it("登记行可查且哈希与构造摘要一致", async () => {
    const registered = await pool!.query<{ challenge_id: string }>(
      `SELECT challenge_id FROM challenge_versions WHERE tenant_id = $1 AND content_version = $2`,
      [DEV_TENANT_ID, CONTENT_VERSION],
    );
    expect(registered.rows.map((row) => row.challenge_id)).toContain(MY_CHALLENGE.meta.challengeId);
  });
});

执行（SESSION_API_COMPOSE=1 是门控开关；依赖容器须已起）：

SESSION_API_COMPOSE=1 pnpm --filter @stackmaster/session-api exec vitest run test/my-challenges/register-my-challenge.compose.integration.test.ts
两个必须记住的纪律：① 登记租户 = 启动面租户——题目版本按（租户,题目,版本）三键定位， 后续换一次性启动地址（POST /auth/launch-tickets）时，服务端由宿主凭证 × SESSION_API_HOST_TENANTS 白名单派生租户， 该租户必须与这里的登记租户一致，否则签发与换票都拿不到题目； ② 版本不可变——重复登记确定性拒绝，改题后递增 challengeContentVersion 重新登记 （测试模板自带旧行/旧对象清理，可直接重跑）。

5 · 浏览器实测（页面分发形态）

两步：把页面产物交给 session-api 同源托管，再用平台后端凭证换一个一次性启动地址。

# ① 构建页面产物(第 2 节已做过可跳过;vm-ui 必须先构建,page-app 的 prebuild 会自动同步 vm-ui 产物)
pnpm --filter @stackmaster/vm-ui build
pnpm --filter @stackmaster/page-app build

# ② 登记题目(真实登记链路;脚本自述用法与缺省值见 apps/session-api/k6/seed-challenge.mjs)
#    ⚠ 登记租户必须与启动面的「锚租户」一致(compose / integration.env 的 SESSION_API_HOST_TENANTS
#      = host-scores-tenant,而脚本缺省租户是 k6-tenant):两者取其一改齐
cd apps/session-api
$env:K6_TENANT_ID='host-scores-tenant'
node --env-file=compose/integration.env k6/seed-challenge.mjs   # 缺省登记 chal-k6-baseline@1.0.0

# ③ 换一次性启动地址(宿主凭证;请求体恰两键 {challengeId, version};响应恰两键 {launchUrl, expiresAt})
$env:SESSION_API_HOST_BACKEND_TOKEN='<宿主共享凭证;本地联调的 dev 合成值见 compose/app.yaml,严禁用于真实环境>'
curl.exe -sS -X POST http://127.0.0.1:13000/auth/launch-tickets `
  -H "authorization: Bearer $env:SESSION_API_HOST_BACKEND_TOKEN" `
  -H 'content-type: application/json' `
  -d '{"challengeId":"chal-k6-baseline","version":"1.0.0"}'    # 换成你自己的 challengeId / 版本亦可

把返回的 launchUrl 贴进浏览器地址栏（顶层导航）：页面服务端换票后 302 到不含票据的干净路径并下发启动授权凭证 Cookie， 页面随即自动建会话并挂出工作区。按〈界面帮助手册〉的完整交互链游玩 → 菜单「提交」→ 等待 verdicted。

四个运维/联调要点：① 启动地址只能打开一次（票据与授权凭证都是单次消费；重复打开 = 401）； ② 换票要求 Sec-Fetch-Mode: navigate，所以必须顶层导航，用 fetch / 脚本抓会 401； ③ 未配 SESSION_API_PUBLIC_ORIGIN、或 SESSION_API_HOST_TENANTS 为空 ⇒ 签发面一律 404（fail-closed，与"题目不存在"同形）； 白名单里的锚租户(= 字典序最小项)必须是题目的登记租户:compose 与 integration.env 都取 host-scores-tenant,所以种子脚本要用 K6_TENANT_ID=host-scores-tenant(脚本缺省 k6-tenant)—— 租户不符的后果是 create_session 422 challenge_invalid(不是 404); ④ 签发的 TTL 缺省 300 秒（SESSION_API_LAUNCH_TICKET_TTL_SECONDS，天花板 3600）。

页面侧零后端的真机冒烟（不需要 Docker，已实测）：

pnpm --filter @stackmaster/page-app test        # 单测(vitest + jsdom;23 例)
pnpm --filter @stackmaster/page-app test:e2e    # 真 chromium + 真 vm-ui 产物(23 例 + 2 skip)

全链的自动化形态 = apps/page-app/e2e/launch-chain.spec.ts（签发 → 顶层导航 → 302 抹票 → connection-status=connected； 另一例断言票据单次消费：同一张票二次导航 = 401）。需要真拓扑，且必须显式开启：

$env:E2E_LAUNCH_CHAIN='1'                          # 否则整文件 skip(不伪装成通过)
$env:SESSION_API_HOST_BACKEND_TOKEN='<宿主凭证>'   # 只经环境变量
$env:SESSION_API_ORIGIN='http://127.0.0.1:13000'
pnpm --filter @stackmaster/page-app exec playwright test e2e/launch-chain.spec.ts
如实边界：上面「换票 + 浏览器实测」与 launch-chain 全链在本仓库当前机器上未实测 （Docker 引擎不可达，起不了依赖拓扑）；页面侧单测与 test:e2e 冒烟已实测通过。三引擎矩阵 （$env:E2E_MATRIX='1'）跑的是同一套 page-app 用例。
