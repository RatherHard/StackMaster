## 一、StackMaster 是什么

StackMaster 是一个**能直接操作内存的 pwn 练习场**。传统 pwn 题给你一个黑盒二进制;StackMaster 反过来——把虚拟机的内存像表格一样摊开在你面前,你逐字节地观察栈帧、亲手把 payload 写进去,看着返回地址被你覆盖。

你操作的不是模拟器玩具:每一次写内存、每一条指令都在**服务端的权威虚拟机**里真实执行,服务端记录完整的动作日志。提交答案时,由独立的裁决服务把你的操作日志**从头重放一遍**来打分——所以成绩无法伪造。

## 二、三条核心规则(先读这个,后面都围绕它)

1. **服务端权威**:你的内存操作、单步、回退、判题,全部以服务端为准。浏览器里显示的一切只是"投影"。
2. **你看不到的确实看不到**:题目的 flag、隐藏判定条件、随机种子只存在于服务端。浏览器任何位置(页面、本地存储、控制台)都不存在这些信息——这不是"藏得好",是结构上就没发给你。
3. **改浏览器没用**:打开 DevTools 改内存、伪造"已通关"状态,既拿不到隐藏信息,也影响不了成绩。成绩只由服务端重放你的操作日志产生。前端显示的"胜利"和正式成绩是两条独立的线(见第八章)。

## 三、打开题目

题目**不是嵌在平台页面里的插件**,也没有 iframe、没有与平台的"握手":平台后端(CTF 平台的服务端)向 StackMaster 换取一个**一次性启动地址**并下发给你,你**直接打开这个地址**(顶层导航——地址栏里就是它)。打开后你不用填任何参数,页面会自己把会话建起来:

1. **服务端换票**:地址里带一次性票据(`…/app/c/<题目>/<版本>?t=<票据>`)。第一次打开时由**页面服务端**校验并消费它,签给你一张短时的**启动授权凭证**(HttpOnly Cookie),然后 **302** 跳到一个**不含票据的干净路径**——此后地址栏里看不到 `?t=`(票据已被消费并抹除);
2. **页面自动建立会话**:落地页与 API **同源**,它用那张 Cookie 建会话、连通道、取题面,并挂出工作区;
3. **等它加载完**:顶部菜单右侧常驻「会话状态 / revision / 连接」;连接状态从 `connecting` 走到 `connected`(断线时是 `reconnecting` / `disconnected`,见第十章)。

三件必须知道的事:

- **启动地址只能打开一次**:票据与启动授权凭证都是**单次消费**的。再打开同一个地址(或以其它方式重放)只会得到 **401**;若页面已经加载出来,提示就是 **「地址已失效,请向平台重新获取」**。这是设计,不是故障;
- **启动地址有有效期**:缺省 **300 秒**(部署可调,上限 3600 秒)。过期未打开同样失效,回平台重新获取即可;
- **不要把地址转给别人,也不要用爬虫 / 脚本抓它**:票据就在 URL 里,服务端一被打开就消费并抹除,**服务端访问日志也不含票据**(整段查询串在落日志前被剥离)——但把地址转发出去,等于把你的入场权一起递了出去。

地址被截断、手打成别的路径时,页面直接显示「地址无效:这不是一个 StackMaster 题目启动地址(缺少题目定位路径)。」并且**不发任何网络请求**。若是打开后提示「地址已失效」,回平台重新获取一个地址;反复失败就联系平台运营方。

## 四、工作区导览

工作区 = **顶部菜单** + **左右两分**的主体:

- **右半侧 = Payload 搭建窗口**(**固定**,不随左边滚动):积木式 payload 编辑器永远在这一半(见第六章);
- **左半侧 = 视图管理窗口**:最上面是「视图列表」按钮(点击展开),下面是**上下堆叠的视图位**——左半侧的可视高按**两个视图位**等分,所以任一时刻大约能看到两个;勾选得更多时,多出来的视图位排在下面,由**左半侧自己纵向滚动**承载(**只滚动、不压缩**:每个视图位都有确定高度,不会出现"被压到看不见一行字节")。

左右两分是**固定的**,紧贴在一起:**不能拖动分界、没有分界手柄、也没有分隔条**。两边各有一条宽度底线(452.4px = 一行字节不被折断的最小可读宽),窄屏放不下两条底线时**页面出现横向滚动**,左右两分的形态不变。

### 固定窗口集:只有勾选与顺序

注册表登记的 **10 类视图各恰一个、常驻**——视图**没有「开 / 关」这回事**:面板上没有关闭钮,菜单里也没有「打开 / 关闭」入口,更没有"新建 / 删除视图"。每个视图只有三种处境:**可见**(有呈现位)、**未勾选**(= 不显示 = 暂离)、**勾选了但滚出了可视区**(滚回去就看到)。所以"隐藏"不是关闭:类型仍在场、内容不丢,勾回来立刻恢复。

> 左半侧每个视图位的类型名写在**视图位内的左上角**(面板内第一个元素),没有独立标题栏;右半侧的 Payload 搭建窗口不带这行名字 —— 它本身就是积木编辑器。

### 视图一览

| 视图 | 看什么 |
|---|---|
| **栈视图 / 自由视图** | 内存字节表。两者是同一个组件,**只有视图类型名不同**:默认区域都取含 RSP 值的区域(没有就取第一个可见区域) |
| **寄存器视图** | 当前全部公开寄存器的值。点值可复制;某个寄存器的值恰好指向某内存区域时,字节视图对应行左缘会出现交叉标注 |
| **调用栈** | 当前调用链(最内帧在最上)。深度超过 64 帧时会明示"仅显示最内 64 帧" |
| **结构视图** | 出题人声明的语义高亮:buffer 起点、返回地址槽、saved RBP 槽、canary 槽等,点击可跳到对应内存 |
| **Payload 搭建** | 积木式 payload 编辑器(**固定在右半侧**,见第六章) |
| **内存 diff** | 最近一次动作前后的字节差异(累积历史看时间线) |
| **时间线** | 你的每一步操作按 revision 排列的历史 |
| **checkpoint(检查点)** | 你保存的快照列表,支持恢复 |
| **指令视图**(调试模式才有真数据) | 反汇编风格的指令流、断点、函数表(见第七章) |

> 教学面板(提示阶梯 + 错误解释)与**题目简介**都不在左右两分里,它们是工作区上方两块可折叠区域(菜单下面)。

### 显示与排序:左半侧的「视图列表」

展开左半侧的「视图列表」按钮(它的标题就是**「视图列表(勾选显示 / 拖拽排序)」**),里面按**当前顺序**列出全部 10 类视图,每条 = 序号 + 勾选框 + 视图名。这里是**显示与否、以及排序的唯一入口**(菜单里那些同名的按钮只负责"聚焦"):

- **勾选框**决定这个视图在左半侧显不显示。未勾选 = 不显示它(视图仍常驻,不是关闭);
- **拖动列表项**调整顺序 = 调整左半侧视图位的上下堆叠次序(拖到列表之外松开则**不移动**);
- **键盘等价路径**:`Space` 勾选 / 取消勾选,`Alt + ↑ / ↓` 把当前条目上移 / 下移一位;条目可聚焦,焦点顺序 = 列表的视觉顺序;
- 列表下方的状态行(屏幕阅读器可读)会播报「已显示「…」/ 已隐藏「…」/ 已把「…」移动到第 N 位」。

> 列表里也有「Payload 搭建」一项,但它的呈现在**右半侧**是固定的 ⇒ 对它的勾选 / 排序没有可见效果;决定左半侧显示与次序的是其余 9 类视图。

### 聚焦与键盘

任一时刻**恰有一个视图处于聚焦**(菜单里对应按钮的按下态;聚焦只把类型名的强调色点亮,**不画边框**):

- **点菜单「视图」组里的视图名** = 聚焦该视图并把它滚进可视区。这排按钮**恒可用、不会置灰**(聚焦不依赖会话是否已连接);
- **`Ctrl + ↑ / ↓`** 在**左半侧**切换当前视图位(上一位 / 下一位),**到边界就停、不环绕**;切换结果在状态行用文字宣读:「当前视图位:「…」(Ctrl + 上 / 下键切换,边界不环绕)」;
- **「重置视图」**(菜单「视图」组的最后一个按钮)= 恢复默认顺序并全选,视图集不变(不是"关掉别的视图")。

每次布局变化,工作区上方的状态行都会用文字告诉你结果。

未显示、以及滚出可视区的视图**不会被卸载**:浏览器只是跳过它们的渲染与绘制(省性能),DOM 与内容都还在,勾回来 / 滚回去立刻恢复。

### 顶部菜单

从左到右是**三组**加右侧状态面:

- **「视图」组**:每个已登记视图一个按钮 = **聚焦并滚动到该视图**(见上);最后一个按钮是**「重置视图」**。**勾选与排序不在这里**——唯一入口是左半侧的「视图列表」;
- **「模式」组**:一个只读标识,显示当前是**解题模式**还是**调试模式**;
- **「运行」组**:
  - **指令步进**:让 VM 恰好执行一条指令然后暂停(会话已结束 / 未连接时禁用);
  - **积木步进**:Payload 搭建窗口是焦点窗口时可用,推进积木程序的一个原子动作;
  - **运行到断点**:仅调试模式、且断点集合非空、通道可用时可用;
  - **切换到调试模式 / 返回解题模式**:仅题目启用调试时显示(见第七章);
  - **提交**:正式裁决入口(见第八章);
  - **重启测试环境**:清空一切,回到题目初始状态;会话已结束时禁用,并出现「新建会话」引导;
- **右侧状态面**:`会话状态 <status> revision <n> 连接 <connectionStatus>`。`<status>` 是公开投影状态(`running` / `paused` / `won` / `failed`,没有会话时显示"无会话");`reconnecting` 时还会显示"第 N 次重试 · 约 X ms 后重试";
- 菜单下面可能出现几条横幅:**断线横幅**(保留最近一次公开投影 + 「手动重连」按钮;连接被同一会话的新连接取代时是警示样式)、**what-if 纪律横幅**(调试模式下常驻,见第七章)、**终态引导**(「测试环境已结束,请新建会话。」)、**动作被拒绝**条(错误码 + 说明 + 教学注解 + 「知道了」)。

## 五、怎么读内存(字节视图)

字节视图是主战场。每行 8 字节,左边是地址,中间是十六进制字节,右边是特殊显示列(可打印字符、寄存器标注、跳转链芯片)。

### 关键概念:可见窗口

出于安全设计,服务端对每块内存区域只下发**锚定区域起点的开头一段**(窗口大小有上限,缺省 256 字节;区域比窗口短则整块下发)。窗口内的字节是真实的;窗口外的格子显示为 `??`——这不是 bug,是"服务端没有下发这里"的诚实表达。用检索或跳转跳到窗口外会得到"在可见窗口之外"的提示,不会报错。

### 常用操作

- **RSP / RBP 锚点**:进入视图时自动滚到 RSP 所在行并高亮;滚远了点「回锚」。寄存器值不在已下发窗口内时,会明示"<寄存器> 内容不在可见窗口";
- **跳转**:输入 `0x` 开头的十六进制 = 绝对地址;纯数字 = 窗口内偏移;
- **检索**:在已下发的窗口字节内搜十六进制串;
- **跳转链**:某行的 8 字节如果"形似一个指针"(小端解释后指向另一块可见内存),行尾会出现地址芯片链,点击直接跳过去。这是你顺着指针找返回地址的主要工具;
- **点寄存器值复制**(非安全上下文会降级为选中 + 手动复制)。

### 值与地址都怎么读

- 十六进制统一小端序(题目固定 little-endian):低地址字节是低位;
- 值显示为 `0x` + 大写十六进制;宽度是题目声明的 32 或 64 位。

## 六、怎么操作内存

### 菜单与检查点面板

- **指令步进**(菜单):单步执行一条指令;
- **检查点面板**:保存快照(可加标签)、两步确认后恢复到某个快照。恢复和撤销都会产生**新的 revision**——时间线里"回退"也是一步,历史不会被抹掉;
- **重启**(菜单):一切归零。

### Payload 搭建(积木)

写 payload 不用手工数偏移:Payload 搭建窗口里用积木搭程序,它会被编译成**原子动作序列**逐步执行。

- 能产生真实操作的积木:**写字节 / 写字符串**(UTF-8)、**压栈 / 出栈**、**调用 / 返回**、**单步**;
- **断点积木**:步进到这里自动暂停;
- 变量、列表、分支、循环、函数:在**客户端编译期**展开求值(数值按 64 位无符号回绕),不产生服务端动作;
- 可以读公开投影(寄存器值、窗口内字节)做计算——比如"把当前 RBP 减 0x10 作为写入地址";
- **运行 / 单步 / 暂停 / 复位**:程序区逐行列出原子步骤并高亮当前步,输出区逐条记录每个动作的结果和错误;
- **编辑即复位**:改动画布后程序过期,运行/单步前自动重新编译并从头开始;
- 展开后的动作总数上限 256,超限会在编译期明确报错。

### 每一步都有版本号(revision)

你每一个**被执行**的动作(包括失败的教学反馈,比如往只读区域写)都会让 revision +1;被拒绝的动作(比如地址不可见)不推进。时间线窗口就是按这个版本号排列的完整历史。内存 diff 窗口能对照"上一个动作前后"的字节变化。

## 七、调试模式(what-if 沙盘)

题目默认启用调试(出题人可关闭,关闭时菜单不显示切换项)。调试模式给你一个**并行的沙盘实例**:指令视图、全内存检索、原生断点、运行到断点、跳转链全延伸。

两条必须记住的纪律(工作区顶部的横幅会一直提醒你):

1. **调试通过 ≠ 提交通过**。裁决以你提交的操作日志重放为准,调试实例里跑通只说明思路可行;
2. 调试实例的地址与真实实例可能不同(题目启用 ASLR 时尤其如此)。**硬编码调试实例里的绝对地址,在真实实例里失效属预期教学语义**——这本身就是 pwn 的第一课。

## 八、提交与正式裁决

### 流程

1. 你认为 payload 就绪后,执行提交(引用你整个会话的**服务端动作日志**,不是你自己上传什么);
2. 服务端返回提交号,裁决状态进入 **pending**(已受理,独立裁决服务正在排队重放)。未决期不会显示任何进度或排队位置——耐心等,界面会自动定期重询;
3. 裁决落库后状态变为 **verdicted**,给出最终结果,**不可逆**。

### 结果类型(11 种)

| 结果 | 人话 |
|---|---|
| `success` | 通过:重放成立且隐藏测试全过 |
| `wrong_answer` | 没打中:重放成立,但目标条件没满足 |
| `invalid_action` | 操作日志里有违规动作,重放无法通过校验 |
| `program_crash` | 重放中程序崩溃(教学语义的崩溃) |
| `memory_fault` | 重放中发生内存访问违规 |
| `resource_limit` | 超出步数 / 内存等预算 |
| `timeout` | 超时 |
| `engine_error` | 引擎内部错误(含溢出安全终止) |
| `challenge_invalid` | 题目包本身校验不成立(不是你的问题) |
| `replay_mismatch` | 独立重放与在线记录不一致(完整性保护,正常使用不会遇到) |
| `cancelled` | 提交被取消(超时或管理干预) |

### 和界面上的"胜利"是什么关系

会话进行中,工作区显示的状态(`running` / `paused` / `won` / `failed`)是**交互判定**,给你即时反馈用;正式裁决由独立服务重放产生,两者**相互独立**。交互界面显示 won 而正式裁决是 wrong_answer 是完全可能的(比如你碰巧触发了成功谓词但隐藏测试没过)。反之,伪造前端显示的 won 拿不到任何东西。

## 九、提示、错误与失败解释

### 提示阶梯

出题人为每道题配置最多 8 级提示:有的按请求揭示,有的在你失败若干次后自动揭示。教学面板里查看,自己决定要不要看——提示是给卡壳时的你,不是通关捷径。

### 错误解释

每个被拒绝或教学性失败的动作都会返回**可解释错误**:错误码 + 人话说明 + 教学注解(出题人按错误码配的)。16 个错误码速查:

| 分类 | 错误码 |
|---|---|
| 操作问题 | `invalid_input_format`(格式错)、`invalid_payload_length`(长度错)、`offset_out_of_range`(偏移越界)、`endianness_mismatch`(端序错) |
| 内存语义 | `permission_denied`(权限不足)、`inaccessible_address`(地址不可见/未映射——两种情况不可区分,这是有意的防探测设计)、`invalid_rip`(返回地址不指向可执行位置)、`canary_violation`(守护标记被破坏)、`invalid_call_argument`(调用参数错) |
| 目标与预算 | `objective_not_met`(目标未满足)、`budget_exhausted`(预算耗尽) |
| 协议层 | `stale_base_revision`(版本过期,重试即可)、`stale_client_seq`(序号过期)、`idempotency_conflict`(幂等键冲突)、`session_terminal`(会话已结束)、`internal_error`(内部错误) |

错误信息永远不包含内部细节(堆栈、路径、隐藏条件)——你看到多少,出题人就打算让你知道多少。

## 十、断线与恢复

- 断线时界面保留最近一次投影并显示重连横幅(自动指数退避重连),**不会**在本地假装继续运行;
- 重连成功后自动对齐最新状态,你接着做就行;
- 同一会话在别处打开新连接会把旧连接踢下线(单连接策略),点横幅上的「手动重连」即可拿回。

## 十二、常见问题

**Q:我打开 DevTools 改了内存/状态,能通关吗?**
不能。你改的只是浏览器里的"投影副本",服务端状态一个字节都不会变;提交时服务端重放的是你的**操作日志**,不是你浏览器里的任何东西。

**Q:为什么有的内存格子是 `??`?**
服务端只下发每块区域的开头一段(安全窗口)。窗口外的内容确实没有发到你的浏览器——不存在"找到了藏起来的字节"这种事。

**Q:为什么地址探测(瞎猜隐藏地址)得不到任何信息?**
对不可见地址的操作,无论那个地址是"隐藏区域"还是"根本没映射",你看到的结果完全一样。这是协议层保证的,扫描得不到任何边信息。

**Q:交互里显示 won,为什么正式裁决不是 success?**
两者独立(见第八章)。正式裁决还要过隐藏测试,那才是成绩。

**Q:undo 之后 revision 为什么还加一?**
"回退"也是一步。revision 是服务端的操作计数,永远单调前进——这样断线恢复、时间线、幂等重试才都靠得住。

**Q:调试模式里跑通了,提交却失败?**
调试是沙盘(what-if),裁决以提交日志重放为准;另外注意调试实例与真实实例的地址差异(第七章)。
