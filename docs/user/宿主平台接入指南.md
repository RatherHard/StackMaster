# 宿主平台接入指南

| 项 | 值 |
|---|---|
| 面向读者 | 想把 StackMaster 题目嵌入自己平台的 CTF 平台开发者 / 运维 |
| 定位 | 使用文档(非冻结契约);协议权威 = `docs/contracts/嵌入协议.md`(消息契约与校验规则 V-1~V-13),实现细节 = `packages/embed-runtime` / `packages/web-component` 的 README |
| 前置知识 | 不要求特定前端框架(宿主侧 SDK 框架无关);理解 iframe 与 postMessage 基础 |
| 日期 | 2026-09-14 |

---

## 一、架构:你负责什么、不负责什么

```text
宿主题目页(你的平台,域 A)
   │  iframe(独立来源,#esid=一次性握手值)
   ▼
插件页(独立来源部署;<pwn-memory-vm> 插件 Shell)
   │  认证 HTTPS/WSS(Cookie 凭证)── 全部业务数据走这里
   ▼
session-api(会话编排)→ vm-worker(权威执行)→ verifier(独立裁决)
```

- **嵌入协议(宿主 ↔ 插件 postMessage)只承载控制面**:握手、自适应高度、主题、语言。**动作、投影、错误、裁决一律不走这条通道**——它们走插件 ↔ session-api 的认证通道,你的页面碰不到也不需要碰;
- 你的页面本身在**选手控制域**内(选手能在你页面上做的事,包括开 DevTools,都在协议威胁模型的预期之内)。所以协议的信任基础不是"宿主是好人",而是:esid 知识证明 + source 绑定 + seq 防重放 + 服务端权威;
- 成绩的权威在服务端裁决(域 4)。宿主页面伪造任何"通关"状态都不影响成绩。

## 二、接入总览(五件事)

1. **让插件页可访问**:部署插件文档页(一个静态目录),或使用已有部署的插件 URL;
2. **宿主后端申请 embed token**:按题目 + 用户 + 租户向 session-api 申请短期凭证(server-to-server,token 永不进 URL);
3. **实现引导配置端点**(token 交付,通道 a,推荐):插件页拿 `esid` 来 POST,你返回 `{embedToken, sessionApiOrigin, challengeId, challengeVersion, embedSessionId}`;
4. **宿主页创建 iframe 并完成握手**:生成一次性 `embedSessionId` 放进 URL fragment,用 `@stackmaster/embed-runtime` 的 `EmbedSession` 完成 hello/ready 握手(推荐),或自行实现 V-1~V-13 全套校验;
5. **处理能力与外观**:按需授予 `auto_resize` / `theme` / `language`,监听高度上报,提供运行中主题/语言切换。

下面逐件展开。

## 三、部署插件文档页(第 1 件)

插件交付物 = `plugin/index.html` + 构建产物 `dist/index.js`(`@stackmaster/web-component` 包),**整目录拷贝即可部署**:

- 页面以 `<script type="module" src="./pwn-memory-vm.js">` 相对路径加载(非根路径部署兼容);
- **受限 CSP 兼容**:零 eval、零动态外部导入、文档页零内联脚本——`script-src 'self'` 即可承载(有自测覆盖);
- 实例化形态:

```html
<pwn-memory-vm bootstrap-endpoint="https://platform.example.com/sm/bootstrap"></pwn-memory-vm>
```

插件页可配置项(attribute,或全局 `window.PWN_MEMORY_VM_CONFIG`,attribute 优先):

| attribute | 作用 |
|---|---|
| `bootstrap-endpoint` | 引导配置取回端点 URL(通道 a;见第四章) |
| `descriptor-origin` | 题目描述包来源 origin 覆盖(缺省随部署) |
| `handshake-timeout-ms` | 握手超时 |
| `hello-max-retries` | hello 重试上限 |
| `max-height-px` | 高度上报收紧上限 |

本地联调:`pnpm --filter @stackmaster/plugin-dev dev`(开发壳,5173)与 `dev:plugin-site`(独立来源插件页,5174);后端拓扑 `pnpm --filter @stackmaster/session-api compose:app:up`(session-api 发布 13000)。

## 四、token 与引导配置端点(第 2、3 件)

### embed token 是什么

session-api 签发给**宿主后端**的短期凭证,签名前 claims 七字段:`tenantId` / `userId` / `challengeId` / `challengeVersion` / `embedSessionId` / `jti`(单次消费 + 吊销键)/ `expiresAt`(TTL 上限 7 天外圈护栏,实际签发窗口更短)。要点:

- token 对浏览器**保持不透明**:插件和宿主前端都不解析、不校验、不留存;
- `embedSessionId` 必须等于本次嵌入的 esid——iframe 重载轮换 esid 后,旧 token 自动失效;
- 签名格式(JWT/PASETO/自有)是实现面细节,你拿到手的是不透明字符串。

### 通道 a(默认):引导配置端点

你实现一个 HTTPS 端点(即 `bootstrap-endpoint`):

```text
POST /sm/bootstrap        请求体:{ embedSessionId }
             2xx 响应体:{ embedToken, sessionApiOrigin,
                          challengeId, challengeVersion, embedSessionId }
```

- 插件页加载后自动以 esid 调用,换取 token 与 session-api 地址,然后自行 `create_session`;
- 你的后端校验 esid 属于一次真实嵌入(你生成它时登记),再交付对应 token;token 不进 URL query、不进 localStorage,响应体即焚于插件内存;
- 失败返回非 2xx,插件显示降级界面(不会泄露你的响应内容)。

### 通道 b(备用):MessageChannel port 交付

opaque origin 部署或不想落地引导端点时,握手完成后经已绑定端点的 MessageChannel port 下发 token。规则:**port 转移是该路径的必需前置**(V-13:禁止以 `targetOrigin:"*"` 的裸 postMessage 承载任何凭证或绑定值)。SDK 的 `deliverTokenViaPort(token)` 封装了校验与搬运(SDK 同样不解析 token)。

## 五、宿主页握手(第 4 件,SDK 用法)

```ts
import { createEmbedSession } from "@stackmaster/embed-runtime";

const session = createEmbedSession({
  pluginOrigin: "https://plugin.example.com",      // 你的插件页来源(V-1 严格相等)
  pluginUrl: "https://plugin.example.com/index.html",
  config: { theme: "light", language: "zh-CN" },   // 随 ready 下发的初始外观
  // opaqueOrigin: true,                           // sandbox 无 allow-same-origin 时声明
  // grantableCapabilities: ["auto_resize", "theme", "language"],  // 缺省全部
  // handshakeTimeoutMs: 10000,                    // clamp 3000–30000
});

const iframe = document.createElement("iframe");
iframe.src = session.buildIframeSrc();   // 自动附加 #esid=<一次性值>,只放 esid
session.attachIframe(iframe);
iframe.addEventListener("load", () => session.notifyIframeLoad());
document.body.appendChild(iframe);

// 事件面(EMBED_SESSION_EVENTS):握手完成 / 高度变化 / 重载 / 不可用 / 违规计数
session.addEventListener(<event>, (e) => { /* ... */ });
```

SDK 替你做掉的事,自研时逐条都是你的义务:

| 义务 | 规则 |
|---|---|
| esid:CSPRNG ≥ 128 bit、base64url 恰 22 字符、一次性、重载轮换 | `generateEmbedSessionId()`;契约层 `minLength: 22` 把熵下限焊死 |
| 来源校验:`event.origin` 严格等于插件来源 | V-1;opaque 部署改用 `event.source === iframe.contentWindow` 绑定(V-1'),**不得把 `origin === "null"` 当信任信号** |
| esid 知识证明:每条消息 `sessionId` 必须等于本次嵌入值 | V-5 |
| seq 高水位:严格递增,重复 / 乱序 / 过期消息丢弃 | V-7 |
| 版本协商:双方支持集交集取最大;交集为空不回 ready | max-wins;插件侧超时自动降级 |
| 能力授予:实际授予 ⊆ 插件声明的能力 | V-8;未授予方向的违规消息丢弃 + 计数 |
| 速率限制:`height_changed` 每秒上限(默认 30)、控制消息每秒上限(默认 10) | V-10;构造选项可收紧 |
| 回发目标:握手完成后一律明确 `targetOrigin`(钉住插件来源) | V-11;仅 hello 接收方向允许 `*`,且 `"*"` 从不是信任控制 |
| 失败静默:违规消息一律丢弃 + 本地计数,零反馈零中断 | V-12;计数经 violation-counters 事件可读,便于你监控 |
| 凭证纪律:任何凭证 / 绑定值不经 `*` 的裸 postMessage | V-13(通道 b 必须先转移 port) |

其余可用 API:`getState()` / `getNegotiatedVersion()` / `getGrantedCapabilities()` / `getViolationCounters()` / `isPortActive()`;时钟 / 调度器 / 随机源 / 宿主窗口全部可注入(测试确定性)。

### iframe 重载

选手刷新 iframe 是正常场景。调 `session.reload()`:生成**新的** esid、作废旧值、seq 高水位清零、重走完整握手;如平台按 esid 发 token,旧 token 随旧 esid 一并作废。

## 六、能力与外观(第 5 件)

| 能力 | 授予后 | 不授予时 |
|---|---|---|
| `auto_resize` | 监听高度上报事件(带 `heightPx`,上限 100000),调整 iframe 高度;SDK 已做节流 | 插件固定高度渲染,不发送上报;你也不必处理 |
| `theme` | 运行中调 `session.sendThemeChanged("light" | "dark" | "auto")` | 插件用内置默认主题;发送了也会被丢弃 |
| `language` | 运行中调 `session.sendLanguageChanged(<BCP-47>)`;插件内置 zh-CN / en,按 BCP-47 确定性降级 | 插件用内置默认语言 |

语言 / 主题切换是插件内即时生效的;未授予能力时插件完全静态运行是合法形态。

## 七、成绩与审计边界(如实)

- **学习者看到的成绩** = 插件内呈现的正式裁决(提交 → pending → verdicted,11 值结果),由独立 verifier 重放产生,插件经自己与 session-api 的 Cookie 通道查询;
- **平台成绩册对接**:MVP 范围内未成文平台侧成绩同步接口(管理后台 admin 不在阶段六范围,生产部署面未做)。当前平台可通过裁判侧受控查询与审计库(域 4)对账;批量成绩接口将在后续阶段随 admin 面立项;
- 不要试图从插件页面拿成绩:宿主页面在协议里不承载任何业务数据,这是设计而非缺陷。

## 八、常见问题

**Q:我必须用 SDK 吗?**
强烈推荐。握手校验规则(V-1~V-13)共 13 条且逐条可测,SDK 已实现并带注入面;自研意味着你把反作弊与防重放的第一道闸维护在自己代码里。

**Q:插件 iframe 该怎么配 sandbox?**
推荐 opaque origin 形态(sandbox 不含 `allow-same-origin`)——此时声明 `opaqueOrigin: true`,信任基础切换为 source 绑定 + esid 知识证明 + seq,协议对此是一等支持路径。两 种形态都安全,按你的部署约束选。

**Q:一个页面嵌多个题目插件?**
每个 iframe 是独立的 embed 会话:独立 esid、独立 token、独立握手,互不影响。

**Q:选手中途登录态变化 / token 过期?**
esid 轮换 + 新 token + `session.reload()` 重走握手即可;插件侧降级界面自带重试入口。

**Q:怎么确认接对了?**
本地用 plugin-dev 开发壳(5173/5174 端口拓扑)对着 compose 后端全链路联调;SDK 的违规计数事件保持零增长、握手完成事件正常到达、插件内能建会话,即为接通。
