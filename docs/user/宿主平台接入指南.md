## 一、架构:你负责什么、不负责什么

```text
平台后端(你的平台,服务端;持宿主凭证 SESSION_API_HOST_BACKEND_TOKEN)
   │  ① POST /auth/launch-tickets        服务端间(HTTPS + Bearer)
   ▼
session-api(会话编排;页面与它同源)
   │  ② 201 { launchUrl, expiresAt }      票据只在 launchUrl 的 ?t= 内
   │
平台后端 ── ③ 把 launchUrl 当题目链接下发给学习者
   ▼
学习者浏览器 ── ④ 顶层导航打开 launchUrl
   ▼
session-api(服务端内换票,零 JS):
   │  ⑤ 票据原子单次消费 → Set-Cookie: sm_launch_grant
   │  ⑥ 302 到不含票据的干净路径(票据即刻脱离地址栏 / 历史)
   ▼
页面(与 API 同源的独立整页应用;自行 create_session)
   ▼
vm-worker(权威执行)→ verifier(独立裁决)
```

- **页面形态 = 与本服务同源的独立整页应用**(`apps/page-app`),由 session-api(或**同域**反代)提供。它**不嵌在你的页面里**——学习者打开的是一个完整页面,不是你的页面里的一个框;
- **你与服务端之间只有一件事**:申请一张一次性的启动地址,然后把它下发出去。业务数据(动作、投影、错误、裁决)全部走**页面 ↔ session-api** 的认证通道,你的后端碰不到也不需要碰;
- **旧形态整体退场**(**不要**再按这些词实现接入):iframe、postMessage、第三方页面里的插件文档页、`esid` 一次性握手值、握手与版本协商、能力授予、高度上报、`auto_resize`、`theme_changed`、`EMBED_THEMES`、校验规则 **V-1~V-13**。逐条对照见第八章;
- 学习者浏览器仍在**选手控制域**内(他能开 DevTools,这是预期的)。所以信任基础不是"平台是好人",而是:票据由**服务端签发**、熵 **≥128 bit**、**短时**(缺省 300 s)、**单次消费**、服务端绑定题目四要素、失败**统一 401 不分因**;
- 成绩的权威在服务端裁决(信任域 4)。谁在自己的页面上伪造任何"通关"状态都不影响成绩。

## 二、接入总览(五件事)

1. **平台后端调签发端点** —— `POST /auth/launch-tickets`,拿回 `201 {launchUrl, expiresAt}`;
2. **把 `launchUrl` 下发给学习者** —— 就是「下发地址」这一形态:一条题目链接 / 一次跳转;
3. **学习者直接打开该地址** —— **顶层导航**(点链接 / 地址栏 / 你平台上的跳转)。**不要**用 `fetch` / `XMLHttpRequest` 去取它,也**不要**放进 iframe;
4. **服务端换票** —— 学习者一打开,服务端就完成了:消费票据 → `Set-Cookie: sm_launch_grant` → **302 到不含票据的干净路径**。这一步**不需要页面 JS 参与**;
5. **页面自行 `create_session`** —— 载荷恰两键,授权来源 = 上一步种下的 Cookie。

> **平台方零凭证入浏览器**:宿主凭证 `SESSION_API_HOST_BACKEND_TOKEN` 只在你的**服务端**与 session-api 之间使用,**永不下发**到浏览器 / 页面 / URL / 日志。浏览器侧从头到尾只持有一个 HttpOnly Cookie。

下面逐件展开。

## 三、第 1 件:平台后端调签发端点

### 3.1 请求

```http
POST /auth/launch-tickets
Authorization: Bearer <SESSION_API_HOST_BACKEND_TOKEN>
Content-Type: application/json

{ "challengeId": "chal-stack-escape", "version": "1.2.3" }
```

请求体**恰两键**:

| 键 | 形态 | 语义 |
|---|---|---|
| `challengeId` | 非空、≤ 128 字符、字符集 `A-Za-z0-9_-` | 题目标识(公开描述包的可分发定位符) |
| `version` | `X.Y.Z` 语义化版本字面(三段均为数字) | 题目内容版本 |

- **没有第三个键**,也**不接受**第三个键:多一个字段即 **400**。**租户不在请求体里**——租户**只**由「宿主凭证 × `SESSION_API_HOST_TENANTS` 白名单」在服务端派生,**永不**从请求体 / 查询参数 / URL 派生(安全红线:不接受请求体或 URL 自报身份)。想自报 `tenantId` / `userId` 的请求体在契约层就被 `strictObject` 拒掉,不是"有但不用";
- 契约层**不携带 `protocolVersion` 字段**(N-1 受理是路由级事实,回显版本判定细节只会扩大探测面);
- 请求体的字符串字段还有一道粗长度闸(> 256 字符即 400),它与契约层的精确长度闸是双保险。

### 3.2 响应(201)

```json
{
  "launchUrl": "https://<页面与 API 同源的那个来源>/app/c/chal-stack-escape/1.2.3?t=<22 字符一次性票据>",
  "expiresAt": 1789200000
}
```

- **恰两键**;
- **票据只在 `launchUrl` 内**——响应**不**另回 `ticket` / `jti`,也**不回显** `tenantId` / `userId`(多回一个字段 = 把同一个秘密复制到第二个可被日志 / 前端缓存捕获的位置;回显租户只扩大跨租户探测面);
- `expiresAt` 是 **Unix epoch 秒(UTC)**;它与 Redis `launch:{jti}` 的 TTL **同值**;
- 地址由服务端按配置 `SESSION_API_PUBLIC_ORIGIN` 拼**绝对 URL**,**永不采信请求头**(`Host` / `X-Forwarded-*` 是 Host 头注入面)⇒ 该配置必须是**页面与 API 同源**的那个来源;
- `launchUrl` 的长度上限 2048 是外圈护栏(本族最坏形态 ≈ 300 字符)。

### 3.3 失败面(闸序固定:401 → 404 → 400 → 429 → 404 → 201)

| 状态 | 触发 | 响应体 |
|---|---|---|
| 401 | 宿主凭证缺失 / 畸形 / 错误 | `{"code":"invalid_input_format","message":"authentication failed"}` |
| 404 | **签发面未启用**(`SESSION_API_PUBLIC_ORIGIN` 未配,或 `SESSION_API_HOST_TENANTS` 未配而成空集合) | `{"code":"invalid_input_format","message":"resource not found"}` |
| 400 | 请求体不是恰两键 / 字段形态不符 / 字符串字段超长(> 256 字符) | `{"code":"invalid_input_format","message":"invalid request"}` |
| 429 | 签发频率触顶 | `{"code":"budget_exhausted","message":"rate limit exceeded"}` |
| 404 | 题目不存在 / 未发布 | 与上面那一行 404 **逐字节同形** |
| 503 | 存储不可用(Redis fail-closed,不降级) | `{"code":"internal_error","message":"storage unavailable"}` |

两种 404 **刻意同形**(部署形态不给调用方探测信号);频率闸刻意排在题目查询**之前**(超额请求不得到达数据库)。全部错误体都是冻结的公开形态,零内部细节。

## 四、第 2、3 件:下发地址与学习者打开

### 4.1 下发(你的交付纪律)

- 把 `launchUrl` 当作**一条题目链接**发给**对应的那个学习者**(题目列表 / 站内跳转 / 一次性链接分发都可以);
- **票据是一次性入场券,不是可转发的公告**:不要把它贴进公开聊天、公告栏或共享文档。契约把「**地址只发给对应学习者**」列为**平台侧交付纪律**——它与「票据一次性 + TTL 300 s」共同构成对**会话固定**(攻击者诱导受害者点开攻击者的地址,受害者在攻击者的会话里答题)的基线缓解。这一条**服务端补不了**,只能你在下发侧守住;
- 地址**只会生效一次**:学习者点开后就 302 到干净路径了,票据当场作废。要发第二次,就**重新调签发端点**取新地址(票据可无限重签)。

### 4.2 打开方式:**必须顶层导航**

- ✅ 可以:点击链接、地址栏输入、你平台上的 302 / 前端 `location.assign`——都是**导航类**请求;
- ❌ 不可以:`fetch` / `XMLHttpRequest` 之类的**子资源**请求。换票路由的第一道闸就是 `Sec-Fetch-Mode: navigate`,子资源请求带的是 `cors` / `no-cors`,必然拿到 **401**——这不是"权限不够",而是这个端点只受理导航;
- ❌ **不要用 iframe 承载**:本分发形态里没有 iframe;而且跨站 iframe 是**第三方上下文**,换票种下的 `sm_launch_grant` 是 `SameSite=Strict`,在那个上下文里 `create_session` 不会被带上 Cookie ⇒ 页面只会拿到 401。这正是「页面与 API **同源**」这条定案的直接后果。

## 五、第 4、5 件:换票与建会话

### 5.1 换票(全部在服务端完成,页面零 JS)

| 步 | 发生什么 |
|---|---|
| ⓪ | 校验 `Sec-Fetch-Mode: navigate`(拒绝子资源 / 嵌入式换票;纯请求头校验,不需要 JS) |
| ① | 票据存在且未过期(Redis `launch:{jti}`,TTL 与 `expiresAt` 同值) |
| ② | 票据**未被消费** |
| ③ | 绑定字段与地址路径**逐字一致**(`challengeId` / `version`;租户来自票据记录,**不在 URL 上**——URL 里连租户位都没有) |
| 消费 | **原子 CAS 单次消费**;**消费成功之后才签发**凭证(先消费后签发,失败不留半态) |
| 签发 | `Set-Cookie: sm_launch_grant`(HttpOnly;`SameSite=Strict`;`Path=/sessions`;`Secure`(测试环境豁免);`maxAge` = 票据 TTL) |
| 响应 | **302** 到**不含票据的干净路径** `/app/c/:challengeId/:version`;并带 `Cache-Control: no-store` + `Referrer-Policy: no-referrer`(= 第 4 件) |

- **换票不建会话**,也不签发会话凭证——它只证明「这个浏览器被授予了 `(租户, challengeId, version)` 的入场权」(第 5 件才建会话);
- **任一校验不满足 ⇒ 401 统一形态**:「票据不存在」「已过期」「已消费」「绑定不符」「`Sec-Fetch-Mode` 不合格」**逐字节同形**,响应体恒为 `{"code":"invalid_input_format","message":"authentication failed"}`。这几态不可区分是**防探测**的结构性要求;
- **Redis 不可用 ⇒ 503** `{"code":"internal_error","message":"storage unavailable"}`,**fail-closed:不降级、不静默放行**;
- 302 的 `Location` 由**结构上无法表达查询串**的函数产出 ⇒ 「忘了抹票据」在这条路径上不可表达(不是靠人记得)。

### 5.2 页面自行 `create_session`(第 5 件,页面侧)

- 页面(学习者已打开的那个同源页面)向 `POST /sessions` 发 `create_session`,**载荷恰两键**:`{challengeId, challengeVersion}`——这是**会话动作协议 v2**;旧的 `embedToken` / `embedSessionId` 已退场,带上即被拒;
- **授权来源 = `sm_launch_grant` Cookie**:同源 ⇒ 浏览器自动呈递(`credentials: "include"`),不需要你或页面做任何事。**载荷里没有授权,也不由载荷证明**;
- 服务端身份派生 = **凭证签名 claims × 凭证签发存储记录**;载荷只提供**导航信息**,且必须与凭证绑定**逐字一致**(不一致 = 拒绝,**不降级**为"以载荷为准");
- 凭证与票据都是**单次消费**:重放 = 401;
- 页面侧纪律(你不用实现,但排障时要懂):**浏览器侧不做授权判断**(从不读票据查询串、不校验租户);`create_session` 失败即呈现「**地址已失效,请向平台重新获取**」并**停止**——**不重试**(单次消费的东西,重试在语义上不可能成功,只会制造噪音与限流计数)。

### 5.3 票据生命周期与一次性(接入方必读)

| 项 | 取值 / 行为 |
|---|---|
| TTL | 缺省 **300 秒**(5 分钟),配置键 `SESSION_API_LAUNCH_TICKET_TTL_SECONDS`,天花板 **3600**(非正 / 超限 ⇒ 服务端拒绝启动);Redis TTL、响应 `expiresAt`、Cookie `maxAge` **同一个值** |
| 熵 / 形态 | ≥128 bit CSPRNG 的 base64url、**恰 22 字符** |
| 消费 | **单次消费**(原子 CAS,消费即删除);**不幂等** |
| 重复打开 | 第二次必然 **401 统一形态**,页面提示「地址已失效,请向平台重新获取」。**重新签发**即可,旧地址不会复活 |
| 载体 | 只在 `launchUrl` 的 `?t=` 内;**不落日志**(服务端**剥离整个查询串**,参数名漂移也免疫,并有运行时断言机检) |
| 浏览器侧 | 302 到干净路径 + `Cache-Control: no-store` + `Referrer-Policy: no-referrer`。**历史记录里留的是原始地址**——「票据进浏览器历史」这条残留风险已如实登记(方案 A 的代价) |
| 服务端语义 | 票据**不进** PG / 审计账 / 指标标签;`launch:` 键域禁止 `KEYS` 类全扫;Redis 掉电 / 刷库 ⇒ 未消费票据失效,须由平台**重新签发**(票据不承载不可重建状态,重签无限次) |

## 六、配置键清单(接入方与运维需要知道的)

| 配置键 | 缺省 | 含义与纪律 |
|---|---|---|
| `SESSION_API_PUBLIC_ORIGIN` | **未配(null)** | 签发响应里 `launchUrl` 的**唯一来源**(精确 origin:禁通配、禁路径、禁尾斜杠)。**未配 ⇒ 签发面未启用,一律 404**(fail-closed);这是**合法部署形态**,不是配置错误。值必须 = **页面与 API 同源**的那个来源 |
| `SESSION_API_PAGE_APP_DIR` | 未配 ⇒ 用仓库内 `apps/page-app/dist` | 页面产物目录。**配了却指不到目录 ⇒ 拒绝启动**;未配且缺省目录不存在 ⇒ **不注册**页面静态路由,但**换票路由照常工作**(页面完全可以由**同域反代**提供) |
| `SESSION_API_HOST_TENANTS` | 未配 ⇒ **空集合** | 租户白名单(逗号分隔)。**租户只由「宿主凭证 × 该白名单」派生**;空集合 ⇒ **签发面整体 404 同形**;提供了键却解析不出任何条目 = 配置错误(拒绝启动) |
| `SESSION_API_LAUNCH_USER_ID` | `launch-anon` | 启动面**占位主体**的 `userId`(身份由服务端配置派生,**永不**来自请求体 / URL)。⚠ **同一部署下所有学习者共享同一个 `userId`** ⇒ **`userId` 维度的统计与配额不可分**(`sessionId` 仍逐次唯一,成绩仍可按会话 / 租户区分)。**不要按 `userId` 做配额,也不要在任何界面 / 报表里把它说成"每个学习者"。** 这是本版**显式接受的代价**(本版没有终端用户账号) |
| `SESSION_API_LAUNCH_TICKET_TTL_SECONDS` | `300`(天花板 `3600`) | 票据有效期(秒) |
| `SESSION_API_LAUNCH_TICKET_ISSUANCE_PER_MINUTE` | `60`(天花板 `100000`) | 签发端点频率闸上限(按凭证绑定的**锚租户**做固定窗口,键 `rate:{锚租户}:launch_tickets`);触顶 **429** |

另外三件与接入直接相关的事:

- **宿主凭证** `SESSION_API_HOST_BACKEND_TOKEN`:服务间共享凭证,`Authorization: Bearer` 呈递。签发端点由它鉴权;**第七章的 `GET /host/scores` 用的是同一把**(单份实现,不复制第二套校验)。它是**服务端间**凭证,**绝不可下发到浏览器 / 页面 / URL / 日志**;租户绑定也由它 × `SESSION_API_HOST_TENANTS` 决定;
- **`SESSION_API_ALLOWED_ORIGINS` 不需要为页面放宽**——页面与 `/sessions` / `/auth` / `/descriptors` **同域**,不存在跨源请求。"同源"既是分发形态定案,也是这里省掉一整类配置的原因;
- **配置缺失是合法的部署形态**(未配 `SESSION_API_PUBLIC_ORIGIN` = 该部署不启用签发面);**配错**才是错误(配了却指不到目录 / 配了却解析不出租户条目 ⇒ 拒绝启动)。这个区分对运维很重要:想临时关掉签发面,不配那个键即可,不必改代码。

> **反代侧的运维硬要求(本指南不给配置片段)**:换票地址里的票据会进入**反向代理的访问日志**——这是方案 A(零 JS 换票)的已知代价,应用侧已由运行时机检保证零票据落日志,而**反代不在本项目控制内**。要求 = **反代必须对该路径的查询串脱敏,或整体不记录查询串**;验收判据 = 脱敏后 `/app/c/...` 的日志行里**不得出现 `?t=` 之后的任何内容**。本仓库**不提供反代 / TLS 配置片段**(上游纪律:**未在真机实测过的东西不给片段**),请按你方既有反代规范落地并用上面的判据验收。

## 七、成绩同步(只读)与审计边界(如实)

### 7.1 学习者看到的成绩

**学习者看到的成绩** = 页面内呈现的正式裁决(提交 → pending → verdicted,11 值结果),由独立 verifier 重放产生,页面经自己与 session-api 的 Cookie 通道查询(`GET /verdicts/:submissionId`)。

**不要试图从页面拿成绩**:本分发形态里**不存在**一条"你的平台页面 ↔ StackMaster 页面"的消息通道(旧形态那条 postMessage 信封已随插件嵌入形态整体退役),成绩**不随页面分发链路流动**——它是服务端间(**你的平台服务端 ↔ session-api**)的只读查询面。这是设计而非缺陷。

### 7.2 平台成绩册对接:`GET /host/scores`(中期 M3 WP-78 起可用)

你的平台服务端可以**批量拉取自己租户的成绩**,用于成绩册 / 排行榜 / 对账:

```http
GET /host/scores?limit=200
Authorization: Bearer <SESSION_API_HOST_BACKEND_TOKEN>
```

凭证、租户与查询面逐条如下(契约常量 `HOST_SCORES_PROTOCOL_VERSION = 1`,Schema 命名空间 `https://stackmaster.dev/schemas/host-scores/v1/`):

**① 凭证**:宿主后端共享凭证 `SESSION_API_HOST_BACKEND_TOKEN`(与启动票据签发端点同一把),经 `Authorization: Bearer` 呈递。它**不是**会话凭证——会话凭证在本接口一律 401。宿主凭证是**服务端间**凭证:**绝不可下发到浏览器 / 页面**。

**② 租户绑定**:你的凭证在部署期被绑定到一个租户集合(运维配置 `SESSION_API_HOST_TENANTS`,逗号分隔)。**租户只由凭证决定**,请求体 / 查询参数都不能自报身份;`?tenantId=` 只能在该集合内**子选**,集合外的值返回 404(与"不存在"同形,零探测信号)。**未配置白名单 = 接口整体 404**(fail-closed)。

**③ 查询参数**(只认这三个,多一个即 400):
| 参数 | 含义 | 边界 |
|---|---|---|
| `cursor` | 上一页响应里的 `nextCursor`(不透明游标,**按 id 的键序**,不是时间) | 非法形态 → 400 |
| `limit` | 本页最多几条 | 正整数,≤ 部署配置的批量上限(缺省 500);**超限 400,不会静默截断** |
| `tenantId` | 在绑定集合内子选租户 | 不在集合内 → 404 |

**④ 响应**:公开上限面,只有**七个字段 / 条**——

```json
{ "items": [ { "id": "…", "submissionId": "…", "sessionId": "…", "challengeId": "…",
               "challengeVersion": "1.2.3", "verdict": "wrong_answer", "decidedAt": 1789200000 } ],
  "nextCursor": "…" }
```

- `verdict` 是 11 值冻结结果类型之一;`decidedAt` 是 **epoch 秒**整数;
- **`nextCursor = null` 表示没有下一页**;翻页方式:把上一页的 `nextCursor` 原样回填到 `?cursor=`。`items` 为空且 `nextCursor` 为 `null` 是**正常终态**,不是错误;
- **拿不到的东西**(结构性,不是权限问题):判题明细 / 谓词 / 隐藏测试命中、提交引用(完整 IR / 快照 / 完整事件日志)、内部堆栈,以及**租户回显**。载荷里连字段位都不存在。

**⑤ 分页语义**:游标是**键序(keyset)**游标,保证**不重不漏于已落库行**,但**不保证并发写入下零遗漏**——裁决在你翻页期间落库时,新行的 id 是随机 UUID,可能落在游标之前。对账场景请以 `submissionId` 去重,并把"翻到 `nextCursor = null`"当作一次快照的边界。

**⑥ 限流**:按**凭证绑定的锚租户**做固定窗口(`rate:{tenant}:host_scores`,缺省 120 次/分钟,运维可调)。子选不同 `tenantId` **不会**给你额外预算——避免用参数轮换放大配额。触顶返回 429。

**⑦ 错误码**(全部为冻结 `PublicError` 形态,响应体零内部细节):

| 状态 | 触发 | 响应体 |
|---|---|---|
| 401 | 凭证缺失 / 畸形 / 错误 | `{"code":"invalid_input_format","message":"authentication failed"}` |
| 404 | 未绑定任何租户;或 `tenantId` 不在绑定集合内 | `{"code":"invalid_input_format","message":"resource not found"}` |
| 400 | 未知查询参数 / 畸形 `cursor` / 畸形或超限 `limit` | `{"code":"invalid_input_format","message":"invalid request"}` |
| 429 | 频率触顶 | `{"code":"budget_exhausted","message":"rate limit exceeded"}` |
| 503 | 存储不可用 | `{"code":"internal_error","message":"storage unavailable"}` |

### 7.3 还没做的事(如实)

- **管理后台 = 只读最小面已落地,完整后台仍不在范围内**:`apps/admin`(信任域 4)已按 **D-MP-5 分支 A** 落地**只读最小面** —— 题目登记列表 / 裁决查询 / 成绩导出三面,**全部为 GET**(零业务写路由);它使用**独立的 admin 凭证**(与宿主后端令牌 `SESSION_API_HOST_BACKEND_TOKEN` **不是同一把钥匙**,两者权限面与轮换周期不同)、**独立的只读数据库角色 `admin_ro`**(非 superuser、非 `BYPASSRLS`),并**直连 PG、不经过 session-api**(禁 app→app 依赖);网络域与页面分发链路分离,**不入页面分发链路**。**仍未做**:写面 / 运营功能(题目上下架、成绩更正、批量导出编排等)、独立域名与证书、跨租户聚合报表 —— 这些归后续 WP。**对宿主平台的影响 = 无**:本章的 `/host/scores` 只读同步面与 admin 面是**两条独立通道**,凭证、端口与网络域均不共用,接不接 admin 都不影响平台侧成绩对账;
- **成绩不推送**:本接口是**拉取式**只读查询。平台若要近实时成绩,请自行按退避节拍轮询 `cursor` 分页;契约不提供 webhook / 订阅面;
- **本接口零写入面**:不存在任何"平台改成绩 / 改提交状态"的入口——裁决的唯一出处是独立 verifier(信任域 4),这是硬门槛。

## 九、常见问题

**Q:我必须自己部署页面吗?**
不需要。页面与 API **同源**,由 session-api 托管(`SESSION_API_PAGE_APP_DIR` 指向 `apps/page-app/dist`),或由**同域反代**托管静态文件。你侧只做两件事:调签发端点,把地址下发出去。若你要自己托管页面,注意两点:必须与 API **同域**;并且**未配 `SESSION_API_PAGE_APP_DIR` 不会影响换票**——换票是服务端语义,与"谁来托管页面"解耦。

**Q:我能用 `fetch` 或 iframe 打开启动地址吗?**
都不能。`fetch` 类子资源请求会被换票路由的 `Sec-Fetch-Mode: navigate` 闸拒(401);iframe 会把 Cookie 置入第三方上下文,`SameSite=Strict` 的授权凭证在那里面不会被带上,页面只会拿到 401。**顶层导航**是这形态唯一支持的开法——点击链接 / 地址栏 / 服务端 302 都行。

**Q:学习者重复点同一个地址 / 刷新页面会怎样?**
票据**单次消费**:第二次打开必然 **401**,页内提示「**地址已失效,请向平台重新获取**」。刷新同理(票据已用掉)。要再开一次,由平台**重新调签发端点**拿新地址——票据可无限重签,旧地址不会复活。

**Q:票据过期了,或者学习者过一会儿才点开?**
TTL 缺省 **300 秒**。过期与"已消费"在响应上是**同一个** 401(逐字节同形,这是防探测的设计)。处理方式只有一条:**重新签发**并把新地址发给他。不要试图延长旧地址的有效期——没有这个面。

**Q:我怎么确认接对了?**
按这五条判据验收(前两条在你侧、后三条在浏览器侧可观察):

1. 签发请求返回 **201**,且响应体**恰两键** `{launchUrl, expiresAt}`;
2. `launchUrl` 的 origin 与你配的 `SESSION_API_PUBLIC_ORIGIN` **逐字一致**,且带 `?t=`;
3. 把这个地址交给浏览器**顶层导航**后,**地址栏停在 `/app/c/<challengeId>/<version>` 且没有 `?t=`**(证明 302 与抹票都生效);
4. 页面进入工作区并连上(连接态显示已连接),即 `create_session` 与 WSS 均成功;
5. 平台 / 反代日志里**搜不到** `?t=`(应用侧有运行时机检保证;反代侧按第六章那条硬要求自查)。

同一地址再打开一次应得 401——这是"一次性"的验收。

**Q:学习者改 URL 里的题号 / 版本,能换题或换租户吗?**
`challengeId` / `version` 是**公开导航信息**,"打开哪一题"确实由它决定;但**授权**由票据绑定决定。改路径与票据记录不符 ⇒ 401。**租户在 URL 里根本没有位置**,不存在自报租户这一说。

**Q:我能按学习者分别统计 / 分别配额吗?**
**不能按 `userId`**。本版没有终端用户账号,`SESSION_API_LAUNCH_USER_ID` 缺省 `launch-anon` ⇒ **同一部署下所有学习者的 `userId` 相同**,该维度的统计与配额不可分。可分的是 `sessionId`(逐次唯一)与租户维度:成绩面(`verdicts`)本就以会话为主键,所以**成绩仍可按会话 / 租户区分**。详见第六章那一行——这条是**显式接受的代价**,不要在界面或报表里把 `userId` 说成"每个学习者"。

**Q:我能在本地把整条链跑一遍吗?**
可以,但需要真实拓扑:起 compose(session-api + PostgreSQL + Redis)、构建页面产物、登记一道题,然后按 `apps/page-app/README.md` §5.2 的四步走(签发 → 把 `launchUrl` 贴进浏览器)。自动化形态是 `apps/page-app/e2e/launch-chain.spec.ts`(需显式开启 `E2E_LAUNCH_CHAIN=1`);它断言的是:签发响应恰两键 → **顶层导航** → 302 后地址栏无 `?t=` → 工作区就位并连上 → 同一张票二次导航 = **401**。**如实登记**:该链在开发机上**未实测**(本机 Docker 引擎不可达,起不了拓扑),上面的判据以契约与实现为准,不代表已跑通的实测结论。
