1.2 打开启动地址后发生什么（进入一局）

进入一局不需要填任何表单。真实序列如下（每一步都是磁盘上的实现）：

#发生什么你会看到
1平台后端向服务端签发一张一次性启动票据（服务端间调用 POST /auth/launch-tickets，用宿主凭证认证），返回体恰两个键 launchUrl / expiresAt；票据值只存在于 launchUrl 里 平台界面上出现一个「开始 / 进入题目」链接或按钮
2你在顶层导航打开它：/app/c/:challengeId/:version?t=<票据>。 服务端校验这是一次页面导航（Sec-Fetch-Mode: navigate，不接受子资源/嵌入式访问） 浏览器地址栏会短暂出现带 ?t= 的地址
3换票（服务端完成，零 JS）：票据存在且未过期 → 原子地单次消费 → 与路径里的题目绑定逐字比对 → 签发起动授权凭证并写入 Set-Cookie: sm_launch_grant（HttpOnly + SameSite=Strict + Path=/sessions）→ 302 到不含票据的干净路径，并带 Cache-Control: no-store 与 Referrer-Policy: no-referrer 地址栏里的 ?t=… 消失（票据不会留在历史与 Referer 里）
4页面装配：按路径取出题目定位 → 运行期加载前端产物 → createSession（请求体恰两个键 challengeId / challengeVersion；不带任何令牌，授权来自上一步的 Cookie）→ 连接认证动作通道 → 取公开描述包（取不到不阻塞会话，只是题目简介与教学面缺席明示）→ 挂载工作区 页面直接变成整页工作区（§1.1），10 类视图全部就位
5顶部菜单状态行显示连接态 会话状态 running · revision 0 · 连接 connected（§2.2）
地址是一次性的：票据缺省有效期 300 秒（部署可调，上限 3600 秒）， 消费即删除，重复打开同一地址必然失败（过期 / 已消费 / 不存在在服务端返回同一种 401， 不给你探测差别）。页面侧的呈现固定为「地址已失效,请向平台重新获取」， 并且不会自动重试（单次消费的凭证重试没有任何成功可能）。 页面把这条提示以浮在顶部的状态行显示（role="status"，不参与布局、不遮挡操作）。
你看到这句话含义与处置
「地址已失效,请向平台重新获取」票据已被消费 / 已过期 / 授权凭证被拒（401）。回平台重新取一次启动地址
「地址无效:这不是一个 StackMaster 题目启动地址(缺少题目定位路径)。」地址被手打、截断或前缀不对。 页面不会发起任何网络请求（形态明显不对的地址不该制造 401 噪音）
「前端资源未就绪(未找到 /vm-ui/index.js)…」或「前端资源版本不匹配…」部署问题（前端产物没部署或版本不一致），告知平台运维
「题目描述包未加载:简介与教学面暂不可用(会话不受影响)。」非故障：会话照常可用，只是题目简介 / 提示阶梯 / 错误教学注解缺席
页面侧不做任何授权判断：它从不读地址里的 ?t=、不校验租户、不判断「这个地址该不该能用」。 唯一的授权事实来自建会话应答（401 = 地址已失效）。

1.3 整页布局与左右两分

工作区是一条有序的视图列表：注册表登记的全部 10 类视图各恰一个、常驻。 视图没有「开 / 关」这回事（D-MP-1 不修订）——面板上没有「×」，菜单里也没有「关闭 / 打开」入口。 每个视图只有两种处境：可见（勾选了），或暂离（未勾选 / 滚出左半侧可视区）。 把「暂离」读成「关掉了」是误读：它一直在地里，勾回来就在原来的位置上。

1.3.1 左右两分（固定 1:1，不可调）

半侧内容行为
左半侧视图管理窗口：上方一个可展开的「视图列表(勾选显示 / 拖拽排序)」按钮， 下方是视图位纵向堆叠区 任一时刻约两个视图位在视野里（上下各一），更多视图由左半侧内部纵向滚动承载； 滚动带丝滑动画，系统开启「减少动态效果」时退化为即时定位
右半侧Payload 搭建窗口（固定） 恒显示积木搭建页（§7），用的是同一个内容元素实例，不随左侧滚动移动；模式切换也不丢状态
没有 gap、没有边框、没有分隔条：两半侧紧密贴合，比例固定 1:1 且不可拖拽调整 （可拖拽的分界本身就是一条分隔条，与本版「无描边、无分隔条」的要求直接冲突）。 也没有列宽档位、「重置布局」、「列内分割」这类入口 —— 它们随旧布局整条废止。

1.3.2 视图的显示与顺序：唯一入口 = 左半侧列表按钮

展开左半侧的「视图列表(勾选显示 / 拖拽排序)」后，你会看到 10 行，每行 = 序号 + 勾选框 + 视图类型名：

操作行为
勾选 / 取消勾选决定该视图是否显示在左半侧（取消 = 暂离，不是关闭）。 每次变更都经 aria-live="polite" 播报「已显示『某某』」/「已隐藏『某某』」
拖拽行调整视图在纵向堆叠中的顺序（落点用行上/下边线标出； 拖到列表之外松开 = 不移动，并播报「落点在列表之外,松开不移动视图」）
Alt + ↑ / ↓键盘等价路径：把该行在列表内上/下移动一位，播报「已把『某某』移动到第 N 位」
Space键盘等价路径：切换勾选（原生勾选框，故不需要记特殊键）
「重置视图」（在菜单「视图」组里）＝ 恢复默认顺序 + 全选（所有视图重新可见）； 焦点与 Ctrl+↑/↓ 的落点复位，视图集不变。 默认顺序 = 登记序：栈视图 / 寄存器视图 / 指令视图 / 自由视图 / Payload 搭建 / 调用栈 / 结构视图 / 时间线 / checkpoint / 内存 diff。 这是把顺序与显隐改乱之后的逃生门。
菜单「视图」组不承载勾选与排序（它只做聚焦导航，§2.1）。 显示与否 + 顺序的唯一入口就是左半侧的列表按钮。
列表里「Payload 搭建」那一行的勾选对右半侧没有可见影响： Payload 搭建窗口固定在右半侧恒显示，因此它不会出现在左半侧的堆叠区里，勾掉它也不会让右半侧消失。 （勾选状态本身仍被模型记录，属于「暂离」语义。）

1.3.3 每个视图位的确定高度：只滚动，不压缩

每个可见视图位的高度由左半侧可视高度等分算出并内联为像素（两个可见位 ⇒ 各占约一半）， 并保底「面板自身开销 + 4 行字节」——也就是说，空间不够时让左半侧滚动，而不是把视图压扁。

事实取值 / 含义
可见视图位数量固定 2 个（上 / 下），不可配置
最小可视数据行每个可见视图位至少装得下 4 行字节（4 行 × 8 字节 = 32 字节 = 「缓冲区首 16 字节 + 保存的 rbp 8 字节 + 返回地址 8 字节」这一教学闭环的最小可视片段）
空间不足时由左半侧纵向滚动承载，视图位不会被压到装不下一行字节
滚出视野的视图位交给浏览器跳过渲染与绘制（content-visibility: auto + 占位尺寸）—— 不是被卸载：DOM 与内容都在，滚回来立刻恢复，且进入视野时不跳动

焦点视图位只靠类型名的颜色区分（琥珀色），不画边框（无描边约束）。 视图的类型名写在视图内左上角，它不是独立的标题栏，也不承载任何控件。

1.3.4 窄屏（宽度不够时）

事实说明
形态不变左右两分不改变：不允许隐藏右半侧、不允许改成抽屉 / Tab 切换、不允许上下堆叠
左半侧宽度下限452.4px（= 58 字符 × 7.8px，保证十六进制行本身不折行）。 两半侧都按此保底 ⇒ 窄屏下网格宽于视口 ⇒ 页面出现横向滚动条，往右滚即可看到右半侧
这是已接受的代价字节视图自带 14rem（224px）的区域侧栏，不在 452.4px 的推导范围内。 因此左半侧宽度小于约 766px 时，字节视图必有某种降级（窄档折叠区域侧栏 / 列头折行等）—— 这是设计上接受的取舍，不是故障。窄档的实际形态见 §4.4
已否决的替代方案「把左半侧底线抬到约 766px」被否决：固定 1:1 ⇒ 需要视口 ≥ 1532px， 1024 / 1366 笔记本会被判为不可用；这等于把「表达力问题」换成「准入问题」
键盘：Ctrl + ↑ / ↓ 在左半侧切换视图位（边界不环绕）， 具体规则见 §12.3。
解题 ↔ 调试模式切换只换绑数据源，布局相关的用户调整（顺序、勾选、焦点）都不动； Payload 搭建窗口里的状态两模式共用、不丢失。

2. 顶部菜单与会话状态条

2.1 菜单按钮逐个说明

菜单是三个分组（按渲染顺序）：「视图」、「模式」、「运行」， 状态行在最右侧。「视图」组 = 聚焦导航 + 「重置视图」； 原「窗口」组即本组（组名改为「视图」），原「布局」组（列宽五档 + 重置布局）已整条废止。

按钮 / 元素可用条件动作与你会看到什么
〔视图组〕10 个聚焦按钮（栈视图 / 自由视图 / 寄存器视图 / Payload 搭建 / 指令视图 / 结构视图 / 调用栈 / 内存 diff / 时间线 / checkpoint） 恒可用（无禁用态） 点击 = 聚焦该视图并把它滚进视野（不会新开实例、不会改勾选或顺序）。 当前焦点视图的按钮呈按下态（aria-pressed）；悬停提示「聚焦『某某』并滚动到该视图」。 默认焦点 = 序首（栈视图）
〔视图组〕「重置视图」恒可用（无禁用态） 恢复默认顺序 + 全选（§1.3.2）。悬停提示「恢复默认顺序并全选(视图集不变,不存在开 / 关语义)」； 状态行反馈「已重置视图:恢复默认顺序并全选」
〔模式组〕模式指示恒显示 文字显示当前档：「解题模式」 或 「调试模式」（不可点，是状态不是按钮）
〔运行组〕「指令步进」已连接且会话未终态 让虚拟机恰好执行一条指令后暂停。每次成功点击 revision 前进；禁用时悬停给出原因（未连接 / 已终态）
〔运行组〕「积木步进」Payload 搭建窗口是当前焦点视图 推进积木程序的一个原子动作并暂停（等于在 Payload 搭建窗口点「单步」）。 不可用时悬停提示「仅 Payload 窗口激活时可用」
〔运行组〕「运行到断点」仅调试模式；断点集合非空；动作通道已连接且未终态 运行到最近断点后暂停；命中后指令视图高亮暂停行并给出暂停原因（§8）。不可用时按当前档给不同提示： 「调试模式下可用(先切换到调试模式)」/「调试模式下、断点集合非空且通道可用时可用(在指令视图添加断点)」
〔运行组〕「切换到调试模式」 / 「返回解题模式」仅当题目启用调试时才显示（未启用的题目隐藏本项） 切换数据档：所有视图换绑数据源，布局与顺序不动（§8.1）。切换后字节视图的滚动 / 锚点重置属预期
〔运行组〕「提交」已连接且会话未终态 把你的服务端动作日志送交独立裁决服务（§10）。禁用时的悬停提示分四种： 「尚未创建会话,不能提交」/「动作通道未连接,等待重连后提交」/「测试环境已结束,请新建会话后再提交」/ 默认说明
〔运行组〕「重启测试环境」已连接且会话未终态；won / failed 后禁用 清空一切回到题目初始状态（revision 仍 +1）。禁用时悬停提示「测试环境已结束,请新建会话」等
〔状态行〕（最右）恒显示 会话状态 <值> revision <n> 连接 <状态>；无投影时会话状态显示「无会话」， revision 为未知时显示「—」；重连中额外显示「第 n 次重试 · 约 x ms 后重试」（§2.2 / §11）
「视图」组从不置灰（聚焦不依赖会话是否已连接）； 模式切换项在题目未启用调试时整个不渲染（不是置灰）。

2.2 会话状态条（菜单右侧）

3. 全局横幅与状态行

4.2 可见窗口：?? 是什么

服务端对每块区域只下发锚定起点的开头一段（缺省 256 字节；区域更短则全量）。因此：

你看到的含义
正常字节已下发窗口内的真实数据
?? 格子窗口外——服务端没有下发这里。不是 bug、不是「藏起来了」，是结构性地不存在于你的浏览器
区域截断标记区域列表 / 投影里 truncated 标记为真 = 该区域只下发了前缀（诚实声明）
对窗口外的跳转 / 检索都不会报错，只会得到「在可见窗口之外」的提示。 不存在「找到藏起来的字节」这种事：隐藏区域与未映射地址在你这边完全不可区分（防探测是协议层保证）。

4.3 锚点与导航

功能操作行为
RSP/RBP 锚点进入视图 / 切换区域时自动 视口自动滚到 RSP 所在行并高亮。滚远了点「回锚 RSP」按钮回去。 若 RSP 的值不在已下发窗口内，明示「<寄存器> 内容不在可见窗口(0x…)」（不渲染空白、不报错）； 寄存器未公开则不显示锚点
跳转输入输入地址后提交 0x 开头十六进制 = 绝对地址；纯数字 = 窗口内偏移。 窗口外 → 「… 在可见窗口之外(仅窗口内可达)」，不滚动不报错；调试档下会先尝试预取（「… 在已缓存窗口之外,正在请求调试窗口……」）
检索输入十六进制字节串（如 0102） 只在已下发窗口字节内搜索；命中列表点击即滚动过去；命中在其他区域会先自动切区域。 无命中显示「窗口内无命中」；命中数有上限，显示「共 N 处命中,显示前 M 处」
对齐偏移[-] / [+] 把行的 8 字节对齐基准在 0–7 之间移动（0 时 [-] 禁用，7 时 [+] 禁用）
寄存器交叉标注自动 + 点击 某寄存器的值恰好指向本行已下发窗口内的地址时，该行左缘出现标注徽标；点击在行内展开「哪些寄存器指向这里」
跳转链芯片自动出现 + 点击 某行 8 字节按小端解释「像一个指向可见内存的指针」时，行尾出现地址芯片链。点击芯片 → 跳到目标行（窗口外则提示）。 链默认横向最多 3 段，「展开完整链」可看竖向全链（上限 32 段）， 循环引用画回环箭头；链末尾若是可见 ASCII 字符串会直接把字符展示出来（≤ 32 字节）
读内存三板斧：跟着 RSP 锚点看栈 → 看到可疑指针点跳转链芯片顺藤摸瓜 → 用检索确认特征字节。 指针追踪在窗口外会截断，这是诚实显示不是故障。

6. 教学组件五件套

6.1 结构视图

出题人声明的「语义地图」。按固定分组排序展示：buffer 起点 → 返回地址槽 → saved RBP 槽 → canary 槽 → 自定义标注； 每条显示名称、所属区域、地址与长度。 点击任一条会发出跳转请求——会把字节视图滚到对应位置。这是你把「抽象的栈帧布局」对上「具体字节地址」的主要工具。 没有标注时提示「暂无结构标注(semanticHighlights 随初始公开投影或同步下发)」。

6.2 调用栈

元素说明
帧条目序号 + 函数标签 + 返回地址。index 0 标注「最内帧（当前函数）」，往下是调用者。 表头附注「调用栈(index 0 = 最内帧;帧基址不下发,由 RSP/RBP 推导)」
截断明示深度超过 64 帧时只显示最内 64 帧，并在最后一帧标注「仅显示最内 64 帧」——故意不显示「+N」，因为帧数本身也是信息
空栈「暂无调用帧(当前无活跃调用链)」

6.3 内存 diff

对照「上一个动作前后」的字节变化：前值 → 后值逐字节标出差异。表头附注「内存 diff(N 字节变化;前值取自动作前已下发窗口)」。

  • 只对照最近一次动作的增量（不是累积历史）——累积历史看时间线；
  • 无可见变化时显示「本动作无可见字节变化」；
  • 前值不在已下发窗口内时，该行明示「前值不可知」，不伪造；
  • 变更区域被截断时提示「变更承载被截断,已按协议以 sync-projection 重新对齐」。

6.4 时间线

你整个会话的操作历史，按 revision 排列：每个动作一行（动作摘要 + 关键参数：write_bytes 0x…(N 字节)、 checkpoint(id) / checkpoint "标签"、submit(id)）； 当前 revision 有「当前 revision」徽标。撤销 / 恢复 / 重启也各占一行——历史从不被抹掉，回退也是一步。 空态提示「暂无历史记录(动作与 checkpoint 将在此累积)」。做题卡壳时回看时间线，经常能发现「哪一步之后 layout 变了」。

6.5 checkpoint（检查点面板）

功能操作与规则
创建输入可选标签（≤ 128 字符，禁止控制字符；超限分别提示「标签不能超过 128 个字符」/「标签不允许包含控制字符」）→ 点「创建 checkpoint」。服务端保存完整快照；revision 照常 +1，时间线多一条
切换（恢复）列表按创建顺序列出所有检查点（标签 / revision / checkpointId）；点「切换」需两步确认 （按钮变为「确认切换」，并问「确认切换到 …(revision N)?」——防误触）。 恢复 = 内容回到快照、revision 继续 +1（回退也是一步）。表头附注「checkpoint(按创建顺序;切换会把内容回退到对应 revision)」
终态会话 won / failed 后不能创建或切换：面板显示「会话已终态,不能创建或切换 checkpoint(请新建会话)」， 服务端也会返回可解释错误
空态「暂无 checkpoint(创建后将按创建顺序列出)」

8. 调试模式与指令视图

8.1 调试模式是什么

一个并行的沙盘实例：题目默认启用调试（出题人可显式关闭；关闭时菜单里连切换项都不显示）。 切换方式 = 菜单「运行」组的「切换到调试模式」。切过去之后：所有视图换绑到调试数据源（字节视图滚动 / 锚点重置属预期）， 指令视图从引导空态变为真实指令流，菜单出现可用的「运行到断点」， 菜单之下出现常驻 what-if 纪律横幅。

两条铁律（横幅会一直提醒）：①调试通过 ≠ 提交通过，裁决只看提交日志的重放； ②调试实例地址可能与真实实例不同——在调试里看到的地址，硬编码进 payload 到真实实例可能失效（ASLR 题尤其如此，这本身是 pwn 第一课）。

调试通道的状态与错误也会明示：「调试实例已对齐(重放完成),调试通道已就绪」/「调试通道已断开:重新切换到调试模式以重新 attach」/ 「调试实例:尚未 attach」等。按需拉取超出覆盖面的内容时提示「… 正在请求窗口……」，仍不可达则明示「在覆盖面之外」。

8.2 指令视图（调试档专属内容）

组成说明
指令流（三段）每行 = 地址 / 伪机器码 / 伪汇编；伪机器码缺失时显示「—」； 跳转类指令尾随目标地址延展，点击直接跳到目标行（表头「地址 / 伪机器码 / 伪汇编」）
RIP 锚点最新暂停地址行高亮 + 「回锚 rip」；锚点行显示「rip = 0x…」；无暂停地址时显示「rip 锚点:暂无暂停地址」
函数表附着时推送的函数列表「函数表(N)」，按起始地址排序，点击跳转
行断点每行有一个断点开关（aria-pressed 表达开关态；悬停提示「添加断点」/「移除断点」）。 断点集合是界面状态（可多个），配合菜单「运行到断点」使用
暂停原因暂停时显示四值之一：单步暂停 / 命中断点,已暂停 / 程序已自行停机(exit / 停机指令) / 预算耗尽,确定性暂停

解题模式下指令视图只显示一句引导： 「指令视图由调试通道承载(伪指令流 / 函数表 / 地址断点)。当前为解题模式——请通过菜单『切换到调试模式』启用后使用。」 它不会伪造指令流（视图一直都在，只是当前数据档不是调试档）。调试档的内存 / 指令来自「推送 + 按需拉取」的缓存：缓存外区域同样以窗口外语义呈现。

9. 教学面板与题目简介

9.1 题目简介（可折叠；加载成功时默认展开）

题目标题、情境摘要、架构参数（架构位宽 / 端序 / 页大小 / 寄存器清单 / canary 状态）， 题目若下发编码表则一并展示。做题前扫一眼，寄存器清单告诉你哪些名字会在寄存器视图里出现。 描述包没取到时显示「题目描述未加载」与说明「题目描述包未成功加载:题目简介、提示阶梯与错误教学注解暂不可用(不影响会话与解题)。」

9.2 教学面板（可折叠，两块）

块机制
提示阶梯出题人配的提示。两种揭示策略：按请求（点「显示下一条提示」才揭示）与 失败 N 次后自动（本地计数，教学性失败才算；未达标显示「再失败 N 次解锁」）。 揭示顺序固定，无法跳级看后面的——讲方法不给答案。未揭示的条目以「提示 N(未揭示)」占位；本题没配则提示「本题没有配置提示」
错误解释器每个错误码配出题人写的教学注解。收到错误时这里显示「错误码 + 解释 + 教学注解」； 没有配注解的错误码会明示「该错误暂无教学注解」；没有错误时显示「当前没有错误」。 错误码是冻结的 16 个（清单见〈学习者上手指南〉）

10. 提交与正式裁决呈现

10.1 流程

阶段触发界面表现
提交点菜单「提交」服务端受理你的规范化动作日志（不是上传任何自制状态）
pending受理成功裁决横幅出现「正式裁决 · 已提交 · 裁决进行中」+「正式裁决由服务端对提交内容独立重放产生;此时不代表通过或失败。」。 界面每 2.5 秒自动重询，不需要你刷新；未决期不显示任何进度 / 排队位置
verdicted裁决落库横幅显示结果：得分方向给「本次提交通过(结果)」/「本次提交未通过(结果)」， 非得分方向给「本次提交未产生成绩(结果)」+「该裁决已产生且不会自动重试;可重新提交生成新裁决(原提交与原裁决不变)。」+ 「重新提交」按钮。 结果来自冻结的 11 值：success / wrong_answer / invalid_action / program_crash / memory_fault / resource_limit / timeout / engine_error / challenge_invalid / replay_mismatch / cancelled。不可逆
unavailable查询异常「裁决暂不可用」+「裁决查询暂时失败;会话不受影响,也不会因此判负。」（断线恢复后自动续询）

10.2 裁决之后

  • 终态会话：状态转换动作与撤销 / 恢复 / 重启全部拒绝；时间线、sync、提交记录仍可看；
  • 开新一局：这是页面分发形态下最容易误解的一点 —— 当前页面手里的启动地址已经用掉了。 终态引导行会给出一个「新建会话」按钮（工作区发出一条 new-session-request 请求事件）， 但在这个独立页面形态里没有谁来消费它（页面的授权来自一次性的启动凭证）。 正规做法 = 回平台重新取一次启动地址（新票据、新凭证、revision 归零、时间线清空）。
  • 结果不理想 → 教学面板看错误解释 + 提示阶梯 → 时间线复盘 → 取新地址再来。

10.3 和界面上的 won/failed 什么关系

会话状态条上的 won/failed 是交互判定（即时反馈）； 正式裁决由独立服务重放你的日志并跑隐藏测试，两者相互独立。 界面 won 而裁决 wrong_answer 是可能的（隐藏测试没过）；伪造前端 won 拿不到任何东西——成绩只在服务端。

11. 断线与重连

情形界面表现你要做什么
网络抖动状态条的「连接」变为 reconnecting，并显示「第 n 次重试 · 约 x ms 后重试」； 断线横幅显示「连接中断,正在重连」+「正在呈现最近一次公开投影(revision N)——重连后自动 sync 对齐;…」。 自动重连按指数退避（起 500ms，上限 8s），成功后自动对齐最新状态不用动，等它恢复
空闲被服务端断开同上（可重连的关闭原因会自动重连）不用动
被新连接踢下线横幅换成警示态：「连接已被同一会话的新连接取代」+ 一个「手动重连」按钮 （单一连接策略：这种情况不会自动重连，防互踢循环） 确认没有别处打开同一会话 → 点「手动重连」
未认证策略关闭同上：不自动重连（同样是为了避免互踢循环） 点「手动重连」；若反复失败，回平台重新取启动地址
长时间断线disconnected；视图冻结在最后已知状态（横幅诚实标注），不会本地假装运行； 横幅内的「手动重连」按钮随时可点查网络后手动重连；期间动作不可用是设计使然
断线横幅下的那句「本工作区不做任何本地 VM 执行降级」是硬门槛：任何情况下都不会退化成「本地跑一遍给你看」。

12. 主题、语言与键盘操作

12.1 终端单主题（本版唯一的主题）

主题只有一个值：terminal（终端风格）。取值集合就是 ["terminal"]。 light / dark 两套预设与 auto（跟随系统深浅色）已整体退役： 没有主题切换入口、没有 auto 别名、没有系统深浅色跟随分支。页面打开即是终端外观。

形态主题值怎么来
默认（页面分发形态）文档根（:root）上直接是终端取值 —— 不设任何锚也是终端
显式锚工作区元素支持写 theme="terminal" 属性（会转写成元素自身的 data-sm-theme 锚）； 集成方也可直接在元素上写 data-sm-theme="terminal"。锚与缺省同值，所以显式写与不写看起来完全一样。 历史上若残留 light / dark / auto 这类旧锚值，也会落到终端取值上（不会回落成浅色）

12.2 终端主题实际是什么样

它不是滤镜，而是一整套 CSS 变量的替换值：21 枚 token（8 个功能对比度 token + 12 个设计 token + 1 个深底画布精灵处理 token）， 键名与旧版一致。关键取值（源码登记值）：

token取值体现为

--sm-fg / --sm-fg-dim#b9ffc4 / #6dd47f磷光绿主前景 / 暗绿次要文字

12.3 语言与键盘操作

  • 语言：内置 zh-CN（默认）与 en；协议 / 状态机词（write_bytes、running、 连接态、视图类型键等）保持原文不翻译，属于「数据」而非界面文案。
  • 跳转视图位（本版新增，取代原分隔条方向键）：Ctrl + ↑ / ↓。 它在左半侧容器上捕获并阻止浏览器默认的页面滚动，作用域刻意限制在左半侧 （这样就不会与积木画布、输入框里方向键的用法冲突）；切换一档可见视图位，边界处不环绕（到首 / 末即停，确定性可预期）； 当前视图名会经常驻状态行用文字宣读（「当前视图位:『某某』(Ctrl + 上 / 下键切换,边界不环绕)」），不只是视觉反馈。 Payload 搭建窗口固定在右半侧，不在切换序列内（否则会停在「左半侧没有对应视图位」的视图上）。
  • 视图列表的键盘路径：列表可展开 / 收起（<details> 原生，aria-expanded）； 条目可聚焦，Space 切换勾选（原生勾选框），Alt + ↑ / ↓ 在列表内上下移动条目； 焦点顺序 = 视觉顺序（渲染顺序即 DOM 顺序）。每次变更都经 aria-live="polite" 播报 「已显示 / 已隐藏 / 已移动到第 N 位」。
  • 其余可达性：全部功能 Tab 序可达，按钮 Enter / Space 原生激活，焦点环可见； 寄存器行 Enter 复制；指令行断点开关是真实按钮。信息全部有文本承载（不依赖颜色 / 图形）—— 焦点视图位虽然只用颜色区分类型名，但同一事实在菜单按钮的 aria-pressed 与状态行文字上都有等价副本。
  • 动画：仅左半侧滚动带丝滑动画，在 prefers-reduced-motion: reduce 下退化为即时定位； 扫描线与光标闪烁在 reduce 下整体关闭。

13. 完整交互链：调试 → 解题 → 提交 → 反馈

以一道标准栈题（32 字节 buffer + saved RBP + 返回地址槽，存在 win 块）为例。地址以结构视图实际显示为准。 每步都标注「你会看到什么」，照着走一遍就熟悉全部界面。

阶段 A · 进入与侦察（沙盘，随便折腾）

A1 打开启动地址。在平台上点「进入题目」，浏览器顶层导航到服务端签发的地址。 你会看到：地址栏里的 ?t=… 一闪即被 302 抹掉； 状态条显示 会话状态 running · revision 0 · 连接 connected；左右两分的工作区已就位（不需要任何开窗操作）。
A2 把要看的视图摆到眼前。默认顺序里「栈视图」「寄存器视图」已经在前两位。 若你要看别的，展开左半侧「视图列表(勾选显示 / 拖拽排序)」勾选它，或直接用菜单「视图」组点栈视图、 寄存器视图、结构视图（每点一次 = 聚焦该视图并滚进视野，不会新开）。 你会看到：栈视图自动锚定 RSP 行（高亮）；寄存器视图列出全部公开寄存器；结构视图给出 buffer 起点 / 返回地址槽 / saved RBP 槽的实际地址。 记下三件事：buffer 地址、返回地址槽地址、两者的偏移（本例 24 字节）。
A3 切调试模式。菜单「运行」组 →「切换到调试模式」。你会看到：菜单之下出现常驻 what-if 横幅； 字节视图滚动重置；指令视图从引导空态变为真实指令流。
A4 看程序找目标。菜单「视图」→ 指令视图。用函数表或「文本检索」定位 win 块（如检索 win）； 记下它的地址。点击 win 函数内的指令行的断点开关设置断点（按钮呈按下态）。
A5 跑到断点验证理解。菜单「运行到断点」。你会看到：指令视图该行高亮，暂停原因「命中断点,已暂停」； 状态条可能变为 paused。现在你在沙盘里确认了「控制流到达 win」长什么样、寄存器此时的值是什么。
A6 侦察完毕。（可选）用「字节检索(全内存)」确认特征字节。结论带走：要劫持到 win，需要把返回地址槽覆盖为 win 地址。

阶段 B · 解题构造（真实会话，一击必中）

B1 切回解题模式。菜单「返回解题模式」。what-if 横幅消失，数据源换绑（字节视图滚动重置属预期）。 注意：刚才调试里的操作不影响真实会话。
B2 聚焦 Payload 搭建。菜单「视图」→ Payload 搭建（或直接看右半侧——它一直固定在那里）。 这样「积木步进」按钮才会亮。画布上有唯一不可删的「🚩 Payload 开始」积木。
B3 搭 payload。从「会话动作」分类拖出「写字节到〔地址〕内容〔hex〕」积木，接到开始积木下方； 地址填 buffer 地址；内容按结构视图的几何填：16 字节填充（如 41×16）+ 8 字节占位（42×8，恰好漫过 saved RBP） + 8 字节 win 地址的小端十六进制（正是 A4 记下的地址）。十六进制一律偶数长度、小端排列。
B4 编译并运行。点「编译」——程序区列出 1 个原子步骤；点「运行」——输出区出现该动作的成功记录。 你会看到：状态条 revision 前进到 1；切到栈视图（或内存 diff）能直观看到返回地址槽被你的字节覆盖、diff 标出差异。
B5 引爆。菜单「指令步进」（执行 leave，RSP 被劫持到你的假 RBP）→ 再「指令步进」（ret 弹出你写的 win 地址）。 你会看到：会话状态翻成 won，revision 继续前进。若没中：回输出区看错误解释（invalid_rip → 检查端序 / 地址）， 或时间线复盘每一步。

阶段 C · 提交

C1 提交。菜单「提交」。你会看到：裁决横幅出现「已提交 · 裁决进行中」。 此时不要关页面；界面每 2.5 秒自动查询。
C2 等待落库。几秒到几十秒后横幅翻转为结果态，显示正式结果。本例预期 success ——交互 won ∧ 隐藏测试全过。

阶段 D · 反馈与迭代

D1 读反馈。success → 这一关通过，时间线留有完整作战记录。wrong_answer → 去教学面板： 错误解释器看方向性提示、提示阶梯揭示下一级（失败次数足够时自动揭示）。program_crash / memory_fault → 内存 diff + 时间线定位是哪一步把程序带崩的。
D2 开新局。终态会话不可继续操作（重启按钮已禁用并给出引导）。开新一局 = 回平台重新取一次启动地址（页面上那个「新建会话」按钮在页面分发形态下没有消费者，见 §10.2）。 新一局是新票据、新凭证、revision 归零、时间线清空。把 B3 的内容换一个变体再来——比如这次故意写错端序， 观察 memory_fault 是什么样子。
这条链的三条安全底线（界面处处体现）：浏览器里的一切只是投影；调试是沙盘、提交才是成绩； 窗口外的字节真的不在你机器上。
