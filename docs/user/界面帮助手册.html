1.2 创建会话表单（开发壳 / 首次进入）

四个输入框 + 两个按钮。在 CTF 平台上这些通常由平台自动完成；开发联调时手工填写：

元素作用
challengeId / challengeVersion要玩的题目标识与版本（由平台下发或联调时指定）
embedSessionId / embedToken一次性会话标识与短期凭证（自动下发；token 单次消费，过期/已用需重新获取）
「创建并连接」按钮创建服务端会话 → 连接认证通道 → 工作区挂载。成功后横幅显示「会话已创建并连接(sessionId=…)」，菜单运行按钮解锁
「新建会话」按钮结束当前会话并走全新创建流程（会话到达 won/failed 终态、或重启被禁用时的正规出路）

1.3 工作区布局模型（固定窗口 · 列式平铺）

工作区的窗口是一个固定窗口集：注册表登记的全部类型、各恰一个实例、常驻。 窗口没有「开 / 关」这回事——标题栏上没有「×」，菜单里也没有「打开 / 关闭」入口； 窗口只可能是「视口内」或「暂离（条带滚出视野）」，滚回去就能看到。 换句话说：不提供关闭、也不提供新开，每个类型的窗口一直都在。

操作行为
窗口常驻固定窗口集的 10 类窗口各一个，从工作区出现的那一刻起就都在（与是否已连接会话无关）；窗口标题 = 该类型的展示名（如「栈视图」），标题里没有类型内序号——不存在「栈视图 1 / 栈视图 2」这种说法
列内分割同一列的窗口纵向二叉均分列高（上下分割）；同列内容超高时列内滚动
列间浏览窗口组织为垂直列，列组成一条水平条带，列与列之间水平滚动可达任意列；从菜单「窗口」组聚焦某个窗口时，条带会自动滚到让该窗口可见的位置
拖拽排布按住窗口标题栏拖动（位移超过 3px 进入拖拽，拖拽反馈只用透明度）：放到目标窗口上半 = 排它前面、下半 = 排在它后面；放到目标列空白 = 追加到该列；放到列区空白 = 开一个新列
焦点窗口点击过的窗口是「焦点窗口」（焦点列 = 焦点窗口所在列）；某些菜单动作只对焦点窗口生效（如「积木步进」要求 Payload 搭建窗口是焦点窗口）
菜单「窗口」组每个按钮 = 一个窗口的聚焦导航：点击即聚焦该窗口并滚动到它，不会新开实例（窗口本来就在）；当前焦点窗口用 aria-pressed 标记；这组按钮恒可用、没有禁用态（聚焦不依赖会话）
常驻的窗口类型（10 类）：栈视图 / 自由视图 / 寄存器视图 / Payload 搭建 / 指令视图（调试档）/ 结构视图 / 调用栈 / 内存 diff / 时间线 / checkpoint（检查点）。 窗口集恒非空，不存在「工作区为空」这种空态引导：未连接会话时窗口照样全在，只是视图里还没有数据可显示。 解题 ↔ 调试模式切换只换绑数据源，布局不动（列序、焦点列、窗口标题全部保持，Payload 搭建窗口里的状态两模式共用、不丢失）。

2. 顶部菜单与会话状态条

2.1 菜单按钮逐个说明

按钮可用条件动作与你会看到什么
「窗口」分组恒可用（无禁用态）一排窗口聚焦按钮（§1.3 的 10 类窗口，一类一个）；点击即聚焦该窗口并滚动到它，不会新开实例（窗口本就常驻）。当前焦点窗口用 aria-pressed 标记；鼠标停在按钮上会提示「聚焦『某某』并滚动到该窗口」
「指令步进」已连接且会话未终态让虚拟机恰好执行一条指令后暂停。每次点击 revision +1；控制流里当前指令会随之前进（在字节/指令视图中观察）
「积木步进」Payload 搭建窗口是焦点窗口且已编译推进积木程序的一个原子动作并暂停；等于在 Payload 搭建窗口点工具栏「单步」
「运行到断点」仅调试模式；断点集合非空；通道可用且未终态运行到最近断点后暂停；命中后指令视图高亮暂停行并显示暂停原因「命中断点已暂停」
「切换到调试模式 / 返回解题模式」题目启用调试时才显示（出题人可关闭）切换数据档：工作区所有视图换绑数据源（§8），布局不动（列序、焦点、窗口标题保持）。切换后字节视图滚动/锚点重置属预期；Payload 搭建窗口状态两模式共用不丢失
「提交」已连接把你的服务端操作日志送交独立裁决服务（§10）。终态后仍可提交（sync/时间线/提交/关闭不受终态限制）
「重启测试环境」未终态时可用；won/failed 后禁用清空一切回到题目初始状态（revision 仍 +1）。终态后点击会看到引导「测试环境已结束，请新建会话」
模式分组里有当前模式指示（「解题模式」/「调试模式」）；运行分组按钮在未连接或终态时呈灰色禁用态， 把鼠标停上去可看出不可用的原因（未连接 / 已终态）。「窗口」分组不在此列——窗口聚焦导航恒可用，从不置灰。

2.2 会话状态条（菜单右侧）

字段取值说明
会话状态running / paused / won / failed交互判定状态（区别于正式裁决，见 §10.3）。running = 程序运行中；paused = 因事件/单步暂停；won/failed = 交互终态
revision0, 1, 2, …服务端权威版本号 = 已被执行的动作数。你的每个操作（包括失败的教学反馈和重启）都 +1；被拒绝的操作不推进
连接connecting / connected / reconnecting / disconnected通道状态；reconnecting 时会显示第几次重试与下次重试间隔（§11）

3. 横幅系统（四种全局提示）

横幅何时出现内容与你要做的事
会话提示横幅创建会话成功 / 关键动作后如「会话已创建并连接(sessionId=…);顶部菜单可步进/重启」——纯提示，无需操作
断线横幅通道断开显示「最近一次公开投影(revision N)+ 重连中(第 n 次,间隔 x ms)」。界面冻结在最后已知状态，绝不本地假装继续运行；通常自动恢复，个别情况给「手动重连」按钮（§11）
what-if 纪律横幅调试模式下常驻「调试通过 ≠ 提交通过（裁决以提交为准）」+（题目启用 ASLR 时）「调试实例地址与真实实例可能不同，硬编码绝对地址跨实例失效属预期教学语义」。切回解题模式即消失
裁决横幅点「提交」后三态流转：pending（已受理，自动重询）→ verdicted（结果 + 11 值类型）→（异常时）unavailable（§10）
拒绝错误提示动作被服务端拒绝错误码 + 人话说明 + 解释（如「地址不可见」），「知道了」消隐；同时写入教学面板的错误解释器（§9.2）

4. 字节视图（栈视图 / 自由视图）

主战场。栈视图与自由视图是同一个组件的两种默认姿态——栈视图会自动滚到 RSP 所在区域，自由视图从第一个区域看起；除此之外能力完全相同，所以放在一起讲。

4.1 组成结构

┌─ 窗口「栈视图」──────────────────────────────────────────────┐
│ ┌─VMA 区域列表──┐ ┌─字节表────────────────────────────────┐ │
│ │ ● stack  0x…  │ │ 0x7FFFF7F0  41 41 41 41 …  A A A A    │ │
│ │ ○ code   0x…  │ │ 0x7FFFF7F8  41 41 …        → stack    │ │
│ │ ○ global 0x…  │ │ 0x7FFFF800  42 42 …  [RSP 锚点行高亮]  │ │
│ │ （按地址有序， │ │ …每行 8 字节：地址段│十六进制段│特殊显示段│ │
│ │  点击切换区域）│ │                                        │ │
│ └───────────────┘ └────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
组成说明
VMA 区域列表（侧栏）题目全部可见内存区域，按地址排序：名称、起始地址、长度。点击某区域 → 右侧字节表跳到该区域开头；在字节表里跳转到别的区域时，侧栏选中项会自动跟随（双向回路）
字节表每行 8 字节，三段式：地址段（0x 大写十六进制）、十六进制段（字节 + 下方对应 ASCII 可见字符）、特殊显示段（语义标注/跳转链芯片，见下）
虚拟滚动区域很长也只渲染可视行（窗口上限 512 行），滚动流畅

4.2 可见窗口：?? 是什么

服务端对每块区域只下发锚定起点的开头一段（缺省 256 字节；区域更短则全量）。因此：

你看到的含义
正常字节已下发窗口内的真实数据
?? 格子窗口外——服务端没有下发这里。不是 bug，不是"藏起来了"，是结构性不存在于你的浏览器
区域截断标记区域列表/投影里 truncated 标记为真 = 该区域只下发了前缀（诚实声明）
对窗口外的跳转/检索都不会报错，只会得到「在可见窗口之外」的提示。不存在"找到藏起来的字节"这种事： 隐藏区域与未映射地址在你这边完全不可区分（防探测是协议层保证）。

4.3 锚点与导航

功能操作行为
RSP/RBP 锚点进入视图 / 切换区域时自动视口自动滚到 RSP 所在行并高亮。滚远了点「回锚」按钮回去。若 RSP 的值不在已下发窗口内，会明示「<寄存器> 内容不在可见窗口」（不渲染空白、不报错）；寄存器未公开则不显示锚点
跳转输入输入地址后回车0x 开头十六进制 = 绝对地址；纯数字 = 窗口内偏移。窗口外的输入 → 「在可见窗口之外」反馈，不滚动不报错
检索输入十六进制字节串只在已下发窗口字节内搜索；命中列表点击即滚动过去；命中在其他区域会先自动切区域
寄存器交叉标注自动 + 点击某寄存器的值恰好指向本行已下发窗口内的地址时，该行左缘出现标注徽标；点击在行内展开"哪些寄存器指向这里"
跳转链芯片自动出现 + 点击某行 8 字节按小端解释"像一个指向可见内存的指针"时，行尾出现地址芯片链。点击芯片 → 跳到目标行（窗口外则提示「在可见窗口之外」）。链默认横向最多 3 段，「展开完整链」可看竖向全链（上限 32 段），循环引用画回环箭头；链末尾若是可见 ASCII 字符串会直接把字符展示出来（≤32 字节）
读内存三板斧：跟着 RSP 锚点看栈 → 看到可疑指针点跳转链芯片顺藤摸瓜 → 用检索确认特征字节。指针追踪在窗口外会截断，这是诚实显示不是故障。

5. 寄存器视图

元素说明
寄存器行纵向列出题目公开的全部寄存器（不藏行）；每行三段：寄存器名 / 当前值（0x 大写十六进制）/ 特殊显示列（该值落在某个可见区域时显示「→ 区域名」）
点击复制点击值复制到剪贴板，反馈「已复制」；非安全上下文（http 等）自动降级为选中 + 提示「已就绪手动复制」，片刻自动消隐
键盘操作Tab 聚焦行，Enter 复制——全程可不碰鼠标
与字节视图联动RSP/RBP 锚点、交叉标注都消费这里的数据；本视图里"→ stack"的寄存器就是字节视图交叉标注的来源

FLAG 开头的秘密寄存器（若题目定义）永远不出现在这里——值在服务端，名字也不会给你。

6. 教学组件五件套

6.1 结构视图

出题人声明的"语义地图"。按固定分组排序展示：buffer 起点 → 返回地址槽 → saved RBP 槽 → canary 槽 → 自定义； 每条高亮显示名称、所属区域、地址与长度（如「buffer 起点 · input-buffer · stack @ 0x7FFFF7F0 · 16B」）。 点击任一条会发出跳转请求——配了字节视图时直接滚到对应位置。这是你把"抽象的栈帧布局"对上"具体字节地址"的主要工具。

6.2 调用栈

元素说明
帧条目序号 + 函数标签 + 返回地址。index 0 标注「最内帧（当前函数）」，往下是调用者
截断明示深度超过 64 帧时只显示最内 64 帧，最后一帧标注「仅显示最内 64 帧」——故意不显示"+N"，因为帧数本身也是信息
空栈程序未调用任何函数时显示空态

6.3 内存 diff

对照"上一个动作前后"的字节变化：左/前列 = 动作前的值，右/后列 = 动作后的值，逐字节标红高亮差异。

  • 只对照最近一次动作的增量（不是累积历史）——累积历史看时间线；
  • 前值不在已下发窗口内时，该行明示「前值不可知」，不伪造；
  • 变更区域被截断时提示「变更承载被截断，已按协议以 sync 重新对齐」。

6.4 时间线

你整个会话的操作历史，按 revision 排列：每个动作一行（动作摘要 + 关键参数）、checkpoint 事件、submit 事件； 当前 revision 有指针标记。撤销/恢复/重启也各占一行——历史从不被抹掉，回退也是一步。做题卡壳时回看时间线， 经常能发现"哪一步之后 layout 变了"。

6.5 checkpoint（检查点面板）

功能操作与规则
创建输入可选标签（≤128 字符，禁止控制字符）→ 创建。服务端保存完整快照；revision 照常 +1，时间线多一条
恢复列表按创建顺序列出所有检查点（标签 + 内容 revision）；点击恢复需两步确认（防误触）。恢复 = 内容回到快照、revision 继续 +1（回退也是一步）
终态会话 won/failed 后恢复被拒绝（终态规则），面板会显示服务端返回的可解释错误

7.2 工具栏五按钮

按钮行为
「编译」把积木图编译成原子动作序列（循环/分支/函数在客户端展开求值）。程序区逐行列出每个原子步骤；编译错误（如引用了题目不允许的动作）在对应积木上标红气泡提示，不产出步骤
「运行」逐个提交原子动作，输出区实时记录每条的结果；遇到断点积木自动暂停（状态 paused）
「单步」推进一个原子动作并暂停（与菜单「积木步进」等价，要求 Payload 搭建窗口是焦点窗口）
「暂停」暂停步进推进（当前动作完成后停下，状态 paused）
「复位步进」游标回到第 0 步（不回滚服务端状态——已经执行的写操作要靠检查点/重启回退）
编辑即复位：改动画布后程序立即过期，运行/单步前会自动重新编译并把游标拨回第 0 步。 状态机五态：idle → running → paused/done/error。展开上限 256 个原子动作、函数内联深度 32、 表达式求值步数 4096——超限在编译期明确报错。

7.4 输出区你会看到的四种条目

情形输出区表现游标
动作成功动作摘要 + 状态（running/paused/won）+ revision推进到下一步

8. 调试模式与指令视图

8.1 调试模式是什么

一个并行的沙盘实例：题目默认启用调试（出题人可关）。切换方式 = 菜单模式分组的切换按钮； 切过去之后：所有字节视图换绑到调试数据源（滚动/锚点重置），指令视图从「切换到调试模式」引导态变为真实指令流， 菜单出现「运行到断点」，工作区顶部出现常驻 what-if 纪律横幅。

两条铁律（横幅会一直提醒）：①调试通过 ≠ 提交通过，裁决只看提交日志的重放； ②调试实例地址可能与真实实例不同——在调试里看到的地址，硬编码进 payload 到真实实例可能失效（ASLR 题尤其如此，这本身是 pwn 第一课）。

8.2 指令视图（调试档专属窗口）

组成说明
指令流（三段）每行 = 地址 / 伪机器码字节（没有字节信息显示"—"）/ 指令文本；跳转类指令尾随目标地址延展，点击直接跳到目标行
RIP 锚点最新暂停地址行高亮 + 「回锚」；暂停位置按三级回退确定：最近单步暂停 → 附着时暂停点 → RIP 公开值
函数表附着时推送的函数列表（按起始地址排序），点击跳转
行断点点击指令行切换断点（断点集合是界面状态，可多个）；配合菜单「运行到断点」使用
暂停原因暂停时显示四值之一：单步暂停 / 命中断点已暂停 / 程序已自行停机 / 预算耗尽确定性暂停
检索双入口字节检索（全内存，异步）与指令文本检索（缓存内，大小写不敏感）分开呈现
地址跳转覆盖面内直接滚动；超出已缓存覆盖面 → 自动预取后重试一次；仍不可达提示「覆盖面之外」

解题模式下指令视图只会看到引导空态「请通过菜单『切换到调试模式』启用后使用」，不会伪造指令流 （窗口一直都在，只是当前数据档不是调试档）。 调试档的内存/指令来自"推送 + 按需拉取"的缓存：缓存外区域同样以窗口外语义呈现。

9. 教学面板与题目简介

9.1 题目简介（可折叠）

题目标题、情境摘要、架构参数（位宽 / 端序 / 页大小 / 寄存器清单 / canary 状态）。正式通道下还会给出学习目标。 做题前扫一眼，寄存器清单告诉你哪些名字会在寄存器视图里出现。

9.2 教学面板（可折叠，两块）

块机制
提示阶梯出题人配的 ≤8 级提示。两种揭示策略：按请求（你点才揭示）与 失败 N 次后自动（本地计数，教学性失败才算）。揭示顺序固定，无法跳级看后面的——讲方法不给答案
错误解释器每个错误码配出题人写的教学注解。收到错误时这里显示「错误码 + 解释 + 教学注解」；没有配注解的错误码会明示「该错误暂无教学注解」。16 个错误码清单见学习者上手指南

10. 提交与正式裁决呈现

10.1 流程

阶段触发界面表现
提交点菜单「提交」按钮即回；服务端受理你的规范化操作日志（不是上传任何自制状态）
pending受理成功裁决横幅出现「已提交/裁决中」；界面每 2.5 秒自动重询（有退避），不需要你刷新。未决期不显示任何进度/排队位置——耐心等
verdicted裁决落库横幅显示最终 11 值结果（success / wrong_answer / program_crash / memory_fault / …）。不可逆
unavailable查询异常横幅提示裁决暂不可查询（断线恢复后自动续询）

10.2 裁决之后

  • 终态会话：状态转换动作与撤销/恢复/重启全部拒绝；时间线、sync、提交记录仍可看；
  • 新开一局 = 「新建会话」流程（新 token、新会话）;
  • 结果不理想 → 教学面板看错误解释 + 提示阶梯 → 时间线复盘 → 新会话再来。

10.3 和界面上的 won/failed 什么关系

会话状态条上的 won/failed 是交互判定（即时反馈）；正式裁决由独立服务重放你的日志并跑隐藏测试， 两者相互独立。界面 won 而裁决 wrong_answer 是可能的（隐藏测试没过）；伪造前端 won 拿不到任何东西——成绩只在服务端。

11. 断线与重连

情形界面表现你要做什么
网络抖动状态条 reconnecting（第 n 次尝试 + 间隔）；断线横幅显示最后已知投影 revision。自动指数退避重连，成功后自动对齐最新状态不用动，等它恢复
空闲被服务端断开同上（语义化关闭码自动重连）不用动
被新连接踢下线「connection replaced」提示 + 手动重连按钮（单连接策略，防互踢循环）确认没有别处打开同一会话 → 点「手动重连」
长时间断线disconnected；视图冻结在最后已知状态（诚实标注），不会本地假装运行查网络后手动重连；期间操作不可用是设计使然

12. 主题、语言与键盘操作

  • 主题：light / dark / auto 三值（auto 跟随系统深浅色）。宿主平台切换时全界面即时生效；配色以可访问性对比度为准；
  • 语言：内置 zh-CN（默认）与 en，跟随宿主切换，未知语言标签确定性回落；协议/状态机词（write_bytes、running 等）保持原文不翻译；
  • 键盘可达：全部功能 Tab 序可达，按钮 Enter/Space 原生激活，焦点环可见；寄存器行 Enter 复制；信息全部有文本承载（不依赖颜色/图形）；动画零。

13. 完整交互链：调试 → 解题 → 提交 → 反馈

以一道标准栈题（32 字节 buffer + saved RBP + 返回地址槽，存在 win 块）为例。地址以结构视图实际显示为准。 每步都标注"你会看到什么"，照着走一遍就熟悉全部界面。

阶段 A · 调试侦察（沙盘，随便折腾）

A1 创建会话。进入题目 → 创建并连接。你会看到：横幅「会话已创建并连接(sessionId=…)」； 状态条 running · revision 0 · connected；工作区里 10 类窗口已全部常驻铺开（不需要任何开窗操作）。
A2 铺开视图。窗口本来就常驻，这一步只是把要用的窗口聚焦到视野里： 菜单「窗口」→ 依次点栈视图、寄存器视图、结构视图（每点一次 = 聚焦该窗口并滚动到它，不会新开）。 你会看到：栈视图自动锚定 RSP 行（高亮）；寄存器视图列出全部公开寄存器；结构视图给出 buffer 起点 / 返回地址槽 / saved RBP 槽的实际地址。 记下三件事：buffer 地址、返回地址槽地址、两者的偏移（本例 24 字节）。
A3 切调试模式。菜单模式分组 →「切换到调试模式」。你会看到：顶部出现常驻 what-if 横幅； 字节视图滚动重置；指令视图从「切换到调试模式」引导态变为真实指令流。
A4 看程序找目标。菜单「窗口」→ 指令视图。用函数表或文本检索定位 win 块（如检索 "win" 或浏览函数表）； 记下它的地址。点击 win 函数内的指令行设置断点（行上出现断点标记）。
A5 跑到断点验证理解。菜单「运行到断点」。你会看到：指令视图该行高亮，暂停原因「命中断点已暂停」； 状态条可能变为 paused。现在你在沙盘里确认了"控制流到达 win"长什么样、寄存器此时的值是什么。
A6 侦察完毕。（可选）用调试档全内存检索确认特征字节。结论带走：要劫持到 win，需要把返回地址槽覆盖为 win 地址。

阶段 B · 解题构造（真实会话，一击必中）

B1 切回解题模式。菜单「返回解题模式」。what-if 横幅消失，数据源换绑（字节视图滚动重置属预期）。 注意：刚才调试里的操作不影响真实会话。
B2 聚焦 Payload 搭建。菜单「窗口」→ Payload 搭建。画布上有唯一不可删的「🚩 Payload 开始」积木。
B3 搭 payload。从「会话动作」分类拖出「写字节到〔地址〕内容〔hex〕」积木，接到开始积木下方； 地址填 buffer 地址；内容按结构视图的几何填：16 字节填充（如 41×16）+ 8 字节占位（42×8，恰好漫过 saved RBP） + 8 字节 win 地址的小端十六进制（正是 A4 记下的地址）。十六进制一律偶数长度、小端排列。
B4 编译并运行。点「编译」——程序区列出 1 个原子步骤；点「运行」——输出区出现该动作的成功记录。 你会看到：状态条 revision 1；切到栈视图（或内存 diff）能直观看到返回地址槽被你的字节覆盖、diff 标红。
B5 引爆。菜单「指令步进」（执行 leave，RSP 被劫持到你的假 RBP）→ 再「指令步进」（ret 弹出你写的 win 地址）。 你会看到：状态条翻成 won，revision 到 3。若没中：回输出区看错误解释（invalid_rip → 检查端序/地址），或时间线复盘每一步。

阶段 C · 提交

C1 提交。菜单「提交」。你会看到：裁决横幅出现 pending 态（"已受理，独立裁决中"）。 此时不要关页面；界面每 2.5 秒自动查询。
C2 等待落库。几秒到几十秒后横幅翻转为 verdicted，显示正式结果。本例预期 success ——交互 won ∧ 隐藏测试全过。

阶段 D · 反馈与迭代

D1 读反馈。success → 这一关通过，时间线留有完整作战记录。wrong_answer → 去教学面板： 错误解释器看方向性提示、提示阶梯揭示下一级（失败次数足够时自动揭示）。program_crash / memory_fault → 内存 diff + 时间线定位是哪一步把程序带崩的。
D2 开新局。终态会话不可继续操作（重启按钮已禁用并有引导）。点「新建会话」走全新流程 （新凭证、revision 归零、时间线清空），把 B3 的内容换一个变体再来——比如这次试试故意写错端序，观察 memory_fault 是什么样子。
这条链的三条安全底线（界面处处体现）：浏览器里的一切只是投影；调试是沙盘、提交才是成绩； 窗口外的字节真的不在你机器上。
