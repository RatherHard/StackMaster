## 一、效力范围、分类标签与变更纪律

### 1.1 分类标签

本文用三个标签对每个跨域字段作唯一分类:

| 标签 | 含义 | 浏览器可见 | 机检含义 |
|---|---|---|---|
| `PUBLIC` | 可下发浏览器,可缓存于浏览器任意位置(IndexedDB、localStorage、Worker) | 是 | 出现在浏览器属预期;不存在于任何 `SERVER_ONLY` 标识符扫描命中集 |
| `SERVER_ONLY` | 禁止出现在任何跨域载荷:API 响应、WSS 帧、postMessage、回放下载、错误文本、公开回放 | 否 | 命中即违规(见第九章 ZR-B/R/P 条目) |
| `BOUNDARY` | 双向跨域传输,但属"玩家自己的输入或短期凭证",不是服务端秘密;服务端按 6.2 全部重新校验,不信任其内容 | 是(仅玩家自报内容) | 服务端不得读取其中未声明字段;Schema 解析必须剥离未知字段 |

判定次序:先问"该字段的值是否由服务端秘密派生"——是则 `SERVER_ONLY`;再问"该字段是否是玩家输入/短期凭证的回传"——是则 `BOUNDARY`;否则才可评 `PUBLIC`,且必须通过第四章论证。

### 1.2 与其他工作包的边界

| 工作包 | 从本文承接 | 不得做的事 |
|---|---|---|
| WP-2(动作协议) | 第六章信封字段分类;I-5 稠密序号规则 | 不得新增未分类的响应字段 |
| WP-3(投影与错误契约) | 第四、五章字段集合与子类型边界;第七章决策 D1–D6;第十章粗化矩阵 | Schema 冻结必须与本文字段集合一致并携带分类标签 |
| WP-4(双包 Schema) | 不变量 I-2 / I-3 的编译期检查义务;私有包 Schema 必须含 `declaredSeedPublicPaths`(seed 策略的显式公开路径声明,供 T-SC4 / ZR-P2 消费——此为对上游 WP-4 任务清单的增补项,按 1.3 记录) | 公开包 Schema 不得能表达任何 `SERVER_ONLY` 字段 |
| WP-5(嵌入协议) | 第六章 `BOUNDARY` 凭证规则 | 不得把宿主自报身份当作认证 |

### 1.3 变更纪律

- 本文标注"冻结"的字段集合与决策,变更须走契约变更流程:先改本文(补论证或改决策)→ 更新 `protocol` / `challenge-schema` 与 golden fixture → 评审通过 → 再改实现;
- 新增 `PUBLIC` 字段而未在本文第四章完成"秘密不进入浏览器"论证,视为违反硬门槛,CI 字段白名单校验(I-1)直接拒绝;
- 为未来能力预留字段(计划书风险表)被明确禁止:扩展靠协议版本号演进,不靠预留字段。

## 二、信任域与数据驻留总表

计划书 9.2 数据分类表扩充信任域与具体存储位置(域编号见计划书 5.2):

| 数据类别 | 浏览器可见 | 分类 | 存储位置 |
|---|---|---|---|
| 公开描述包 | 是 | `PUBLIC` | CDN(域 1,带哈希/签名);对象存储 `public-bundles` 回源 |
| 私有判题包(隐藏 flag、隐藏测试、完整 IR、seed) | 否 | `SERVER_ONLY` | 对象存储 `private-bundles`(静态加密、最小权限);域 3 进程内存 |
| 用户动作记录(受限动作请求) | 提交内容可见 | `BOUNDARY` | 浏览器(构造);PostgreSQL `action_log`(append-only,域 3);域 4 verifier 读取重放 |
| 私有 VmState、服务端快照、完整事件日志、私有目标条件 | 否 | `SERVER_ONLY` | 域 3 Worker 进程内存(权威);COW 快照 → PostgreSQL `checkpoints`;诊断 trace → 对象存储 `traces` |
| 公开投影 / ProjectionDelta | 是 | `PUBLIC` | 域 3 生成 → 域 2 通道 → 浏览器缓存(IndexedDB);服务端仅缓存最近 N 个投影(5.7) |
| 短期会话凭证(embed token、会话 token) | 是(短期持有) | `BOUNDARY` | 浏览器(仅会话期);Redis `token:{jti}`(域 2,带 TTL);PostgreSQL `sessions`(域 3) |
| 幂等键、限流计数、会话路由 | 否 | `SERVER_ONLY` | Redis `idem:{sessionId}:{key}`、`rate:*`、`route:*`(域 2,全部带 TTL) |
| 审计日志(含内部堆栈、文件路径、隐藏测试信息) | 否 | `SERVER_ONLY` | PostgreSQL `audit_log`(append-only,域 3/4);归档对象存储 |

驻留三原则(结构保证,非流程约定,计划书 5.2):

1. **秘密不出执行域**:`VmState`、私有题目包、隐藏测试、seed 只存在于域 3 Worker 进程内;
2. **跨域只传投影**:投影白名单过滤与脱敏在域 3 内完成后才离开;域 2 与网络通道上只有公开投影;
3. **构建期隔离可机器验证**:引擎 crate 与 `challenge-compiler` 不进浏览器构建图(CI 产物扫描,5.8 门禁 6)。

## 三、`VmState` 字段集合冻结(纯后端类型)

### 3.1 两条归属规则(本阶段冻结)

**规则 1:`VmState` 是纯后端类型,不进入 JSON Schema 契约。**
它不出现在 `@stackmaster/protocol` 包中,这正是其安全属性:不存在任何被认可的序列化路径,意味着任何跨域载荷中出现该类型或其字段名,按定义即违规,无需逐次判断"是否泄密"。契约侧不存在"私有两个版本的字段子集"这种灰地带——`SERVER_ONLY` 类型没有契约,只有禁令。

**规则 2:实现语言由 ADR-8 产能决策决定(WP-6)。**
本阶段只冻结字段集合——字段名、语义、不变量与相互关系(下表);vm-core 用 Rust 还是回退 TypeScript 不影响本表。回退时 `VmState` 仍不得进入 TS 构建图中任何浏览器可达的包(CI 导入图检查)。

### 3.2 字段集合(冻结,8 字段)

来源:计划书 6.2。内部形态为语义冻结,供阶段二实现;具体数据结构属引擎内部,可自行演化,前提是保持本表的分类与不变量。

| 字段 | 语义(冻结) | 为何 `SERVER_ONLY`(禁止下发论证) | 存储位置 |
|---|---|---|---|
| `registers` | 寄存器全集到 64 位值的映射 + FLAG 位 | 完整寄存器集含未白名单寄存器;其值可被私有逻辑写入秘密派生内容(解密中间值、隐藏地址)。公开子集经 `visibleRegisters` 白名单后另行下发(第四章) | 域 3 进程内存;COW 快照 |
| `memory` | 分页虚拟内存(固定页大小,COW):代码区、全局区、堆区、栈区、题目关键区(6.1) | 含隐藏区域与隐藏对象的全部字节;下发任何区域都等于下发原始快照的一个切片。可见区域字节经白名单 + `maxBytesPerRange` 截断后另行下发 | 同上 |
| `callFrames` | 调用帧内部栈:函数标识、返回地址、saved `RBP`、内部参数 | 深度与内容未被裁剪前不公开(见决策 D2 的裁剪规则);内部参数可含私有布局信息 | 同上 |
| `instructionPointer` | 当前执行位置(64 位) | 直接下发可暴露私有代码区域的存在与位置(MVP 中代码区恒公开,但类型本身不因 MVP 布局而降级)。公开形态是 `controlFlow.currentInstruction`(第四章) | 同上 |
| `privateEventLog` | 私有事件 append-only 日志:内部事件、隐藏判定事件、公开事件的全集来源 | 含隐藏测试触发记录与私有目标条件求值痕迹;序号空洞、条目数都是侧信道(决策 D4)。公开子集经白名单过滤后另行下发 | 同上;审计归档对象存储 |
| `constraints` | 运行时约束的权威执行状态:步数、内存、wall-clock、调用深度、动作日志长度、输出上限、超时,以及**私有谓词求值次数预算**(按会话累计,跨 undo/reset 不重置)与**回退/重置次数预算**(两维度为本阶段冻结新增,依据见 D1 约束 5) | 是服务端资源预算的完整集合;完整下发可帮助选手把动作精确顶到限额做探测。公开部分由公开描述包单独显式声明(7.1),不是对本字段的投影 | 同上 |
| `seedState` | 随机源状态:`strategyId`、版本、内部状态字节 | 种子值与状态字节即随机化秘密本身;泄露可复现全部随机行为。`strategyId` 与版本号同属私有包 seed 策略字段(7.1),**不进公开描述包**——策略元数据泄露搜索空间(如"栈基址在 N 个候选中随机"直接给出熵上界),与回退神谕(D1 约束 5)复合会降低穷举成本。公开面只允许文案声明"存在随机化"这一事实,不声明策略、候选空间或熵上界;seed 策略与运行环境版本写入服务端回放信息(6.3,域 3/4 审计记录) | 同上 |
| `status` | 权威 VM 状态:`running` / `paused` / `won` / `failed`;won/failed 为会话终态(D1 约束 5) | 这是私有目标条件的求值**结果来源**;公开的是其在动作响应边界上的投影 `PublicStatus`(决策 D1),不是本字段的实时读取通道 | 同上 |

寄存器名称集合(冻结,计划书 6.1):`RSP`、`RBP`、`RIP`、`RAX`、`RBX`、`RCX`、`RDI`、`RSI`、`RDX`、`R8`、`R9`、`R10`、`R11`、`R12`,加题目 VM Profile 声明的 FLAG 子集。扩展寄存器走 VM Profile Version,不靠本集合预留。

### 3.3 `VmState` 机检标识符清单

浏览器产物与跨域载荷扫描(第九章 ZR-B9 / ZR-R2)使用以下标识符(词边界匹配):

```text
类型名:  VmState  RuntimeConstraints  SeedState  VirtualMemory  VmEvent
字段名:  privateEventLog  seedState  instructionPointer
crate:   vm-core  vm-runtime  vm-worker  vm-engine  challenge-compiler
```

说明:不使用 `status`、`registers`、`memory`、`callFrames`、`constraints` 等通用词做独立命中词(误报率高);它们仅作为 `VmState` 引用关系的导入图检查对象。`CallFrame` 单独出现不违规(`PublicCallFrame` 是公开类型),命中词用 `VmState` 与字段名;`VmEvent` 词边界匹配不会命中公开的 `PublicEvent`,故可作独立命中词。浏览器 UI 代码亦不得以 `instructionPointer` 等被禁标识符命名导出符号(公开投影中的对应概念叫 `controlFlow.currentInstruction`)。

**共现形态规则**:真实 VmState 误下发序列化出来的恰恰是通用键名(`registers`、`memory`、`status` 等),而 `privateEventLog`/`seedState` 反而常为空或缺席——仅靠词边界扫描会漏检该形态。补充规则:单个 JSON 对象内同时出现 ≥ 3 个 VmState 字段名键(registers、memory、callFrames、instructionPointer、privateEventLog、constraints、seedState、status)即判定为 VmState 序列化违规;`privateEventLog` / `seedState` / `instructionPointer` 单独命中即违规。

## 五、`ProjectionPolicy` 分类(SERVER_ONLY 配置类型)

`ProjectionPolicy` 决定公开投影的内容边界(计划书 6.2)。**整体分类:`SERVER_ONLY`。** 它驻留域 3,由公开描述包的可见布局与私有判题包的隐藏对象排除集组装而成;浏览器只接收它产生的效果(脱敏后的投影),永不接收策略本身。

| 字段 | 为何 `SERVER_ONLY`(整型配置不下发的论证) |
|---|---|
| `visibleRegions: string[]` | 单看是公开布局的镜像,但策略对象整体承载"排除集"语义:下发完整名单等于宣告"其余区域皆为隐藏",给出隐藏区域的存在性与命名空间。公开布局的唯一 sanctioned 来源是公开描述包(7.1) |
| `visibleObjects: string[]` | 同上;对象名单的补集即隐藏对象清单 |
| `visibleRegisters: string[]` | 白名单补集含"秘密汇寄存器"(I-3),下发名单可帮助玩家定位哪些寄存器被题目设计为敏感 |
| `maxBytesPerRange: number` | 本身非秘密,但随策略整体驻留域 3;其数值约束冻结见决策 D3 |
| `errorDetailLevel: "coarse" \| "educational"` | 属判题配置;泄露判定口径无直接危害,但按"整型不下发"原则处理,其效果体现在错误脱敏(第十章) |

Schema 归属:WP-3 将 `ProjectionPolicy` Schema 冻结进 `@stackmaster/protocol` 的 **server-only 子路径导出**,并打 `x-sm-class: server-only` 标签——**Schema 存在不等于可下发**;它供后端各包(challenge-compiler、session-api、verifier)跨语言一致性校验消费。CI 双重检查:(a) dependency-cruiser 禁止浏览器可达包(vm-ui、web-component、embed-runtime、react-wrapper)导入 server-only 子路径,防止 server-only 类型进入浏览器构建图诱发误序列化;(b) 任何浏览器可达响应 Schema 的字段不得引用 `ProjectionPolicy` 类型(第九章 ZR-P1 的组成部分)。

## 七、派生公开字段粒度判定(决策记录,冻结)

派生公开字段 = 从私有状态派生其值的公开字段。本节记录粒度判定结论;每条以"结论 + 约束"形式成文,约束均落入第八章不变量或第九章机检条目。

### D1:`PublicStatus` 的 won/failed 公开时点与时间差侧信道

**问题**:won/failed 的公开时点是否通过时间差侧信道泄露隐藏目标条件?

**结论:在下列五条约束下无时间差侧信道,公开时点冻结为"动作响应同步携带"。** 约束全部可机检:

1. **无重询旁路**:won/failed 只在动作求值边界随响应下发;`sync-projection` 只重发最近一次已生成投影,不触发谓词重新求值,不构成可重询接口。提交(submit)的正式裁决走独立 verifier 异步链路(9.1),其时延由队列与重放主导,且裁决结果只取 11 种稳定结果类型,无部分匹配信息;
2. **恒定成本判定**:私有谓词求值的步数预算在题目资源预算内固定,与秘密值内容无关;隐藏字节比较禁止逐字节提前退出——提前退出会使"匹配前缀长度"成为可测信号。由单字节突变步数恒定测试强制(T-SC2,10.3);
3. **无进度字段**:不存在"已通过 N 项 / 共 M 项"类字段(I-7);失败响应只携带触发动作的可解释错误(E-4);
4. **交互与正式裁决分离**:交互会话的 `won`/`failed` 与正式裁决 `success`/`wrong_answer` 相互独立;前者是教学反馈,伪造它不改变成绩(ZR-T4),后者仅出自域 4 verifier;
5. **回退不可重询,神谕带宽受预算约束**:won/failed 为会话终态,`undo` / `checkout_checkpoint` / `reset` 在终态会话上以确定性错误拒绝;非终态会话的回退不重新求值历史判定;时间线回放与查看不受终态影响(它们只重放投影,不改状态)。交互式 won/failed 本质是设计内的验证通道(4.4"运行到结果"),无法也不应消除,其穷举带宽由 `constraints` 的**谓词求值次数预算**(按会话累计,跨 undo/reset 不重置,3.2)与每用户/每租户会话创建限流(9.2)共同限定,不构成无界神谕;预算的公开部分由公开描述包声明(7.1),完整预算属 `constraints` 私有。

### D2:`callStackSummary` 边界

**结论**:内容冻结为 `{index, functionLabel, returnAddressHex}`;深度上限常量 `CALL_STACK_MAX_DEPTH = 64`,超限截断,截断以不含计数的统一标记表达(不得显示"+N 帧",否则帧数成为隐藏控制流深度的信号)。**MVP 中代码区恒公开**,调用深度是公开程序的确定性行为,玩家可自行推导,故深度本身公开无泄露;含隐藏代码区/隐藏控制流的题目超出 MVP 范围,由 WP-4 检查器在题目校验期拒绝(公开描述包不得声明隐藏代码区域)。帧基址不直接下发,由玩家从可见 `RSP`/`RBP` 推导,保留教学价值。若未来引入非公开代码区(非 MVP),`functionLabel` 与 `returnAddressHex` 整体替换为统一占位帧(标签与地址一起隐藏),与 D5 的 `currentInstruction` 占位规则对齐。

### D3:`visibleRegions` 边界与 `maxBytesPerRange` 默认值策略

**结论**:

- **区域级**:仅白名单区域进入投影;隐藏区域无占位、无条目、无计数;可见区域与隐藏对象不重叠由编译期检查强制(I-2);相邻可见区域之间的"间隙"含义只有"不可见"——与公开布局的补集一致,不含额外信息;隐藏映射地址与未映射地址的访问结果由 I-9 统一,探测扫描无法区分"此处存在隐藏区域"与"此处未映射",故间隙不构成隐藏区域存在性信号;
- **字节级**:`maxBytesPerRange` 默认 **256**,单策略上限 **4096**,单 revision 投影字节总预算 **8192**(数值冻结;依据:MVP 教学视图 buffer 64 B + saved `RBP` + 返回地址 ≈ 128 B,256 留观察余量;4096 与总预算供 WP-3 落为 Schema maxima)。字节窗口锚定区域起点,不支持玩家任选偏移窗口(简化脱敏面;时间线回看走历史投影);截断统一 `truncated` 标记,不含省略字节数;
- **写入可见性**:对可见区域的写入(无论来源是玩家动作还是教学伪 syscall)都属于可见表面;私有逻辑向可见区域写入秘密内容属题目设计错误,由差分测试兜底检测(T-SC4)与编译期别名检查(I-2 的别名变体)拒绝。

### D4:`publicEvents` 过滤与编号

**结论**:公开事件是私有事件日志经白名单过滤后的子集;私有事件被丢弃时**不留占位**;`seq` 采用公开事件流**独立稠密编号**,禁止沿用私有日志序号——否则序号空洞可被用于计数隐藏事件(经典计数侧信道)。每动作公开事件数上限 256,超限按确定性规则聚合(聚合不依赖任何私有状态)。

### D5:`controlFlow` 与伪指令展示

**结论**:当前指令展示文本由服务端从展示数据单独生成(7.3),不是可执行 IR 的任何形态;MVP 代码区恒公开,`RIP` 展示恒可行;若未来引入非公开代码区(非 MVP 范围),`currentInstruction` 必须整体替换为统一占位符(地址与文本一起隐藏),不得只藏地址留文本。`pausedOn` 枚举(`read` / `write` / `call` / `ret` / `exception`)是玩家动作触发的暂停原因,属教学反馈,公开。

### D6:交互状态与正式裁决的关系

**结论**:交互会话的 `PublicStatus`(won/failed)与正式裁决(11 种结果类型,出自域 4 verifier)相互独立。浏览器伪造 won 状态只影响本地显示,不影响成绩与权威状态(ZR-T1/T4 验证);正式裁决只能由 verifier 对规范化动作日志独立重放产生。此分离使"前端显示"与"权威结果"在信任模型上彻底解耦。won/failed 的终态语义见 D1 约束 5。

## 十、侧信道判定规则

### 10.1 错误精度粗化策略(`errorDetailLevel`)

两级共同遵守:错误只能由 `(code, 玩家输入, 可见状态)` 确定性生成(E-1–E-6,I-8);禁止任何依赖隐藏状态的分支改变措辞、字段有无或数值。

| 允许暴露的内容 | `coarse` | `educational` |
|---|---|---|
| 错误码(冻结枚举) | ✓ | ✓ |
| 静态最小文案 | ✓ | ✓ |
| 目标地址(仅当落在可见区域,否则统一占位,E-2) | ✗ | ✓ |
| 玩家输入值的解释(如何被解释:little-endian qword 等) | ✗ | ✓ |
| 可见区域的权限/对齐事实(为什么不在可执行/可写区域) | ✗ | ✓ |
| 教学提示(检查 padding、little-endian、`RSP` 位置——4.4) | ✗ | ✓ |
| 隐藏区域地址/名称/存在性 | ✗ 禁止 | ✗ 禁止 |
| 私有谓词标识、参数、部分匹配结果、命中计数(E-4,I-7) | ✗ 禁止 | ✗ 禁止 |
| capability 名称、内部堆栈、文件路径、seed 信息(E-6) | ✗ 禁止 | ✗ 禁止 |

`coarse` 用于正式判题与 verifier 语境及策略要求的场合;`educational` 用于交互会话(默认),其展开解释是本项目教学价值核心(4.4),但解释字段全部由可见状态参数化。

### 10.2 确定性通道无相关性判定(T-SC1:秘密变体等价测试)

**原理**:本项目的确定性纪律(6.3)使投影长度、事件数量、错误序列成为 `(可见状态, 动作)` 的确定性函数——因此相关性判定可以做到**精确相等**,无需统计。

**方法**:取 fixture 题目,仅替换秘密值(长度变体 8/16/32/64 字节 + 同长不同值变体),其余(布局、代码、玩家动作脚本)完全相同;动作脚本必须包含**探针变体**——对若干可见区域外固定地址的读写动作,同步验证 I-9:隐藏映射地址与未映射地址在所有变体下的观测完全一致;逐动作回放,收集每步响应;**判定:全部响应经规范化序列化(WP-6 规则)后字节完全相等**。允许差异字段注册表(I-10)**默认为空集**;任何非空差异即违规。未来新增豁免字段须走 1.3 契约变更并在 I-10 注册。

**覆盖通道**:响应 JSON 字节长度(隐含投影长度)、`publicEvents` 数量与内容、错误 `code` 序列、`semanticHighlights` 集合、`callStackSummary` 深度、`truncated` 标记、探针动作的统一拒绝形态。

**落地纪律**:T-SC1 对 CI fixture 与**每道发布题目**(13.2 发布管线,针对其声明秘密生成变体)均为必过项——T-SC4 的 seed 差分对固定(非 seed)秘密无效,T-SC1 是唯一兜底。

### 10.3 恒定成本判定(T-SC2:单字节突变步数恒定测试)

**目的**:强制 I-6——隐藏字节比较不得逐字节提前退出;提前退出会使"最长匹配前缀长度"成为可测信号。这是时序之外的第二条通道:步数计数。

**方法**:

1. **fixture**:私有包含固定隐藏比较谓词(候选 vs 秘密,定长);
2. **突变**:对候选逐位置(0..len-1)、逐值(0x00–0xFF 抽样)生成突变候选,并覆盖全部前缀形态(全等、首字节差、尾字节差、位置 i 为首个差异);
3. **测量**:以**谓词求值步数**(指令预算消耗,引擎确定性指标)为主判据,动作时延为辅;
4. **判定**:全部突变候选的谓词求值步数集合方差为零;步数随差异位置或差异内容变化即违规。

**落地纪律**:引擎侧属性测试(proptest)随 CI 运行;每道发布题目对其谓词实现必跑(13.2 发布管线)。本测试是 10.4 时序判定的前提。

### 10.4 时序无相关性判定(T-SC3)

时序不是确定性通道,判定走统计方法,流程冻结、数值标定:

1. **基线标定**:对秘密不变的固定脚本测得动作时延分布(每动作 p50/p95),归档为噪声基线;同一脚本多次运行给出自然抖动带;
2. **变体测量**:秘密按长度(8/16/32/64 字节)与汉明距离(同长逐位翻转 1/2/4 字节)变体,重复固定脚本;
3. **判定**:对时延关于秘密长度/汉明距离做回归,斜率与 0 无显著差异,且各变体 p95 落在基线自然抖动带内。数值阈值(显著性水平、抖动带宽度)在实现期按基线标定并归档——方法与判定流程本文冻结,不留主观判断;
4. **约束**:判定前必须先完成 I-6(单字节突变步数恒定,T-SC2,10.3)——步数恒定是时序无相关的前提;时序修复优先靠消除内容相关分支,不靠注噪。

**触发纪律**:引擎或谓词实现变更时全量回归;题目发布管线按抽样运行(T-SC2 的步数恒定已覆盖主通道,时序测试作引擎级保障)。

### 10.5 随机秘密投影差分测试方法(T-SC4,计划书 9.2)

**目的**:证明"投影差异只来自被声明公开的随机化,随机秘密本身不显形"。

**方法**:

1. **同 seed 确定性(前提)**:同 seed 同脚本两次运行,投影序列规范化后字节一致(6.3);
2. **异 seed 差分**:同脚本不同 seed 运行,逐 revision 对投影做树 diff;**判定:差异字段路径 ⊆ 私有包 seed 策略显式声明的 `declaredSeedPublicPaths`**(例:公开宣告的随机栈基址)。其余任何字段路径出现差异即违规;
3. **实现形态**:属性测试(fast-check / proptest)随机生成秘密内容与 seed,断言上述两条;对每组 fixture 题目在 CI 运行,并纳入题目发布管线(13.2);
4. **秘密汇兜底**:随机秘密流入白名单寄存器/可见区域(违反 I-3 设计的题目)由此测试暴露为差异——差异即发布阻断。

### 10.6 修复纪律

- 任何一侧信道判定失败,修复方向是**结构性收窄**(白名单、统一占位、恒定成本),不是加噪声;
- **禁止**以随机填充/随机化响应内容掩盖设计泄漏——内容层随机化破坏投影确定性(6.3)与回放一致性;
- 时序噪声只允许在编排器层作为最后手段,必须归档说明并复测 T-SC3;
- 修复后全部 T-SC1–T-SC4 重跑。
