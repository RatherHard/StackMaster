# 阶段一任务分解:冻结信任模型、数据分类和会话协议

本文件是计划书第十二章"阶段一"的执行层拆解,与计划书冲突时以计划书为准。

## 一、阶段定位

**目标**:交付一套冻结的契约与安全规则,使阶段二(Rust VM Core 与会话编排)、阶段三(投影层与权威 API)、阶段四(教学 UI)全部在这套契约上实现,不再回头改字段。

**产出物性质**:契约与规则——Schema、类型定义、分类表、fixture、策略文档;**不是行为实现**。本阶段结束时没有可运行的 VM、没有 API 服务、没有 UI。

**硬门槛**(计划书原文):

> 任何无法证明"秘密不进入浏览器"的字段设计不得进入下一阶段。

本阶段同时要完成计划书列出的五项确认:产品边界、最小 DSL、字段分类规则、秘密零驻留清单、判题安全原则。

### WP-3 投影与错误契约

**对应章节**:6.2、4.4、5.6

- [x] `PublicError` 枚举 + **可解释错误格式**——本项目的教学价值核心:
  - 错误类型至少覆盖 4.4 清单:输入格式错误、payload 长度错误、偏移不足或过长、端序错误、权限错误、非法 `RIP`、Canary 破坏、参数寄存器错误、目标条件未满足;

- [x] 引擎进程协议复用声明:编排器 / verifier ↔ vm-worker 复用同一份动作、投影与错误 Schema,不另造私有格式(5.6)。

**交付物**:`packages/protocol` 扩展 + 错误格式文档

**完成标准**:错误枚举覆盖 4.4 全部类型;每类错误的解释字段通过 WP-1 粗化规则检查;契约版本策略成文。

### WP-4 题目双包 Schema 与最小 DSL 范围

**对应章节**:7.1–7.4、6.1

可与 WP-2 / WP-3 并行(依赖 WP-1 的分类规则)。

- [x] **公开描述包** JSON Schema,字段限于 7.1 清单:题面与学习目标、VM Profile 公开元数据、可见区域布局与公开对象标签、允许动作及参数 Schema、资源限制公开部分、提示阶梯与公开错误映射、UI 所需非秘密初始投影;
- [x] **私有判题包** JSON Schema,字段限于 7.1 清单:完整初始内存与寄存器、隐藏 flag / 隐藏字节 / 虚拟文件内容、私有对象与隐藏区域、权威成功 / 失败谓词与隐藏测试、seed 策略、编译后 IR、题目专用判题配置;
- [x] 字段分类检查器(可机检):
  - public / private 字段禁止混装;
  - 公开包不得通过默认值、引用 ID 或 Schema 元数据推导私有字段;
  - `virtual_file:flag` 一类 capability 仅允许出现在私有 Schema,不得进入公开 Schema、公开事件、公开回放或公开投影(7.3);
- [x] 最小 DSL 范围冻结文档:
  - 指令集(6.1):`push` / `pop` / `mov`、基本算术与位运算、有限跳转、`call` / `syscall`(教学伪操作,固定有限无宿主副作用)、`ret`、教学化 `read` / `write`;
  - 表达式白名单(7.3):常量、只读寄存器引用、命名内存区域查询、有界整数与位运算、比较、布尔组合、固定长度切片、有界字节匹配、枚举值比较;
  - 明确禁止项(7.3):任意脚本回调、`eval` / `Function` / 动态导入、用户自定义函数与任意 WebAssembly、文件系统 / 网络 / 进程访问、无限循环、动态拼接 capability 名称;
  - "扩展 = 选择受审计的内置 opcode / predicate / 操作 ID + Schema 约束参数,不是动态注册处理函数"(7.2);
- [x] 多阶段题目状态机 Schema 形态:每个状态含允许操作、前置条件、迁移条件、有限副作用、失败条件、资源预算;循环必须有静态上限或动态指令预算(7.2);
- [x] 四类版本字段进入双包结构:DSL Schema Version、VM Engine Version、VM Profile Version、Challenge Content Version(7.4,策略细节见 WP-6)。

**交付物**:`packages/challenge-schema`(双包 Schema + 分类检查器)+ `docs/最小DSL范围.md`

**完成标准**:分类检查器对正反样例包给出明确通过 / 拒绝结论;DSL 白名单成文且无任何脚本语言能力;公开包 Schema 无法表达任何私有字段。

### WP-5 iframe handshake 与嵌入协议

**对应章节**:8.1、8.2、9.2

依赖 WP-2(消息信封携带 sessionId 等字段),可与 WP-3 / WP-4 并行。

- [x] 版本化消息信封 schema(归 `packages/protocol`):协议版本、消息类型、会话 ID、序列号、可选请求 ID、结构化负载;消息 Schema 单一来源在 protocol 包,`embed-runtime` 只是宿主侧 SDK(阶段五实现);
- [x] handshake 流程设计成文(时序图):
  - 初始握手、能力声明与"宿主不支持能力"的处理路径(13.3);
  - opaque origin(sandbox 无 `allow-same-origin`)场景的附加控制:一次性不可预测握手值、会话绑定、消息认证、序列号防重放,或握手后转移绑定的 `MessageChannel`;不得把 `event.origin === "null"` 或 `targetOrigin: "*"` 当作唯一信任控制(8.1);
- [x] 消息校验规则清单成文(8.2):
  - 校验 `event.origin`、`event.source`、使用明确 `targetOrigin`;
  - 校验版本、字段类型、字段范围、消息大小;
  - 拒绝未知消息类型;处理重复、乱序、过期消息;限制消息频率;
  - **不把宿主声称的"已通过"、分数或最终状态当作权威结果**;
  - 宿主不得通过 postMessage 直接修改插件内部 DOM 或任何 VM 状态;
- [x] embed token 绑定字段冻结:租户、用户、题目版本、iframe 会话、过期时间(6.2、9.2);签发与校验流程只做设计,实现在阶段五;
- [x] 边界声明写入协议文档:独立来源 iframe 只隔离宿主与插件 DOM,不保护插件内客户端秘密;Shadow DOM 与 Web Component 不是安全边界(8.1)。

**交付物**:嵌入协议 Schema(入 `packages/protocol`)+ `docs/嵌入协议.md`

**完成标准**:消息信封有 schema;校验规则逐条可测;handshake 时序图覆盖常规路径与 opaque origin 路径。

## 六、决策点与风险

| 决策点 / 风险 | 说明 | 应对 |
|---|---|---|
| ADR-8 产能决策 | 计划书规定阶段一结束时决定 vm-core 语言;拖延会使 WP-1 的 `VmState` 归属悬置 | WP-6 显式排期;无论结果如何,JSON Schema 契约不受影响 |
| 侧信道判定主观性 | "错误精度是否过细""时序是否泄露"缺乏客观标准会导致 13.5 无法机检 | WP-1 必须产出可执行判定规则与差分测试方法,而不是原则性描述 |
| 契约冻结被实现期突破 | 阶段二/三实现中发现契约不便,悄悄绕过契约 | 契约变更纪律:先改 `protocol` / `challenge-schema` + fixture 并过评审,再改实现;禁止实现侧偏离 |
| 为未来能力预留字段 | 堆、ROP、更多防护属于 T3,预留字段违反路线纪律且扩大暴露面 | 只冻结 MVP 闭环(栈帧 / buffer / return address)所需最小契约;扩展靠版本号演进,不靠预留(YAGNI) |
| Schema 与双语言漂移起点 | 阶段一若不建立 fixture 纪律,漂移从第一天开始 | WP-6 的 Rust 消费冒烟不是形式项,是纪律起点 |
