## 一、定位与依赖边界

`challenge-compiler` 是**私有判题包装载链的上游把关点**(引擎进程协议 §5:跨包语义由 challenge-compiler / 编排器把关,worker 按单包 Schema 复验)。它只被后端包(session-api、verifier、会话编排核心)依赖,dependency-cruiser 规则 `challenge-compiler-dependents-restricted` 强制;浏览器可达包导入即违规,公开产物扫描同时拒绝 `challenge-compiler` 标识(13.5,ZR-B3 / ZR-B9)。

**整体 SERVER_ONLY**:装载产物含私有判题包完整状态与完整 IR,任何字段不得进入跨域载荷。

## 二、装载管线(层次化 fail-closed)

```text
输入(双包对象 / 双包 JSON 文本)
  ├─ 第 0 层(仅文本入口):严格 JSON 扫描器 —— 重复键拒绝(XS-DUP-KEY)、
  │   JSON.parse 不可观察的畸形输入在词法层拒绝
  ├─ 第 1 层:Ajv Schema 校验(公开包 + 私有包各自,ownProperties / 严格模式)
  ├─ 第 2 层:WP-4 检查器全量前置(checkChallengePair:公开单侧 + 私有单侧 + 跨包一致性,
  │   含 XS-PROG-MODE / XS-ENC-TOKEN / XS-ENC-PROBE / XS-CODE-WRX / XS-ARCH-WIDTH /
  │   XS-SYSCALL-DECL / XS-IFACE-REF / XS-CUSTOM-REF / XS-IR-LABEL / XS-STAGE-* / XS-PRED-REFS)
  ├─ 第 3 层:编译器编译期校验(按双程序形态分派,见 §三)
  └─ 产物:装载成功的题目(双包 + 按模式程序产物)
```

- 任一层出现违规即整体拒绝,后续层不执行(上层以下层输出为前置条件);
- **装载失败方向恒为 `challenge_invalid`**(`LOAD_FAILURE_RESULT_DIRECTION`):不产出部分程序、不近似执行;不存在带病会话;
- 违规是**内部诊断层**(`CompilerViolation`,含 ruleId / message / path),面向发布管线与管理后台(信任域 4);玩家可达错误只允许稳定 PublicError code,题目装载失败一律映射 `internal_error`(复用 challenge-schema `PUBLIC_FACING_ERROR_CODE_FOR_VIOLATIONS`,导出为 `PLAYER_FACING_ERROR_FOR_LOAD_FAILURE`),由会话服务层执行映射并禁止透传 message / path(错误两层模型,challenge-schema 语义文档 §五 R7 同纪律);
- 入口 API:`loadChallengePair(对象)` 与 `loadChallengePairTexts(文本)`;后者先走严格扫描器再复用同一管线。

## 三、编译期校验规则注册表(XC-*)

规则 ID 是内部诊断标识,不属冻结契约面;新增规则须在本表登记并附必触发红灯样例(整改方案 §七回归纪律;红灯样例位置见 `test/`)。

| 规则 ID | 语义 | 层 |
|---|---|---|
| `XC-OPCODE-SHAPE` | 逐 opcode 操作数量与形态符合冻结表(`OPCODE_OPERAND_SHAPES`,即 `docs/contracts/最小DSL范围.md` §三.1 表);自定义助记符必须零操作数(语义由微算子表承载,操作数无语法位置) | 装载 + 生成 |
| `XC-OPERAND-REF` | IR 指令的寄存器 / 内存基址引用必须落在**私有初始寄存器集**(运行时封闭集,与 XS-PRED-REFS 的谓词引用同一基准;FLAG 寄存器在初始集内、可作只读操作数) | 装载 |
| `XC-IR-TARGET` | 静态控制流立即数目标(jmp / je / jne / jb / jae / call 的 immediate)必须解析为界内指令索引(0 ≤ 目标 < 指令数) | 装载 |
| `XC-IR-REACH` | 纯静态程序(全部控制流为立即数目标且无动态目标节点)中,全部指令必须自入口可达——编译器产物不接受死代码(13.2「不可达目标」);含动态目标节点(ret / jmp R / jmp M / call R)时保守过近似为全图可达,静态判定失效 | 装载 |
| `XC-IR-TERMINATE` | 可达**回边**(目标 ≤ 来源的静态边;直线后继严格递增,故环 ⟺ 存在回边)存在 ⇒ 题目必须声明 `stages[]`(7.2「循环必须有静态上限或动态指令预算」;每阶段 `maxInstructionSteps` 必填,XS-STAGE-BUDGET 强制 ≥ 1) | 装载 |
| `XC-STAGE-SIDE-EFFECT` | 阶段副作用 `fileId` 必须落在 `secrets.virtualFiles`(结构化引用,拒绝动态拼接,7.3;WP-4 检查器未覆盖的增量) | 装载 |
| `XC-STAGE-ACTIONS` | 阶段 `allowedActions` ⊆ 公开包 `allowedActions`(DSL 文档 §七:「阶段动作不得超出题目允许面」;Schema 只封 12 动作枚举,与公开允许面的交集语义归实现层) | 装载 |
| `XC-LABEL-DUP` / `XC-LABEL-BOUND` / `XC-LABEL-REF` / `XC-ENTRY-BOUND` | 生成面标签消解:labelId 唯一、标签索引界内、控制流引用可解析、入口界内 | 生成 |
| `XC-ENC-NO-MATCH` / `XC-ENC-AMBIGUOUS` | 字节模式生成:每条指令必须恰有一个 token 匹配(op + 操作数形态逐位兼容,寄存器 / 接口号烘焙等值);多 token 同形态 = 编码不唯一,拒绝 | 生成 |
| `XC-ENC-VALUE-RANGE` | 字节模式生成:内联立即数 / 跳转地址落 archBits 无符号域,位移落有符号域(与 XS-ARCH-WIDTH 同一域定义) | 生成 |
| `XC-ENC-OVERFLOW` | 字节模式生成:程序编码字节(含入口偏移)不得越出代码区;指令数受 `MAX_IR_INSTRUCTIONS` 同护栏 | 生成 |
| `XC-ENC-PAD` | 字节模式生成:尾部填充 token 必须存在且零内联字节(纯指令流约定,DSL 文档 §三.4.3;填充不能用任意字节);字节模式必须提供 codeRegion 几何 | 生成 |
| `XC-MIGRATE-VERSION` / `XC-MIGRATE-REMOVED-OPCODE` | 版本迁移:版本不可识别或无已登记迁移路径即拒;被移除 opcode(`read` / `write`,G4)无自动等价改写,fail-closed | 迁移 |

### 装载产物

- **IR 模式(公开包无 `encodingTable`)→ 编译产物** `IrCompiledProgram`:消解后指令流、labels 元数据、显式 `entrypointIndex`(缺省 0)、CFG 事实(可达指令数、回边清单);
- **字节模式 → 编码表装载** `ByteLoadedProgram`:自 `entrypointAddressHex` 线性探测译码的指令流(≤ `MAX_IR_INSTRUCTIONS` 或区域尾止,D4.6),每条含 token 地址(区域相对字节偏移)与**内联操作数值**(恰 `archBits/8` 字节小端提取——宽度自证,D4.7;XS-ARCH-WIDTH 在译码产物上结构性不触发,仅值型检查且已由 XS-ENC-PROBE 前置完成)。

## 四、语义决策记录(实现期裁决,契约未定死处的对齐点)

1. **IR 模式寻址 = 指令索引**。`compiledIr.entrypointIndex` / `labels[].instructionIndex` 与控制流立即数目标同一空间(«IR 模式:labels[] 编译期索引»,DSL 文档 §三.4.5);字节模式地址 = 代码区字节偏移(绝对地址形态进内联立即数,与 RIP / ret 弹出值一致)。两地址空间不同,XS-PROG-MODE 保证不混用。
   - ⚠ **WP-4 对齐点 A**:引擎实现(vm-core)落地 IR 模式控制流时,须把控制流立即数解释为指令索引(或与引擎自报的等价映射);`ret` 弹出值在 IR 模式的解释同理。
2. **末条指令的直线后继 = 隐式程序结束**(终结点)。
   - ⚠ **WP-4 对齐点 B**:引擎侧直线越过指令数组末尾须同语义(而非 `invalid_rip`);若裁决为 `invalid_rip`,本包 CFG 的隐式终结分类随之调整(只影响终止性分类,不影响拒绝面)。
3. **`ret` / `jmp R` / `jmp M` / `call R` 为动态目标**:保守过近似(gadget 语义,控制流可到任意指令边界)。可达性判定只在纯静态程序中精确;动态目标节点的运行期循环不可静态判定,由 worker 资源面(9.1 最大执行步数)与阶段预算兜底——静态回边 × 预算是编译期断言,动态循环是运行时不变量,两层合起来才是完整终止性。
4. **`call [interface]` 的 CFG 后继 = 直线下一条**(引擎管理调用,D4.2 ①,不占玩家栈);接口效果序列含 `exit` 时该 `syscall`/`call` 为终结点。
5. **`syscall` 保留带 [0x0, 0xFF] = 内置 exit(I)**:终结点(«当前仅 exit(I)» 的封闭集现状,DSL 文档 §三.1;新增内置语义时随版本演进调整分类)。
6. **标签操作数 = 取地址语义**:凡立即数合法的槽位均可引用标签(IR 模式解析为指令索引,字节模式解析为绝对字节地址内联)——`mov RAX, label` 即地址装载,与控制流槽位同一消解机制。
7. **byte 模式不做 CFG 断言**:探测译码是入口可达直线流(D4.6),跳转目标不在装载期校验(运行时取指未知 token / 截断 → `invalid_rip` 兜底); gadget 即任意 token 边界取指,是字节模式一等能力。

## 五、生成面(compileProgram)

作者程序(`AuthorProgram`:冻结 IR 形态 + 编译器内部标签操作数 `{kind:"label"}`)→ 按公开包 `vmProfile.encodingTable` 有无分派(与 XS-PROG-MODE 同判据):

- **IR 模式**:标签消解为指令索引 valueHex 立即数,产冻结形态 `compiledIr`(labels[] 保留、entrypointIndex 显式);
- **字节模式**:两遍编码——第一遍 token 匹配 + 偏移计算(内联定宽,标签值不影响长度),第二遍回填标签目标(绝对字节地址)并组装字节流;寄存器 / 接口号烘焙进 token(同一助记符多 token = 不同编码,D4.7),立即数 / 位移内联恰 `archBits/8` 字节小端;产出代码区完整 `contentHex`(入口偏移前置零 + 程序 + 零内联填充 token)+ `entrypointAddressHex`。

**自消费纪律**:生成产物必须再经 `loadChallengePair` 全量校验方可进入私有包(测试矩阵以「compile → load 绿」断言固化;手写字节流经 WP-4 探测译码兜底,编译器产物经同一道门)。

## 六、版本迁移(migrateChallengePair)

- 信封版本 `schemaVersion`(`CHALLENGE_PACKAGE_SCHEMA_VERSION`,当前 1):当前无历史发布版本,`REGISTERED_MIGRATIONS` 为空——非当前版本输入 fail-closed(`XC-MIGRATE-VERSION`),不做投机迁移;递增信封版本时在此登记 N-1 → N 步骤(7.4 兼容窗口的机检锚点)。
- DSL 版本 `dslSchemaVersion`(当前 2):1 → 2 为 G4 重定基——**结构性迁移**:版本字段推进 + 被移除 opcode(`read` / `write`)fail-closed(`XC-MIGRATE-REMOVED-OPCODE`,语义变更无自动等价改写,须作者按 v2 词汇改写:内存读写走 `mov R,M` / `M,R` 与会话动作 `write_bytes`,虚拟文件读取走作者接口);其余 v1 形态在 v2 下合法(v2 为增量演进:interface 槽、`customInstructions`、`interfaces` 均为新增可选声明面)。
- 迁移不改写判题语义与内容字段;产物必须再经 `loadChallengePair` 全量校验(migrate → load 组合纪律,测试固化)。

## 七、测试矩阵与移交

- 每条 XC-* 规则附必触发红灯样例;冻结形态表以「每 opcode × 每声明形态」绿灯矩阵锁定(`test/ir-operand-shapes.test.ts`);WP-4 规则(XS-*)在管线中的透传生效做回归守卫;
- **双模式样例**:同一逻辑程序(栈帧 + 条件分支 + 收尾)的 IR 编译产物与字节模式 token 流均通过装载管线,跳转目标按各自地址空间消解并断言(`test/ir-compile-labels.test.ts`)——此即 **WP-9 跨模式一致性测试的产物来源**;执行轨迹逐条一致(引擎侧)归 WP-9 / WP-4;
- 32 / 64 位双位宽样例、自定义指令(NOP0:bit_mask 恒等)、作者接口(`call [interface]` / `syscall` 派发)均覆盖;私有样例全部由测试期 builder 现场构造,**永不入 git**(CLAUDE.md 红线)。

## 八、明确不属于本包

- DSL 源(作者语言)文法定义与解析器(作者程序当前以编程形态输入;文本语言随题目制作需求另行立项并走契约流程);
- 谓词求值、seed 派生、状态机运行时强制(归 WP-5 引擎判题面);
- IR / 编码表的执行语义本体(归 WP-4 vm-core);
- worker 资源限制、进程管理(归 WP-8)。
