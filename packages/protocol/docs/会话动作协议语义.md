## 一、范围与冻结清单

本 WP 冻结:

1. `ActionRequest` 信封(6 字段)与 12 种动作的 `args` Schema(`schema/action-request.schema.json`);
2. `ActionResponse` 信封(6 字段)、5 种响应状态(`schema/action-response.schema.json`);
3. 11 种稳定结果类型(`schema/verdict-result.schema.json`);
4. 协议语义:revision 与 undo 语义、`baseRevision` 拒绝规则、幂等语义、单会话串行表达、会话生命周期命令集、服务端校验基线(本文);
5. 机检产物:`schema/classification.json`(字段分类清单,WP-1 §6)与 `test/fixtures/`(典型 / 非法样例,WP-6 golden fixture 的增量来源)。

**不归本 WP 冻结**(边界声明):

- `projectionDelta` / `publicEvents` / `userVisibleError` 的完整 Schema 归 **WP-3**。(WP-3 已冻结:provisional 前置声明已删除并由完整 Schema 替换,信封未改动;错误码冻结名与能力矩阵、投影与增量语义见 `docs/投影与错误契约语义.md`——本文中出现的错误码名称自此以该文 §4.2 冻结枚举为准,恰与本文占位名一致;)
- 会话级命令(create-session / sync-projection / submit / close-session)的完整请求 / 响应 Schema 依赖认证上下文与编排器实现,归**阶段二 / 三**;本 WP 冻结其在生命周期中的位置、前置条件与失败语义(第五节);
- 传输层信封(WSS 消息帧、HTTP 路由)归 **WP-5** 与阶段三;本文只约定与传输无关的协议语义。

**与 VM Profile 解耦**(docs/develop/Vm 模块设计.md):动作协议不绑定地址位宽(32/64 位)、寄存器名称集合或区域布局——协议层只传十六进制字符串与不透明标识符,位宽与名称合法性由服务端按题目 VM Profile 重新校验(6.2 第 6 条)。

## 二、信封与字段分类

### 2.1 `ActionRequest`(浏览器 → 服务端,整体 `BOUNDARY`)

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `protocolVersion` | `const 1` | 只接受当前版本;N-1 窗口由服务端按路由双版本受理(第五节) |
| `sessionId` | 不透明字符串(1–128) | create-session 由服务端签发;有效性由会话表与 token 绑定校验(6.2 第 2 条),泄露危害由短期凭证缓解(WP-1 §6.1) |
| `clientSeq` | 整数 ≥ 1 | 客户端会话内严格递增序号;串行与防乱序语义见第四节 |
| `baseRevision` | 整数 ≥ 0 | 乐观并发控制:必须等于服务端当前 `revision`,否则拒绝(第四节) |
| `idempotencyKey` | 不透明字符串(1–128,客户端生成,推荐 UUID v4) | 防重;服务端生成映射,键值不承担安全性(ZR-T3,第四节) |
| `action` | `{ type, args }` 判别对象 | `type` ∈ 12 种冻结动作;`args` 按 type 逐一校验(第三节) |

全部字段 `BOUNDARY`(WP-1 §6.1):服务端对一切入站数据按同一契约**重新校验**(5.6),不信任客户端类型标注。strictObject → `additionalProperties: false`(I-1):未知字段在契约层必须**拒绝**——不存在"剥离后接受"的弱路径,strip-then-accept 会静默放行篡改信封;"剥离"仅指拒绝之后的规范化序列化与日志脱敏环节**排除未声明字段、不读取其内容**(ZR-T2:浏览器提交的任何自制状态字段既不生效也不落盘)。

**标识符字符集约束**(冻结):`sessionId` / `idempotencyKey` 与服务端签发的 `requestId` / `checkpointId` 均限定 `^[A-Za-z0-9_-]{1,128}$`。动机:服务端以字符串拼接组合键(如 `idem:{sessionId}:{key}`,WP-1 §2),受限字符集使组合键单射性无需转义约定,并消除控制字符(`:`、换行、NUL、零宽字符)的审计日志注入面;服务端签发 ULID/UUID 与客户端生成 UUID v4 均天然满足。长度上限 128 按 Unicode code point 计(JSON Schema maxLength 口径);TS 侧 Zod 按 UTF-16 码元计,对增补平面字符只会**更严**(保守方向的安全偏差),WP-6 golden fixture 不得以增补平面字符断言长度边界。

### 2.2 `ActionResponse`(服务端 → 浏览器,整体 `PUBLIC`)

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `requestId` | 不透明字符串 | **服务端生成**的请求关联 ID,非客户端回显(WP-1 §6.2);客户端以传输层请求-响应对应 + 本地 `idempotencyKey` 账簿关联(第四节) |
| `revision` | 整数 ≥ 0 | 服务端权威 revision;本动作处理后的当前值(含被拒绝时返回未变化的当前值,第四节) |
| `status` | `running` / `paused` / `won` / `failed` / `rejected` | 前四者 = 权威 VM 状态(PublicStatus)在响应边界的值;`rejected` 只出现在动作响应、不进入公开投影(WP-1 §4.2) |
| `projectionDelta` | 对象 \| `null` | 本动作产生的公开投影增量(WP-3 冻结形态);无投影变化时为 `null` |
| `publicEvents` | 数组 ≤ 256 | 本动作的公开事件(D4 白名单过滤);上限 `MAX_PUBLIC_EVENTS_PER_ACTION = 256` |
| `userVisibleError` | 对象(可选) | 脱敏后的可解释错误(WP-3 冻结结构);仅拒绝与可解释失败时出现 |

信封字段集合冻结:新增字段必须先按 WP-1 §1.3 完成分类与硬门槛论证。响应同样 strictObject:CI 与测试按 I-1 白名单校验响应(ZR-P1 / ZR-R3 的契约基础)。载荷占位约束(冻结):`projectionDelta` 非 null 时,其 `revision` 必须等于信封 `revision`(增量所描述的目标版本即本响应版本)。

### 2.3 分类标签与机检

- 每个落盘 Schema 根节点携带 `x-sm-class`(`boundary` / `public`);嵌套子树分类随根继承(机检按根标签处理整棵树),字段级分类落盘在 `schema/classification.json`,由生成管线从 `src/common/classification.ts` 产出;CI 机检(ZR-P1 / I-1)直接引用该清单,**机检条目须引用 WP-1 文档条目 ID**(单一来源纪律)。`fieldClasses` 键集必须与对应 Schema 顶层 `properties` 键集严格一致(schema-drift 测试断言,新增字段漏改分类时机检即失败);枚举型根 Schema(verdict-result)无字段,`fieldClasses` 为空集,机检不得对其断言非空;
- **provisional 子树机检标记**:载荷占位 Schema(`projectionDelta` / `publicEvents` / `userVisibleError`)在落盘 JSON Schema 中携带 `x-sm-provisional: true`,并在 `classification.json` 以 `provisionalFields` 登记——"非冻结"声明由散文变为机检面(schema-drift 测试断言标记存在);WP-3 冻结时移除标记并整体替换(已执行:标记全库退场,schema-drift 现断言任何产物不得再出现 `x-sm-provisional`);
- `Schema 存在不等于可下发`:server-only 类型(WP-3 的 `ProjectionPolicy` 等)只进 server-only 子路径,由 dependency-cruiser 禁止浏览器可达包导入(WP-1 §五)。

## 三、动作语义(12 种,逐一冻结)

### 3.0 通用规则

- **服务端重新校验**:args Schema 只做结构与字面校验;地址合法性、区域权限、操作数范围、资源预算由服务端在执行前重新校验(6.2 第 6 条),并按锁定题目版本解析(9.1)——协议**不接受**客户端提交的规范化 IR 替代受限动作(9.1);
- **I-9 统一不可见访问结果**:对任何非可见地址(隐藏映射或未映射)的读写 / 调用,全部可观察结果(错误 code、占位符、无事件、revision 不前进、响应字节)与规范"未映射地址"完全一致——探测扫描无法区分两者;
- **可见 ≠ 可写**:对**可见**区域但权限不符的访问属已执行动作,产生可解释的 `memory_fault` 类教学反馈(4.4),revision 前进;错误解释按 WP-1 10.1 粗化规则生成;
- **终态规则**(WP-1 D1 约束 5):`won` / `failed` 为会话终态。终态会话上的一切状态转换动作、以及 `undo` / `checkout_checkpoint` / `reset`,均以**确定性错误**拒绝(同一输入恒同字节响应);`sync-projection`、时间线查看与 `submit` 不受终态影响。

### 3.1 状态转换动作(改变 VM 内容)

| 动作 | args(冻结) | 语义 | 服务端重新校验点 |
|---|---|---|---|
| `write_bytes` | `addressHex`、`bytesHex`(偶数长度 hex;协议上限 4096 字节) | 向目标地址写入字节(构造 payload 覆盖 buffer / 返回地址的教学动作) | 地址可见性(I-9 统一拒绝)、区域可写性、题目级长度预算(公开包声明,7.1)≤ 协议上限 |
| `push` | `valueHex`(≤ 64 位) | 值入栈(`RSP` 按位宽递减;字节序由 VM Profile 决定) | 栈区域可写性、栈深度预算 |
| `pop` | `{}` | 弹出栈顶(`RSP` 递增);弹出结果仅经公开投影可见 | 栈区域可读性、栈底边界 |
| `call` | `targetHex` | 压入返回地址并跳转(教学动作,非任意指令执行) | 目标可见性与可执行性(I-9 统一拒绝形态)、调用深度预算 |
| `ret` | `{}` | 弹出栈顶作为新 `RIP`;非法 `RIP` / Canary 破坏产生可解释错误(4.4,WP-3 枚举) | 同上 |
| `step` | `{}` | 单步执行**恰好一条**指令(4.4"单条机器动作") | 步数预算 |
| `run_to_event` | `pauseOn` ∈ `read` / `write` / `call` / `ret` / `exception` | 运行直到触发指定类别事件后暂停(4.4"执行到关键事件") | 步数 / wall-clock 预算:预算耗尽时**确定性暂停**(`status: "paused"` + 预算类可解释错误),不产生部分推进的假象 |

设计说明:`step` 恒为单步、`run_to_event` 无自定义步数——"步数"不作为动作自由度暴露,连续推进走 `run_to_event` 或重复单步;这缩小了脱敏面,也使步数预算语义只存在于服务端(9.1 资源约束)。`pauseOn` 枚举与 WP-1 D5 `pausedOn` 同源;伪 `syscall` 不提供暂停事件,扩展走协议版本演进,不靠枚举预留。

### 3.2 会话控制动作

| 动作 | args(冻结) | 语义 |
|---|---|---|
| `pause` | `{}` | 在当前指令边界暂停;`status` 变化进入投影 |
| `undo` | `{}` | 撤销上一次已执行动作:内容回退到前一状态,**revision 照常 +1**(见 4.1) |
| `checkout_checkpoint` | `checkpointId` | 恢复到该 checkpoint 的内容(新 revision 携带旧内容);`checkpointId` 归属校验在服务端(6.3) |
| `reset` | `{}` | 重置到题目初始状态(内容 = 初始状态,revision +1) |
| `create_checkpoint` | `label?`(≤ 128 字符,玩家自报,拒绝 C0/C1 控制字符) | 服务端保存 COW 快照(6.3);不改变投影(`projectionDelta: null`),revision 照常 +1 |

`create_checkpoint` 的 **checkpointId 回传通道**(冻结决策):服务端签发的 `checkpointId` 不经 `ActionResponse` 信封回传——信封字段集合冻结为 WP-1 §6.2 六字段,`publicEvents` 无 checkpoint 类别,`payloadHex` 受 I-10 值来源约束(编码服务端签发 ID 即违规),私加响应字段或塞入事件负载都是契约突破。sanctioned 通道是 `list-checkpoints` 查询(§5.1):客户端创建后刷新 checkpoint 列表(时间线 UI 本就需要该查询面),再以 `checkpointId` 发起 `checkout_checkpoint`。

undo / checkout / reset 的**内容回退不重新求值历史判定**(WP-1 D1 约束 5):回退不是对隐藏谓词的重询接口;三者与 `undo` 在终态会话上一致拒绝。

## 四、核心协议语义

### 4.1 revision:唯一权威序号与 undo 语义

- `revision` 是服务端权威单调计数器,**值 = 已执行(非拒绝)动作数**(WP-1 v1.1 §4.1 / I-5;措辞由"仅成功动作 +1"修订而来的论证见 WP-1 §1.3.1):每个被接受的动作用 `+1` 精确推进——**包括** `undo` / `checkout_checkpoint` / `reset` / `pause` / `create_checkpoint`;被拒绝的动作不推进(增量 ∈ {0, +1},ZR-P5 运行时断言,判定基准 = "动作是否进入执行");
- **undo = 内容回退、版本前进**:`undo` 产生**新 revision**,其内容等于前一状态。不做"版本号倒退"——这保证 revision 单调、投影增量 / 断线同步 / 幂等缓存语义统一,且时间线(revision + checkpoint 引用,4.4)天然表达"撤销也是一步";
- 失败但**已执行**的动作(如写可见但不可写区域 → `memory_fault` 反馈)同样 +1:它改变了可观察状态,投影增量承载该变化;只有**进入执行前被拒绝**的动作(参数校验失败、`baseRevision` 过期、不可见地址、终态违规、幂等冲突等)revision 不变。

### 4.2 `baseRevision` 拒绝规则

1. 服务端校验 `request.baseRevision == 当前权威 revision`;相等 → 执行;不等 → **拒绝**(`status: "rejected"` + 占位码 `stale_base_revision`,WP-3 冻结名),`revision` 返回当前值,`projectionDelta: null`、`publicEvents: []`;
2. 拒绝是确定性的:同一 `(会话状态, 请求)` 恒产生字节相同的响应(I-4 / T-SC1 的契约前提);
3. 客户端收到拒绝后的恢复路径:调 `sync-projection` 取最新公开投影与 revision → 以新 `baseRevision` 重发新动作(或按第四节幂等重放);
4. 首个动作的 `baseRevision` 为 create-session 返回的初始 revision(0)。

### 4.3 幂等语义(`idempotencyKey`,ZR-T3)

1. **窗口**:服务端以 `(sessionId, idempotencyKey)` 在幂等窗口内缓存**最终响应**;窗口 TTL 属实现期配置(阶段三),协议只要求:窗口内同键重放必须返回**字节相同**的缓存响应,动作日志不追加(响应确定性使"缓存即字节一致"可断言);
2. **同键同负载** → 返回缓存响应(幂等重放);**同键不同负载** → 确定性拒绝(占位码 `idempotency_conflict`):键被复用于不同内容是协议违规,不得静默当作新请求。「负载」定义为**规范化序列化后的完整 `ActionRequest`**(六个信封字段与 `action` 全体;传输层帧字段不在契约内)——重试必须原样重发同一请求(同 `clientSeq`);同键而 `clientSeq` / `baseRevision` / `action` 任一不同即冲突。一致性比较基于规范化序列化(WP-6 冻结规则;规则落地前过渡实现可比较原始字节,阶段二落地时切换);
3. **窗口过期**的同键请求按新请求处理(可能因 `baseRevision` 过期被 4.2 拒绝)——窗口是效率设施,正确性由 `baseRevision` 与串行保证;
4. 键由客户端生成、服务端生成映射(WP-1 §6.1):键的碰撞后果限于动作被拒,不产生安全问题。

### 4.4 单会话串行:`clientSeq` 与确认

- 服务端**单会话内串行**处理动作(6.2 第 5 条):一个会话的会话队列一次只执行一个动作,响应顺序 = 执行顺序;
- `clientSeq` 是玩家侧序号:客户端在同一会话内**自 1 起严格递增**。服务端维护已处理 `clientSeq` 高水位:新请求 `clientSeq ≤` 高水位且非幂等重放 → **确定性拒绝**(占位码 `stale_client_seq`)——这是防重放与乱序检测的协议层表达;
- **推荐客户端模式:stop-and-wait**(发出一个动作、等响应再发下一个)。此模式下传输层顺序即串行顺序,`requestId`(HTTP 事务本身 / WSS 按序帧)即"确认序号"的载体;客户端并发发送同一会话多个动作时,乱序到达者将被高水位检查拒绝,后果由客户端承担;
- 被拒绝的请求同样消耗其 `clientSeq`(已被处理);断线后恢复:客户端以 `sync-projection` 对齐 revision,再以**新的** `clientSeq` 继续(旧序号区间随会话高水位作废);
- 服务端实现应对单会话 `clientSeq` 设上限(实现期配置,阶段二 / 三):触顶后的一切请求确定性拒绝,恢复路径是重新 `create-session`(旧会话资源按会话生命周期回收)。客户端应自 1 起稠密使用序号,不做跳号预留;
- `clientSeq` 不作为权威序号(权威是服务端 `revision`,WP-1 §6.1);它只承担串行确认与防乱序。

### 4.5 响应形态小结(冻结)

| 场景 | `status` | `revision` | `projectionDelta` | `publicEvents` | `userVisibleError` |
|---|---|---|---|---|---|
| 动作执行,VM 继续 | `running` / `paused` | +1 | 增量 | 本动作公开事件 | 缺省 |
| 动作执行触发终态 | `won` / `failed` | +1 | 增量 | 本动作公开事件 | 缺省(判定细节禁止下发,I-7) |
| 已执行的教学性失败(权限 / 非法 RIP / Canary 等) | `paused` / `failed`(按引擎语义) | +1 | 增量 | 可见事件 | 可解释错误(WP-3 格式) |
| 预算耗尽(`run_to_event` 未命中) | `paused` | +1(以最后一致状态为准,无部分推进) | 按下方确定性规则生成 | 按 D4 聚合规则返回聚合事件集(含 truncated 标记,形态归 WP-3),不得静默丢弃 | 预算类错误 |
| 协议级拒绝(stale revision / 不可见地址 / 终态违规 / 幂等冲突 / 乱序序号) | `rejected` | 不变 | `null` | `[]` | 必有 |
| `create_checkpoint` 成功 | 不变(仍 `running` / `paused`) | +1 | `null` | `[]` | 缺省 |

`projectionDelta` 为 null **当且仅当**本动作未产生任何可观察状态变化——判定必须是 `(动作, 执行前可见状态)` 的确定性函数(I-4),禁止按隐藏状态分支选择形态;"revision 前进但增量为 null"的合法情形仅限无可观察变化的控制类动作(如 `create_checkpoint`)。预算耗尽属已执行动作:已发生的公开事件按 D4 聚合规则携带 truncated 标记返回,不得以空数组丢弃——丢弃会让"投影有变化却无任何事件"成为合法形态,削弱回放可解释性,也与 D4 的聚合义务冲突。

## 五、会话生命周期命令集(9.1)与版本窗口

### 5.1 生命周期(命令集冻结;命令 Schema 归阶段二 / 三)

```text
create-session      校验用户 / 租户 / 题目权限,绑定 token 与题目版本 → 返回 sessionId、初始 revision、初始公开投影
  → action / step / run_to_event / pause          服务端串行执行并返回投影(本文协议)
  → undo / checkout-checkpoint / reset            服务端恢复状态并重新投影(非终态)
  → create-checkpoint                             服务端保存快照,时间线只存引用
  → list-checkpoints                              枚举本会话 checkpoint 引用(checkout 前置查询与时间线数据源)
  → sync-projection                               断线重连后重新同步最近公开投影
  → submit                                        提交引用服务端规范化动作日志 → 独立 verifier 裁决(11 种结果类型)
  → close-session                                 结束会话
```

- `sync-projection` 只重发最近一次已生成投影,不触发谓词重新求值,不构成可重询接口(WP-1 D1 约束 1);响应携带当前 `revision` 与完整最近投影,客户端据此对齐 `baseRevision` 账目;
- `list-checkpoints` 返回本会话服务端保存的 checkpoint 引用列表(`checkpointId`、`label?`、内容 revision、创建顺序),是 `checkout_checkpoint` 的前置查询(§3.2 的 ID 回传通道)与时间线 UI 的数据源。字段分类意图全部 `PUBLIC`(`checkpointId` 为服务端签发的不透明标识符,与 `requestId` 同类;`label` 为玩家自报;revision 公开),完整请求 / 响应 Schema 归阶段二 / 三,冻结时按 WP-1 §1.3 落分类论证;只读查询,非终态与终态会话均可用;
- `submit` 引用**服务端**记录的规范化动作日志(9.1):浏览器不提交自制快照、状态哈希或成功标志;正式裁决(11 种结果类型,第六节)只能由域 4 verifier 独立重放产生,与交互 `won/failed` 相互独立(D6 / ZR-T4);
- 终态会话:状态转换动作与 undo / checkout / reset 拒绝(3.0);`sync-projection`、`list-checkpoints`、时间线查看、`submit`、`close-session` 可用。

### 5.2 版本与 N-1 兼容窗口(5.6)

- 本协议版本号:`protocolVersion: 1`;**破坏性变更**(字段删除 / 改名 / 类型或语义变化、枚举值删除)递增版本,新 Schema 落新目录(`…/session-action/v2/`);
- 兼容窗口:过渡期服务端**按路由同时接受** N 与 N-1 两个版本(各自独立 Schema 校验),窗口期结束下线旧版;窗口时长为实现期运维参数(阶段三);
- 非破坏性变更(追加可选字段)仍须走 1.3 变更流程并更新 fixture,但不强制递增版本;
- `ActionResponse` 不携带版本字段:响应由服务端生成,客户端按其发起请求的版本解释响应(传输层信封按 WP-5 携带会话级版本协商结果)。

## 六、11 种稳定结果类型(9.1,冻结)

| 结果 | 语义 | 产生域 |
|---|---|---|
| `success` | 隐藏测试与目标条件全部通过 | verifier(域 4) |
| `wrong_answer` | 提交 / 重放结果不满足目标条件 | verifier |
| `invalid_action` | 动作日志含违规动作,重放无法通过校验 | verifier |
| `program_crash` | 重放中 VM 程序崩溃(教学语义的崩溃) | verifier |
| `memory_fault` | 重放中发生内存访问违规 | verifier |
| `resource_limit` | 步数 / 内存 / 输出等预算超限 | verifier |
| `timeout` | wall-clock 超时 | verifier |
| `engine_error` | 引擎内部错误(含溢出安全终止,ADR-8) | verifier / 编排器 |
| `challenge_invalid` | 题目包本身未通过校验,判题不成立 | verifier |
| `replay_mismatch` | 独立重放与在线记录不一致(可疑完整性) | verifier |
| `cancelled` | 会话 / 提交被取消(超时、管理干预) | 编排器 |

- 与交互 `PublicStatus`(`won` / `failed`)的关系见 WP-1 D6:两者独立,伪造前端 won 不影响成绩(ZR-T4);
- 枚举值即契约(5.6):前端不得解析枚举之外的非契约字段;扩展结果类型 = 破坏性变更,走版本演进;
- 对学习者只展示有限且有帮助的信息:内部堆栈、文件路径、隐藏测试与宿主异常只进受控日志(9.1,WP-3 错误格式承接)。

## 七、服务端校验基线(6.2 第 1–7 条,协议落点)

服务端对每个 `ActionRequest` 的处理必须逐条满足(实现归阶段二 / 三;本表为契约级验收基线):

| # | 基线(计划书 6.2) | 协议落点 |
|---|---|---|
| 1 | 从认证上下文派生用户 / 租户 / 题目 / 题目版本,不接受请求体自报身份 | 信封无任何身份字段;`sessionId` 有效性由服务端会话表 + token 绑定决定(2.1) |
| 2 | 校验会话 token 绑定(租户 / 用户 / 题目版本 / iframe 会话 / 过期) | `sessionId` 与 token 绑定校验;embed token 字段归 WP-5 |
| 3 | 校验 `baseRevision` 与当前状态一致 | 4.2 拒绝规则 |
| 4 | 以 `idempotencyKey` 防重 | 4.3 幂等语义 |
| 5 | 单会话内串行处理 | 4.4 串行表达 |
| 6 | 重新校验动作参数 / 地址 / 区域权限 / 操作数 / 资源预算 | 3.0 通用规则 + 第三节各动作"重新校验点"列;协议层上限(4096 B / 256 事件)只是外圈护栏 |
| 7 | 只从服务端题目包和服务端 VM 状态执行 | 协议不含任何状态上载通道:strictObject 使自制快照 / 状态哈希 / 成功标志字段直接被拒绝(I-1 / ZR-T1 / ZR-T2) |
| 8 | (9.2 / 5.6 补充)校验失败响应面:一切校验失败——含契约层 Schema 校验——只允许产出冻结 `PublicError` 形态;禁止透传校验器原始错误文本、字段路径(Zod issue path / Ajv `instancePath`)或未声明字段内容;原始载荷仅进 server-only 审计日志 | "错误类型也是契约"(5.6)、内部信息不下发(9.2);错误枚举与格式归 WP-3;阶段二实现的第一个数据流出口即此条 |

补充(9.1 / 9.2):请求大小与嵌套深度限制、每租户限流与并发预算、审计记录归编排器实现(阶段二 / 三);本协议的一切拒绝路径都必须是确定性的(I-4),禁止按隐藏状态分支改变拒绝行为。
