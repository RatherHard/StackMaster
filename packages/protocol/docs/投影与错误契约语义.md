## 二、`PublicStateProjection` 与子类型

### 2.1 根 Schema(服务端 → 浏览器,整体 `PUBLIC`)

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `revision` | 整数 ≥ 0 | 服务端权威 revision(已执行非拒绝动作数,WP-1 I-5);投影版本锚点 |
| `visibleRegions` | 数组 ≤ 64 | 仅 ProjectionPolicy 白名单区域;隐藏区域**无占位、无条目、无计数**(D3 / I-9) |
| `visibleRegisters` | 数组 ≤ 32 | 仅白名单寄存器(I-3);值为教学观察对象 |
| `callStackSummary` | 数组 ≤ 64 | 调用栈摘要(D2 裁剪形态);超深以末帧 `truncated` 标记表达 |
| `controlFlow` | 对象(必填) | 当前指令与暂停事件(2.5) |
| `semanticHighlights` | 数组 ≤ 32 | 教学语义标注(2.6) |
| `status` | `running` / `paused` / `won` / `failed` | 权威状态的公开形态(D1);**`rejected` 不属于投影**,只属于 ActionResponse.status |

strictObject(I-1):投影同样是白名单校验对象(ZR-P1),未知字段在契约层即拒绝——不存在"忽略后接受"。

**消费形态**:动作响应携带 `ProjectionDelta`(增量,按"教学动作或关键事件"粒度,第十章);断线重连的 `sync-projection` 重发**最近一次完整投影**(9.1 sanctioned 路径),复用本 Schema。客户端只在首帧 / 重连 / 带 truncated 标记的增量后持有完整投影,平时以增量合并。

### 2.2 `VisibleMemoryRegion`

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `regionId` | 不透明标识符 | 公开布局 ID;错误解释(`explanation.regionId`)只能引用此处出现过的 ID(I-2) |
| `label` | 展示文本(1–128,拒绝控制字符) | 公开对象标签(公开描述包声明) |
| `startAddressHex` / `byteLength` | 地址 hex;整数 1 … 16 MiB | 可见区域边界(公开布局) |
| `permissions` | `^r?w?x?$` 非空 | **规范序**子集(`rwx` 合法、`wr` 非法)——同一权限事实只有一种字节形态,客户端不必做权限归一化 |
| `bytesHex` | 偶数长度 hex,≥ 1 字节 | 当前区域内容(经 maxBytesPerRange 裁剪后的可见字节) |
| `truncated` | 必填布尔 | 区域内容是否被裁剪;与 presence-only 标记(2.4)不同,区域级布尔是**常态字段**——"完整展示"也是需要显式表达的教学事实 |

### 2.3 `PublicRegister` 与值形态

- `name`:`^[A-Za-z_][A-Za-z0-9_]{0,31}$`(形态校验宽松——VM 模块设计允许题目自设寄存器名;**白名单成员资格由服务端按题目 VM Profile 在生成端强制**,契约层不做 I-3 判定);
- `valueHex`:`^0x[0-9A-F]{1,16}$`——**大写**十六进制(WP-1 §4.2 规范化输出面)。与入站侧宽松 hex(`[0-9a-fA-F]`)的不对称是**有意的**:投影是服务端单方生成的输出面,单一规范形态使 T-SC1 字节等价断言与 ZR-P3 确定性断言有稳定锚点;客户端永远不必解析小写形态。增量 `changedRegisters` 复用同一 Schema。

### 2.4 截断标记纪律(presence-only,WP-1 v1.2)

`PublicCallFrame.truncated`、`PublicEvent.truncated`、`DirtyRange.truncated` 均为 `z.literal(true).optional()`:**标记存在 = "其后还有被省略的内容",标记缺席 = 无省略**。显式 `false` 一律拒绝——布尔三态(有 / 无 / 明确没有)中的第三态不携带任何信息,却让生成端多一种可错形态。**不携带省略计数**:计数是可累计的侧信道量(D2 / D4,省略深度的精确值不进入公开面)。

### 2.5 `PublicControlFlow`

- `currentInstruction`(必填):`{ addressHex, text }`——当前指令的可见地址与反汇编文本(公开代码布局);
- `pausedOn`:`read` / `write` / `call` / `ret` / `exception` | `null`——**与 ActionRequest 的 `pauseOn` 枚举同源**(D5:暂停请求的触发类别与暂停原因的报告类别是同一张枚举表),可空表达"未因事件暂停"。

### 2.6 `SemanticHighlight` 与 `PublicEvent`

- `SemanticHighlight`:`kind` ∈ `buffer_start` / `return_address_slot` / `saved_rbp_slot` / `canary_slot` / `custom` + `targetRegionId`(须引用可见区域)+ 地址范围 + `label`。全部公开教学标注(栈帧布局教学的核心载体);`custom` 供题目声明公开自定义标注,不预留其他枚举值;
- `PublicEvent`:`seq`(动作内 0…255)+ `kind` ∈ `read` / `write` / `call` / `ret` / `syscall` / `exception` + 可选 `addressHex` / `byteLength` / `payloadHex` / `truncated`。`payloadHex` 与 `byteLength` 同时存在时长度必须一致(Zod superRefine,§六);值来源约束(I-10:只承载玩家输入或可见内容)由生成端强制,契约层只校验形态。

## 三、`ProjectionDelta` 增量语义

### 3.1 字段(整体 `PUBLIC`)

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `revision` | 整数 ≥ 0 | 增量目标版本;**必须等于信封 revision**(ActionResponse superRefine,§六) |
| `dirtyRanges` | 数组 ≤ 256,**必填**(可空) | 可见写入的合并范围(3.2);无写入携带空数组(字段恒在,I-8) |
| `changedRegisters` | 数组 ≤ 32,**必填**(可空) | 值发生变化的白名单寄存器新值子集;无变化携带空数组 |
| `controlFlow` / `status` / `callStackSummary` / `semanticHighlights` | 可选 | **整体替换语义**:存在即整体替换客户端缓存中的对应部分;缺席 = 该部分无变化 |

可选字段的存在性确定性(I-4):字段出现当且仅当该字段在本次动作中发生了可观察变化,是 `(动作, 执行前可见状态)` 的确定性函数,禁止按隐藏状态分支选择形态。

### 3.2 `DirtyRange` 与合并规则

`{ regionId, startAddressHex, bytesHex, truncated? }`。`dirtyRanges` 是"本次动作可见写入列表"经**合并规则**(相邻 / 重叠归并为极大连续区间)得到的确定性函数——服务端维护 dirty range 合并连续写入,不逐条指令发完整投影(第十章)。对不可见地址的写入被 I-9 统一拒绝,永不产生 dirty range:探测扫描无法借 dirty range 绘制隐藏区域边界。

**字节预算(D3)**:单增量 `dirtyRanges` 字节总数 ≤ `MAX_PROJECTION_BYTES_PER_REVISION = 8192`;单 range 生效上限由策略 `maxBytesPerRange`(默认 256,协议上限 4096)收紧。真实写入超预算时,服务端按**地址升序**承载至预算耗尽、对最后一个 range 打 `truncated` 标记(不含省略字节数);客户端收到带标记增量后以 `sync-projection` 重新对齐。契约层的求和校验(superRefine,§六)拒绝的是"生成端未按预算裁剪"的缺陷增量。

## 四、`PublicError`:错误码与可解释错误格式

### 4.1 结构(整体 `PUBLIC`)

```text
PublicError {
  code: 16 值冻结枚举,
  message: 1–512 字符静态最小文案,
  addressHex?: 地址 hex | null,     // 逐 code 形态见 4.3 能力矩阵
  explanation?: {                    // 逐 code 字段白名单见 4.3
    regionId?, permissions?, valueHex?, interpretedAs?,
    alignmentBytes?, expectedBytesLength?, actualBytesLength?, hints?
  }
}
```

可解释性是本项目教学价值核心(计划书 4.4):educational 级错误向玩家解释"这个值被如何解释、为什么被拒绝"。但解释字段全部由**可见状态**参数化(10.1 矩阵 / I-10),逐 code 允许面由 `ERROR_CODE_CAPABILITIES` 能力矩阵冻结并在 superRefine 中机检——矩阵之外的组合在契约层即拒绝,杜绝"解释字段夹带私有信息"的实现事故。

**coarse / educational 的区别不在 Schema 形态,而在生成端**:同一 Schema 下,coarse 级载荷只填 `code` + `message`(解释字段整体缺席);`errorDetailLevel` 属于 ProjectionPolicy(§5.1),不进入 PublicError 契约。粒度选择按 `(code, errorDetailLevel)` 确定性生成,禁止按隐藏状态分支(I-4)。

**E-6 分工**:`message` ≤ 512 是"静态模板 + 参数展开"的上限;值级违规(内部堆栈、文件路径、隐藏区域名、capability 名称等)由 ZR-B7 语料扫描承接——Schema 宽度与值级扫描各管一半,Schema 不试图用正则表达"什么字符串像内部路径"。

### 4.2 16 个错误码(计划书 4.4 全覆盖)

教学动作类(计划书 4.4 九类形态逐一对应):

| # | code | 计划书 4.4 类别 |
|---|---|---|
| 1 | `invalid_input_format` | 输入格式错误 |
| 2 | `invalid_payload_length` | payload 长度错误 |
| 3 | `offset_out_of_range` | 偏移不足或过长 |
| 4 | `endianness_mismatch` | 端序错误 |
| 5 | `permission_denied` | 权限错误 |
| 6 | `invalid_rip` | 非法 `RIP` |
| 7 | `canary_violation` | Canary 破坏 |
| 8 | `invalid_call_argument` | 参数寄存器错误 |
| 9 | `objective_not_met` | 目标条件未满足 |

协议与引擎类:10 `inaccessible_address`(不可见地址,I-9 统一形态)、11 `budget_exhausted`(资源预算)、12 `stale_base_revision`、13 `stale_client_seq`、14 `idempotency_conflict`、15 `session_terminal`、16 `internal_error`(引擎内部错误,含溢出安全终止的外露形态,ADR-8)。

### 4.3 逐 code 能力矩阵(冻结,superRefine 机检)

`addressHex` 四种形态:

- **forbidden**:字段必须整体缺席(显式 `null` 也拒绝)——协议级拒绝类没有内存语境,"缺席"即"无地址"的唯一确定性形态;
- **null-only**:恒为 `null` 统一占位(I-9:不可见访问不区分隐藏映射与未映射;M-3 抉择选 JSON null 而非伪 hex 常量——伪 hex 会被客户端当真实地址渲染);
- **free**:真实地址 | `null` | 缺席,由 `(code, 可见状态, errorDetailLevel)` 确定性选择;真实地址须落在可见区域(E-2);
- **required-real**:必须携带真实可见地址(权限 / Canary 教学解释的地址锚点)。

| code | addressHex | explanation | 允许的解释字段 |
|---|---|---|---|
| `invalid_input_format` | forbidden | optional | `hints` |
| `invalid_payload_length` | free | optional | `regionId`、`expectedBytesLength`、`actualBytesLength`、`hints` |
| `offset_out_of_range` | free | optional | `regionId`、`expectedBytesLength`、`actualBytesLength`、`hints` |
| `endianness_mismatch` | forbidden | optional | `valueHex`、`interpretedAs`、`hints` |
| `permission_denied` | **required-real** | optional | `regionId`、`permissions`、`hints` |
| `invalid_rip` | free | optional | `regionId`、`permissions`、`valueHex`、`interpretedAs`、`alignmentBytes`、`hints` |
| `canary_violation` | **required-real** | optional | `regionId`、`valueHex`、`hints` |
| `invalid_call_argument` | forbidden | optional | `valueHex`、`hints` |
| `objective_not_met` | forbidden | **forbidden** | —(E-4 恒为零解释:不泄露目标匹配进度,I-7) |
| `inaccessible_address` | **null-only** | optional | `valueHex`(玩家自供目标值的回显)、`hints` |
| `budget_exhausted` | forbidden | **forbidden** | — |
| `stale_base_revision` | forbidden | **forbidden** | — |
| `stale_client_seq` | forbidden | **forbidden** | — |
| `idempotency_conflict` | forbidden | **forbidden** | — |
| `session_terminal` | forbidden | **forbidden** | — |
| `internal_error` | forbidden | **forbidden** | —(内部细节只进受控日志,9.1) |

解释字段取值来源约束(E-3,生成端强制):`expectedBytesLength` / `alignmentBytes` 的值来源 ⊆ {协议级公开上限、公开描述包预算、可见区域边界、对齐常量};`actualBytesLength` / `valueHex` 是玩家自供内容(回显无害,I-10);`hints` 为服务端静态模板教学提示(检查 padding、little-endian、`RSP` 位置,10.1),≤ 4 条、单条 ≤ 256 字符,禁止谓词信息与 E-6 禁项。`alignmentBytes` 只接受 `1 | 2 | 4 | 8` 字面量。

### 4.4 与响应信封的耦合(冻结)

`status: "rejected"` 时:`userVisibleError` 必有、`projectionDelta` 恒 `null`、`publicEvents` 恒空(拒绝动作不产生投影与事件,且必须可解释)——Zod superRefine + 落盘 JSON Schema `if/then` 双侧同步(§六)。教学性失败(已执行动作,如写不可写区域)不属 rejected:revision 前进、投影增量承载变化,错误经 `userVisibleError` 携带(WP-2 §4.5 响应形态表)。

## 五、ProjectionPolicy、版本策略与引擎进程复用

### 5.1 `ProjectionPolicy`(server-only 专用面)

```text
ProjectionPolicy {           // 整体 rootClass = server-only(WP-1 §4.5)
  visibleRegions:  不透明标识符数组 ≤ 64,
  visibleObjects:  不透明标识符数组 ≤ 64,
  visibleRegisters: 寄存器名数组 ≤ 32,
  maxBytesPerRange: 整数 1…4096(默认 256 为策略取值,非协议字段),
  errorDetailLevel: "coarse" | "educational"
}
```

**"Schema 存在不等于可下发"**:本 Schema 虽落盘入库(供 Rust 侧 challenge-compiler / verifier 消费),但 Zod Schema 只从 `@stackmaster/protocol/server-only` 子路径导出,**不经包入口进入任何浏览器可达构建图**;落盘产物打 `x-sm-class: "server-only"` 标记;dependency-cruiser 规则 `protocol-server-only-backend-consumers-only` 禁止后端三包(challenge-compiler / session-api / verifier)之外的工作区包导入该子路径(WP-1 §五)。策略随题目版本锁定(9.1):同一会话内策略不变,投影形态可复现。

空白名单合法(全隐藏投影,verifier 独立重放场景可表达)。

### 5.2 `protocolVersion` 策略(5.6,成文)

- 投影与错误契约**不设独立版本号**:三者(`ProjectionDelta` / `PublicError` / `PublicStateProjection`)只经 `ActionResponse` 信封与 `sync-projection` 下发,随**会话动作协议**版本(`SESSION_ACTION_PROTOCOL_VERSION = 1`)演进——客户端解释响应所依据的版本即其请求携带的 `protocolVersion`(WP-2 §5.2);
- **破坏性变更**(字段删除 / 改名 / 类型或语义变化、枚举值增删——含错误码增删)递增会话动作协议版本,新 Schema 落新目录(`…/session-action/v2/`);**兼容窗口**:过渡期服务端按路由同时接受 N 与 N-1 两个版本(各自独立 Schema 校验),窗口期结束下线旧版;窗口时长为实现期运维参数(阶段三);
- 非破坏性变更(追加可选字段)仍须走 WP-1 §1.3 流程并更新 fixture,但不强制递增版本;
- `$id` 目录由版本常量派生(`schema-drift` 测试断言),版本切换时旧目录冻结不回改。

### 5.3 引擎进程复用声明(5.6 第 4 类契约)

**编排器 / verifier ↔ vm-worker 复用本文全部 Schema,不另造私有格式**:

- vm-worker 进程协议(stdio / 本地 socket JSON)的投影、错误与增量消息形态即 `PublicStateProjection` / `PublicError` / `ProjectionDelta`;编排器对 vm-worker 输出**按同一契约重新校验**(5.6)后才能进入下发通道——脱敏与白名单过滤在执行域内完成(ADR-7),编排器与浏览器上只允许出现公开投影;
- verifier 复用同一份回放引擎与投影生成实现(ADR-8:禁止第二套实现),其独立重放产生的投影 / 错误与交互路径字节一致(T-SC1 断言的前提);
- 协议版本策略同 §5.2:引擎进程协议与会话动作协议共享本文 Schema 面,独立版本号在阶段二接线时按 5.6 登记(不共用编号空间,但 Schema 来源唯一)。

## 六、superRefine 与 JSON Schema 的表达力边界(TS / Rust 双侧一致性)

**实验结论(WP-3 任务 #1)**:`superRefine` 对 `z.toJSONSchema` 透明——跨字段 refinement 不进落盘产物。处置分三类:

| 规则 | TS 侧 | JSON Schema 侧 | Rust 侧一致性来源 |
|---|---|---|---|
| `rejected` 耦合(必有 error、delta null、events 空) | `ActionResponseSchema.superRefine` | **`if/then` 显式注入**(generate.ts,`ACTION_RESPONSE_REJECTED_COUPLING`;schema-drift 测试冻结注入形态) | 落盘 Schema 直接表达 |
| `ProjectionDelta` 字节求和 ≤ 8192 | `superRefine` 求和 | 不可表达 | golden fixture:边界正例(恰 8192)+ 超限反例(`projection-delta/invalid/05`) |
| `ActionResponse` 增量 revision === 信封 revision | `superRefine` 比较 | 不可表达 | golden fixture:正例 + 反例(`action-response/invalid/11`) |
| `PublicEvent` payloadHex 长度 === byteLength | `superRefine` | 不可表达 | golden fixture:正例(`action-response/valid/01`)+ 反例(`action-response/invalid/12`) |
| `PublicError` 逐 code 能力矩阵 | `superRefine`(矩阵机检) | 不可表达 | golden fixture:**每种违规形态至少一个反例**(`public-error/invalid/03`–`09`) |

纪律:TS 侧 superRefine 与 JSON Schema 注入形态**必须同步修改**(generate.ts 注释锚定);Rust 侧校验器以落盘 JSON Schema + golden fixture 双输入实现等价拒绝,WP-6 已收口:"同一样例集双侧同结论"断言在 `tooling/contract-smoke`(冒烟 §2,2026-09-05)。fixture 命名即违规原因登记(`invalid/NN-<violated-rule>.json`),使每条不可表达规则都有具名承接。
