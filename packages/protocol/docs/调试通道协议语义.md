## 一、范围与冻结清单

本 WP 冻结:

1. 调试通道信封(六字段,8.2 基线同形)与 12 值封闭帧类型判别联合(`schema/debug-frame.schema.json`);

## 二、信封与字段分类

### 2.1 `DebugFrame` 信封(整体 `BOUNDARY`;字段分类:WP-1 清单 §6.8)

| 字段 | 类型(冻结) | 语义与规则 |
|---|---|---|
| `protocolVersion` | `const 1` | 调试通道协议版本;连接级锚定:首帧定版,漂移拒绝(§四) |
| `type` | 12 值封闭枚举 | 方向由类型唯一决定(§三);未知类型契约层拒绝,扩展 = 调试协议版本演进 |
| `sessionId` | 不透明字符串(1–128) | 帧绑定会话:必须与连接绑定凭证的会话一致,不一致拒绝(同一 Cookie 凭证模型,复用认证实现) |

### 2.2 `DebugVariantBundle`(整体 `SERVER_ONLY`;字段分类:WP-1 清单 §6.9)

编排器(WP-41 session-api 组装)↔ 调试 worker 进程间契约;浏览器永不可见,仅经 server-only 子路径导出。字段表、结构性排除(无 `judgingConfig` / 隐藏测试 / seed 值字段)与整体级论证见 WP-1 清单 §6.9;draws 计数语义见 §七。

## 三、帧族(12 值,逐一冻结)

帧名即 wire 记法(snake_case,与 12 动作 `type` 同记法纪律)。方向由类型唯一决定:客户端 → 服务端类型出现在服务端发送侧、或服务端 → 客户端类型出现在客户端发送侧,均属契约违规(接收端方向检查,V-6 同纪律;fixture 红灯以 type ↔ payload 错位形态锁定——判别联合使"方向错误的载荷形状"无法被对侧解析)。

### 3.1 客户端 → 服务端(5 帧)

| 帧 | payload(冻结) | 语义 | 服务端重新校验点 |
|---|---|---|---|
| `debug_attach` | `{origin: {kind: "revision", revision} \| {kind: "checkpoint", checkpointId}}` | 绑定会话并请求重放对齐(§四);起点二选一由 `origin` 判别联合以**结构表达互斥**(不依赖跨字段规则,TS 与 Rust 校验结论一致) | 会话归属、调试 entitlement(WP-43 `debugMode` 声明面)、重放对齐可行性 |
| `debug_window` | `{addressHex, byteLength(1..4096)}` | 任意地址窗口读取(D3 对公开投影维持冻结,任意窗口仅存在于调试通道) | 地址 ∈ 变体镜像映射面;`byteLength` ≤ 协议上限(超限契约层即拒) |
| `debug_step` | `{}` | 调试实例单步执行恰好一条指令(步数不作动作自由度暴露,与 12 动作 `step` 同纪律) | 调试实例自身资源预算(共用每会话动作预算,§五) |
| `debug_run_to_breakpoint` | `{breakpoints: AddressHex[1..64]}` | 运行直到命中任一地址断点后暂停(`debug_paused` 回执);预算耗尽确定性暂停(reason = `budget`) | 断点数量 ≤ 协议上限;步数 / wall-clock 预算 |
| `debug_search` | `{patternHex(偶长 hex,1..256 字节), maxHits?(1..256)}` | 全内存字节检索;`maxHits` 缺省 = 服务端上限 `DEBUG_SEARCH_MAX_HITS` | 模式非空偶长(奇数 hex 契约层即拒);命中数预算 |

### 3.2 服务端 → 客户端(7 帧)

| 帧 | payload(冻结) | 语义与生成纪律 |
|---|---|---|
| `debug_attached` | `{revision, status, paused?: {addressHex}}` | attach 完成 + 重放对齐后的状态回执:`revision` = 对齐后的调试实例 revision(重放进度锚点),`status` 与 PublicStatus 同枚举,`paused` 出现 = 对齐后处于暂停态(暂停落点地址) |
| `debug_window_data` | `{addressHex, bytesHex, truncated?}` | 窗口读取回执;`bytesHex` 值来源 ⊆ 变体镜像内存(零装载保证公开性);`truncated` 为 presence-only 标记(出现即 `true`,不含省略字节数,§4.3 DirtyRange 同款):窗口跨区域边界或触达服务端生效上限时出现 |
| `debug_paused` | `{reason: step\|breakpoint\|program_halt\|budget, addressHex}` | 执行暂停事件回执:`step` = 单步落点,`breakpoint` = 断点命中,`program_halt` = 程序自行停机(exit / 停机指令),`budget` = 步数 / wall-clock 预算耗尽的确定性暂停(与 `run_to_event` 预算语义同形态:不产生部分推进的假象) |
| `debug_search_results` | `{hits: [{addressHex, bytesHex}]≤256, truncated?}` | 全内存检索回执;`hits[].bytesHex` = 命中处字节回显(与请求 `patternHex` 等长;等长性为生成端义务,超出 JSON Schema 跨字段表达力,由 fixture 与 WP-44 包含性机检兜底);按地址升序确定性排序,超限截断以 presence-only 标记表达 |
| `debug_instruction_stream` | `{instructions: [{addressHex, bytesHex?, text, jumpTargetHex?}]≤256, truncated?}` | 伪指令流批量回执(按需分批拉取):`text` 为服务端生成的伪汇编展示文本(≤ 128 字符,PublicText 同纪律),`bytesHex?` = 该地址处公开代码区字节,`jumpTargetHex?` = 跳转目标(仅控制转移条目出现,pwndbg 式跳转链承载面)。**展示数据非可执行 IR**:源 = 公开代码区字节,引擎 IR 不出进程(D5 边界在调试通道同样适用,ADR-DC1 条款 8) |
| `debug_function_table` | `{functions: [{label, startAddressHex, byteLength}]≤256, truncated?}` | 函数表回执:服务端从公开代码区符号面生成的函数边界与标签(`label` ≤ 128 字符,PublicText 同纪律) |
| `error` | 冻结 `PublicError` | 错误帧 = 冻结 `PublicError` 形态,16 错误码封闭枚举**零扩展**:请求侧校验失败(地址不可达 / 模式非法 / 超上限)复用 `invalid_input_format` 等;预算耗尽复用 `budget_exhausted`(429 冻结形态两边一致);通道级失败(未认证 / 畸形帧 / 频率超限)同样只产出该形态,零校验器细节透出(基线 #8 通道面)。逐 code 能力矩阵(E-1–E-6 / I-8)在调试通道原样适用 |

## 四、连接生命周期与锚定

1. **连接建立**:独立 WSS 端点,同一 Cookie 凭证模型与会话锚定(复用认证实现,ADR-DC1 决议 3);升级前完成凭证认证,帧内无身份字段;
2. **连接级版本锚定(同款自建)**:首帧 `protocolVersion` 即本连接的解释版本,此后任何帧携带其他版本一律拒绝;响应帧不携带新版本(信封按请求版本解释);受理集合锚点 `SUPPORTED_DEBUG_CHANNEL_PROTOCOL_VERSIONS`(N-1 窗口约定同会话动作协议 §5.2 形态);心跳走 RFC 6455 协议层 ping/pong,不设应用层心跳帧(D-API-6 同款);
3. **attach 与重放对齐**(ADR-DC1 条款 3):attach 后编排器将调试实例从动作日志 revision 0(或 checkpoint 对应的日志位置)确定性重放到请求起点,以 `debug_attached` 回执对齐态。动作日志(类型 + 参数)是玩家输入,属公开面,重放对齐不携带秘密;**禁止把真实 checkpoint 快照恢复进调试进程**(快照含秘密)——`checkpoint` 起点只是日志位置引用,不携带快照字节;
4. **调试交互不进权威日志**(条款 4):调试侧执行只改调试实例;append-only 权威动作日志仍只含真实会话动作;verifier 回放面与 `replay_mismatch` 语义零改动;
5. **方向与串行**:每连接双向帧序 = 发送序;服务端按到达序串行处理调试实例指令(`seq` 只承担传输层关联,防重放与串行由连接状态承担);
6. **单帧大小**:沿用 `MAX_WSS_FRAME_BYTES = 1048576`(1 MiB 外圈护栏,与本包 WSS 通道同值);超限在 JSON.parse 前拒绝,走冻结 `PublicError` 错误帧。

## 五、限额关系与 what-if 纪律

- **限额共用**(ADR-DC1 条款 6):调试动作与解题动作共用同一套每会话动作频率预算(D-API-50~53),**不设第二类限额**;指令粒度的调试步进会产生大量帧,与解题互相挤占预算——后果登记以 `/metrics` 观察后调参;预算耗尽以冻结 `budget_exhausted` 错误帧拒绝(429 冻结形态两边一致);
- **what-if 纪律**(条款 7)是 UI 呈现义务,不是帧字段义务:调试通道下发的数据本身可公开(零装载保证);"调试通过 ≠ 提交通过"的不可误读、ASLR 开启时硬编码绝对地址跨实例失效的教学语义,由前端渲染纪律与 WP-F8 验收承接,不进入本契约面;
- **ASLR 基址差异**(R1):调试实例是"同结构、异基址"的兄弟实例(开启时),`debug_window` / `debug_instruction_stream` 下发的绝对地址是调试实例地址——这是 what-if 语义的组成部分,不是泄露面(调试域内无真实秘密)。

## 六、跨字段规则载体(红线 fixture 对照表)

本协议**零 TS-only 跨字段规则**:所有互斥与条件规则均以 JSON Schema 可表达形态承载(结构判别联合 / 生成管线 if/then 注入),保证 TS(Zod)与 Rust(jsonschema + semantic)对同一组样例**同判**。规则载体明细:

| # | 规则 | 载体 | 红灯 fixture |
|---|---|---|---|
| 1 | 帧类型封闭 + type ↔ payload 耦合 + 信封字段白名单 | 判别联合 + strictObject(结构) | `debug-frame/invalid/01-unknown-type.json`、`03-type-payload-mismatch.json`、`07-unknown-payload-field.json`、`06-unknown-envelope-field.json` |

| 4 | 窗口上限 `DEBUG_WINDOW_MAX_BYTES` = 4096 | `.max()`(结构) | `debug-frame/invalid/04-window-over-cap.json` |
| 5 | 检索模式非空偶长 hex | `.regex` + `.min(2)`(结构) | `debug-frame/invalid/08-search-odd-pattern.json` |
| 6 | 断点数组 ≥ 1 且 ≤ `DEBUG_MAX_BREAKPOINTS` | `.min/.max`(结构) | `debug-frame/invalid/09-breakpoints-empty.json` |
| 7 | 地址 / 标识符形态(hex 0x 前缀、OpaqueId 字符集) | 公共 Schema pattern(结构) | `debug-frame/invalid/10-window-bad-address.json`、`12-bad-seq.json` |
| 8 | 变体 strictObject 排除面:`judgingConfig` / `seed` 等未知顶层字段即拒 | strictObject(结构) | `debug-variant-bundle/invalid/01-contains-judging-config.json`、`02-contains-seed-field.json` |

## 七、调试变体镜像契约定案(供 WP-41 / WP-42 并行对接)

### 7.1 字段表(冻结)

| 字段 | 类型 | 语义 |

| `challengeContentVersion` | semver(X.Y.Z) | 题目内容版本(与双包同一冻结格式) |

| `memoryRegions` | `[{regionId, kind, startAddressHex, byteLength, permissions, contentHex, isHidden}]`(1..64) | 与真实镜像逐字段同构:`kind` ∈ code/global/stack/heap/key/custom,`byteLength` 1–16 MiB 且 4096 倍数(VMA 页对齐),`permissions` = r/w/x 规范序子集,`contentHex` = 非空偶长 hex;ASLR 关 ⇒ `startAddressHex` 与真实镜像一致,开 ⇒ 调试派生基址 |
| `registers` | `[{name, valueHex}]`(1..256) | 变体初始寄存器;名称模式与题目寄存器声明面同一冻结模式(双命名空间保留模型) |
| `canarySlots?` | `[{objectId, kind: "canary", addressHex, byteLength(1–8), visibility, containsSecret}]`(≤64) | canary 槽位清单,照真实私有包 canary 对象结构;**值已派生**:期望字节写入所属区域 `contentHex`,槽对象不携带值(与真实 canary"期望值引擎初始化时从初始内存截取"同构) |

**结构性排除**(strictObject 即拒):无 `judgingConfig`、无隐藏测试(`hiddenTests` / `judging`)、无 seed 值字段(`seed` / `seedHex` / `seedPolicy`)。

### 7.2 draws 规范槽序(冻结,双方照此实现)

`derivation.draws` = 变体构造时 `SeedDeriver::next_u64`(`splitmix64-stream-v1`)的调用总数(声明值;与回放元数据 `DerivationPathSummary.draws` 同语义,不含种子值)。派生消费按以下**规范槽序**进行,TS SeedDeriver(WP-42)与任何复算方(确定性属性测试、机检)必须按同一序消费:

1. **基址槽**(仅 `aslrEnabled = true`,恰 1 次 draw):派生调试实例基址种子值;页对齐与逐区域基址偏移策略归 WP-42 实现(契约面只有次数与顺序);
2. **区域秘密槽**(按 `memoryRegions` **数组序**):对每个由派生生成内容的隐藏区域(编译器裁量派生面),每槽消耗 `ceil(区域 contentHex 字节数 / 8)` 次 draw;每次 draw 产 64 位,小端字节序取前 8 字节,尾块取低位有效字节;
3. **canary 槽**(按 `canarySlots` **数组序**):每槽消耗 `ceil(byteLength / 8)` 次 draw,取字节序同上。

槽序写死为数组序(规范序):`memoryRegions` 数组序 + `canarySlots` 数组序,双方不重排、不并行化。契约层可校验的耦合只有 §六 #10–#12 三条(ASLR ⇄ baseAddresses / draws 下限 / canary 可见性);"draws 与槽数的精确对应"超出 JSON Schema 表达力,由 WP-42 的确定性属性测试(同种子同序列、同槽序同字节)与结构同构断言承接。

### 7.3 对接注意事项(转 WP-41 / WP-42)

- **WP-41(session-api 侧组装 / 消费帧族)**:组装时 `challengeId` / `challengeContentVersion` / `vmProfileVersion` 必须取自会话锁定的题目身份三元组;`engineProcessProtocolVersion` 用既有常量;attach 起点的 `checkpoint` 分支只引用日志位置,禁止真实快照字节入调试进程;attach → 重放对齐 → `debug_attached` 回执的集成测试以本契约 fixture 为样例底座;
- **WP-42(challenge-compiler 侧产出 / SeedDeriver)**:`memoryRegions` 字段集与私有包 `initialState.memoryRegions` 逐字段同构是"结构逐字节同构断言"的依赖面,不得增删字段;canary 期望值不落在 `canarySlots` 条目上,而是写入所属区域 `contentHex`(断言时从区域切片比对);`draws` 按 §七.2 规范槽序消费并在契约中如实登记;秘密槽值与真实值不同断言(双种子差分)在本契约样例上展开;
- 双方共同:`algorithmId` 引用 `DEBUG_VARIANT_SEED_ALGORITHM_ID` 常量(不硬编码字符串字面量);变体镜像不落浏览器可达构建图(server-only 子路径纪律,dependency-cruiser 强制)。

## 九、推流时机(推送模型定案;阶段四轨道 B 增补,2026-09-11)

协议 v1 的 C→S 帧族**无拉取请求帧**(§三.1 五帧封闭);`debug_instruction_stream` / `debug_function_table` 是 S→C 展示帧,其触发面 = 服务端**推送模型**定案:

| 触发 | 推送帧 | 帧序确定性 |
|---|---|---|
| attach 完成(`debug_attached` 下发之后) | `debug_function_table` 恰一次 | `debug_attached` → `debug_function_table` →(若 `debug_attached.payload.paused` 存在)当前暂停地址的 `debug_instruction_stream` |
| 每次暂停(`debug_paused` 下发之后,含 attach 携带的 paused) | `debug_instruction_stream` 恰一帧 | `debug_paused` → 暂停落点地址(`payload.addressHex`)的 `debug_instruction_stream` |

- **maxItems 服务端常量**:每次暂停推送的指令上下文条数 = `DEBUG_CONTEXT_INSTRUCTION_ITEMS = 16`(服务端常量,远低于协议 caps `DEBUG_INSTRUCTION_STREAM_MAX_ITEMS = 256` 的单帧批量上限;本协议无 C→S 拉取帧,推送是唯一触发面,不存在客户端请求侧的 `maxItems` 自由度);
- **requestId 定案**:`debug_function_table` / `debug_instruction_stream` 推送帧**不带 `requestId`**(S→C 主动推送语义,非任何请求的应答);唯一例外 = `debug_attach` 主帧携带 `requestId` 时,其伴生的 `debug_function_table` 推送帧回显该值(attach 应答族的伴生上下文);`debug_instruction_stream` 推送帧一律不带(含 attach 携带 paused 触发的推流)。信封其余字段(protocolVersion 连接锚定版本、sessionId、seq 严格递增)与 §二 / §四 同纪律;
- **展示条目线形**:worker 对展示条目缺席的可选字段(`bytesHex` / `jumpTargetHex`)序列化为 `null`,本契约要求"缺席而非 null"(`strictObject` + optional,§三.2)——服务端发射点归一化为字段缺席(条目其余字段原样,零内容推导),归一化后逐帧过冻结 `DebugFrameSchema`(WP-44 发现的线形差异在本点收敛);
- **推送失败呈现**:编排器域失败照帧处理同形——冻结 `error` 帧(16 错误码封闭枚举零扩展)+ 连接不断(推送只降级展示上下文可见性,不影响已下发的主帧回执与连接存活)。
